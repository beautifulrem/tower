## 1. 总评

**第 96 轮的 1 条重要条目与 5 条次要条目都已按所问关闭**（核对见 §3）。§5 的 9 条观察全部落地。回应 “偏离与未决” 的八条中，六条接受，两条部分接受：一条是卫星之内的放宽，带出 R97-D11-01；另一条是超时证据，取舍接受、标注带出 R97-D7-01。

**ADR-224 的结构性写法成立**（§3.3）：
- **回退位置的除外**：只在密钥路径表的 `~/.tower/**` 一项定义一次，对本 Goal 的一切工具适用。`10` L547 与 `11` §11.3.4 (2) 都改为引用它，R96-D11-01 所述的审批风暴不再发生。
- **钥匙串一行成为唯一清单**：安装器的安装阶段在列，硬链接一行引用它。T7、`07` L622 与 A3 同步。
- **无锚定模式以写允许范围为界分两侧**：
  - 之外处处匹配，撤回了 ADR-223 的收窄，R96-D11-03 (1) 的四种后果都消失；
  - 之内的跟踪状态取自 base 树，来源确定。
- **每个 Host 一个临时目录**：观察器不再追踪流式更新，删除改由目录的生命周期保证。Pi 一侧的两种边缘与 Host 的预合并、背压都不再影响删除。
- **准入检查 h**：等待中的 Goal 有了合法状态 `ready{slot}`。探测失败与 “未被拒绝” 同一去向。
- **情形 E 的另一半**：复用 Tower 自动改名保留，从不删除。

**卫星之内的放宽**（对探查点的回答）：
- **ADR-165 的理由在自动路径上成立**：
  - 名字形如凭据的本地文件按名字判为机密、不可取消，不播种；
  - 交还与带回排除清单中的机密文件，也排除被 git 忽略的路径；
  - `$GS/npmrc` 是白名单净化副本；
  - 钥匙串在 S2 中拒绝，bash 的环境是白名单；
  - base 中被跟踪的 env 文件按普通文件处理，读取经密钥扫描，与 ADR-078 一致；
  - S0 下与此前相同，第 3 条硬底线先于例外。
- **写明的理由不完整**：“S2 对它们的读拒绝只拦住 Agent 读自己写的东西” 不全为真。至少还有两条路径会把真实凭据写进写允许范围：
  - 人在人工编辑检出中放入、既不在本地文件清单中也不被 git 忽略的凭据形文件，经交还或带回写入卫星；
  - 沙箱外工具（用户扩展、MCP 服务器，以用户权限运行）写进卫星的凭据文件。

  此前它们由 S2 读拒绝兜住，现在 Agent 运行的程序可以不经任何分类读到它们（R97-D11-01）。

**超时与中止命令的证据**：
- 取舍本身接受：验证器经自己的执行器在槽位中运行，不经 Pi 的 bash，验证结论的证据不受影响；`command_result` 是观测，不是判定。
- 但这类命令的 “完整日志” 现在只是 Pi 截断后的尾部，界面仍称 “完整日志”，`00` §0.5.1 没有登记（R97-D7-01）。

**ADR-224 带出、或本轮扫描发现的新问题**：
- **启动闸门的唤醒与适用范围**（R97-D6-01）：准入的重算时机不含 “闸门打开”；重启清理的终止范围、探测与检查 h 在只重启 Supervisor 时是否适用，都没有写。
- **Full output 路径的读取出读取凭据卡**（R97-D11-02）：Host 临时目录在 `~/.tower/**` 之下，bash 按 Pi 的提示读取全文文件时，分类为 `secrets.access`。
- **卫星之内放宽的理由漏算两条路径**（R97-D11-01）。
- **未同步的复述**（R97-D15-01）：“启动时清空 `~/.tower/tmp/`” 有四处没有加存活 Host 的例外，其中 G44 (c) 是一条正确实现也会失败的测试断言；`07` L1328 仍写卫星中未跟踪的 env 读拒绝。
- **超时证据的标注**（R97-D7-01）。

### D11 安全与自主度

**R97-D11-01｜次要**（卫星之内的放宽：写明的理由漏算两条真实凭据进入写允许范围的路径）

- **问题**：
  - ADR-224 的理由（`11` L167 (ii)，`15` ADR-224 R96-D11-03 (2)，回应 “偏离与未决”）是：卫星中不播种含机密的本地文件（ADR-165），名字形如凭据的未跟踪文件只会由 Agent、它运行的工具或人交还时写入，所以 S2 对它们的读拒绝 “只拦住 Agent 读自己写的东西”。
  - 复核：自动路径上这一前提成立（§1）。但下面两条路径会把**人或用户的真实凭据**写进写允许范围，而 S2 读拒绝此前恰好兜住它们。
    - **(a) 人工编辑交还与检验带回**：
      - 接管提示明确请人 “需要运行时请自行复制进来”（`10` L946）。
      - 交还第 5 步只按路径排除**本地文件清单中的**机密文件，并按忽略规则排除被忽略的路径（`10` L971）；带回排除本地文件排除集（`10` L922）。
      - 人放进来的凭据形文件若既不在清单中、也不被 git 忽略（例如本机生成的开发证书私钥），就进入 T1，写回卫星。
      - ADR-224 自己的列举也写了 “或你交还时写入”，但没有把它算进代价。
    - **(b) 沙箱外工具的写入**：
      - 用户扩展与 MCP 服务器在 S2 之外以用户权限运行（`11` L228），以卫星为工作目录或根（`05` L1022）。
      - 它们写进卫星的文件不受 S2 约束。例如一个拉取环境文件的工具，写出的就是真实凭据。
      - 一次 `tool.external` 的批准（或 Goal 内同类授权）之后，这样的写入就落在卫星中。
  - 写入之后：
    - Agent 运行的程序读取这些文件 “不经分类、照常成功”（`11` L167 (ii)），例如测试或应用启动时加载环境文件；
    - 只有 `cat` 一类直接读取才出单向门卡。
  - 致命三要素把写允许之内的这类文件 “不计为私有数据”（`11` L544），在 (a)(b) 两种情形下不为真。
- **为什么是次要**：两条路径都要人先做一步（复制文件，或批准沙箱外工具）。写明的不变式 “Tower 不会自动把机密交给 Agent 可影响的进程”（§11.7.0）不被违反；`11` §11.7 的 diff 扫描在进入 `in_review` 前仍会拦下提交中的密钥。但放宽的理由写成了一个全称判断，而实现与三要素的计算都以它为前提。
- **后果的类别**：人或用户级工具放进卫星的真实凭据，可被 Agent 运行的程序读取并进入模型上下文，没有任何告知；三要素警告在这种情形下少报。
- **文档位置**：`11` L164、L167、L228、L544；`10` L922、L946、L971；`05` L1022；`15` ADR-224；`round-96-response.md` “偏离与未决” 第一条。
- **期望的回答形态**（任选其一，都在已有的唯一定义处加一句）：
  - **结构性**：
    - 交还第 5 步与带回的写回集合中，名字命中 `isSecret` 名字模式、且在 base 中未被跟踪的路径，与清单中的机密文件同样排除（保留 T0 / T_pin 的版本，在交还结果中列出）。这样 ADR-165 的前提对人一侧成为真。
    - 沙箱外工具一侧，在 `11` §11.3.4 写明：它们写进写允许范围的凭据形文件不在 (ii) 的前提之内，三要素按 “加载了能写文件系统的沙箱外工具” 计为真（与 T7 的分级同口径）。
  - **如实写出**：把 (a)(b) 两种情形登入 T 表的残余与 `00` §0.5.1，并把 `11` L544 的 “不计为私有数据” 限定为 “未交还过、也未加载能写文件系统的沙箱外工具时”。

**R97-D11-02｜次要**（bash 按 Pi 的提示读取全文文件，分类为读取凭据，出单向门卡）

- **问题**：
  - Pi 截断 bash 输出时，在工具结果末尾写 `Full output: <path>`（`bash.ts:348-352`）；超时与中止时，错误文本中同样带这一行（`:371-381`）。模型按这条提示用 `cat`、`tail`、`sed -n` 读取它，是常见的行为。
  - ADR-224 之后这个路径在 `~/.tower/tmp/<hostId>/` 之下（`05` L473），因此：
    - bash 的读取命令按参数路径分类为 `read.*`（`11` L188），路径命中密钥路径表的 `~/.tower/**` 一项（L167），追加 `secrets.access`（L164：“bash 中路径能求出的这类读取命令同样如此”）；
    - 第 3 条硬底线对 bash 只 “由 S2 保证”（L219），分类上不 forbid；L164 “先后” 中硬底线先于例外的一句只写给文件工具。
  - 结果：
    - 标准修复与生产热修中，人收到一张带 S2 句子的读取凭据单向门卡，内容是 Agent “试图读取凭据”，而读的其实是它自己命令的输出；
    - spike、依赖升级与调研三种预设下直接 forbid。
  - ADR-224 之前，这个文件在系统临时目录中，同一读取只归 `read.external`，不出读取凭据卡。`~/.tower/mcp-cwd/<hostId>/` 也有同类关系，ADR-218 为它在路径检查中写了除外；Host 临时目录没有对应的处理。
  - 简报与 `05` 都没有告诉 Agent 这个提示所指的文件不可读。文件工具一侧有 “必然拒绝” 的返回文字（L164），bash 一侧没有。
- **违反的不变式**：读取凭据卡的含义——“让你知道 Agent 试图读取凭据”（ADR-125 的信号，`11` L164、`00` L105）。这类误报一旦频繁，信号就被稀释；R96-D11-01 中同类的稀释被定为问题。频率低于该条（只在截断且模型跟随提示时发生），也不阻断工作，所以定为次要。
- **后果的类别**：误报的读取凭据单向门卡，削弱凭据读取的告知价值；三种预设下 Agent 的正常排查被拒绝，没有改用的指引。
- **文档位置**：`11` L164、L167、L188、L219、L359；`05` L473；`07` L82–L91；`00` L105；`15` ADR-224；Pi `core/tools/bash.ts:342-352, 371-381`。
- **期望的回答形态**（一处唯一定义加一句，C42/G46 各补一组）：
  - 在 `11` L167 的 `~/.tower/**` 一项写明：各 Host 的临时目录不因这一项命中，与 stdio MCP 空目录同一处理。读写它们仍按第 3 条硬底线：文件工具 forbid、不出卡；bash 中路径能求出的读写同样带 `hardFloor`、不出卡，返回文字与 L164 的必然拒绝相同（“需要全文时重跑并重定向到 `$TMPDIR`”）。
  - 或者由 tower-goal 的 `tool_result` 钩子把结果中的 `Full output: <path>` 一行改写为这句指引（Tower 已在该钩子中做脱敏，`11` §11.7.1），使模型不再被引向一个不可读的路径。

### D6 系统架构与可靠性

**R97-D6-01｜次要**（启动闸门：打开时准入不重新计算；只重启 Supervisor 时的适用范围未写）

- **问题**：
  - **(1) 唤醒**：
    - `06` L298 列出准入重新计算的全部时机：“每当槽位释放、评审余量变化、依赖满足、或收到新请求时”。
    - 检查 h（L320–L321）在探测有结果、本 Goal 的终止一轮完成之前把 Goal 放在 `ready{slot}` 中；L145 写 Run “由 §6.2.4 的检查 h 在 `ready{slot}` 中等到清理结束”。
    - 冷启动时自动解除的 Goal 在首帧之后即请求准入（`13` §13.10，L283），而探测最长 10 s（`06` L1177），所以它们几乎都先落在 `ready{slot}` 中。
    - 探测有结果、或一个 Goal 的终止一轮完成时，上列时机一个都不发生；这时没有活跃 Run，也就没有槽位释放。照文字实现，排队的 Goal 会一直等到某个无关事件发生，而人在 `ready` 中没有可以重新触发准入的命令。
    - 验证、安装器与检验检出一侧写了 “有结果后按结果以 S2 或 S0 启动”（L296），Run 的准入一侧没有。
  - **(2) 只重启 Supervisor 时的适用范围**：
    - `06` §6.1.3（L63）写明 Supervisor 崩溃时 Engine Host 继续运行，重启后补齐事件、Run 继续。
    - 但 `06` L145 的终止范围是 “存在未结束 Run 的 `runs.process_token`”，L198 写 “Supervisor 或 Host 重启后” 执行，L116 写每次 Supervisor 启动都检查。照文字读，Host 仍存活、Run 仍在进行时，Tower 会终止这个 Run 的工具进程与后台服务，并对它显示 `清理中`、使 `goal.take_over` 返回 `E_BUSY`。
    - 终止范围是既有的写法，但 ADR-224 的检查 h 与 `清理中` 卡片现在以它为前提。
    - 探测 “本次启动”（L1177，`13` L325 “每次 Tower 启动”）在只重启 Supervisor 时是否重做，没有写。若重做且结果翻转为 S0，存活 Host 中的 Run 仍按 S2 运行，新的活动按 S0 启动——一种没有定义的混合姿态。
- **后果的类别**：
  - (1)：启动后排队的 Goal 长时间不开 Run，界面停在 `就绪 · 等待启动自检`。每次启动都会发生，没有数据丢失。
  - (2)：一种实现在 Supervisor 重启后终止正在运行的 Run 的进程（Agent 的命令失败、开发服务被杀）；另一种不终止。探测的翻转在存活 Host 上没有去向。
- **文档位置**：`06` L63、L116、L145、L198、L296、L298、L320–L321、L1177；`13` §13.10（L283）、§13.11.1（L325）；`12` L413。
- **期望的回答形态**：
  - (1) 在 L298 的重算时机中加 “本次启动的探测有结果、某 Goal 的终止一轮完成”。
  - (2) 在 L145 写明终止范围是 “Host 已不存在的未结束 Run 的令牌，以及未解决 `bg_process_survived` 的令牌”，存活 Host 中的 Run 不在此列。写明探测与检查 h 只在 main 冷启动时执行；只重启 Supervisor 时沿用 main 保存的本次结果（或重做探测，但翻转不影响存活 Host，直到它们退出）。

### 不扣分的观察

1. **界面与告知**：
   - 整机因探测转入 S0 时，`12` §12.6.6 只有通用的 `沙箱 S0 · 仅策略层 ◇` 徽标，原因只在 S0 审批卡与设置页诊断中出现。宜让徽标的悬停复用 `本机的沙箱未通过启动自检（硬链接）`，或明确不另作告知。
   - `12` L682 的硬链接 `EPERM` 说明宜限定为 “验证在 S2 中运行时”：在本身不支持硬链接的卷（如 exFAT）上，`link()` 同样返回 `EPERM`。
2. **情形 E 的告知与下一步**：
   - **外部写入的告知**：`10` L1264 对未解除的外部写入写 “随旧卫星丢失”，Goal 页写 “外部改动随工作目录丢失”。只丢了 gitdir 时，工作目录连同其中的外部写入已改名保留为 `<goalId>.kept-*`，这句不再为真，宜写 “未并入重建的工作目录，保留在 <路径>”。
   - **改名失败**：失败时 `satellite_missing` 的条目只有 “重试 / 放弃”。人移走该路径之前，重试不会成功；宜在条目中写出路径与 “移到一边后重试”。
   - **`.kept-*` 的信任提示**：“保留的目录” 中的 `_gitdirs/<goalId>.kept-*` 含 Agent 写过的 git 元数据，宜在列出处引用 `00` §0.5.1 中对 Agent 写过的仓库元数据的提示。
3. **情形 E 的顺序与触发**：
   - `06` L916 的 “按改名成功处理：置标记、重建，仍在原位的另一半按情形 E 重建的第一步改名保留” 读起来是先置标记、后改名，而唯一定义（`10` L1264）是改名在置标记的事务之前。照前者实现，若在两者之间崩溃，续做（L140）会把仍在原位的一半移入旁路目录并在成功后删除。宜改为 “先按情形 E 改名另一半，再在同一事务中置标记”。
   - 情形 E 自己的改名发生在置标记之前，`06` L139 的排除不覆盖这段窗口；③ 为自己的改名写了排除，情形 E 没有。持 `wtLock` 或写一句同样的排除即可。
4. **措辞与登记**：
   - `16` L22 `waitReason` 一行的 `slot` 注记只列 “机器资源 / 等待服务端口”，未列 “等待启动自检 / 残留进程”；反过来，`12` §12.6.5 有启动自检一行，没有机器资源与服务端口的文案。
   - `16` L727 仍写单一启动点 “M1 中它是架构约定……只保证将来能在一处加入调度约束”，而 M1 已有启动闸门。
   - `16` L914 自检一行没有 10 s 时限。
   - `06` L936 `goal.rebuild_satellite` 的步骤没有提另一半的改名（引用 `10`，只是措辞）。
   - `04` L1136 写 “工作目录中”，作用范围 (ii) 是整个写允许范围。
   - `11` L359 的 “被跟踪的 env 文件除外” 与 (i) 的 “不论跟踪状态” 并读不顺，宜限定为 “卫星中”。
5. **CA 证书包允许清单的覆盖**：
   - 工具自带的 CA 包不在清单中，如 Python certifi 的 `cacert.pem`、Homebrew Python 中 pip 自带的那一份，在 S2 中被 `*.pem` 读拒绝。A3 只测 Node、git 与 curl。这对 M1（只支持 Node）影响小，属于 M2 的校准；宜决定清单能否含 `**/certifi/cacert.pem` 这类名字规则。
   - 企业代理做 TLS 拦截时，用户常以 `NODE_EXTRA_CA_CERTS` 或 `cafile` 指向主目录中的 CA 文件。S2 中 Agent 与安装器读不到它，`$GS/npmrc` 的白名单也去掉了 `cafile`。回应写了 “本来就读不到”，正文没有登记。宜在 `00` §0.5.1 登记，或给出把它复制进 `$SH` 允许清单的路径。
6. **`mcpBaseEnv` 的 `TMPDIR`**：结论确定（§3.3），但须把三行连起来读。宜在 `05` L455 的定义中直接写 “含本 Host 的 `TMPDIR`”。
   - MCP 服务器与扩展写在其中的文件，现在对 Agent 的 `read` 与其他沙箱外工具都属于第 3 条硬底线，S0 下同样如此，并随 Host 退出删除。宜在 `00` §0.5.1 L105 补半句，并提示可在 `mcp.json` 中为该服务器设置输出目录。
7. **S0 下三要素的 “私有数据”**：`11` L544 “检查密钥路径表中的路径是否存在”。无锚定模式在写允许之外处处匹配，这无法逐路径扫描，宜写为 “按显式条目判定”（实际上几乎恒为真）。
8. **观察器与 Host 退出的先后**：
   - Host 退出即删除目录。观察器若还没处理该 Host 最后几条 `tool_execution_end`，这几条命令的全文复制会退回到截断文本。`07` L91 已写明接受，宜加一句 “删除在 Supervisor 处理完该 Host 已转发的结束事件之后”。
   - 打包模式下长寿 Host 的临时目录在退出之前没有上限，超时命令的全文也留在其中，`13` 的磁盘告警不覆盖它。
9. **扩展的转译缓存**：Pi 以 jiti 加载扩展，只设 `moduleCache: false`（`loader.ts:576-579`）。jiti 的文件缓存默认在 `os.tmpdir()` 之下，现在随每个 Host 删除，每次 Host 启动都会重新转译扩展。宜在 SP2 的 Host 启动测量中确认这部分开销，必要时为 Host 显式指定缓存位置（不在 Agent 可写的位置）。
   - `hostId` 宜保持短：它进入 `TMPDIR`，Unix 套接字路径在 macOS 上限 104 字节。
10. **A3 的档位数**：
    - `06` L1177 与 A3 的通过条件都写 “四种档位模板”；但检验检出用验证器档位（`10` L895），A3 的硬链接一组实测的是 Agent、验证器与安装阶段三种。宜写 “三种档位（检验检出与验证器同一档位）”，或在 A3 中补一次 `_inspect/<goalId>` 内的创建。
    - 探测一次超时就使整次会话转入 S0（已如实写出），A3 的 “测试构建的钩子让探测超时一次” 覆盖了这条路径。
11. **顺延规则的同步清单**：
    - `14` L399 的 “`00`、`14` §14.1 与本节同步” 中，`00` 不含 M1 的周数与日期；而顺延时会过期的 `16` L477（当前值 “38 个日历周 …… 第 34 周末冻结”）、`14` L600（E9 “M1 第 35 周（用第 34 周末的 M1 冻结构建）”）与甘特图都不在清单中。
    - 规则写 “顺延 1 周”。单次增量超过顺延后的余量（约 1.12）时，宜写 “至少 1 周，按 ADR-136 计”。
    - 增人备选在全职线上只剩约 0.06 人周的余地：合计 130.03 时 T = 24.01，需要 27 个工作周、34 周。规则对它没有说法，宜写一句它是否随之重算。
