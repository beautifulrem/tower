## 1. 总评

**第 89 轮的 3 条次要条目都已按所问关闭**（核对见 §3）。§5 的 12 条观察全部落地。回应 “偏离与未决” 的五条全部接受，但第一条的取舍带出观察 7，第五条所说 “没有第二份清单” 不成立（观察 1）。

**ADR-217 的主体成立**（§3.3）：
- **两个基准**：相对路径以 `roots` 与 `05` §5.3.5 求出的实际工作目录各解析一次，任一结果落在硬底线即 forbid（`11` L222 (b)）。
  - 例外只给 “工作目录是本 Host 空目录、结果仍在其中” 一种。以 `..` 越出空目录的结果照常判定。
  - R89-D11-01 所说的 “越出服务器实际的工作目录” 被挡住；R88-D11-02 的误判也没有回来。
  - 残余 “从不跨 Host” 因各 Host 的空目录都在第 3 条（写）之内而成立。
- **相对的 `config.cwd`**：一律以本 Host 的空目录为基准求出。含 `..` 的结果另不得落在硬底线之内（`05` L439），C21 补了三组（`05` L1461）。
- **`file:` URI**：按 RFC 8089 取路径、解码后照 (1)(2) 检查。非本地主机按不透明参数、至少 ask，与没有已知基准的相对路径同一口径（`11` L221），C21 补了一组。
- **置换的 `resume`**：列入窗口起点的封闭列表（`03` L75），`16` L38、`07` L1591/L1672 改为引用，`06` L865 的逐字引文由 (q) 比对。G26c (b) 补了失败一支（`14` L91）。
- **`hostId` 的先后规则**（`11` L222 (a)）：下一个 Host 进程只在上一个进程确认退出、目录删除之后才启动；启动恢复的清理排在 main 交回端口之后。观察 1 所问的先后由此确定，失败分支见观察 9。
- **交接时自检失败**：`03` L98、`06` F4b、`05` L434、`04` L974 一致，按运行中途停止进入 `paused(prepare_failed)`。其他副本见观察 4。

**ADR-217 带出的新问题**：
- **本 Host 空目录中的结果命中密钥路径表**（R90-D11-01）：
  - 密钥路径表含 `~/.tower/**`（`11` L160），而 (b) 对 “任一结果” 都按 (2) 检查密钥路径。例外只免除 “因该目录在第 3 条中而 forbid”。
  - 所以照字面，`owner/repo`、`sub/x` 这类参数在默认工作目录的服务器上都成为 `secrets.access`，只有 “仅这一次”。这与 (b) 本身写的 “与其他相对路径一样至少 ask” 及 `00` L99 不一致。
  - `file:` URI 解码之后，回退位置下（`<wtRoot>` 在 `~/.tower/worktrees/` 之下）以卫星文件 URI 为参数的代码智能类调用同样全部成为 `secrets.access`。
- **带回期间的 `E_BUSY` 只补了一半**（R90-D6-01）：
  - ADR-217 让 `goal.abandon` 在带回写回期间返回 `E_BUSY`，但 `06` L933 仍写 “任何非终态可放弃”，`16` L293 的 `E_BUSY` 原因清单没有这一项，且写着 “`abandon` 始终允许”；
  - 同一形状的交还写回窗口（`paused(human)`、`syncState='syncing'`）没有任何守卫：`goal.abandon` 与再次 `goal.hand_back` 都能在写回中途进入。

**全范围扫描**在 ADR-217 之外新发现：
- **以 `~` 开头的值只按主目录解释**（R90-D11-02）：
  - 路径扫描把一切以 `~` 开头的值都排除在相对路径之外（`11` L221 (3)），只按 (1) 的 “`~` 路径” 处理，而 (1) 没有定义哪些值算 `~` 路径；
  - 不展开 `~` 的服务器把这类值当作相对它自己工作目录的路径。ADR-217 正是以 “服务器按自己的工作目录解析相对参数” 为依据加了第二个基准，这一解释却从不被检查；
  - 又因 (1) 的结果不是 `opaque`，在按工具名的 Goal 级授权之下只是 `notify`。

### D11 安全与自主度

**R90-D11-01｜次要**（本 Host 空目录中的结果命中密钥路径表的 `~/.tower/**`：例外只免除硬底线，`owner/repo` 一类照字面成为 `secrets.access`；回退位置下的卫星同此）

- **问题**：
  - **密钥路径表含 `~/.tower/**`**：`11` L160 “`~/.tower/**`（凭据存储文件的补全，ADR-179…）”。
  - **(b) 对任一结果都查密钥路径表**：`11` L222 (b) “任一结果落在第 3 条硬底线之内即 forbid…；命中 §11.3.1 密钥路径表的按上一条 (2) 归 `secrets.access`；其余至少 ask”。
  - **例外只免除第 3 条**：“工作目录是本 Host 的空目录时…，以它为基准求出、仍在该目录之内的结果**不因该目录在第 3 条中而 forbid**——所以 `owner/repo`、分支名这类不是本地路径的参数不会因此被拒绝，**与其他相对路径一样至少 ask**”。
  - **两者合读**：本 Host 的空目录 `~/.tower/mcp-cwd/<hostId>/` 在 `~/.tower/**` 之下。照字面，默认工作目录的服务器收到的每个含 `/` 的参数（`owner/repo`、分支名、MIME 类型、`sub/x`），以空目录解析的结果都命中密钥路径表，成为 `secrets.access`：
    - 审批卡只有 “仅这一次”（`11` L219）；
    - 被标为读取密钥。
    这与 “与其他相对路径一样至少 ask” 不同，`00` L99 “其余照常需要你批准” 也没有提到。G46 (bk)（`14` L134）只写 “出现审批卡”，裁决不了是哪一类。
  - **回退位置**：
    - `<wtRoot>` 回退到 `~/.tower/worktrees/…` 时，卫星也在 `~/.tower/**` 之下。`10` L542 写明 “把 `~/.tower` 当作整体处理的规则对它们的例外只在两处定义”，路径扫描与密钥路径表都不在其中。
    - 所以回退位置下，沙箱外工具指向本卫星的参数都成为 `secrets.access`：以 `roots` 解析的相对路径、绝对路径，以及 ADR-217 之后解码出的 `file:` URI。代码智能类工具正以文件 URI 指明卫星中的文档，ADR-217 使这一类调用在回退位置下每次都是 “仅这一次” 的密钥审批。
  - **两种实现**：照字面实现得到上述结果；照 (b) 的意图（“与其他相对路径一样”）实现，则例外一并免除 `~/.tower/**` 一项。两者的审批卡类别、可选授权与审计记录不同。
- **后果的类别**：不放宽任何保护（照字面更严），但 `secrets.access` 本应是少见而有分量的审批，被大量与密钥无关的调用触发，会稀释这类卡片的含义；文档对同一调用给出两种卡片。
- **为什么是次要**：不丢数据、不放宽保护；但这是 ADR-217 刚定义的例外与已有规则的交集，实现会分叉，契约与验收测试裁决不了。
- **文档位置**：`11` L160、L219、L221、L222；`10` L542；`00` L99；`14` L134（G46 (bk)）；`05` L1461（C21）。
- **期望的回答形态**：在 `11` L222 (b)（唯一定义）二选一：
  - **例外一并免除**：以本 Host 空目录为基准求出、仍在其中的结果，既不因第 3 条 forbid，也不因密钥路径表中的 `~/.tower/**` 归 `secrets.access`。密钥路径表的其他条目照常适用，例如结果恰为空目录中名为 `.env` 的文件。回退位置下指向本 Goal 卫星（`10` §10.4.3 的允许项）的结果同此，在 `10` L542 的例外列表中补一处；
  - **或如实写明不免除**：这类参数在默认工作目录下出现 `secrets.access` 的审批卡，只有 “仅这一次”；回退位置下指向卫星的参数同此。`00` L99 与 G46 (bk) 的期望写明卡片类别。

**R90-D11-02｜次要**（以 `~` 开头的值只按主目录展开解释：不展开 `~` 的服务器按自己的工作目录解析它们，这一侧从不受检查，在按工具名的授权之下只是 `notify`；`~` 路径本身没有定义）

- **问题**：
  - **规则**：`11` L221 (1) 对 “绝对路径、`~` 路径与 `file:` URI” 经 `realpath` 后查硬底线；(3) 的相对路径定义排除 “以 `/`、`~` 或 `<scheme>://` 开头” 的值。所以一切以 `~` 开头的值都只走 (1)，不走 (3) 与 (b)。
  - **“`~` 路径” 没有定义**：Pi 的 `expandHome`（`runtime.ts:89-96`）只展开恰为 `~` 与以 `~/` 开头的值，`05` L439 对配置值也照这一规则（D53）；shell 另有 `~user` 形式。规则没有说 `~user/…`、`~foo` 一类算不算 `~` 路径：
    - 算，则门禁以某种方式展开它们；
    - 不算，则它们既不是 (1) 也不是 (3)（以 `~` 开头被 (3) 排除），只是普通字符串，什么都不检查。
  - **服务器怎样解释**：工具参数由服务器解释，而不是由 shell 解释。用一般文件 API 实现、不自行展开 `~` 的服务器，把 `~/…` 与 `~user/…` 都当作相对自己工作目录的路径。ADR-217 正是以 “服务器按自己的工作目录解析相对参数” 为依据加了第二个基准（`11` L222 (b)），但这一基准只用于 (3) 定义的相对路径。
  - **两种解释不一致的后果**：
    - 以 `~` 开头、其后含 `..` 的值，按主目录展开求出的位置与按服务器工作目录求出的位置可以完全不同。门禁只检查前者；后者可以落在第 3 条硬底线中的位置：影子目录、安装器私有目录、其他 Host 的空目录，或绝对 `cwd` 附近的主检出。
    - (1) 的结果不是 `opaque`，所以在 “本 Goal 内同类”（按工具名）的授权之下，这类调用只是 `notify`，不出审批卡。而以 `..` 开头的同类相对路径会被 forbid（G46 (bk) 的 ADR-217 一组）。
  - **后果的类别**：经授权的沙箱外工具在不出卡的情况下写入 Tower 的完整性存储或其他 Host 的空目录，越过 “不可授权覆盖” 的硬底线与 ADR-217 声称的 Host 边界。
- **为什么是次要**：与 R89-D11-02 同一口径——需要用户配置了一个接受路径参数、又不展开 `~` 的服务器，并由人授予过该工具的 Goal 级授权；路径扫描本是尽力而为（`11` L221 末句，T7/T26）。但这不是 “工具根据非路径参数自行决定位置” 那一类已登记的限制：值本身就是路径，只是两种解释。ADR-217 已为相对路径确立了 “按服务器可能采用的每个基准各查一次” 的原则，这里没有沿用；实现者对 `~user` 形式会各自取舍。
- **文档位置**：`11` L219、L221、L222；`05` L439（D53 的展开规则）；`14` L134（G46 (bk)）；`05` L1461（C21）。
- **期望的回答形态**：在 `11` L221（唯一定义）补一句：
  - **定义 `~` 路径**：恰为 `~` 或以 `~/` 开头的值（与 Pi 的 `expandHome` 一致）；
  - **其他以 `~` 开头、含 `/` 的值按 (3) 的相对路径处理**；
  - **`~/…` 两种解释各查一次**：一次按 (1) 以主目录展开；一次按 (3)/(b) 把它当作字面的相对路径，以服务器的基准解析。任一结果落在硬底线即 forbid；按字面解释的一侧使 certainty 为 `opaque`、至少 ask。或者明写只按主目录解释，把 “不展开 `~` 的服务器” 登记为残余，T7/T26 同步；
  - C21 或 G46 (bk) 补一组只写期望：以 `~` 开头、按服务器工作目录解释时越出该目录而落在硬底线位置的参数，即使已授予 “本 Goal 内同类”，也被 forbid（若取第一支）。

### D6 系统架构与可靠性

**R90-D6-01｜次要**（带回写回期间 `goal.abandon` 返回 `E_BUSY`，与 `06` L933、`16` L293 的 “始终可放弃” 并存；同一形状的交还写回窗口没有守卫）

- **问题**：
  - **ADR-217 的新句**：`06` L914 “写回进行中（写入 `syncState:'syncing'` 的事务到转入 `verifying` 的事务之间），该 Goal 上其他会改写状态或 `human_checkout` 的命令（如 `goal.abandon`…）返回 `E_BUSY`”。
  - **与其他定义并存**：
    - `06` L933 的 `goal.abandon` 行仍写 “任何非终态可放弃”，没有例外；
    - `16` L293 `ProtoError.code` 的 `E_BUSY` 原因清单（drain、准备阶段、卫星重建）没有这一项，并写 “`abandon` 始终允许”。这句处在准备阶段的括注中，但清单本身是 `E_BUSY` 各原因的登记处；
    - 按 `06` L933 或 `16` L293 实现的放弃会在带回中途成功，随后带回的最后一个事务在 `06` L499–L500 的 CHECK 上失败。这正是第 89 轮观察 9 要消除的结局。
  - **交还写回窗口没有守卫**：
    - `goal.hand_back`（`06` L905）同样分事务进行：① 同一事务写 `syncState='syncing'`、`targetTree`、`params`；② 逐批文件级写回；③ 写检查点与决定、清除 `human_checkout`，再按原因写 `pending_hand_back` 或开 Run/验证。
    - 它的前置条件只有 “`human_checkout` 非空”；`goal.discard_human_edits`（L907）要求 `syncState='idle'`，`goal.resume`、`goal.take_over` 因 `human_checkout` 非空返回 `E_STATE`。但 `goal.abandon`（L933，从 `paused(human)` 放弃时清除 `human_checkout`）与再次 `goal.hand_back` 都没有守卫。
    - 写回中途放弃时，写回继续写入一个已放弃 Goal 的卫星，③ 再对终态 Goal 写 `pending_hand_back`（`CHECK (pending_hand_back IS NULL OR state='paused')` 失败）或尝试离开终态。
    - 再次交还时，第二次的 ① 覆盖 `targetTree` 与 `params`，而 ②③ 与崩溃续写 “只从这里读取”（L905、`06` L144），两次写回交错。
    - 第 89 轮观察 9 只点了带回，因为那里有 CHECK 可以作证。交还一侧没有 CHECK 挡在中途，ADR-217 引用的原则（“写回进行中 → `E_BUSY`”）同样适用，却没有写到这里。
- **为什么是次要**：人工编辑检出在放弃时保留（`10` §10.8.4），人的改动不丢；状态机对终态的转移校验会让 ③ 以内部错误告终。但同一个命令表中两行给出相反的结果，实现会分叉；交还一侧的交错可能让两次写回的参数混在一起。
- **文档位置**：`06` L144、L499–L501、L905、L907、L914、L933；`16` L293；`10` §10.8.4。
- **期望的回答形态**：在 `06` L914 的那句改为一处共用的规则（或在 L905 加一句同样的守卫）：
  - **写回进行中**：`human_checkout.syncState='syncing'` 且写回正在本进程中进行，不论交还还是带回。这期间该 Goal 上会改写状态或 `human_checkout` 的命令返回 `E_BUSY`，含 `goal.abandon` 与再次 `goal.hand_back`/`inspect.bring_back`。崩溃后由 §6.1.6 续写完成，不需要人的命令解除；
  - `06` L933 补 “写回进行中返回 `E_BUSY`（L914）”，`16` L293 的原因清单补这一项，并把 “`abandon` 始终允许” 限定为准备阶段；
  - 顺带写明 `inspect.bring_back` 本身在这期间按前置条件 “无 `human_checkout`” 返回 `E_STATE` 还是 `E_BUSY`（L914 现在把它列为 `E_BUSY`）；
  - G33 或 G35 一类补一组只写期望：交还写回中途请求放弃 → `E_BUSY`、界面显示 “稍后重试”。

  - D6 为 95；D11 为 90。
- **是否还有可追问的问题：有。** 新增共 **3** 条：阻断 0、重要 0、**次要 3**。
  - **D11**：R90-D11-01、R90-D11-02。
  - **D6**：R90-D6-01。
  - **第 89 轮核验**：
    - 3 条全部按所问关闭，其中 R89-D11-01 带出 R90-D11-01，R89-D4-01 留两处旧复述（观察 1）；
    - §5 的 12 条观察全部落地，观察 9 带出 R90-D6-01；
    - 回应的五条偏离与未决全部接受，第一条的措辞与第五条的理由见观察 7、1。
  - **其他核对**：
    - lint 全部通过（exit 0；ADR 217，section_refs 7951，(v) 98 条命令，(e) 222 对，(i′) 5 个事件，(D) 365 个短语，(z′) 53 处，(C) 19 行并覆盖 §14.8），与第 89 轮记录逐行一致。
    - Pi v1.2.0：ADR-217 的引文都是原文；本轮条目与观察所依据的 `expandHome`、`hasResources`、`close()` 已逐个核实（见文首）。
    - 排期结论成立：WBS 123.41；余量 0.12 / 0.14 / 0.36 / 0.45 / 0.12；依赖链 19.91；增人 129.37、T 23.89、33 周；M1 38 周（2027-07-30）。
  - **不扣分的观察**：
    1. **归因窗口起点的两处旧复述**：
       - `04` L987 仍列三项（“交还时选‘交给 Agent 继续’、`交给 Agent 修复`、评审中 `请求修改`”），L995 写 “上面三个决定之一”；`12` L425 以 `04` §4.8.12 为出处。
       - `10` L409 “人之后明确把工作交给 Agent（`hand_back{continue_agent}`、`retry_after_human_change`、`request_changes`）时窗口起点前移”，读来是完整列表。
       - 唯一规则在 `03` L75，去向不受影响；但回应 “没有第二份清单可比对” 不成立。宜同步，`04` 可写 “或在 ‘交还后仍暂停’ 期间以说明改为交给 Agent 继续”，并按 §3.1 登入 (D)。
    2. **置换的 `resume` 在决定载荷上不可区分**：
       - `03` L75 以这次 `human.decision{resume}` 为窗口起点，但 `06` L882 的产出与 `02` §2.7 都没有在决定上留下置换的标记。`lastHandToAgentDecisionSeq`（`07` L1600）只能从当时的状态（`pending_hand_back.mode` 与当前原因）重新推出。
       - 重放可以确定地推出，所以不影响确定性。宜在该决定上记一个字段（例如 `reason.code` 或 `handBack.mode:"continue_agent"`），使窗口与重建都不必回溯状态。
    3. **`handBack.mode` 的形状副本**：`06` L905 产出列写 `handBack:{externalResolution, resolvePinHits}`，`16` L144 同；`02` L528 已有 `mode`。宜同步一处。
    4. **交接时自检失败的副本**：
       - `03` L55（`running` 行）、`02` L158、`08` L412（自称 “与 `02`、`03` §3.2.1、`16` 统一”）、`16` L29 与 L196、`12` L429 都只列 Run 中途遮蔽一种。`08` L412、`16` L196 也未列 ADR-187/215 的启动自检。
       - `08` §8.13.2（L755）的诊断锚点（“最后一个 `prepare.progress`” 或 “被阻断的那次工具调用”）对交接一支都不适用。
       - 宜各补半句，或改为引用 `03` L98。
    5. **`file:` URI 的细节**：
       - scheme 与 `localhost` 不区分大小写（RFC 3986 §3.1、RFC 8089），宜写明，免得按字面前缀匹配的实现把大写的 `FILE:` 当作 “其他 scheme”，在授权下降为 `notify`；
       - 查询与片段不属路径部分，而不严格的服务器可能把它们并入路径，宜对两种取法各查一次（与 ADR-217 两个基准同一原则）；
       - `file:` 之后不以 `/` 开头的写法未定义，宜按不透明参数处理。
    6. **`..` 按词法规范化先于符号链接解析**：`11` L222 (b) “`..` 按词法规范化，已存在的部分取 `realpath`”，而操作系统先解析符号链接再处理其后的 `..`。Agent 可以在卫星（`roots` 基准）中建符号链接，于是按 `roots` 解析的服务器实际到达的位置可能与门禁求出的不同。相对路径恒为 `opaque`、逐次 ask，有界。宜改为按物理解析求值，或两种都查。
    7. **绝对 `cwd` 指向主检出**（回应偏离第一条）：
       - 取舍可接受（§3）。但 `05` L439 不启动时的文字 `…请写绝对路径` 对 “求出主检出” 一种恰好引导用户写出 `00` L99 劝阻的配置；`00` L99 “`owner/repo` 这类…不会因此被拒绝” 对这一配置不成立。
       - 宜把文字改为 “请写指向你自己目录（不是仓库检出）的绝对路径”，`00` L99 补半句；`11` L222 (b) 末句可点名 “绝对 `cwd` 在主检出时，单个文件名与非路径参数作用于主检出” 是这一限制最直接的情形。
    8. **等价写法**：`05` L439 与 `11` L222 (b) 的例外按字面写法（“未写 `cwd` 或写 `.`”“不含 `..` 的其他值”）区分。
       - `./` 求出空目录本身，不是 “其中不存在的子目录”；
       - `x/..` 含 `..`，求出空目录本身，按 “不得落在硬底线之内” 反而不启动；
       - 宜都按求出的目录定义。
    9. **先后规则的失败分支**：
       - “其目录已删除之后才 spawn” 没有写删除失败的出口。例如服务器在其中留下不可删除的条目，“重启并恢复” 或下一个 Run 会停住，宜按 Host 启动失败进入 F4b。
       - 残留服务器若在启动时缓存了工作目录的绝对路径，之后按该路径写入的会落进后继进程新建的同名目录，与 “不越过该 Host 进程的生命周期” 的字面不符。它属于 §11.8.2 的残余，宜在 (a) 写明，或在后继进程启动前终止上一个进程记录下的服务器进程组。
       - Supervisor 在 “建目录” 与 “main 登记 Host” 之间崩溃时，启动恢复按 “不属于存活 Host” 判定的时点，宜一并写明。
    10. **Pi 引文与措辞**：
        - ADR-216 第 89 轮更正（`15` L3821）“以参数指明服务器的资源工具仍会经 `getClient()` 重新打开” 紧接 “首次连接失败的 stdio 服务器”，读来像是资源工具能重开这类服务器。实际上资源工具只到达 `hasResources` 为真的服务器，该标志在连接成功后才设置（`index.ts:466-471`，`runtime.ts:391`）。ADR-217 本身的写法（L3865）是对的。
        - `11` L222 (a) 与 ADR-217 “Pi 只在进程正常退出的 `exit` 钩子中终止” 漏了 `close()` 在 `dispose` 时的进程组终止（`stdio.ts:152-179`）。另外 Host 因信号或致命错误终止时 `exit` 钩子都不运行，所以残余条件宜写 “Host 非正常退出（含被信号终止、超出内存上限）”，不只是 “被强杀”。
        - `runtime.ts:409-416` 宜为 `:409-418`。
    11. **MCP 工具到服务器的映射**：(b) 要按 “该服务器” 取工作目录，但没有写门禁怎样由 `mcp__<server>__<tool>` 得到服务器。Pi 对名字做规范化，冲突时加哈希后缀（`tools.ts:78-92`），所以按名字解析可能取错服务器。宜写 “取自注册时的记录（Tower 的工厂按条目记下工作目录），不按名字解析”。有界：相对路径恒为 `opaque`。
    12. **非事件写入的字段**：
        - `06` L221 的 “最后一次写入不是事件的字段取被重建的库中的值”，要求重建知道每个字段最后由谁写入，而事件日志没有这一信息。它实际等于 “有非事件写入者的字段一律取旧值”。宜照此写，并列出已知的非事件写入者（目前只有 §6.1.6 一处）。
        - 同段首句 “一切领域写入都经过 `EventLog.append`” 与这一例外宜互相引用。
        - `goals` 的重放来源括注只写 `goal.*` 与 `goal.state_changed`，而 `pending_hand_back`、`pending_openings` 等列来自 `human.decision` 等事件，宜改为 “例如”。
    13. **界面文字**：
        - `04` L664 的置灰提示 `先扩展预算，再继续` 不分预算是否已扩展，扩展之后仍显示；且这期间 `继续` 已改名为 “重新验证” 或 “交给 Agent 继续”。宜按 `04` L1508 `继续` 的条件显示，并用改名后的文字。
        - `04` L974 “原因文字与上面两条启动失败相同” 之前列了三条扩展与包的启动失败，只有前两条是交接时再跑的自检，宜点名。
    14. **打包模式作为可能的默认值**：`06` L284 写 SP2 不达标时 M1 默认改为 `packed`。那时 “同一 Host 承载的其他 Goal 共用空目录”（`11` L222 (a)）就成了常态，而不只是设置项下的残余。宜在 T 表或 `00` L99 的 “打包模式下” 一句中点明。
    15. **排期的舍入口径**：安全线余量以已舍入的 14.44 × 2 计（未舍入 0.114），新人份额 2.49（未舍入约 2.50）。这是历来口径，结论不变。
- **设计是否完成：ADR-217 正确地关闭了第 89 轮的三条次要条目。**
  - 门禁以服务器实际的工作目录为第二个基准，越出空目录的相对路径与含 `..` 的相对 `cwd` 都受硬底线约束，“从不跨 Host” 成立；`file:` URI 解码后按绝对路径检查；置换的 `resume` 移动归因窗口的起点；十二条观察全部落地。
  - 本轮没有重要条目。3 条次要条目分两类：
    - **ADR-217 的新规则与已有规则的交集**：R90-D11-01（例外与密钥路径表的 `~/.tower/**`）、R90-D6-01（带回的 `E_BUSY` 与 “始终可放弃”，以及交还一侧）；
    - **此前各轮未发现的旧规则缺口**：R90-D11-02（以 `~` 开头的值）。
- **下一轮建议**：
  1. **R90-D11-01**：例外一并免除 `~/.tower/**`（回退位置下的本卫星同此），或如实写明卡片类别。
  2. **R90-D11-02**：定义 `~` 路径；其他以 `~` 开头的值按相对路径处理；`~/…` 两种解释各查一次，或如实登记残余。

  4. §5 的十五条观察各补半句；其中观察 1 宜配合 §3.1 的 (D) 登记。
