## R90-D11-01：本 Host 空目录与回退位置下的卫星命中密钥路径表的 `~/.tower/**`

**决定**：取评审的第一支——例外一并免除；回退位置下本 Goal 的卫星同此。

**唯一定义**：`11` §11.3.4 “沙箱外工具的路径检查” (2)（L221）。
- 密钥路径表的 `~/.tower/**` 一项在路径检查中不含两处由 Tower 拥有、不存放密钥的位置：
  - 本 Host 的空目录 `~/.tower/mcp-cwd/<hostId>/`（每个 Host 进程新建）；
  - `<wtRoot>` 回退时本 Goal 的卫星工作区（`11` §11.6.2 回退位置例外中 Agent 的读写项），只对本 Goal 的调用，与默认位置下相同。
- 表中其他条目（如其中未被 git 跟踪的 `.env`）照常适用。第 3 条硬底线也照常适用：以绝对路径写本 Host 空目录仍 forbid，只有 (b) 的例外不按第 3 条 forbid。

**同步**：
- (b) 的唯一例外（L222）写明 “也不按密钥路径表的 `~/.tower/**` 归 `secrets.access`（上一条 (2)）”，`owner/repo`、分支名 “按 `tool.external` 至少 ask”；
- `11` §11.3.1 密钥路径表的该项（L160）只引用 (2)；
- `10` §10.4.3（L542–L545）“例外只在三处定义”，补第三处，引用 (2)；
- `00` §0.5.1（L99）“也不当作读取密钥”；
- G46 (bk)（`14` L134）：`sub/x` 与 `owner/repo` 的卡片类别是 `tool.external`，不是 `secrets.access`；补回退位置一组：以本卫星文件的 `file:` URI 读取，出现 `tool.external` 的审批卡，不出现 `secrets.access`。

## R90-D11-02：以 `~` 开头的值只按主目录解释

**决定**：取评审的第一支——两种解释各查一次，取更严格者。

**唯一定义**：`11` §11.3.4 路径检查 (1)(3)（L221）。
- **`~` 路径**：以 `~` 开头的值按 shell 的规则展开：
  - 恰为 `~` 或以 `~/` 开头的展开为你的主目录，与 Pi 的 `expandHome` 相同；
  - `~user/…` 展开为该用户的主目录；
  - 无法展开的不作 `~` 路径。
- **(3) 不再排除以 `~` 开头的值**：同一个值既按 (1) 展开，又按字面的相对路径以 (b) 的基准（`roots` 与服务器的工作目录）各查一次，两种解释的结果都判定、取更严格者。
- 字面一侧使 certainty 为 `opaque`、至少 ask，所以按工具名的 Goal 级授权不再把这类调用降为 `notify`。按字面落在硬底线中的照常 forbid、不可授权覆盖。

**同步**：
- `00` §0.5.1（L99）：“以 `~` 开头的值既按你的主目录、也按字面的相对路径各检查一次”；
- G46 (bk)（`14` L134）补一组（已授予 “本 Goal 内同类”）：
  - 按服务器的工作目录字面解释时以 `..` 越出空目录、落在另一个 Host 空目录中的 `~/…` 值 → forbid，不出现审批卡；
  - `~/notes.txt` → 出现审批卡，不因授权降为通知。

## R90-D6-01：写回期间的 `E_BUSY` 只补了带回一侧

**决定**：一条共用的规则，交还与带回都适用。

**唯一定义**：`06` §6.4.3 `inspect.bring_back` 行的 “**写回进行中**”（L914）。
- 范围：`human_checkout.syncState='syncing'` 期间，不论交还（`goal.hand_back` 的 ① 到 ③）还是带回（写入 `syncing` 的事务到转入 `verifying` 的事务）。
- 规则：该 Goal 上其他会改写状态或 `human_checkout` 的命令返回 `E_BUSY`，界面显示 “稍后重试”。这些命令包括 `goal.abandon`、再次 `goal.hand_back` 或 `inspect.bring_back`、`goal.discard_human_edits`、`goal.request_changes`、`contract.amend`、`goal.accept`。
- 这一判定先于各命令自己的前置条件。所以这期间 `inspect.bring_back` 返回 `E_BUSY`，不按 “无 `human_checkout`” 返回 `E_STATE`（评审的附带问题）。
- 崩溃后由 §6.1.6 续写完成，不需要人的命令解除。

**引用**：
- `06` `goal.hand_back`（L905）的前置条件；
- `goal.discard_human_edits`（L907）的 `syncState='idle'` 前置条件；
- `goal.abandon`（L933）“任何非终态可放弃（交还或带回的写回进行中返回 `E_BUSY`…）”；
- `16` §16.1.12 `ProtoError.code`（L293）：`E_BUSY` 原因清单补这一项，“`abandon` 始终允许” 限定为准备阶段。

**验收**：G31（`14` L107）补一组：
- 场景：带回写回期间请求 `goal.abandon`；交还写回期间请求 `goal.abandon` 与再次 `goal.hand_back`；
- 期望：三个请求都返回 `E_BUSY`、界面显示 “稍后重试”、状态与 `human_checkout` 不变；写回完成后放弃照常被接受。

## 偏离与未决

- **`~user/…` 也作 `~` 路径**：评审建议把 `~` 路径定义为与 `expandHome` 一致（只有 `~` 与 `~/`），其他以 `~` 开头的值只按相对路径处理。本轮按指示 “以 `~` 开头的值既按主目录、也按服务器的基准各查一次”：`~user/…` 另按 shell 的规则展开检查。这只多查一侧，更严，不放宽任何保护。代价是实现要查询其他用户的主目录。
- **回退位置下的免除只给卫星工作区**：§11.6.2 回退位置例外中 Agent 的读写项还有 `_gitdirs/<goalId>` 与 `_stores/<goalId>/`。本轮只免除卫星工作区——代码智能类工具以文件 URI 指明的正是它。这两处在回退位置下仍按 `~/.tower/**` 归 `secrets.access`，比默认位置下严格。若实践中出现以它们为参数的沙箱外工具调用，再在同一处 (2) 补列。
- **`file:` 查询与片段 “各查一次”**：没有区分 “查询中本身含路径的值”。查询部分整体并入路径的那一侧本来就会产生一个不同的路径，照常判定。
- **观察 2 复用 `handBack.mode`，没有新加 `reason.code`**：`HumanDecision.handBack` 的注释原写 “仅 hand_back”，现扩到置换的 `resume`。`16` §16.1.5 与 `02` §2.7 一致，(o) 不比对这一注释。
- **(D) 只能登记带汉字的形状**：纯标识符的三项写法不在 (D) 的比较范围内（短语须含至少 5 个汉字），新写出的同类复述仍须靠评审发现。唯一规则只在 `03` §3.2.1；`06` §6.4.3 的逐字引文由 (q) 比对。
- **未决**：无。
