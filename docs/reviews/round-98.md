## 1. 总评

**第 97 轮的 5 条次要条目都已按所问关闭**（核对见 §3）。§5 的 11 条观察中，十条落地，一条部分落地：顺延的同步清单漏了 ADR-038 的〔当前值〕，见 R98-D14-01。回应 “偏离与未决” 的判断如下：
- 七条接受；
- 两条部分接受：
  - 检出含凭据形文件时改名保留：方向接受，但保留的触发范围盖住了人按 Tower 的提示复制进来的机密文件，带出 R98-D13-01；
  - 三要素按 “加载了任何沙箱外工具” 计：取更严的一边可以接受，但后果没有算完，带出 R98-D11-01。

**ADR-225 的结构性写法成立**（§3.3）：
- **写回集合多排除一类路径**：唯一定义在 `10` §10.8.4 第 5 步，§10.8.3 引用。ADR-165 的前提 “Tower 自己的路径不把真实凭据放进写允许范围” 对人一侧成为真。
- **分类的先后**：唯一定义在 `11` §11.3.3 第 3 条。文件工具与 bash 中路径能求出的访问先判硬底线，Pi 的 Full output 文件不再出读取凭据卡。§11.3.1 的 “先后” 与 `05` L473 只引用它。
- **启动闸门的唤醒**：两个解除事件进入准入的重算时机（`06` L298）。
- **终止范围**：限于 Host 已不存在的未结束 Run，以及未解决的 `bg_process_survived`（`06` L145）。§6.1.10、检查 h 的注释与 G44 (c) 同步。
- **探测结果的缓存**：失败的结果不跨启动沿用，保住了 “下次启动重新探测”。
- **截断标签**：以错误文本中是否带 `Full output:` 为条件，不以 `outcome` 为条件。对照 Pi 源码，这一条件与 “曾被截断” 等价。
- **四处清空写法与 G44 (c)**：都已改。

**ADR-225 带出、或本轮扫描发现的新问题**：
- **只重启 Supervisor 时的其余前提**（R98-D6-01）：
  - (a) 即时投递目录 `~/.tower/run/` 仍在每次 Supervisor 启动时清空，存活 Host 的云 SDK 凭据文件因此被删除。与 R97-D15-01 同类。
  - (b) drain 一行假定 “Host 已随 main 退出”，Supervisor 在 drain 中途崩溃而 Host 存活时没有去向。
- **Host 崩溃而 Tower 仍在运行时**（R98-D6-02）：崩溃的 Run 立即以 `crashed` 结束，因此不属于 “未结束的 Run”，它的命令与后台进程不在任何一轮终止之内。`10` L437 写的却是 “Supervisor 或 Host 崩溃后重启时……终止残留进程”。
- **准入仍缺检查 d 的唤醒**（R98-D6-03）：内存压力刹车回落、验证槽位与服务的预留释放、端口段回收，都不在重算时机中。
- **三要素在 MCP 用户上恒为真**（R98-D11-01）：ADR-225 之后，配置了 MCP 的 Goal 三项都为真。触发率表格过期；三个收紧选项都清不掉这条警告；远程的 `quick_ratify` 对这类用户永远不可用。
- **探测缓存的键不含 Tower 自己的档位模板**（R98-D11-02）。
- **写回集合的新排除**（R98-D13-01）：
  - 保留检出的触发条件盖住了被忽略的路径与清单中的机密文件，而接管提示正是请人把它们复制进来；
  - 交还对话框没有这一类的文案，`04` 仍写 “然后删除检出”。
- **ADR-038 的〔当前值〕**（R98-D14-01）：仍为 38 周、2027-07-30，不在同步清单中。
- **`11` L360 的 S0 原因**（R98-D15-01）：仍是通用的 `本机没有可用的 OS 写入沙箱`。

### D6 系统架构与可靠性

**R98-D6-01｜次要**（只重启 Supervisor 时的其余前提：即时投递目录被清空；drain 一行没有 Host 存活的去向）

- **问题**：
  - **(a) 即时投递目录**：
    - ADR-225 写明只重启 Supervisor 时，存活 Host 重新接上，其中的 Run 照常进行（`06` L145、L322）。
    - 但 `~/.tower/run/<deliveryId>/` 仍写 “Supervisor 每次启动时清空它”，没有存活 Host 的例外：`06` L138（“每次启动都清空 `~/.tower/tmp/` 与 `~/.tower/run/`”，例外只给 `tmp/<hostId>/`）、L1067，`11` L450，`16` L725。
    - 这个目录中有交给 Engine Host 的云 SDK 凭据文件，它在 Host 的整个生命周期内都要存在，“Host 退出即删”（`05` L475，`11` L518）。
    - Pi 在显式设置 `GOOGLE_APPLICATION_CREDENTIALS` 时，每次判定凭据都检查该文件是否存在（`ai/src/env-api-keys.ts:40-44`）。照文字实现，Supervisor 重启后，存活 Host 中的 Run 下一次请求即按 “没有凭据” 失败（`06` §6.8 F7）。
    - 这与 R97-D15-01 对 `tmp/` 指出的是同一类问题，G44 (c) 的新组没有覆盖。
  - **(b) drain 一行**：
    - `06` L146 的 drain 行写 “Host 已随 main 退出”，然后按 `draining_for.target` 进入暂停。
    - Supervisor 在 drain 中途崩溃而 Host 存活时（例如人暂停后、Run 尚未结束），这一行的前提不成立：Run 可能仍在 Host 中收尾。是等 Host 中的 Run 结束后再执行原目标，还是按此行直接转入暂停，没有写。
    - 相邻的 Run 中崩溃一行已经区分了 “Host 已不存在”，drain 一行没有。
- **后果的类别**：
  - (a)：存活 Host 的模型请求在 Supervisor 重启后失败，Goal 转入认证类暂停；只影响使用云 SDK 凭据文件的用户，没有数据丢失。
  - (b)：两种实现，一种在 Run 仍活跃时把 Goal 置为 `paused`，状态与实际不符；另一种等待。
- **文档位置**：`06` L138、L146、L1067；`11` L450、L518；`16` L725；`05` L475；`14` G44 (c)（L132）。
- **期望的回答形态**：
  - (a) 在 `11` §11.7.0 即时投递目录的唯一定义处写明：启动时清空其中消费者不是存活 Host 的投递（存活 Host 的投递随该 Host 退出删除）。`06` L138、L1067 与 `16` L725 改为引用；G44 (c) 的新组补一条断言 “存活 Host 的投递文件仍在”。
  - (b) 在 drain 一行的条件中加 “Host 已不存在”；Host 存活时，重新接上后由 Supervisor 继续这次 drain（等 Run 结束再执行原目标）。

**R98-D6-02｜次要**（Host 崩溃而 Tower 仍在运行时，崩溃 Run 的命令与后台进程不在任何一轮终止之内）

- **问题**：
  - Engine Host 退出或挂死时，Run 立即以 `crashed` 结束（`05` L651，`06` L64，`08` L390），随后自动 “重启并恢复”：`ensureSatellite` → 新 Host → `resume`。
  - ADR-225 把终止范围写成 “**Host 已不存在**的**未结束** Run 的令牌，以及未解决 `bg_process_survived` 的令牌”（`06` L145）。崩溃的 Run 已经结束，`bg_process_survived` 只在 settle 第 3 步产生，所以这次崩溃的 Run 两项都不满足。
  - 而 `10` L437 写 “Supervisor 或 Host 崩溃后重启时……终止残留进程，然后补做 `agent_bg_done`。**由此**：`claimed`/`verifying`/`in_review` 中……不会有 Agent 进程写卫星”。`06` L198 也写 “Supervisor 或 Host 重启后”。照 L145 的范围实现，这两处所说的终止在 Host 崩溃时不会发生。
  - Pi 的 bash 以 `detached: true` 派生（`bash.ts:112-114`），Host 进程退出时这些子进程不会随之结束。新 Run 的 settle 只终止带新 Run 令牌的进程，旧令牌的进程一直留着。
  - 挂死的 Host（“进程仍在 → 视为挂死”）在新 Host 启动之前是否被终止，也没有写。
- **为什么是次要**：
  - 这是 ADR-225 之前就有的缺口，新的写法使它可以确定地读出来。
  - 按严重度口径，它接近 “违反写明的不变式”（`10` L437 的 “由此”）。但残留进程的写入会经归因表落为来源不明的外部写入，触发 `external_change` 暂停，不会被静默记成人的改动，也不会产生虚假的 “已验证”。
- **后果的类别**：崩溃前的长命令、开发服务或监视进程在新 Run 与之后的状态中继续运行：
  - 占用该 Goal 的端口段，使新 Run 的服务启动失败；
  - 写入卫星，造成误报的外部写入暂停；
  - 挂死的 Host 若未被终止，同一会话有两个 Host。
- **文档位置**：`06` L64、L145、L198、§6.8 F4（L1190）；`05` L651；`08` L390；`10` L437；Pi `core/tools/bash.ts:112-114`。
- **期望的回答形态**：在 `06` L145 的唯一定义中把范围写为 “Host 已不存在、且在 Host 退出时尚未结束的 Run 的令牌（含因此以 `crashed` 结束的）”，并在 §6.1.3 Engine Host 一行写明 “重启并恢复” 之前：先终止挂死的 Host，再按该令牌做一轮终止并补 `agent_bg_done`。或者删去 `10` L437、`06` L198 中的 “或 Host”，并在 `10` L437 的 “由此” 处登记这一窗口。

**R98-D6-03｜次要**（准入的重算时机仍缺检查 d 的解除事件）

- **问题**：
  - `06` L298 列出准入重算的全部时机：槽位释放、评审余量变化、依赖满足、收到新请求，以及 ADR-225 加的检查 h 的两个解除事件。
  - 检查 d（L316，`13` L205–L210）在两种情况下使 Goal 停在 `ready{slot}`（“机器资源”）：
    - 预留之和超过额度；
    - 内存压力刹车处于 warn 及以上。
  - 两者的解除都不在上列时机中：
    - 内存压力回落不是事件；
    - 验证槽位结束、服务停止（`inspect.close` 回收端口段，检查 g 与之共用分配器）释放的是预留与端口，不是 Run 的槽位（检查 a 的 “槽位”）。
  - 当前没有活跃 Run、只有排队 Goal 时，照文字实现，这些 Goal 会一直等到某个无关事件。人在 `ready` 中没有重新触发准入的命令。这与 R97-D6-01 (1) 是同一类问题。
- **后果的类别**：Goal 在资源已恢复后仍停在 `就绪 · 等待机器资源` 或 `就绪 · 等待服务端口`；没有数据丢失。
- **文档位置**：`06` L298、L316–L318；`13` L205–L210；`12` L414。
- **期望的回答形态**：在 L298 的重算时机中加 “资源预留或端口段释放、内存压力回落到 warn 之下”；或写明有 Goal 因检查 d、g 等待时，准入按固定间隔（如 30 s）重查一次。

### D11 安全与自主度

**R98-D11-01｜次要**（三要素：加载了沙箱外工具即计私有数据为真之后，配置了 MCP 的 Goal 三项恒为真，表格、收紧选项与目标都未相应处理）

- **问题**：
  - ADR-225 把私有数据写为 “本 Goal 加载了沙箱外工具（用户扩展或 MCP 服务器）时……为真”（`11` L544）。
  - ADR-032 早已规定配置了 MCP 时不可信内容与对外通信都为真（L545–L546），MCP 来自用户的全局 Pi 配置，没有按 Goal 关闭的入口。所以 **配置了 MCP 的用户，每个合同都触发警告**。
  - 由此带出的未处理之处：
    - **表格过期**：触发率测算表（L552–L556）的 “标准预设 · S2 · 用户配置了 MCP” 一行仍写私有数据 “同上”、警告 “仅当有可读 `.env` 类文件”。“无 MCP” 一行没有考虑用户扩展。“仅当 worktree 有未忽略 `.env` 类文件” 在 ADR-224 之后本已不准。
    - **收紧选项清不掉**：三个选项（L560：`net.other` 改为 `forbid`、`secrets.access` 改为 `forbid`、移除外部上下文）都不改变由 MCP 推出的三项。界面上 `批准` 在 “致命三要素未处理” 时不可用（`04` L1100），人只能每次写理由坚持批准。
    - **远程 `quick_ratify`**：条件之一是 “无致命三要素警告”（`16` L1134，`04` L1260）。这类用户在手机上永远不能快速批准。
    - **目标**：“S2 下触发率 ≤ 10%，采纳率 < 20% 且触发 > 10% 判定为滋扰并复审”（L558，`16` L902）。对这类用户，触发率恒为 100%、采纳率恒为 0，这条复审规则会把一条有意的规则判为滋扰。
    - **判定依据**：“加载了” 在批准之前计算，应以静态清单（`05` §5.10）为准；只注册钩子、不注册工具的扩展算不算，没有写。T7（`11` L692）的分档用 “能写文件系统的沙箱外工具”，与此处 “Tower 无法判定” 的说法不一致。
- **为什么是次要**：规则本身取更严的一边，不违反不变式；但一条警告在一类用户上恒为真、又给出清不掉它的选项，会使人习惯性地坚持批准，削弱的正是这条警告存在的理由（R1-D11-04 要求收紧以避免滋扰）。
- **后果的类别**：MCP 用户的每个合同都要写理由坚持批准；远程快速批准对他们不可用；E3 的复审规则误判。
- **文档位置**：`11` L544–L560、L692；`04` L1100、L1112、L1260；`16` L902、L1134；`00` L102；`15` ADR-032、ADR-225。
- **期望的回答形态**（任选其一，在 §11.8 的唯一定义处加一句并改表格）：
  - **如实写出**：更新表格各行；写明配置了 MCP 时警告恒出现、收紧选项中没有能清除它的一项，`quick_ratify` 对这类 Goal 不可用；E3 的触发率与采纳率按 “是否配置 MCP” 分层计算，复审规则只看无 MCP 的一层。
  - **收窄**：私有数据只在静态清单中有沙箱外工具、且本 Goal 的写允许范围内实际存在名字形如凭据的未跟踪文件时为真（批准时可求、运行中授权时重算）。并写明只注册钩子的扩展是否计入。

**R98-D11-02｜次要**（探测结果的缓存键不含 Tower 自己的档位模板）

- **问题**：
  - `06` L1179：结果连同键（本机、开机会话、Supervisor 所用沙箱运行时的版本）记入自检日志，“Tower 再次启动时键相同且上次结果为‘已拒绝’的直接沿用”。
  - 探测验证的是 Tower 自己生成的三种档位模板是否拒绝创建硬链接；`11` L360 写 “确切的规则……以 SP6a A3 的探测为准”。档位模板随 Tower 的版本变化，而沙箱运行时是 Tower 固定的版本（`14` SP6a），二者不一定一起变。
  - 同一开机会话中 Tower 自动更新并重启时（常见），如果新版本改了档位模板而没有改运行时版本，缓存的 “已拒绝” 被沿用，新模板没有经过探测。
  - 写明的不变式是 “探测未能确认拒绝时不以路径规则不完整的 S2 运行”（ADR-224/225 的安全不变式之一）。照文字实现，这条不变式在更新之后不再由探测保证。
- **后果的类别**：一个改动了硬链接规则的 Tower 版本，可能在未经探测的档位上以 S2 运行；硬链接规则失效时，只读的共享输入或 Tower 私有的文件可经另一个名字被改写（T7 所列的一类）。
- **文档位置**：`06` L1179；`11` L360、L692；`13` L325；`14` SP6a A3。
- **期望的回答形态**：在 `06` L1179 的键中加 “Tower 的版本（或三种档位模板的哈希）”，`13` L325 同步。

### D13 隔离、git 与并发

**R98-D13-01｜次要**（写回集合新排除类的保留触发盖住了人按提示复制进来的机密文件；界面未同步；带回只改这类文件时返回 “没有改动”）

- **问题**：
  - **(a) 保留触发的范围**：
    - `10` L972：名字形如凭据、“在该 Goal 的 base 中未被跟踪” 的路径不写回，“H 中有这类路径与 T0 不同时……H 改名保留、不删除”。
    - 被 git 忽略的路径与本地文件清单中的机密文件，在 base 中同样未被跟踪，也从不在 T0 或 T_pin 中。其中名字形如凭据的（`.env`、`.env.local`、`*.pem` 等）在字面上落在这条触发之内。
    - 接管提示正是请人把它们复制进来（L946：“此副本不含本地机密文件；需要运行时请自行复制进来”），`inspect_with_secrets` 则由 Tower 自己复制进检验目录。
    - 照字面实现，每次人按提示复制了 `.env` 之后交还，或带回一个带机密的检验目录，目录都被改名保留、不删除。Tower 从不删除 `.kept-*`，这些真实凭据的副本会在磁盘上积累，并且每次都出一条 “已保留” 的通知。
    - ADR-225 的理由（R97-D11-01 (a)）针对的是 “既不在清单中、也不被 git 忽略” 的文件；另一种实现会只对这一类保留。两种实现差别很大。
  - **(b) 界面**：
    - 交还对话框只为清单中的文件写了 `已排除：<路径>（本地机密文件）` 与 `（本地文件）`（`04` L660，`12` L683），没有这一新类的文案。“你的改动” 可能把 `certs/dev.key` 计在内，人会以为它已交还。
    - `04` L668 仍写 “交还时……然后删除检出”，没有提到这类改动使检出被保留。
  - **(c) 带回**：只改了这类文件时，T1 等于 T_pin，`inspect.bring_back` 返回 `E_STATE`（“检验检出没有改动”，`06` L917），与人看到的不符。
- **后果的类别**：
  - (a)：真实凭据的副本在保留目录中积累，“已保留” 的通知变成每次交还都有的噪声，削弱它提醒人工作仍在的作用；
  - (b)(c)：人对哪些改动进入了 Goal 的认识与实际不符。
  - 没有凭据进入 Agent 可读的位置（`_human/**`、`_inspect/**` 与 `.kept-*` 都属于第 3 条硬底线与 `tower_data`）。
- **文档位置**：`10` L923、L946、L972、L1014–L1016、§10.8.3 第 7 步（L915）；`06` L917；`04` L660、L668；`12` L683；`14` G46 (bl)；`15` ADR-167、ADR-225。
- **期望的回答形态**：
  - (a) 在 `10` L972 的唯一定义处把这一排除与保留触发限定为 “未被忽略、不在本地文件清单中” 的路径。被忽略的路径与清单中的机密文件仍按原规则排除，随目录删除（它们的原件在主检出中）。
  - (b) `04` §4.6.7 与 `12` L683 各补一行，如 `已排除：certs/dev.key（名字形如凭据、不在 base 中；不交还，副本将保留）`；L668 写 “这类改动存在时检出改名保留”。
  - (c) `inspect.bring_back` 的 “无改动” 判定写明：只有这类路径不同时，返回的提示列出它们，并说明它们不会带回。

### 不扣分的观察

1. **硬底线命中的告知强度**：
   - ADR-225 之后，bash 中路径能求出、指向硬底线位置的读取（主检出、`_human`、`_inspect`、其他 Goal 的卫星、`$TI`）在分类时即 forbid，只记 severity 1 的 `policy_block`。同样的读取若经混淆、由 S2 拒绝，则记 severity 2 的 `sandbox_violation{user_checkout | credential, read}`，进入需要你。直接的尝试得到的信号反而弱于混淆的尝试。
   - 文件工具自 ADR-223/224 起就是这样，正文也写明了 “不出卡”，所以只记观察。
   - 宜考虑一条守卫：硬底线命中的目标属于 `16` L173 的 severity 2 受保护类别时，按同一类别记 severity 2；但 Host 临时目录与 `~/.tower/tmp/**` 除外，否则会重新带回 R97-D11-02 的误报。
2. **截断标签的匹配与回退**：
   - Pi 从不单独输出一行 `Full output:`，而是在状态行之前附 `[Showing … Full output: <path>]`（`bash.ts:348-352`）。宜写明匹配这一后缀，而不是按子串匹配：命令自己的输出可能含有同样的文字，会被误标为截断（误判方向是保守的）。
   - 正常结束且截断、但全文文件未通过校验（或已不在）时，证据回退为截断后的 `output`，仍会标为 “完整日志”。宜把标签改为由 “是否复制了全文文件” 推导，一并覆盖这一分支。
3. **返回文字与作用范围**：
   - 第 3 条对 Host 临时目录给出的是 bash 的重定向建议。对 MCP 截断结果（Pi 提示 “read it with offset/limit”，`extensions/mcp/tools.ts:183-199`），这条建议不对路，宜复用 §11.3.1 “以更窄的参数重新调用” 一句。
   - `00` L106 写 “它的临时目录（`$TMPDIR`）”，而 `05` L473 约定文档中的 `$TMPDIR` 指系统临时目录。宜写 “它的临时目录（Agent 环境中的 `$TMPDIR`）”。
   - 第 3 条 “S2 与 S0 相同” 不分 Goal 与 Scratch，与 Scratch（M2）的 “真实检出读允许”（`11` L412–L413、T25）不一致。M2 设计 Scratch 时宜限定。
   - 镜像一项只写了 “写”，S0 下读取镜像中 `objects/` 之外的文件是硬底线还是读取凭据卡，宜写一句。
4. **只重启 Supervisor 的边缘情形**：
   - **同时有存活 Run 与旧 Run 的存活者**：一个 Goal 的旧 Run 有未解决的 `bg_process_survived`，当前 Run 在存活 Host 中进行。Supervisor 重启后，旧令牌在终止范围内，按 `06` L145 显示 `清理中`、`goal.take_over` 返回 `E_BUSY`，并在 Run 进行中补 `agent_bg_done` 检查点。这与 “不显示 `清理中`” 的先后宜写一句。
   - **探测进行中 Supervisor 崩溃**：“沿用本次启动的结果” 无结果可用，宜写 “重新探测”。
   - **键变化时的翻转处理**：解除 `s0_grant_pending`、重算三要素只写了 “启动时”。“存活 Host 中的沙箱档位与之对应” 读来是按 Host，而档位按 Run 选择，宜改为按 Run。
   - **Trace 解压文件**：`~/.tower/tmp/` 中正在打开的 Trace 解压文件，在只重启 Supervisor 时会被清空（`06` L1127）。宜让它进入一个属于 main 的子目录，或在清空时保留。
   - **情形 E 的告知**：崩溃落在 “另一半” 改名与置 `satellite_rebuilding` 的事务之间时，续做不知道已有 `.kept-*` 工作目录，告知会写成 “随工作目录丢失”（Goal 页仍列出 `.kept-*`）。
5. **终止范围的复述**：`10` L437、`13` L324、`16` L1067 仍写 “未结束的 Run 与有未解决 `bg_process_survived` 的 Run”，没有 “Host 已不存在”。三处都写了 “范围以 `06` §6.1.6 为准”，所以只记观察。修 R98-D6-02 时宜一并同步。
6. **措辞**：
   - `00` L106 理由栏 “这些情形下 Pi 不交回全文文件的路径” 宜改为 “Pi 只在错误文本中给出路径、没有最终 `details`，Tower 不从错误文本取路径”。
   - `14` L216 W4 的摘要 “探测结果按本机与开机会话缓存” 漏了运行时版本（修 R98-D11-02 时一并改）。
   - ADR-225 的 Pi 核实写 “会使该 Host 的工具调用失败”。流在 `closeTempFile` 之前没有 `error` 监听者，更可能使 Host 进程崩溃。属于历史文字。
7. **增人备选的取整**：“超过 130.02 为 34 周” 以 T 先舍入到 0.01 为前提；不舍入时超过 130.00 即需 27 个工作周。宜在 `14` L401 写明舍入规则，或改为 “超过 130.00”。
8. **存储与隐私清单**：
   - 观察器复制的全文 `goals/<goalId>/logs/<toolCallId>.log` 没有大小上限，不在 `13` §13.11.3 的磁盘统计与 `10` 的磁盘压力顺序之内，默认进入系统备份。
   - `09` §9.12.1 的存储清单没有 `~/.tower/tmp/<hostId>/` 一行，而其中是未经脱敏的原文（`11` §11.7.1 残余），打包模式下与长寿 Host 同寿。
9. **Tower 沙箱版 `exec` 的拒绝约定**：Pi 只在 `ops.exec` 以 `Error("aborted")` 或 `Error("timeout:<N>")` 拒绝时生成状态行（`bash.ts:374-379`）；其他拒绝原样抛出，没有尾部与状态行。`07` 的 `outcome` 推导与截断标签都依赖这一点。宜在 D38 或 `05` §5.3.5 写一行约定，并在 C12 中断言超时与中止经 Tower 的 `exec` 时的文字。

### 设计是否完成

ADR-225 以已有唯一定义处的一句话正确关闭了第 97 轮的五条条目：
- 交还与带回不再把人放进检出的凭据形文件写回卫星；
- 分类的先后使 Pi 的 Full output 文件不再出读取凭据卡；
- 启动闸门在两个解除事件时唤醒准入；
- 只重启 Supervisor 时不终止存活 Host 中的 Run；
- 超时证据如实标注为截断的尾部；
- 旧的清空写法同步。

本轮 8 条分三类：
- **新写明的路径与已有规则的相遇**：
  - R98-D6-01：只重启 Supervisor 的路径遇上即时投递目录的清空与 drain 一行；
  - R98-D6-02：新的终止范围遇上 Tower 运行中的 Host 崩溃；
  - R98-D13-01：新的保留触发遇上接管提示中复制进来的机密文件；
  - R98-D11-02：新的缓存遇上 Tower 自身的更新。
- **取舍的后果没有算完**：R98-D11-01（三要素在 MCP 用户上恒为真）。
- **未同步的复述与既有缺口**：R98-D14-01（ADR-038 的〔当前值〕）、R98-D15-01（S0 原因）、R98-D6-03（检查 d 的唤醒，与 R97-D6-01 (1) 同类）。
