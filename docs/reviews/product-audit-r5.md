### 0.4 手机页与推送

- 在演示数据上开启手机页（开了“本地网络”开关）。没带令牌、令牌错误都返回 401；带令牌后能读状态、回答问题、放一边、暂停；对不存在的条目、已处理的条目、不能暂停的状态都返回人能读懂的错误。放行受控操作、覆盖哨兵这类决定在服务端被拒绝。
- **本机 Tailscale 处于停止状态时，`tailscale ip -4` 仍会打印旧地址。** Tower 按这个地址监听，失败信息是 “Can't assign requested address (os error 49)”，不会说是 Tailscale 停了。应用启动时遇到这种失败只写一条日志（`lib.rs:135`），手机页就静默地没开。打开本地网络开关后，返回的第一条链接（也就是二维码里的那条）指向这个失效的 Tailscale 地址，还被标成 “tailscale”。
- 读代码（`remote.rs:45`）确认：**没有 Tailscale 地址时，即使本地网络开关是关的，也会监听所有网卡**。这和 SECURITY.md 说的“在普通局域网上监听是另一个单独的开关”不一致。
- 推送（`inner.rs:129`）：推送失败完全静默（stderr 丢弃、没有状态显示、没有“发一条测试推送”）；每次推送启动一个 curl 子进程后不回收。安全问题见 D12。

## 3. 前 20 项修复（按优先级）

“需要维护者”的条目标为 **［维护者］**。每项后面写它能带来的分数提升（估计值，不能叠加超过各维度上限）。

### 必须先做（决定 D3 / D12 能否回到 85 以上）

**1. 用“反事实复跑”取代文件名单（D3 +4，D5 +1，D14 +1）**
不变式：*一条标准之所以通过，只能是因为源码的改动。* 实现：在验证的 Agent 阶段，额外做一次复跑：只保留合同范围里声明为“源码”的改动，其余新增或改动的文件（任何配置、脚本、清单、点文件、合同范围外的新文件）一律恢复成基线版本或删除。原来通过、复跑失败的标准记为高严重度哨兵，目标暂停。它与现有的“恢复原测试再跑”是同一机制，可以合并成一个“只留源码”的步骤。名单保留，只用来给评审排序和写说明。

**2. 每次验证加一条“必败金丝雀”（D3 +3）**
不变式：*一个必然失败的测试必须失败。* 实现：验证时由 Tower 在保留区放入一个断言必然失败的测试，用每条标准的测试框架运行。如果它“通过”了，说明断言层或测试框架在运行时被改动，直接判为高严重度哨兵（“测试框架失效”），而且这次验证的所有通过结果都不计为事实。这条能挡住 R2b 和 R3 两类，也包括今后任何让断言失效的新写法。

**3. 保留测试：只为指定标准复制，输出一律不回传，失败时交给人（D3 +2，D2 +2）**
- 合同里明确标出哪条标准是保留测试，保留文件只在这条标准运行时出现；其他标准运行时不存在。
- 保留文件存在期间产生的任何输出都只给人看；把 `verify.rs:783` 那个把泄露写成期望行为的测试改掉。
- 保留测试失败时不自动返工（Agent 拿不到信息，只会去找测试，R1 就是这样），而是变成一张决策卡：人看到输出后可以“给 Agent 一句提示”、“自己改”或“放弃”。
- 保留标准一律离线运行，运行完核对保留文件的哈希。

**4. 推送：Agent 写的文字绝不进入外部程序的参数，令牌绝不离开本机（D12 +3，D4 +1）**
不变式：*Agent 可控的文本只能作为数据，不能被任何程序当作选项或文件引用解释。* 用 Rust 的 HTTP 客户端发送（或者通过标准输入传正文）；问题类条目只推送固定句式（“G-0003 有一个问题等你”），不推送 Agent 写的原文；只接受 https。点击链接里不放长期配对令牌，换成一次性、几分钟内有效的短链，或者干脆不带令牌，由已配对的手机自己保存的令牌负责认证。

**5. 验证的生命周期隔离（D12 +2，D3 +1）**
不变式：*一次验证中启动的东西不能活过这次验证，下一次验证也不会沿用它的路径。* 每次验证使用新的随机目录，结束后删除；结束时杀掉所有后代进程，而不只是进程组（可以按沙箱配置或专用用户来追踪）；准备阶段结束后核对检出中被跟踪的文件与 pin 一致，运行标准时测试路径和保留文件只读。

**6. 手机页的监听与 Tailscale 检测（D12 +2，D11 +2，D1 +1）**
没有 Tailscale 地址、本地网络开关又是关的时候，拒绝启动并说明原因，不要回退到所有网卡。按网卡和守护进程状态判断 Tailscale（停止时 `tailscale ip` 仍会打印旧地址），不要只看 `100.` 前缀。启动失败时在设置页和收件箱里给出可操作的提示（“Tailscale 已停止：打开 Tailscale，或开启本地网络”），而不是只写日志。二维码只编码实际可达的链接。同时更正 SECURITY.md 第 26 行。

### 应该做（各维度从 85 到 90 的关键）

### 4.2 Tower 缺什么

1. **装不上**：没有签名安装包、没有自动更新、只支持 macOS、仓库私有。主流产品全部做到一键安装。
2. **不能离开笔记本运行**：Cursor、Codex、Claude、Conductor、Devin 都有云端执行，合上电脑任务照跑。
3. **界面行为的取证**：Cursor 和 Codex 让 Agent 自己操作应用并附上视频或截图；Tower 的 `look` 标准只在固定地址截前后两张图，没有交互过程。
4. **原生手机端**：Cursor iOS、Claude 手机端有原生推送、实时活动、在手机上合并；Tower 是局域网或 Tailscale 上的网页加 ntfy。
5. **GitHub 原生流程**：从 issue 派任务、堆叠 PR、在 PR 里自动评审和修复 CI。Tower 能开 PR、跟踪 CI 结果，但流程从桌面发起。
6. **定时任务与事件触发**：Routines、Automations。Tower 放在 ROADMAP 的 Later。
7. **引擎数量**：Conductor 和 Zed 支持 4–8 个 Agent，Tower 支持 2 个。
8. **安全扫描**：Copilot 的回路里有 CodeQL、密钥扫描和依赖公告，Tower 没有。

### 4.3 Tower 独有的东西

搜索范围内**没有找到**任何已发布的产品做到下面几点（找不到不等于不存在）：

- **由 harness 自己在干净检出中独立复跑验收标准**。Copilot 最接近，但它是在 Agent 自己的回路里跑测试，属于自我验证，不是独立复核。
- **对 Agent 隐藏的保留测试**。目前只出现在基准测试和研究里（SpecBench 等）。
- **基线红 → 绿判定、“恢复原测试再跑”、测试篡改哨兵**。
- **按目标生成的 macOS Seatbelt 沙箱**，并且把凭据、其他项目和网络都挡在外面。本轮 R1 中，一个有动机的 Agent 花了 4 分钟到处搜索，没有读到任何不该读的东西。
- **完整的简体中文界面**（Claude Code 明确不做）。

2026 年的研究（例如关于“验证视野”和“谁来验证构建者”的论文）表明，独立验证器加行为监控能把作弊得逞的比例降低一个数量级以上。这正是 Tower 选的方向。但本轮也说明，**只要验证器和被验证的代码共享同一个测试运行时，独立复跑就可以被运行时手段绕过**。第 3 节第 1、2 项是把这条差异化优势变成真正护城河的关键。
