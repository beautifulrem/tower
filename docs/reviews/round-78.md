### D13 隔离、git 与并发

**R78-D13-01｜次要**（本地文件的忽略判定在用户检出中求值，与决定检查点、pin、T1 成员的上下文不同；残余登记窄于实际）

- **问题**：

    - ADR-205 的守卫与复制前复核都是 “在用户检出中 `git check-ignore` 为真”（`16` L703）。

    1. **Goal 创建之后才忽略并批准的文件，这是 M1 的常见路径。**
       - 人按提示把路径加入 base 中的 `.gitignore`（`16` L703 提示的第二种做法）。已有 Goal 的树仍是旧的 `.gitignore`，M1 不 rebase。
       - 或者加入 `.git/info/exclude`：影子的副本只在创建时复制，L183 的刷新条件 “每次 fetch 新 base 时” 在 M1 中对已有 Goal 不会成立，至少语义不明。
       - 此后该 Goal 遇到两个复制点之一：
         - “我来改” 时播种进 H（`10` L929），交还时 T1 收进它，记为 `author:"human"` 的检查点，随 seal 进入用户仓库的分支；

    3. 写在仓库级配置（`.git/config`、`config.worktree`）中的 `core.excludesFile`。最小配置只复制全局的那一个。
    4. 路径在 base 中被跟踪、在用户检出中未跟踪且被忽略（例如用户分支删除了它）。

       - `envHash` 记录了本地文件，所以记录本身如实，但 “从影子检出 pin” 的槽位此时与 pin 不同。

  - **登记的位置**：残余只写在 `15` L3217，`16` 的 `ProjectLocalFile` 行、`11` 威胁表与 `00` §0.5.1 都没有。
