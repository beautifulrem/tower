## 1. 总评

ADR-175 按第 49 轮的期望形态处理了四条问题，其中三条完整落地，一条漏了一处：
- **串行机制**：采用第一种期望形态。`16` L513 写明唯一定义：复核与写出在同一把按 Project 的本地文件锁下完成；取锁的是该 Project 的 `add`、`approve`、`remove`、`mark_secret`、`unmark_secret` 与各复制点的“复核 + 写出”；这把锁是 Supervisor 进程内的异步互斥，不阻塞其他命令。`07` 伪代码改为 `localFilesLock(goal.projectId).run(...)`，`supervisor.turn` 不再出现。锁体内只做清单查询与写出，持锁者不再等待槽位、项目锁或其他队列，因此没有循环等待（§3.1）。
- **重放**：采用第二种期望形态。`07` L488：重放只对原 `env.localFiles` 中列出的路径读入、判定、写出（其中当前仍为 `seeded` 的条目），原验证之后才批准的条目不写出；当前已不再 `seeded`、因而未写出的条目归入“复现条件不同”。两个方向都有了规则。E13 的单列与 `07` 一致。
- **项目级通知**：`08` L36 写明水位按 §8.10.1 的 3 s 规则推进，推进后侧栏 `◇` 不再计入，行内说明在这次访问中保持显示，离开本页后消失；`08` L34 与 `04` L194 写明多项目时为 `◇ N 个项目`；`04` L1303、G46(aj) 同步。
- **漏改**：`12` L326 已改为“侧栏底部的设置入口”；`14` L215、`15` L1115 已加括注。**但 `14` W11 行（L229）仍写“按条目的最后查看序号”，没有括注**（第 49 轮点名过这一行）。另外，`06` L930 只改了推进条件，说明栏仍写“序号不大于水位的事件类本地文件通知不再显示”，与 `08` L36 的“这次访问中保持显示”不一致。

### 3.1 ADR-175 的边界检查

| 检查 | 结论 |
|---|---|
| 锁的范围与复制点 | ✓ `16` L513 的五个复制点（卫星创建或重建、验证槽位、检验检出、人工编辑检出、验证重放）都在“各复制点的‘复核 + 写出’”之内。`07` 伪代码只展示验证槽位一处；其他复制点没有排队，读取与写出相邻，“复核”可以与读取一起在锁内完成，也可以读取在锁外、复核在锁内。两种实现都保证 `mark_secret` / `remove` 生效后不再写出该条目，不扣分（见 §5 观察） |
| `inspect_with_secrets` | △ 复核按“仍为 `seeded`”书写，而带机密的检验会有意复制 `isSecret` 条目。`16` 把这个复制点限定为“`inspect_with_secrets` 的普通文件部分”，机密部分是人显式发起的例外，不受复核约束。读法唯一，不扣分 |
| 内容命中写入与自动恢复 | ✓ 二者不在取锁名单中。验证槽位的判定在锁外（`readSeededLocalFiles`），其他复制点的判定若在锁内进行，Supervisor 写入 `secretBy = content` 也不需要再取锁，不会自锁。若内容命中写入恰在另一复制点的写出期间提交，被写出的是更早读入、已判定为非机密的字节，“查询键 = 槽位内容 = 记录”仍成立，不构成暴露 |
| 与单写者模型 | ✓ 锁只在 Supervisor 的事件循环中排队；被锁挡住的是 CommandBus 中同一 Project 的五个本地文件命令，其余命令照常经 `decide` → `EventLog.append`。`06` §6.2.1 的“单个事务 p95 < 2 ms”不受影响：等待发生在事务之前，事务本身不跨 `await` |
| 死锁 | ✓ 获取顺序：卫星准备为“项目锁（镜像，`10` §10.3.1 第 1 步）→ 本地文件锁（第 4 步）”；验证为“槽位 → 本地文件锁”；命令只取本地文件锁。持本地文件锁时只做清单查询与文件写出，不取槽位、项目锁或卫星互斥锁，也不等待 CommandBus 上的其他命令。没有循环等待 |
| 持锁者失败 | △ 写进验证槽位可能经 MessagePort 交给 Verifier Runner。Runner 崩溃、槽位被抢占或验证被取消（卫星丢失时 `verifying` 的取消，`10` L1161）都会使写出的 Promise 失败，`run()` 随之释放锁。正文没有逐条写，但这是异步互斥的常规用法，不扣分 |
| 命令顺序 | △ 正文没有写锁是否先进先出。同一 Project 的本地文件命令只经这把锁排队，常见的异步互斥实现按到达顺序放行；且 `unmark_secret` 需要确认对话，人很难在一次写出期间连续提交相反的两条命令。不扣分 |
| 命令回执延迟 | △ 本地文件命令在写出期间等待；ADR-175 以“写出只涉及几个小文件”说明量级，正文没有本地文件大小上限。`13` L30 的“人的命令 → 回执 p95 ≤ 50 ms”针对全部人类命令，本地文件命令频率很低，不影响 p95。不扣分（见 §5 观察） |
