## 2. 改动清单

### 2.1 状态与出口（检查 j）

- `03` §3.2.1 `human` 行：放弃改动的去向改为“接管前为 `paused(*)` → `alsoApplies` 中最高者；接管前为 `running` 或原因已解除 → 保持 `paused(human)`”（与 `10` §10.8.4、`06` §6.4.3、`16` §16.1.1 一致）。
- `03` §3.2.1 表后：新增“`pendingHandBack` 非空时，上表出口被它取代，原因解除或 `resume` 时按 `mode` 进入 `verifying`/`running`”（ADR-104）。
- `04` §4.18.3 叠加原因行：“与旧 pin 绑定的叠加原因清除（ADR-099）” → “只清除由 pin 推导的，由运行行为推导的保留（ADR-103）”。
- `02` §2.4：`takeoverFrom`/`pendingHandBack` 注释归位。
- `06` §6.1.6、§6.3、§6.4.3：`take_over_from` → `takeover_from`。

### 2.2 残留关键词（检查 k）

- `04` §4.6.5 seal 说明结构：trailer 块补 `Tower-Contract`、`Tower-Verified-At`（ADR-105）。
- `07` §7.4.3（两处）与 `14` P38：`pnpm-workspace.yaml` 键补 `catalogs`。
- `10` §10.8.4 交还第 5 步：“嵌套 .git 扫描同 ADR-071” → “H 中不含确认为仓库的目录（接管时未复制，ADR-101）”。
- `15` 修订注：ADR-036 ← ADR-105（seal 说明与 trailer 集合）；ADR-071 ← ADR-101/102；ADR-081 ← ADR-101（拒绝交接）；ADR-089 ← ADR-101；ADR-092、ADR-098 ← ADR-105（`runner_patched` 只报相对 base 的变化）。

### 2.3 嵌套仓库扫描（检查 l）

- `05` §5.5、`06` §6.2.2 GitService、`07` §7.3.2、`16` §16.2.6：全量粗筛时机统一为“Run 开始前、每次接管/检验之前、丢事件或监视降级时，以及 S0 下的每次 settle 与影子操作前”，引用 `10` §10.3.1。
- `06` §6.2.2：预算 “2 万文件 ≤ 150 ms” → 以 `13` §13.11.1 为准（增量每回合 ≤ 10 ms，全量 10 万条目 ≤ 1 s，单次 ≤ 200 个新候选）。
- `10` §10.7.1 第 1 步：“嵌套 .git 扫描（ADR-071，Tower 自己的文件遍历，不经 git）” → “嵌套仓库识别（ADR-071/101/102，两步），X 只含 base 中未跟踪的仓库目录”。
- `11` T29 缓解：“嵌套 `.git` 每次扫描并排除……嵌套仓库记 `nested_repo`” → 两步识别；只有 base 中未跟踪的记 `nested_repo`；全部不复制到两种检出。
