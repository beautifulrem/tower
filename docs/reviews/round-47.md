## 1. 总评

ADR-172 按第 46 轮的期望形态处理了四条问题，主体落地是干净的：
- 自动恢复有了事件 `project.local_file_unmark_reverted`，`16` L285、`06` L408、`10` L1242、`02` L113、`04` L1301、`11` L339 六处一致，producer `sm`、`source = system`，与清除 `unmarked` 同一事务；
- “未复制”有了载体：项目级 Fact `local_file_unreadable{path}`。`Fact.kind` 在 `02` 与 `16` 都是 33 个，集合相同；`06` 的 `facts` 表 `goal_id` 可空、producer CHECK 含 `verifier` / `git`，CHECK `(goal_id IS NOT NULL OR project_id IS NOT NULL)` 满足；
- 通知只对“这次本应复制的条目”发出，其他条目缺失只在设置页显示 `◇ 文件不存在`；重新判定命中的文案按条目原状态如实给出；
- `envHash` 公式加入了 `canonicalJSON(localFiles)`，`07` L488 与 L711-716 一致，L862 的“键覆盖全部输入”有了依据；
- `07` §7.4.1、`04` §4.18.3、`16` L511 都加了“未复制”的 Claim 提示，不改变 `decide()`；
- 排期：WBS 121.62，各线、余量、依赖链 19.7、增人 127.41 / 23.53 / 33 周、M1 38 周，全部经脚本复核成立；`14` 甘特中的旧余量也已更新，`14` 与 `15` 一致。

M1 头号安全不变式这一条线，本轮仍然没有发现缺口。ADR-172 只增加记录与提示，不改变“谁可以把本地文件复制出用户检出”的规则：Fact 的 `data` 只有路径，`envHash` 只收 `seeded` 条目的内容哈希，机密与未批准条目不进入。

沿 ADR-172 新加的三个落点（Fact 的生命周期、`envHash` 的本地文件项、失败提示的来源）复查，还有三处**次要**问题，都不触及安全不变式，也不丢用户数据：
1. `local_file_unreadable` 的“失效”没有持久化的落点：成功读取不留任何记录，而 Fact 的新鲜度是派生值；`07` §7.3.3 新鲜度表只列了三个失效条件中的一个。
2. `envHash` 的本地文件项与验证流程的顺序不衔接：`verify()` 在取槽位、复制之前就查缓存；“验证结果上记录的本地文件哈希与 `extra`”在 `criterion_check` 中没有字段，G46(ai) 断言的对象不存在。
3. “本次验证中 `<路径>` 未复制”没有按验证记录的来源（Fact 是项目级、按条目去重的，不绑定某次验证）；`07` §7.10.3 的返工消息模板没有列出这一行。

### D6 系统架构与可靠性

**R47-D6-01｜次要**（`local_file_unreadable` 的失效没有持久化的落点；`07` 新鲜度表只列一个条件）

- **问题**：
  1. **失效靠什么记录**：
     - `16` L511 规定这条 Fact 在三种情况下 `expired`：下一次成功读取、移出清单、改为机密；L1 通知“随它失效而消失”。
     - 但 Tower 中 Fact 的新鲜度是派生值（`02` L429-431、`07` §7.3.3）：`facts` 表没有新鲜度或失效列（`06` L594-605），账本中与 Fact 相关的事件只有 `fact.recorded`；`superseded_by` 需要一条取代它的 Fact，而“成功读取”不产生任何 Fact。
     - “移出清单”可以由 `project_local_files` 中行不存在派生；“改为机密”可以由 `mark_secret` 命令的事件晚于 Fact 派生。**“下一次成功读取”不留下任何持久记录**：卫星创建、检验检出与人工编辑检出的复制都不写账本，验证槽位的复制也只把内容哈希折进 `envHash`。
     - 结果：
       - 进程内可以把它标为失效，重启后的投影无从得知，通知会重新出现；
       - 或者实现者自己发明一条记录（新事件、`superseded_by` 指向一条虚构的 Fact、或在 `project_local_files` 上加列），不同复制点（VerifierScheduler、PrepareService、检验与接管命令）可能各写一套。
     - 这正是第 46 轮要求的“重启后是否还在、自动消失由什么触发”中“消失”的一半。
  2. **`07` L334 只列一个条件**：新鲜度表写“下一次复制时成功读取该条目”，没有“移出清单或改为机密”。按表实现时，被移除或被标为机密的条目，其通知会一直挂着（这两种情况下不会再有“本应复制”的读取）。`16`、`02` L415、`04` L1300、`15` L1752 写的都是三个条件。
  3. **“改为机密”需要按转移定义**：`inspect_with_secrets` 时 `isSecret` 的条目也属于本应复制的范围（`16` L511、`04` L1300）。若派生规则写成“当前 `isSecret` 即失效”，这类 Fact 一产生就失效，检验场景的通知不会出现。
- **为什么是次要**：不影响安全（不复制的结论不依赖这条 Fact），不丢用户数据；L1 通知不进入 Needs-You、不消耗打扰预算。后果限于一条可能残留或重复出现的通知，以及实现者自行补记录。
- **文档位置**：`16` L130、L511；`02` L415、L429-431；`06` L594-605；`07` §7.3.3（L318-334）；`04` L1300；`15` ADR-172（L1752）。
- **期望的回答形态**：
  - 在 `16` L511 写明失效的落点。可以是：
    - 成功读取一个有 `fresh` Fact 的条目时，Supervisor 记一条事件（例如 `project.local_file_readable{projectId, path}`，producer `sm`，只在存在 `fresh` 的 Fact 时记录），投影据此派生 `expired`；
    - 或在 `project_local_files` 上加一列（如 `unreadable_fact_id`），在同一事务中写入与清除，失效由该列为空派生；
    - 或明确它是进程内状态：重启后 `fresh` 的此类 Fact 保留到下一次复制时重新判定，并写明这一点。
  - “改为机密”写成转移：`mark_secret` 使非 `isSecret` 的条目变为 `isSecret` 时失效；产生时已是 `isSecret` 的条目（检验场景）只按成功读取与移出清单失效。
  - `07` L334 的“变为 expired 的条件”补齐三个条件，或改为“见 `16` `ProjectLocalFile` 行”而不列条件。

### D7 诚实与验证

**R47-D7-01｜次要**（`envHash` 的本地文件项与 `verify()` 的顺序不衔接；“记录的本地文件哈希与 `extra`”没有字段）

- **问题**：
  1. **缓存查询在复制之前**：
     - `07` L714-716 与 `16` L511 把 `envHash` 的本地文件项定义为“该槽位实际复制的 `(path, contentHash)`，取自复制时的同一次读取”。
     - 但 `verify()` 的第 3 步 `cacheHit(c, tree, envKey(goal), depsKey(pin))`（L395）在取槽位、`slot.checkout`、播种（L406-408 起）之前执行；全部命中时根本不取槽位，也就没有“复制时的读取”。
     - 查询键的本地文件项从哪次读取得到，正文没有写。实现者可以：
       - 查询前单独读一次用户检出（这与“同一次读取”的字面不符，但 G46(ai) 第二组“内容变化 → 缓存不命中”要求查询键反映当前内容）；
       - 或把缓存查询挪到复制之后（每次都取槽位，缓存失去大半意义）。
     - 前者还需要说明：查询时读到的与复制时读到的不同（人在两次读取之间改了文件）时，结果记在哪一个键下、是否重新查询。
  2. **记录的值没有字段**：
     - `16` L511 与 `07` L261 写“验证结果入账时记录的本地文件哈希、指纹的 `extra` 部分……取自该槽位复制时的这一份”。
     - 但 `criterion_check` 的数据结构（L833-855）只有 `env.envHash`，没有本地文件列表；`verify()` 记录的 `workspaceFingerprint` 是 `` `wt1:${tree}` ``（L415），不含 `extra`。
     - G46(ai) 第二组断言“记在验证结果上的本地文件哈希与指纹 `extra` 等于槽位中实际写出的那一份”，按现有数据结构无法核对。
  3. **种子文件变化后结果是否变旧，两处说法不同**：
     - L488 与 L259-261 的意图是“被播种文件的内容哈希进入指纹的 `extra`”，从而使结果在文件变化后变旧；
     - 但 L415 记录的指纹不含 `extra`，L328 写 exec 标准“按 tree 比较”。按后者实现，人在用户检出中修改一个已播种的文件后，已通过的 `criterion_check` 仍为 `fresh`，直到下一次验证才通过 `envHash` 体现出来。
     - 这一点的源头早于 ADR-172，但 ADR-172 明文引用了“记录的 `extra`”，使两种实现都能在正文中找到依据。
- **为什么是次要**：
  - 后果属于诚实一侧，而且有界：第 1 点的错配需要人恰好在两次读取之间改文件；第 3 点只影响“已通过之后又改了本地文件”这一情形，下一次验证就会纠正；
  - 交付物是 tree，本地文件属于用户环境，不进入 seal；
  - 不涉及安全，不丢数据。
- **文档位置**：`07` L259-264、L320、L328、L395、L406-415、L488、L711-716、L833-855、L862；`16` L511；`15` ADR-172（L1755-1757）；`14` G46(ai)。
- **期望的回答形态**：
  - 在 `07` §7.4.8（或 `verify()` 注释）写明缓存查询的键：例如“查询键的本地文件项取自查询时对 `seeded` 条目的读取；未命中时进入槽位，结果记在复制时那一份算出的 `envHash` 下；两者不同则不复用缓存、照常运行”。
  - 在 `criterion_check.env` 增加 `localFiles: {path, contentHash | "not_copied"}[]`（取自复制时的读取，机密与未批准条目不进入），使“记录的本地文件哈希”有字段可查，也供 R47-D8-01 使用；
  - 二选一并写明：
    - `criterion_check` 的指纹包含 `extra`，本地文件变化使结果 `stale`（同时改 L415 与 L328 的“按 tree 比较”）；
    - 或者 `extra` 不用于 `criterion_check`，本地文件的变化只经 `envHash` 在下一次验证时体现，并删去 `07` L261、`16` L511 中“记录的 `extra`”的说法。
  - G46(ai) 第二组的断言改为针对上述字段。

### D8 注意力与交互

**R47-D8-01｜次要**（“本次验证中未复制”没有按验证记录的来源；返工消息模板没有列出这一行）

- **问题**：
  1. **来源**：
     - `07` L458 与 `16` L511 写“本次验证有本应复制而未复制的条目（Fact `local_file_unreadable`）时”附提示。
     - 但这条 Fact 是项目级的（`goalId` 为空），同一条目只保留一条 `fresh`：若卫星重建时已经记过一条，这次验证再读不到也**不会新增** Fact。Fact 本身因此不能说明“是不是这次验证没有复制”。
     - `criterion_check` 中也没有本次复制的本地文件列表（见 R47-D7-01 第 2 点）。
     - 结果：实现者只能用“显示卡片时存在 `fresh` 的 Fact”来判断。这样一来：
       - 验证时文件正常复制，之后检验检出读不到它，旧失败卡片上也会出现“本次验证中未复制”；
       - 验证时没有复制，人随后恢复了文件，Fact 失效，暂停卡片上的提示随之消失，而失败的原因并没有变化。
     - 返工证据在 `decide()` 时生成，受影响较小；`verify_failed` 卡片在暂停期间可以存在很久，受影响较大。
  2. **模板**：`07` §7.10.3 的“返工消息模板”（L1643）逐项列出返工证据的内容：失败的标准、阻断性哨兵、`lfs_excluded` 一行、未播种机密本地文件一行、固定一句。它没有列出 ADR-172 的“未复制”一行。按模板实现时会漏掉这一行，而 `07` §7.4.1、`04` L1483 与 G46(ah) 都要求有。
- **为什么是次要**：提示只是 Claim，不改变 `decide()`；返工有上限，结局有界；不涉及安全，不丢数据。但第 1 点会让卡片上的“本次验证”陈述不如实，第 2 点会使两处正文给出不同的返工内容。
- **文档位置**：`07` L458-460、L1643；`16` L511；`04` L1483；`06` L234；`14` G46(ah)。
- **期望的回答形态**：
  - 在 `07` §7.4.1 写明提示的来源取自本次验证的记录（例如 R47-D7-01 建议的 `criterion_check.env.localFiles` 中 `not_copied` 的条目），不取自显示时 Fact 的状态；Fact 只负责项目级的 L1 通知。
  - `07` L1643 的模板加上“本次验证有本应复制而未复制的本地文件时的一行提示（§7.4.1，ADR-172），并写明 Agent 无法恢复”。
