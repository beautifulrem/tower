**主干需要裁定的事项**：
1. **`insteadOf` 中的 userinfo**：用户全局配置中，`url."https://user:tok@host/".insteadOf = https://host/` 一类改写经 `[include]` 进入临时配置。git 在内部改写 URL 之后，仍会把带凭据的 URL 放进传输辅助进程的参数。Tower 无法只剔除这一条而保留其余的 include。本轮把它登记为 T33 的残余，由模式脱敏兜底。是否要求 Tower 在检测到这类改写时改为不 include、显式写出全部有效配置？代价是 `10` 的配置构造会更复杂。
2. **M2 推送的目标远端**：§10.12 仍写 `git push -u origin`。ADR-155 的远端统一只针对“为 base 获取”的命令，推送目标是否也应改为可配置（例如 `remote.pushDefault` 或项目设置）？此外，以 URL 寻址的推送不能用 `-u` 设置上游，需要另写 `branch.<x>.remote`。这两点都属于 M2，本轮未改。
