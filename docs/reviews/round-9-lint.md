## 2. 改动清单

### 2.1 `pendingHandBack` 与交还

- `02` §2.4：`pendingHandBack.noteRef?: string` → `decisionId: DecisionId`（意图取 `HumanDecision{hand_back}.note`），注释顺序整理。
- `06` §6.3 DDL 注释：`{mode, at}` → `{mode, at, decisionId}`。
- `06` §6.4.3 `goal.resume`：“`post_settle_activity` 作为保留原因时，其解除即人在禁用可疑扩展后 `resume`” → “`post_settle_activity` 与 `app_quit` 交还即解除，不作为保留原因（`16` §16.1.1，R9-D4-01c）”。

### 2.2 嵌套仓库与检出（ADR-106）

- 早期预警全量时机统一为 `10` §10.3.1 的五种（Run 开始前、交接/检验前、Tower 写回完成后、丢事件或监视降级时、S0 下每次 settle 与影子操作前）：`05` §5.5、`06` §6.2.2、`07` §7.3.2、`13` §13.11.1、`16` §16.2.6。`05`/`06`/`07` 的“S2 下以文件系统事件维护”改为“卫星存在的所有非终态”（与 `10` 的监视生命周期一致）。
- 两种检出不再是 CoW 副本：`06` §6.6.1 目录树注释（`_human`、`_inspect`）、`04` §4.7.3 表、`07` §7.4.2 检验检出、`13` §13.11.1 人工编辑检出行 → “由影子树物化，仓库形态目录不写出”。

### 2.3 实况行（检查 m）

- `08` §8.6.5：示例改为 `执行 · edit · src/checkout.ts +12 −3`、`执行 · bash · pnpm test checkout · 14s`，并注明模式名到徽章文字的映射。
- `10` §10.3.1：`preparing · pnpm install · 47s` → `准备中 · 物化依赖 · pnpm install · 47s`；`preparing · 预取 · …` → `准备中 · 预取 · …`。
- `04` §4.0：`准备中 · 依赖 · …` → `准备中 · 物化依赖 · …`。
- `13` §13.11.1：`preparing · 预取 <对象> · 已下载/总量` → `准备中 · 预取 · <对象> <总大小> <百分比>`（验证时 `验证 · 预取 · …`）。
- `12` §12.6.4：子状态词表补 `宿主`（与同节表格、`08` 一致）。
- `01` §1.4 的英文示例是研究结论的原文引用，未改。

### 2.4 检测器与 seal（检查 n、k）

- `07` §7.10.1：`burn_vs_progress` 行标签 → `` `burn_without_progress` ``；`symlink_escape` 阻断列补“指向 Tower 管理的根时阻断集成，`10` §10.1.2”。
- `10` §10.6 seal 说明结构标题：“其中第 2 段可选” → “第 2 段可选、第 3 段在解析失败或无 Agent 提交时省略”（与同一代码块一致）；`16` §16.2.6 同步。
- `16` §16.1.13 新增 5 条废弃行：卫星侧扫描作 Verified 依据 / 固定布局判定；检出为 CoW 副本；`post_settle_activity`/`policy_wall`/停滞阻断及 run 类可返工；`pendingHandBack.noteRef` 与双重判定；无条件 `Tower-Verified-At`。
