本文件关闭 `round-100.md` §4 的重要条目 R100-D13-01、5 条次要条目与 §5 的 9 条观察。行号为修改后的位置。

**收敛规则**（同 ADR-186–227）：只用三种办法关闭条目：
1. 把说法改弱，但保证为真；
2. 删除或推迟不属于 M1 主循环的机制；
3. 在已有的唯一定义处加至多一条守卫、一行或一个字段。

**本轮的取向**：
- 重要条目用第 2 种办法关闭**整类**。人工编辑检出的去留自 ADR-193 起约八轮反复产生条目：ADR-199 移到一边，ADR-221 删除前比较，ADR-222 清除时保留，ADR-225/226/227 写回集合中决定副本去留的触发条件。每一轮都在 “何时可以安全删除人的副本” 上补一个分支。本轮不再判定这件事：**Tower 从不自动删除人的副本**，只结束对它的使用、列出它，由人一键删除。
- 五条次要条目各在已有的唯一定义处加一句，引用处只改为引用。

新增的只有：
- 命令 `goal.delete_kept`（仅本机；不是 HumanDecision，不产生事件）；
- Goal 页与存储面板中的列出与 `删除`；
- 人的工作现场合计超过 10 GB 时的一次 severity 1 提示；
- 审批卡与 Goal 页的两行说明。

删去的有：
- `goal.take_over` 的参数 `moveAside` 与 “移到一边并重新开始”；
- 交还、带回与启动续写之后的删除前比较，及 “比较不同则改名保留”；
- 写回集合中只为决定副本去留的判定与逐条列出。

不新增状态、事件类型、表、列、决定种类、Needs-You kind、landmark、`wait_reason` 值或常驻进程。

安全不变式全部保留：
- Tower 不会自动把机密交给 Agent 可影响的进程。新增传入 Host 的只有非机密的区域、端点、账号与 gateway id，不进入 bash；原始密钥仍只经即时投递文件；
- 保留的检验目录中由 `inspect_with_secrets` 带上的机密副本，对 S2 与验证器沙箱读写均拒绝（ADR-082），存储面板注明；
- `goal.delete_kept` 只在本机，只接受按名字属于该 Goal 的人的工作现场路径，逐级 `O_NOFOLLOW` 删除；
- 回退后权限与默认位置相同；Agent 的三种沙箱与安装器安装阶段都拒绝创建硬链接与钥匙串查找；
- 沙箱外工具的级别下限仍为 ask，按工具名授权的条件不变。

安全问题只写到设计层面。

## R100-D13-01（重要）：人新建的被忽略文件按整个目录比较；Tower 物化的目录使副本例行保留；第 8 步的唯一定义看不到 “按不同处理”

按任务指示以删除关闭整类，没有采用评审建议的 “按文件、相对 Tower 写入的内容判定”。判定的粒度、参照与第 8 步的引用都不再需要，因为不再有任何删除去依赖它们。

**唯一定义**：`10` §10.2 “人的工作现场不自动删除”（L258，新增一段）。
- **不删除**：Tower 从不自动删除人工编辑检出 `_human/<goalId>`、检验目录 `_inspect/<goalId>` 与各 `<goalId>.kept-*`。
- **只结束使用**：以下操作都只清除 `humanCheckout` 或结束检验，目录与其中的一切原样留在原路径，成为**已脱离的副本**：
  - 交还（含 `take_external`）、放弃改动、放弃 Goal；
  - 检验带回、`inspect.close`（不论有无修改、`modified` 取何值）；
  - 验收或放弃触发的检验清理。

  一切包括被 git 忽略的文件、未交还的文件与 H/.git 中人做的提交。
- **路径再被需要时**：同一 Goal 再次接管或打开检验需要这一路径时，Tower 先按 “Tower 自动改名保留” (a) 把它改名为 `<原名>.kept-<时间>`，再照常独占新建（L254、L256）。
  - (a) 原为 “删除来源目录之前的比较不同”，已删除，所以改名处仍是四处；
  - 仍在使用中的路径（`humanCheckout` 非空、检验打开中、以 `keep` 关闭待处理）照旧返回 `E_STATE`。
- **列出与删除**：Goal 页 `保留的目录` 与设置的存储面板按 Goal 列出路径、逻辑大小与来源，各带 `删除`。
  - 命令为 `goal.delete_kept{goalId, paths}`（`06` §6.4.3 L911，仅本机；`16` §16.5 同步）；
  - 确认框先列出将丢失的内容：与本 Goal 最近检查点不同的文件、被 git 忽略的条目（被忽略的整个目录写明其中一切随之删除）、H/.git 中人做的提交数；
  - 使用中的路径返回 `E_STATE`，写回进行中返回 `E_BUSY`；
  - 没有自动、定时或磁盘压力下的删除。
- **代价，如实写出**：
  - 每次接管与每次检验都留下一个目录，直到人删除；
  - 人的工作现场不计入 30 GB 预算、单独计量，合计超过 10 GB 时提示一次（`10` §10.4.4）；
  - 量级在 `13` §13.11.3（L367）：单个约为被跟踪内容 0.05–0.5 GB 加构建产物；依赖目录在 APFS 上 CoW、几乎不占新块，无 CoW 时 0.3–2 GB；不删除即约每周 0.5–20 GB，数周内即可超过总预算。
- **写回集合的排除不变**：含机密的本地文件、凭据形且 base 未跟踪的路径、清单中的文件与被忽略的路径都不进入 T1。只删去为决定副本去留而设的触发与逐条列出。被忽略的文件在交还对话框中以一行灰字 `被 git 忽略的文件不交还，留在副本中` 说明（`10` §10.8.4 第 5 步 L975）。

评审的 (a)(b)(c) 三处都随之消失：
- (a) 漏判：不再删除，所以不会丢文件；
- (b) 误判使副本例行保留：现在是规则本身，代价已登记，删除入口与提示已给出；
- (c) 第 8 步看不到 “按不同处理”：第 8 步不再删除 H（L1016）。

## R100-D5-01（次要）：AWS 混用来源、写入的 profile 名、区域的判定、首次运行只取变量名、API Key 类 provider 的非机密配置

**唯一定义**：`11` §11.7.1 “云 SDK 凭据链” 行（L518）。
- **(a) 两者并存**：环境中同时有 `AWS_PROFILE` 与原始密钥对时，同终端中的 Pi 用原始密钥（`bedrock-converse-stream.ts:162-164, 215-217`）。Tower 写投递文件，不传你的 `AWS_PROFILE`。
- **(b) profile 名**：投递文件使用 Tower 保留的 `tower-<hostId>`，不与你配置中的任何段同名。
- **(c) 区域**：在每次 `host.spawn` 时判定，不在首次运行时固定：
  1. 记录的 `AWS_REGION`、`AWS_DEFAULT_REGION` 原样传入；
  2. 都没有，而你设了 `AWS_PROFILE`（含并存的情形）或 Tower 传的是 `default` 时，读该 profile 在配置文件（记录的 `AWS_CONFIG_FILE`，否则 `~/.aws/config`）中的 `region`，写为 `AWS_REGION`；
  3. 仍没有时补 `us-east-1`。

  这与 Pi 的取法相同：只有原始密钥时 Pi 回落 `us-east-1`；有 profile 时 Pi 交给 SDK 从该 profile 读区域，Tower 改传保留名时由第 2 步写出同一个值。你之后在 profile 中改的区域，在下一次 Host 启动时生效。唯一的差别写明：只有 profile 而它没有区域时，终端中的请求因缺区域失败，Tower 补 `us-east-1`。
- **(d) 记录的值**：该行所列的非机密变量（配套变量、配置变量与指向文件的变量）的值，在首次运行时经你确认后记入 Tower 的密钥库，随所属条目存放。“重新读取” 替换它们。
  - 同步：`05` §5.3.6 首次运行检测（L489）、`06` `engine.reread_login_shell`、`16` 钥匙串条目一行（L725）；
  - 原始密钥的值仍不随 “重新读取” 刷新（已知限制不变）。
- **(e) API Key 类 provider 的配置变量**：以下变量原样传入 Host、不进入 bash，密钥仍走运行时注入：
  - Azure OpenAI：`AZURE_OPENAI_BASE_URL`、`AZURE_OPENAI_RESOURCE_NAME`、`AZURE_OPENAI_API_VERSION`、`AZURE_OPENAI_DEPLOYMENT_NAME_MAP`；
  - Cloudflare：`CLOUDFLARE_ACCOUNT_ID`、`CLOUDFLARE_GATEWAY_ID`。

  “变量 → provider” 的对应以各 provider 的 `resolve` 为准（D62）。ADR-049 的类型表下补一行〔ADR-228 补记〕。

## 偏离与未决

- **R100-D13-01 没有采用评审的判定改法，而是删除整类**（按任务指示的收敛规则）：
  - 代价是磁盘：每次接管与每次检验都留下一个目录，不删除时数周内可超过 30 GB 总预算。`13` §13.11.3 如实写出量级，`10` §10.4.4 给出 10 GB 的一次提示，Goal 页与存储面板给出删除入口；
  - Tower 从不替人删除，所以真正需要保留的副本不会被稀释成例行保留的灰字（评审 (b) 的担心）——列出的都是人自己的目录，由人决定。
- **检验目录取同一规则，而不是保留原规则**：原规则在关闭、验收与放弃时会删除人新建的被忽略文件（评审观察 2），不满足 “不丢人的工作”。取同一规则后，`[丢弃]` 改为 `[不带回]`，`inspect.close{modified:"discard"}` 的取值不变、只放弃带回。代价同上；检验时带上的机密副本随目录保留，靠 S2 与验证器沙箱的读写拒绝保护，存储面板注明。
- **新增一条命令 `goal.delete_kept`**：此前各轮倾向不新增命令，本轮按任务要求的 “一键删除” 新增。它仅本机、不是 HumanDecision、不产生事件，(v) 98 → 99。
- **再次接管时的改名由 Tower 自动完成，不再需要人点击**：取代 ADR-199 的 `E_STATE` 与 “移到一边”。它占用 “Tower 自动改名保留” 原 (a) 的位置，所以改名处仍为四处。
- **R100-D8-01 的复审线（中位 > 3 条/小时、反射批准率 > 90%）是本轮给出的初值**：由 M1 自用期的 E3 数据校正。规则本身（“不提供”）不变，承担那一面的仍是逐次 ask。
- **R100-D13-02 计在系统线，没有按 ADR-136 改派**：系统线余量 1.12，远高于改派阈值。
- **R100-D5-01 (d) 的值存放在密钥库**（按任务的 “安全存储”），随所属条目存放，`16` 钥匙串一行的 “只存两类” 不变。
- **§16.1.13 旧行的 “现行” 列**：第 70、71、93、98、99 轮各一处改写为现行规则（lint 的原则：“现行” 列写当前文字）。
- **未决**：无。逐次批准的可用性代价仍然存在，已登记、单独度量并有复审点；沙箱外工具的可核实能力声明仍为 M2 决定点。
