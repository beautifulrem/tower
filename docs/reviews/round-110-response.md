## R110-D13-01（重要）：“不可访问” 包含 “被删除”，又被套用到叶目录上

**按指示，在 `06` §6.1.6 Project 不可达一行（L139）的唯一定义处关闭。**

- **必需路径只有根**：
  - 根是附着检出，以及该 Goal 的卫星、检验检出与验证记录所在的 `<wtRoot>`；人工编辑检出贡献的是它所在的 `<wtRoot>`（迁移之后取 `relocatedFrom` 中它所在的旧 `<wtRoot>`）。
  - 根之下的目录不是必需路径：卫星、`_gitdirs`、`_stores`、验证槽位、人工编辑检出、检验目录、要物化的目录及其旁路目录。

## R110-D13-02（次要）：路径丢失确认的条件与 `syncing`

## R110-D13-03（次要）：`relocatedFrom` 的写入条件

**按指示**（唯一定义在 `06` L921 “旧位置的记录”）：
- **只对 `<wtRoot>` 确实改变的 Goal 执行**。设置了 `worktreeRoot`，或新旧检出在同一父目录下同名时，只改 `attach` 与 `defaultCheckout`：不追加、不结束记录、不重建。
- **去重**：按 `wtRoot` 去重，已有条目只更新 `at`。与迁移后的新 `<wtRoot>` 相同的条目移除。
- **多附着点**：旧 `<wtRoot>` 仍是其他 Goal 的当前位置时，同样追加。列出范围只含已没有当前 `WorktreeRecord` 的目录（`10` §10.2 “列出的来源” 为唯一定义），所以活跃卫星不会被列出。

- **合并与拆分**（M1 中已有的命令，`06` L920）：
  - 合并时，保留方的 `relocatedFrom` 取两者的并集；被并入一方的 `<wtRoot>` 与保留方不同时一并追加；`defaultCheckout` 取保留方的。
  - 拆分出的 Project 不继承这两项，旧位置仍记在原 Project 中。

## R110-D12-01（次要）：清除遗留清单

唯一定义在 `09` §9.12.4 “不可访问的根”（L575）。
- **内容最小化**：只存 `[{wtRoot, at}]`，不存 Project、Goal 或目录名；同一根只有一条。评审建议加 `projectId`/`goalId`，本轮没有采纳，见 “偏离与未决”。
- **写入次序**：清单先写入并落盘（临时文件、`fsync`、原子改名），再提交清除的数据库事务。执行或续做中才变为不可访问的根，同样先记入清单，再追加 `filesDone`。所以任何时刻崩溃，未删除的根要么在 `roots` 中，要么在清单中。
- **列出范围**：引用 `10` §10.2 的唯一定义，即其下 Tower 创建、已没有当前 `WorktreeRecord` 的目录。`09` L575 与 `04` L1287 的摘要补回这一限定。
- **移除**：
  - 其下已没有这类目录时，条目移除。
  - 不可访问的条目可在 “清理工作目录” 中 `从列表移除`，只删条目，不触碰磁盘（`10` L457、`04` L1287）。
  - `all` 档把这时可访问的清单根与其他根一样处理，并移除这些条目（`09` L569）。“清除全部” 之后，清单中只剩当时不可访问的根，可由你移除。移除之前它们留在 `~/.tower` 中，如实登记。
- **目录布局**：`06` §6.6.1（L1058）补列该文件；备份排除一行（L1102）写明它与 `goal-id-hwm` 一样不排除。
- **两句过时的说明**：`09` L561 与 `10` L259 末句补 “清除遗留清单中的根除外”。

## R110-D11-01（次要）：`tool_result` 脱敏处理器出错时 Pi 放行原文

**按指示**，`05` §5.6.5 第 6 项（L1062）补写：
- 脱敏处理器以 try/catch 包住自身。出错时经 `bridge` 自报，计入 F13。
- 它**返回**一个隐去原文的常量结果，**不重新抛出**：`content` 只有 `工具结果未能脱敏，已隐去`，`isError: true`，`structuredContent` 与之一致、不含原输出（ADR-004）。
- 构造这个结果不读原结果，所以本身不会再失败。失败的方向是 “隐去”，从不是 “放行”。

## R110-D7-01（次要）：base 确认中的环境错误

**按指示**（`07` §7.4.6，L873、L882）：
- 只有运行器报告该用例失败的一次，才算 “base 上失败”。
- 以下几种情形是**无结论**：检出或物化失败；以文件系统错误结束；运行器没有给出该用例的结果；或该次之后槽位所在的 `<wtRoot>` 判为不可访问。

- “基线已坏” 同样只取有结论的运行。

  - 可达判定没有逐类列出 “持久的上级”，统一为 “按所在的根”。根只有附着检出与 `<wtRoot>` 两类，人工编辑检出与检验目录总在某个 `<wtRoot>` 之下（`10` §10.2），所以不需要 “其父目录” 的回落。
  - T1 的保留只在放弃时执行。路径丢失的确认与迁移在 `syncing` 时返回 `E_STATE`（R110-D13-02），所以这是唯一会在写回未完成时清除 `targetTree` 的出口（③ 之前 ① 已重新物化来源目录，或如实告知）。
  - 没有采用 “允许迁移之后从 T1 续写”：那需要在 `syncing` 中改变卫星位置，并重排重建与续写的先后，超出本轮必要的修改。附着检出永久丢失而写回中断的 Goal 只能放弃，这时交还的改动同时在人工编辑检出（可访问时）与 `handback-t1` 中，如实登记。
  - M1 没有取回 `handback-t1` 的界面入口，目标页写出由你执行的只读命令。这与情形 D “只保留分支” 的做法相同。
- **R110-D12-01**：条目不带 `projectId`/`goalId`。原因有二：列出只需要根，判别靠 “没有当前记录”；多存标识只会在 “清除全部” 之后多留数据。
- **R110-D11-01**：隐去的结果带 `isError: true`，使模型不把它当作成功的输出。
- **观察 1**：第三次的暂停取已有的 `prepare_failed` 运行中途一支，而不是新增原因。它与 “Tower 工具被同名扩展遮蔽” 同类，都是 tower-goal 无法履行职责，不在启动时自动解除。
