# 第 27 轮评审回应 · `04` 与 `12`

依据 `15` ADR-153（R27-D15-01 中属于 `04`/`12` 的部分，以及 `lfs_excluded`）。

| 条目 | 处理 |
|---|---|
| R27-D15-01 接管条件（`04` L940） | §4.8.11 改为“只在检出完成标记存在时出现”，删去“至少运行过一次”；与 R26 / ADR-151 的 `E_STATE`（“工作区尚未建立”）一致；`12` `wait slot`、`prepare_failed` 行本已写“已完成检出”，无需再改 |
| R27-D15-01 卡片的 HTTP 状态类别（`04` L949，`12` L411） | 启动失败示例改为 `LFS 对象缺失：128 个（HTTP 4xx）`；写明网络与服务端失败只显示状态类别（`HTTP 4xx` / `HTTP 5xx` / `网络不可达`），原始输出经脱敏只进诊断日志，对应 G43(c) |
| ADR-153 `lfs_excluded` | `04` §4.8.11 新增条目与卡片第 5 行提示清单：`◇ LFS 已排除 N 个文件（按项目配置保留为指针）`，不是失败；`12` `AnomalyChip` 增加准备阶段的两项 `◇` 提示（依赖准备未完成、LFS 已排除），展开显示被排除路径与规则来源 |
