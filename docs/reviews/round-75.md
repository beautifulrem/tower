## 1. 总评

**第 74 轮的 1 条与 §5 的 4 条观察全部在唯一定义处落地**：
- R74-D11-01：已解决。取 “Pi 的项目信任恒为假 + 声明性资源以显式路径传入”，比评审给出的严格一边更严，也保留了更多声明性资源。
- 第 74 轮 §5 的 4 条观察全部按回应改动并已核对。

**ADR-202 的主干成立**：
- **M1 中没有项目来源的代码在 Host 中执行**：
  - SDK：`SettingsManager.fromStorage(storage, {projectTrusted:false})`，不传 `resolveProjectTrust`。`reload()` 只在传入回调时才做引导加载与询问（`resource-loader.ts:520-528`），因此连 `project_trust` 事件都不会发出。
  - 项目设置为 `{}`：其中的 `extensions`、`packages`、资源路径与其他设置一概不生效，项目包不会被安装（`package-manager.ts:1781-1785` 拒绝访问项目包存储）。
  - 项目扩展、`.pi/mcp.json` 不读；内置 MCP 只读用户级配置；codemode、tool-search 不读项目文件。
  - Host 之内的 Pi 不执行项目代码；Tower 的 RunSpec 与 Host 骨架（`05` L90–L92、L340–L360）与之一致。
- **“非可执行资源” 确实不执行代码**：
  - 技能、提示模板只读取并解析 Markdown 与 frontmatter，主题只解析 JSON（`theme.ts:551-555`）；`SYSTEM.md`/`APPEND_SYSTEM.md` 只读成文字。
  - 技能目录中的脚本只能由 Agent 经 bash 运行，在 S2 下即在沙箱内。S0 下 Agent 本来就以用户权限运行（T23），不是新路径。
  - 提示模板只在人的文字以 `/` 开头且允许展开时生效：开场以 `expandPromptTemplates:false` 发送（`05` L275），展开本身也只是文字替换。
- **显式入口不受信任控制**：`additionalSkillPaths` 等在 `reload()` 中与信任判定无关地合并（`resource-loader.ts:599-676`）。RPC 的对应参数经 `main.ts:781-793` 进入同一组选项。
- **不需要物化**：
  - 传入的是卫星中的路径：复核已证明 `.pi`、`.agents` 与 base 相同，base 树中的普通文件在卫星中内容一致。
  - 读规则也已覆盖：S2 读允许列表含卫星内 `.pi/**`、`.agents/**`，祖先目录的技能经 “Host 实际枚举的已启用技能 `baseDir`” 动态加入（`11` L349、`05` L443）。
  - 没有副本，也就没有清理问题。回应 “没有采用物化” 的理由（技能以相对路径引用目录内其他文件）成立。
- **排除符号链接与被忽略文件**：
  - Pi 的自动发现与显式文件加载都跟随符号链接（`package-manager.ts` 的 `collectSkillEntries`、`skills.ts` 的 `statSync`），只取 base 树中的普通文件比 Pi 更严。
  - 卫星中路径分量若被替换为符号链接，快照的差异会显示出来，复核即为不信任。
  - S0 下被忽略文件的盲区因而关闭。
- **T16 残余写得如实**：用户级扩展或 MCP 若自己执行卫星文件，Agent 的代码会经它在沙箱外运行。`11` §11.8.2 残余段、T16 评级 “中” 与理由都写明了，属于用户确认的那段代码的行为。
- **信任提示**：`11` L579–L581 分两组，第二组附 “会在 Tower 中、沙箱之外以你的权限运行代码”。`04` L1455 与之一致（措辞见 §5 观察 2）。
- **G46 (bh)(1)**：覆盖三类代码不加载（工具、子进程、安装根、Host 不读引用文件）、声明性资源随复核的 “加载—不加载—加载”、S0 下被忽略的技能不传入，以及信任提示两组。期望可观察、可判定。

**全范围扫描新发现 1 条：重要 0、次要 1。**

### D11 安全与自主度

**R75-D11-01｜次要**（上下文文件的三道防护按区分大小写的名字匹配，窄于 Pi v1.2.0 实际加载的名字集合）

- **问题**：
  - **正文的规则**：
    - S2 写拒绝列出 `**/AGENTS*.md`、`**/CLAUDE.md`（`11` L350）。同一行对 `.git` 特意写成逐字符的大小写类，这两项却没有。
    - 默认 `protected` 为 `**/AGENTS*.md`、`**/CLAUDE.md`（`02` L307，`11` L208、L210）。
    - 上下文文件复核用 `':(glob)**/AGENTS*.md' ':(glob)**/CLAUDE.md'` 求差异（`11` L597）。
    - `07` L1275 列 `**/AGENTS.md`、`**/AGENTS.override.md`、`**/CLAUDE.md`；S2 读允许列表列祖先目录中的 `AGENTS.md`/`AGENTS.override.md`/`CLAUDE.md`（`11` L349，`05` L443）。
    - `09` L450 写 “每个目录按 `AGENTS.override.md` → `AGENTS.md` → `CLAUDE.md` 取第一个存在的文件”。
    - 正文没有规定这些模式的大小写比较规则。
  - **Pi v1.2.0 的实际行为**：
    - 每个目录的候选为 `AGENTS.override.md`、`AGENTS.md`、`AGENTS.MD`、`CLAUDE.md`、`CLAUDE.MD`，以 `existsSync` 判定（`core/resource-loader.ts:185`；`docs/configuration.md:18`；`CHANGELOG.md:2245`）。
    - 在 macOS 默认的大小写不敏感卷上，`existsSync` 对任何大小写变体都返回真。M1 只在 macOS 上提供 S2。
    - 所以 Pi 加载的名字集合在两个方向上都比正文的模式宽：多了扩展名大写的两种写法；在大小写不敏感卷上，任何大小写变体都算。
  - **照字面实现**：
    - Seatbelt 的 `regex` 区分大小写（这正是 `.git` 写成大小写类的原因），git 的 glob pathspec 也区分大小写。
    - Agent 在卫星根目录新建一个与候选名只差大小写的上下文文件时，三道防护都匹配不上：
      - S2 写拒绝不命中；
      - 复核看不到差异，不生成简报提示与 severity 2 哨兵；
      - 验证时不按 `protected_path` 列出。
    - 下一个 Run 中 Pi 照常把它当作上下文文件加载。由于 `AGENTS.override.md` 排在候选首位，它的大小写变体还会遮蔽 base 中原有的 `AGENTS.md`。
- **所放进的后果类别**：
  - 被提示注入的 Agent 可以给同一 Goal 的后续 Run 植入自动加载的指令，正文为这条路径设的防护（`11` T4 L678：S2 写拒绝、默认 protected、上下文文件复核）都不触发。
  - 验收时这个文件以普通新文件出现在差异中，不带 “Agent 指令文件” 标记（`07` L1275 的 severity 2 下限也不适用）。人若未留意，它会并入仓库，影响此后所有 Goal。
  - 危害属于指令类：代码执行仍受 S2 约束，Agent 也能把指令写进其他会被读到的文件。T4 本就把指令类评为低，所以是次要。
- **为什么不是观察**：
  - 这是一条安全规则的匹配语义没有定义。两种实现（区分或不区分大小写）在 macOS 默认卷上的行为实质不同，而照字面实现会让 T4 列出的三道缓解对 Pi 实际加载的文件失效。
  - `09` L450 对 Pi 事实的陈述也因此不完整。
- **文档位置**：`11` L208、L210、L349、L350、L572、L597、T4 L678；`02` L307；`05` L443；`07` L1275；`09` L450；`15` ADR-091、ADR-120（`.git` 名字比较规则的先例）。
- **期望的回答形态**：在一处唯一定义（例如 `11` §11.8.1 的上下文文件复核，或 `16` 的一行）写出：
  - **名字集合**：取 Pi v1.2.0 的候选清单 `AGENTS.override.md`、`AGENTS.md`、`AGENTS.MD`、`CLAUDE.md`、`CLAUDE.MD`。
  - **比较规则**：在 ASCII 大小写折叠下比较名字，与 `.git` 的现有做法相同。
  - **三道防护都按这一规则**：
    - Seatbelt 写拒绝写成逐字符的大小写类；
    - 默认 `protected` 与复核的差异求取按大小写不敏感匹配（例如对快照差异的路径按名字折叠后过滤，而不是依赖区分大小写的 pathspec）；
    - 读允许列表与 `07` L1275 引用同一集合。
  - `09` L450 改为引用该集合。
  - G 用例补一组：在卫星根目录新建只差大小写的上下文文件（含 `override` 变体），期望 S2 拒绝；S0 下复核提示，验证时按 `protected_path` 列出。
  - **或者**把说法改弱：在 T4 中如实登记 “大小写变体不在防护之内” 的残余，并说明评级为何仍为低。

    4. **M2 的 RPC 设计备忘**：
       - CLI 启动时 `runMigrations(cwd)` 会把项目 `.pi/commands` 迁移为 `.pi/prompts`（`main.ts:668`，`migrations.ts:257-263`），不看信任。这一步在沙箱外写卫星的 `.pi`，会让下一个 Run 的复核变成不信任。
       - SDK 路径不经过它，M1 不受影响。建议在 ADR-202 的 M2 推迟项中记一句。
