# 第 16 轮评审回应 · `04` 与 `12`

一行一条：条目 → 处理位置与方式。依据 `15` ADR-137 – ADR-139 与 `02`、`03` 的主干修订（`Continuation` 载荷与 `claim`、`drainingFor`、停止条件的求值与再武装）。

| 条目 | 处理 |
|---|---|
| R16-D4-02 / R16-D15-01 #6（`04` L1371） | ADR-137：§4.18.3 硬预算上限行改为两个分开的动作——`扩展预算`（只提高额度，不解除暂停）与 `继续`（额度不高于已花费时置灰）；`12` §12.6.5 `budget_hard_cap` 行同步 |
| ADR-137 `claim` | `04` §4.18.3、§4.19 停下未提交行与 §4.7.2：`按当前状态送去验证` 写明内容仍是 Agent 的，失败照常自动返工，轨迹记 `人代为提交`；`12` §12.6.5 `budget_hard_cap`、`idle_without_submit` 行同步 |
| ADR-137 较旧 seal 合入 | `04` F7 第 6 步：合入较旧汇总提交且目标已有新内容时不进 `integrated`，只记 `local_merged`；`accepted` 退回 `in_review` 并提示 `◇ base 已含较旧版本` |
| ADR-137 `nested_repo_live` 消失 | `04` §4.8.9、§4.8.11：无论是否有其他原因，一律加入 `human`、显示“条目已消失，确认后继续”，其他原因以 `另有：…` 显示；`12` §12.6.5 对应行同步 |
| R16-D7-01 / ADR-137 keep/revert 告知 Agent | `04` §4.8.7：`run` 目标下采纳或撤销后，下一回合以 `tower.external_resolved` 开场，轨迹显示 `Tower 注入`；`settle` 目标下采纳后的验证按你的改动处理（失败不自动返工） |
| ADR-137 `run` 载荷 / `settle` 定义 | `04` §4.8.11：继续目标列表改为“重新执行收尾序列（有效提交保留）”，增加“人代为提交”；期间的决定按顺序作为下一回合开场，显示为 `Tower 注入` |
| R16-D6-01 / ADR-138 暂停后立即退出 | `04` F12 与 §4.18.3 应用退出行：确认框为“暂停中”的目标单列“下次启动仍为暂停，不会自动恢复”；重启后以原来要进入的原因暂停，应用退出只作叠加原因 |
| ADR-138 drain 期间显示 | `12` §12.6.4 实况行表新增“正在暂停”行：`‖ 暂停中（等待当前步骤结束）· <drainingFor.reason>`，有更高原因时替换 |
| ADR-138 nudge 守卫 | `04` §4.19 停下未提交行：不满足提醒条件时直接暂停、不提醒 |
| R16-D8-01 / ADR-139 停止条件 | `04` §4.8.10：卡片写出命中的具体路径或命令，以及“调用在执行前被拒绝”；“继续”= 该对象静默到本 Run 结束（计时 / 返工计数重新计）；“这里不该停”= 该条件静默到下次修订合同，合同页标 `已停用 · 到下次修订`；`natural` 条件不产生此卡片，表现为问题；`12` §12.6.5 `stop_condition` 行同步 |
| R16 其余各项 | 不在 `04`/`12` 中 |
