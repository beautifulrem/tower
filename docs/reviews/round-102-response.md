1. 把说法改弱，但保证为真；
2. 删除或推迟不属于 M1 主循环的机制；
3. 在已有的唯一定义处加至多一条守卫、一行或一个字段。

新增的只有：

- `11` §11.7.1 模型凭据一行中 “与 `pi /login` 存储的凭据的先后” 一段（复用 Pi 已导出的 `readStoredCredential` 与公开的 `removeRuntimeApiKey`）；

不新增状态、事件类型、表、列、命令、决定种类、Needs-You kind、landmark、`wait_reason` 值、锁或常驻进程。

安全不变式全部保留：
- Tower 不会自动把机密交给 Agent 可影响的进程。模型密钥仍只经运行时注入、只在 Host 内存中；不注入时 Pi 读你自己的 `auth.json`，与终端相同。bearer 令牌与原始密钥并存时连投递文件都不写。`ANTHROPIC_AUTH_TOKEN` 仍不放进 Host 环境。
- 沙箱外的 Tower 进程不在 Agent 可控的 git 元数据上运行 git。交还对话框的提交数与删除确认框一样，只由隔离 worker 只读解析 H/.git。
- 沙箱外进程不可发现卫星。`GIT_CEILING_DIRECTORIES` 明确列在 Host 环境的唯一定义中。
- Tower 从不自动删除人的工作现场。`goal.delete_kept` 仍只在本机、由人确认；确认框过期或求值失败时都不静默删除。

安全问题只写到设计层面。

## R102-D5-01（次要）：运行时注入的密钥压过 `pi /login` 存储的凭据

取评审的第一种写法（“与终端相同”）。

- **唯一定义** `11` §11.7.1 模型凭据一行（L517），新增 “与 `pi /login` 存储的凭据的先后”：
  - Tower 只在你的 `auth.json` 中**没有**该 provider 的存储凭据时注入导入的密钥。
  - 每次 `host.spawn` 与每个 Run 创建会话之前，以 `readStoredCredential(provider, authPath)` 检查：有存储的凭据（`/login` 的订阅或密钥）时不调用 `setRuntimeApiKey`，已注入的以 `removeRuntimeApiKey` 移除。所以用哪份凭据、由谁计费与终端相同。
  - 首次运行与模型选择器对这类 provider 写明 `已有 pi /login 的凭据，Tower 用它`。
  - 如实写明：Host 运行中你在终端 `/login` 时，正在进行的 Run 仍用已注入的密钥，下一个 Run 起改用存储的凭据。
- **(b) ADR-229 新写的一句**（`11` §11.7.1 云 SDK 凭据链，少见配置）改为：
  - 存储了 Bedrock 的凭据时 Tower 也不注入 `AWS_BEARER_TOKEN_BEDROCK`，用哪份凭据与终端相同；
  - ①–③ 的区域变量照常传入，区域可能与终端不同（同一行登记的两处差别）。
- **(c) 标注与并存**：
  - `ANTHROPIC_AUTH_TOKEN`：有存储的凭据时两边都用它，不标注；没有存储的凭据、shell 中另有 `ANTHROPIC_API_KEY` 时，确认卡片与模型选择器写明 `你的终端用 ANTHROPIC_AUTH_TOKEN，Tower 用 ANTHROPIC_API_KEY`。
  - `AWS_BEARER_TOKEN_BEDROCK` 与原始密钥对并存：终端用令牌（`amazon-bedrock.ts:64`），Tower 同样只注入令牌、不导入原始密钥、不写投递文件、Host 环境中不带 `AWS_PROFILE`，与终端相同。
- **同步**：`05` §5.3.6 SDK 一条与首次运行（L486、L489）；`05` §5.11.1 D57 登记新依赖的两个 Pi 接口（L1443）；`04` §4.18.1 第 2 步；`16` 云 SDK 凭据一行。
- **测试**：G46 (d) 第八组（订阅登录加 `ANTHROPIC_API_KEY` 并在 Host 运行中 `/logout`；令牌与密钥并存；bearer 令牌与原始密钥并存）。

## R102-D13-01（次要）：删除确认框的提交数、求值失败、没有 Goal 行的目录

- **(a) 提交数**（`10` §10.1.2 同一行，L53）：
  - 从 `HEAD`、全部 loose ref 与 `packed-refs`（含人新建的分支与 `refs/stash`）沿父链数提交；
  - 遇到 Supervisor 交给 worker 的本 Goal 已知提交 id（数据库中记录的检查点、pin、seal 与 base 的提交），或对象库中没有的对象，即停。按提交 id 判定，所以人照 `10` §10.2 自行 `repack` 之后结果不变；
  - 只在 reflog 中的提交（如较早的 stash 条目）不计入，所以确认框写 `至少 N 个提交` 并列出它们所在的 ref 名；
  - 达到解析器 200 个提交的上限时写 `200+ 个提交`；
  - 没有已知 id 时（Goal 已清除或没有 Goal 行）只以对象缺失为界，自含对象的 H 会把历史一并数入，偏保守。
- **(b) 求值失败**（`10` §10.2，L259）：任何一步失败（含磁盘满时临时索引写不出对象、解析超时）时，该部分写 `无法计算，删除前请自行检查`，其余照常列出（文件数与大小只需遍历目录），删除仍可用，确认按钮写 `仍然删除`。磁盘满时人仍能在 Tower 中释放空间。
- **(c) 没有 Goal 行的目录**（同处）：
  - 标 `来源未知（清除全部后遗留）`，删除流程相同；
  - `goal.delete_kept` 对它只校验路径在已知 Project 的 `<wtRoot>` 之下、名字为所列形状，不要求 Goal 行存在；
  - `04` §4.15 存储面板、`06` §6.4.3 `goal.delete_kept` 一行（L911）同步。
- **测试**：G46 补组（stash 与 `repack` 前后、临时索引写入失败、清除全部之后重新列出的目录）。

## §5 观察

1. **更正 ADR-229 给出的理由**：
   - ADR-229 以 “请求级 `env` 会话路径不传” 说明 Tower 不能不经进程环境给出 profile，漏了存储凭据的 `env` 一支（这一支确实可行）。
   - 真实理由：`ModelRuntime` 只接受一个凭据存储，它同时承担你的 `auth.json` 中 OAuth 令牌的刷新与落盘；文件型 `AuthStorage` 不从包入口导出，Tower 要自己实现 `auth.json` 的读写与跨进程锁，正是 D57 不采用的一类。结论不变。
   - `11` §11.7.1 云 SDK 凭据链一行改写依据；ADR-229 的 Pi 核实一条加〔ADR-230 更正〕。
2. **`registerNativeProvider`**：`11` §11.7.1 模型凭据一行登记这条途径与不采用的理由（要随 Pi 的每个版本维护 Anthropic provider 的副本）。
3. **F8 的横幅**：`08` §8.1 写明磁盘满是应用级横幅：显示在主窗口顶部直到解除，不是 Needs-You，不经过级别，不计入 Dock 角标与打扰预算，取自 Supervisor 的进程内状态，随 `system` 主题推送。`06` §6.8 F8 改为引用。
4. **`00` §0.5.1 凭据一行**（L112）：影响列补 “部分凭据类型（如以头部发送的令牌）只在你的终端中可用，首次运行如实标注（`11` §11.7.1）”。
5. **过期确认与 drain 之后的接管**：`goal.delete_kept` 增一个字段 `listedAt`（确认框求值的时刻）；所列路径上目录的建立时间晚于它时返回 `E_STATE`，界面重新求值。从 `running` 接管时，drain 之后的改名先等进行中的 `goal.delete_kept` 结束（`10` §10.2、`06` §6.4.3）。
6. **估计独占大小**（`10` §10.4.4，L568）：限定在 0 与逻辑大小之间；没有记录时取逻辑大小；合计在每次产生或删除这类目录之后与打开存储面板时求值（`mtime` 一项为一次目录扫描，不常驻监视）。`13` §13.11.3 同步。
7. **E6 复审线的窗口**（`14` L570）：任一次每周计量时的存量（不是增量），M1 中即自用期内任一次计量。“与对应检查点相同的副本” 的份额不由 E6 度量，属于 M2 决定点自己的数据。
8. **“逐个删除” 与多选**：统一为 “由人逐行或多选 `删除`”（`08` §8.1、`10` §10.3.2、`06` §6.8 F8、`14` §14.4.1）；M2 的 “一键批量删除” 写明 “不需逐个选择”（`14` L456）。
9. **清除结果与机密副本**：`09` §9.12.4 的清除结果对带了本地机密文件的检验目录另注明 `含本地机密文件的副本`。
10. **措辞与引用**：
    - `11` §11.7.1 与 D62 的抛出位置改为 coding-agent `core/model-runtime.ts:676`；
    - Anthropic 工作负载身份联合写明 “这是范围选择而不是做不到”：它与 Vertex 同类，推迟到 M2；
    - `14` G46 标题的 ADR 列表补到 ADR-230、轮次补到 R102；
    - `14` W17 的 “F8” 改为 “`06` §6.8 F8”。

## 偏离与未决

- **R102-D8-01 没有复用水位，也没有新增读类消息**：存储提示不是事件、没有序号，复用水位需要新命令与新 scope。改为界面状态后，代价如实写明：每个窗口各自记，界面重新加载后条件仍成立时再显示一次。
- **R102-D13-01 (a) 没有照评审建议以 H/.git 的 reflog 第一条取起始检查点**：reflog 是 H/.git 中人与 Agent 代码都能改写的文件。停止条件改用 Tower 数据库中的已知提交 id。没有 Goal 行时退回 “对象缺失”，偏保守，已写明。
- **R102-D13-01 (b) 求值失败时仍允许删除**：删除由人显式发起，确认框写明 `无法计算，删除前请自行检查`，按钮为 `仍然删除`。磁盘满时这是人在 Tower 中释放空间的途径。
- **R102-D12-01 没有传 Tower 自有的 `logPath`**：理由见该条。
- **R102-D15-01 工具链变量改为封闭列表**：与 `16` §16.8 的七个相同，比原来的 “…” 偏严。用到其他工具链变量的用户，其 Host 子进程（MCP 服务器、扩展）看不到它们。这一点登记在唯一定义中，不另设放行机制。
- **R102-D5-01 Host 运行中的 `/login`**：从下一个 Run 起生效，不在 Run 中途切换凭据，已写明。
- **未决**：无。
