## 1. 总评

**第 93 轮的 7 条次要条目都已按所问关闭**（核对见 §3）。§5 的 14 条观察全部落地。回应 “偏离与未决” 的七条都接受，但有一处未写出的偏离：forbid 使凭据读取的尝试降为 chip，见 R94-D11-01。

**ADR-221 的主体成立**（§3.3）：
- **辅助进程与 Pi 的语义**：Pi 的三个工具把编码、BOM、行尾都放在内存中处理，`operations` 只搬字节，所以用 `cat`、经 `sh` 重定向写入、`mkdir -p` 实现时语义不变。`head -c 4100` 与 Pi 的 `IMAGE_TYPE_SNIFF_BYTES` 相同，纯字节判定可以移植。同一次 `edit` 读与写之间文件被改动的窗口与 Pi 自己的实现相同，属于已登记的残余 (i)。
- **按次启动**：内存并入已有的 `p90_g`，Host 的测量口径因此完整；`edit`/`write` 在中止时等文件操作结束，settle 时不会有还在写的辅助进程。
- **必然拒绝不询问**：不出注定无效的审批卡，判定与 S2 不一致时访问仍由 S2 决定，不越权。
- **写回失败的崩溃窗口**：① 经旁路目录物化，② 还原整个写回集合，③ 先改名再置标记，④ 在同一事务中生成告知。L140 中 “原路径上只可能是重建自己 `rename` 到位的目录” 成立。
- **删除前比较**：推广到本进程中的交还、带回与启动续写；带回删除中断的重启改为比较。`04` 的承诺因此为真。

**ADR-221 带出的新问题**（都是次要）：
- **辅助进程规格的三处余项**（R94-D5-01）：
  - “反复失败由 `07` §7.7.1 处理” 在 M1 不为真：S1 只看 bash 命令的退出码；
  - 超时杀掉或崩溃的写入可能留下半截文件，工具结果没有说；
  - 16 MB 上限与 10 s 超时在 S0 下是否适用，没有写。
- **启动恢复的顺序**（R94-D6-01）：③ 断言 “改名之后崩溃，重启续写因卫星不在而失败，再进入本步”。但 `06` L139 的卫星丢失一行同样命中，而且不排除 `syncing`，§6.1.6 也没有行间顺序。
- **`write_back_failed` 在 “继续” 之后不关闭**（R94-D8-01）：① 失败转入检出丢失，或人自己删了副本时，人若选 “继续”，这条 severity 2 的条目一直打开，文字也已过时。
- **辅助进程没有延迟预算**（R94-D10-01）：一次 `read` 要起三个沙箱进程，`13` 与 `16` 没有每次操作的开销目标、测量或回退。同样位于 Agent 主路径上的 git 垫片是有的。
- **必然拒绝使凭据读取的尝试只剩一个 chip**（R94-D11-01）：第 93 轮之前这是一张单向门审批卡，ADR-125 把凭据读取的拒绝定为永不降级的 severity 2。现在 `read` 读取凭据只记 `policy_block`（severity 1），而同样的尝试经 bash 仍会出卡片。
- **“经批准的目标” 的匹配口径**（R94-D11-02）：比较用字面还是 `realpath` 形式、包含关系算不算，都没有写，而 G46 的 `~/.aws` 链接组依赖这一点。
- **新的 `.kept-*` 目录没有同步到清除与目录枚举**（R94-D12-01）：`09` §9.12.4 的保留清单仍是 “四种”。回退位置下的 “清除全部” 照文字会删除 `_inspect/<goalId>.kept-*`，而那里只有人在写回期间保存的改动。卫星的 `.kept-*` 在 `16` 中的类别随位置变化。
- **观察器只删除了一部分 Pi 输出文件**（R94-D12-02）：`full_output_path` 只在输出超过 1 MB 时出现。50 KB–1 MB 的截断输出与超时、中止的全文文件都不会被删除，`09`、`11` 写的 “复制之后即删除” 对它们不成立。
- **G46 文件工具组与 C42 (d) 的时序**（R94-D14-01）：如果换链接在调用之前就已完成，分类就能看到主检出，调用按必然拒绝直接 forbid、不记 `sandbox_violation`，与期望相反。如果要求换链接发生在分类与执行之间，则需要测试接缝，文字中没有。

**R94-D5-01｜次要**（辅助进程规格的三处余项：M1 的循环检测不覆盖文件工具；写入被杀之后的半截文件；S0 下的适用范围）

- **问题**：
  - **(1) 兜底的说法在 M1 不为真**。`11` L160 写 “反复失败表现为反复失败的工具调用，由 `07` §7.7.1 的循环/停滞检测处理，不另设规则”。但 `07` L1331 写明 M1 只实现 S1、S5、心跳与合同停止条件，而 S1 的定义是 “同 `(normalized, failureSignature)` 且 `exitCode≠0`”（L1359），只针对 bash 命令。文件工具反复失败（辅助进程反复起不来，或同一路径反复被必然拒绝）在 M1 中没有检测器。
  - **(2) 写入失败可能已部分落盘**。写入经 `/bin/sh` 重定向，先截断目标文件再写。超时被杀或进程崩溃时，文件可能已经空了或只写了一半。文字说 “报告为失败的写入不会在之后落盘”，这句话为真，但工具结果只写原因，没说文件可能已被改动。对 `edit` 而言，模型看到的是 “修改失败”，往往以为原文件不变；之后的 `edit` 会因 `oldText` 找不到而失败，或者在半截文件上继续改。另外，“等它退出” 应指整个进程组（`sh` 可能派生 `cat`，而不是 `exec` 它）。
  - **(3) S0**。上限与超时只写在 S2 的句子里；`05` L388 说 “S0 下没有档位，在 Host 中直接执行”。在 Host 进程内用 `fs` 调用时，超时无法以 “杀掉进程” 实现；`13` L173 的 “≤ 16 MB” 又以上限为前提。
- **后果的类别**：
  - (1) 是不为真的说法：实现者要么把 S1 扩到文件工具，要么什么都不做。
  - (2) 使 Agent 在一个已被改动的文件上做出错误判断。写入的是卫星中 Agent 自己的文件，有检查点与验证兜底，有界。
  - (3) 在 S0 下实现分叉。
- **文档位置**：`11` L160；`07` L1331、L1359；`05` L388；`13` L173；`16` L895。
- **期望的回答形态**：在 `11` L160（唯一定义）中：
  - 把 (1) 改为 “M1 不另行检测”（或把 S1 的键扩到文件工具的 `(tool, path, 错误)`）；
  - 写入在辅助进程已启动之后失败时，工具结果写 “文件可能已部分写入，请重新读取后再改”，并把 “等它退出” 写为进程组；
  - 写一句 S0 下上限是否适用、超时是否适用（例如上限适用、超时不适用），`13` L173 随之。

### D10 性能

**R94-D10-01｜次要**（每次文件操作一个沙箱进程，一次 `read` 起三个，却没有开销预算、测量与回退）

- **问题**：
  - `11` L160 只写 “代价是每次文件操作多一次进程启动”。按 Pi 的调用顺序，一次 `read` 是 `access` → `detectImageMimeType` → `readFile` 三次操作（`read.ts:127, 129, 135/155`），`edit` 是三次，`write` 是两次。每次都经同一 S2 包装（`sandbox-runtime` → `sandbox-exec` → 系统命令）启动。
  - 同样位于 Agent 主路径上的两个机制都有每次调用的预算：git 垫片 “单次额外开销目标 ≤ 5 ms；SP5 实测回填；超过 10 ms 时改为 `posix_spawn` 直通”（`13` L319，`16` L887）；门禁判定 “p95 ≤ 5 ms”（`11` §11.4）。辅助进程没有对应的一行，SP6a 的 A1–A12 也没有测量沙箱包装的启动开销。
  - Agent 一个 Run 中读几百个文件是常态。包装的启动若在数十毫秒量级，一次 `read` 就要增加约百毫秒，一个 Run 累计以十秒计。并行批次能摊薄一部分，但也会同时起很多沙箱进程。
  - `16` L895 的回填依据写 E7（分类器离线语料），它测不到这一项。
- **后果的类别**：Agent 主循环可能出现不受控的延迟回归，而 M1 的门槛发现不了。实现也会分叉：有的照字面每次操作起一个进程，有的把同一次 `read` 的三次操作合并为一次启动（例如 `access` 时就取回整份内容，供随后的判定与读取使用；三次调用在同一次 `execute` 中，S2 照样在打开的那一刻判定）。
- **文档位置**：`11` L160；`13` L319、§13.11.1；`16` L887、L895；`14` SP6a。
- **期望的回答形态**：在 `13` §13.11.1 或 §13.1 为辅助进程加一行，写明每次文件操作的额外开销目标（例如 p95 ≤ N ms）、在哪个 SP 或 E6 中测量、超出时的回退（例如允许同一次工具调用的多次操作共用一次启动）。`16` L895 的回填依据随之改正。

### D11 安全与自主度

**R94-D11-01｜次要**（必然拒绝使文件工具读取凭据的尝试只剩 severity 1 的 chip）

- **问题**：
  - `11` L162：S2 下文件工具求出的路径命中读拒绝（含密钥路径表）时，调用带 `hardFloor`，“不出审批卡、不可授权，也不发生访问、不记 `sandbox_violation`”。forbid 在门禁中只记 `policy_block`（`11` L268；`16` L170 “sev 1，提示性”；`07` L1527 “chip”）。
  - 第 93 轮之前，同一次 `read` 读取凭据会归 `secrets.access`，出一张单向门审批卡（双确认）。而 ADR-125 把凭据读取被沙箱拒绝定为 severity 2、“可能表明提示注入或越权意图”、永不降级、不入良性清单（`11` L372）。现在，Agent 未经要求就用 `read` 读取凭据——这正是 ADR-125 要捕捉的信号，`read` 又是 Agent 读文件的主要途径——只留下一个 severity 1 的 chip。同样的尝试经 bash 仍出卡片。
  - 写入上下文文件名、`user_config` 写入、读取用户主检出等也落在同一处理中，其中一部分此前就是硬底线 chip（这是已有设计）。新增的损失主要在凭据读取上。
  - ADR-221 与回应只说 “安全不变式全部保留”“经批准的目标不是降级”，没有讨论这条 forbid 本身产生什么注意力信号。
- **后果的类别**：访问本身被挡住，边界更严；损失的是检测信号。可能由提示注入引起的凭据探测，经最常用的工具时变得最不显眼，与 ADR-125 的意图相反。实现会分叉：有的照文字只记 chip，有的自行补告警。
- **文档位置**：`11` L162、L268、L372；`16` L170、L174；`07` L1522、L1527；`04` L1133；`00` L104；ADR-125、ADR-221。
- **期望的回答形态**：在 `11` L162 补一句：forbid 的目标若属于 `16` §16.1.6 的 severity 2 受保护类别（至少 `credential` 的读），按同一 `(category, op, target)` 记 severity 2 的 `sentinel`，去重键与 `sv:` 相同，措辞同 `sandbox_violation`。或者如实登记 “文件工具的这类尝试只记 chip”，并在 ADR-125 中写明它只适用于实际发生且被拒绝的访问。

**R94-D11-02｜次要**（“经批准的目标” 的匹配口径：字面还是 `realpath`，相等还是包含）

- **问题**：
  - `11` L372 写 “目标在该次批准所列的路径之中时，不论类别都记为 severity 1”。两点没有写：
    - **形式**：审批卡列出的是分类器从 bash 命令中求出的路径（字面形式）；`sandbox_violation.target` 是 “精确到文件的规范化路径”（`16` L174），由 Seatbelt 的拒绝日志得到，是真实路径。
    - **相等还是包含**：“之中” 可以读成 “等于所列的某一项”，也可以读成 “在所列的某个目录之下”。
  - G46 的 `~/.aws` 链接组（`14` L134）依赖前一点：`~/.aws` 是指向别处的符号链接，人批准 bash 读取 `~/.aws/credentials`，期望 “只有一条 severity 1 的提示”。若按字面比较，`target` 是链接目标处的真实路径，与所列路径不等，结果为 severity 2，这一组不通过。
  - 后一点关系到信号的强弱：若包含关系算数，人批准了一条所列路径很宽的命令（例如列出主目录）时，该命令中所有被拒绝的凭据读取都降为 severity 1。
- **后果的类别**：验收组与规则相互依赖，实现会分叉；按包含关系实现时，一次范围很宽的批准会压低本应是 severity 2 的凭据信号。
- **文档位置**：`11` L161（比较的规范形式）、L372；`16` L174；`14` L134 G46。
- **期望的回答形态**：在 `11` L372 补一句匹配口径，例如：“与 §11.3.1 比较的规范形式相同，所列路径与 `target` 各取字面与 `realpath` 两种形式，任一相等即算；只按相等、不按包含；`credential` 类只在相等时适用”。

### D14 路线图与可验证性

**R94-D14-01｜次要**（G46 文件工具组与 C42 (d) 的换链接时序未定义，期望的 `sandbox_violation` 与必然拒绝相反）

- **问题**：
  - G46（`14` L134）文件工具组的设置是 “另一次由后台进程完成同样的换法后再 `read` 经该链接的凭据夹具”，期望 “主检出与凭据夹具都未被写入或读出，工具报错并记 `sandbox_violation`”。
  - 照字面，换法 “完成后” 才发出 `read`。分类时求出的 `real` 已经落在用户主检出中，而主检出是显式的读拒绝（`11` L357）。按 `11` L162 “允许一侧以 `real` 判定、拒绝一侧任一形式命中即算”，这次调用直接 forbid，**不发生访问、不记 `sandbox_violation`**，与期望相反（主检出本身也是第 3 条硬底线）。
  - C42 (d)（`05` L1499）写 “由后台进程（`sleep 1; ln -sfn …` 放到后台）完成同样的换法，结果相同”。同一批中的 `read` 通常在 1 s 的换法之前就已执行完；下一条消息中的 `read` 又在换法之后才分类，同样被 forbid。两种时序都观察不到 “分类之后、访问之前” 的换法，也就测不到使用时强制。
  - 这两组是 ADR-220 引入的，第 93 轮没有指出；ADR-221 写明必然拒绝 “不记 `sandbox_violation`” 之后，矛盾才变得明确。
- **后果的类别**：M1 验收（SP6b 第二批失败阻塞冻结）中的一组期望与唯一定义相反，或者测试只是碰巧通过（没有真正测到访问时的强制）。实现者要么改测试，要么削弱必然拒绝。
- **文档位置**：`14` L134 G46 文件工具组；`05` L1499 C42 (d)；`11` L160、L162、L357。
- **期望的回答形态**：二选一并写进两处：
  - 要求换法发生在分类与执行之间，并写明测试接缝（例如在辅助进程启动之前由夹具钩子完成换法，或在 Tower 的 `operations` 中注入可控延迟）；
  - 或者把 “换法完成后再调用” 的一组期望改为 “直接 forbid、不出卡、不记 `sandbox_violation`”，与 `~/.aws` 链接组相同，并把旧期望登入 `16` §16.1.13。

    - 排期结论成立：WBS 123.71；余量 0.12 / 0.14 / 0.22 / 0.26 / 0.12；依赖链 19.91；增人 129.70、T 23.95、33 周；M1 38 周（2027-07-30）。
  - **不扣分的观察**：
    1. **按次启动的进程身份**：辅助进程不带 Run 令牌，也不在 `exec` 记录的进程树中。Host 崩溃时，正在写的辅助进程会读到标准输入的 EOF，写完它已收到的那部分后退出，重启清理（`06` L145、L198）不会找到它。窗口至多一次操作，结果与 R94-D5-01 (2) 相同，可以在那一句中一并写出。
    2. **`/bin/test` 与错误码**：`edit.ts:179-181` 把 `error.code` 写进 “Could not edit file” 的文字。`test` 只有退出码，分不清 “不存在” 与 “被沙箱拒绝”。宜写明映射：先判 `-e`，再判 `-r`/`-w`，分别给出 `ENOENT` 与 `EACCES`。
    3. **`read` 中止后的辅助进程**：`read.ts:116-119` 在中止时立即拒绝，它的辅助进程最多再跑 10 s。只读，无害；`11` L160 “settle 时没有仍在写的辅助进程” 的论证只针对 `edit`/`write`，可以加 “`read` 的辅助进程只读，由 10 s 超时收回”。
    4. **必然拒绝的路径数据与基础档**：`11` L355 的读允许列表含 “Seatbelt 基础档中的 OS 目录”。L162 的 “同一份路径数据” 若不含它们，`/usr/include`、SDK 头文件一类的读取会被误判为必然拒绝。模型收到 “批准也不会改变；改用 `ask_user`”，而 bash 的 `cat` 其实能读。文字已写 “误判为拒绝的只少一次本可成功的读写”，宜同时要求路径数据显式包含基础档的读路径，或把 “允许列表之外、但未被显式拒绝” 的路径留给常规分类。另有两处同类细节：`read` 的名字变体取最严格者，一个从未被打开的变体落在拒绝范围时，也会 forbid 一次合法的读取；`11` L372 “实际只作用于 bash” 不完全对，竞态或误判为允许时，文件工具同样会出现 “批准后被拒绝”。
    5. **③ 与 ① 的两个失败分支**：③ 的改名本身失败时（例如目录被占用），文字仍会置 `satellite_rebuilding=1`，而 L140 “原路径上只可能是重建自己 `rename` 到位的目录” 随之不成立。宜写 “改名失败时不置标记，只生成 ④ 的条目”。① 的 `renameat` 遇到原路径已存在时 “不覆盖”，但没有写旁路目录如何处理，条目中 “Tower 以你交还时的内容重新建立的” 此时也不为真。宜写 “旁路目录按 §10.2 改名保留并列出”。工作目录与 gitdir 两次改名之间崩溃时，两者的时间戳不同，与 L256 “时间相同” 不符，只是措辞问题。
    6. **交还预算的措辞**：`13` L330 仍写 “交还：一次 `add -A` 比较（同指纹预算）+ 逐文件复制”。删除前比较之后是两次求树，带回也没有对应的一行。宜写 “两次（求 T1 与删除前比较；第二次沿用同一临时索引的 stat 缓存）”，并补带回。
    7. **S0 下删除全文文件**：S0 下 Agent 读得到 Pi 的全文文件，Pi 的提示 “Full output: <path>” 也引导它去读（`bash.ts:348-352`）。观察器复制之后立即删除，使这一提示在 S0 下同样失效，而 `07` L84 的理由只是 “S2 下 Agent 也读不到它”。宜写 S0 下推迟到 Run 结束再删，或如实写出。删除前也宜校验路径是临时目录的直接子项、名字符合 Pi 的前缀。
    8. **① 失败后 T1 的可达性**：① 也失败时，③ 清除 `targetTree` 且不写决定，T1 只剩在影子对象中，宽限期之后会被 gc。条目已如实写 “你的改动未能保留在目录中”，宜补 “在影子中保留至 <日期>，可经诊断导出”，或明写不可恢复。
    9. **改名保留的界面与验收**：`10` L256 写 “Goal 页与该 Goal 的下一条通知列出”，`04` 与 `12` 没有给出它在 Goal 页上的位置，也没说明交还成功而目录被改名保留时，哪一条通知承担这一告知。G31 “还原也失败” 一组只断言卫星从检查点重建，没有断言旧卫星与 gitdir 被改名为 `.kept-*`。
    10. **§10.2 的旧理由**：`10` L254 写 “上述两种来源中都没有未交还的改动”。ADR-221 之后，交还第 8 步在清除 `humanCheckout` 的事务之后才比较并删除，中途崩溃留下的 H 可能含写回期间保存的改动。因为不会被删除，所以不丢数据，但这句理由不再成立；带回的删除中断有重启比较（L928），交还没有，两侧不对称。
    11. **“一律” 的范围**：`16` L644 与 ADR-221 标题写 “删除来源目录前一律比较”，而人显式丢弃时（`goal.discard_human_edits`、`inspect.close{discard}`、放弃 Goal 时选丢弃）不比较。这样做是对的，宜把 “一律” 限定为 “Tower 在写回成功之后删除时”。
    12. **`04` L667 的无条件措辞**：“（原来的工作目录改名保留在 <路径>）” 只在卫星仍在原位时成立；③ 的另一支 “卫星已不在” 时没有路径可写。
    13. **补记的落点**：`15` L1429 写 “落点在安全线的 W10、系统线的 W3 与 Agent 线的 W6”，`14` L216 与 ADR-221 末段只写 W10 与 W3。不影响数值。
    14. **`04` L1133 的措辞**：“只在批准能起作用的地方出现” 之后紧接着列出 S2 下 bash 读取凭据的卡片，而那里批准恰恰不起作用。宜改为 “文件工具只在批准能起作用的地方出卡；bash 照旧出卡”。
- **设计是否完成：ADR-221 正确地关闭了第 93 轮的七条次要条目。**
  - 辅助进程有了取值与形态，内存回到已有的进程树预留；注定无效的审批卡消失；写回失败处理自身可以在崩溃之后续做；删除来源目录之前的比较成为一般规则，`04` 的承诺因此为真。
  - 本轮 9 条都是次要，分三类：

    - **新目录与新删除的覆盖面**：R94-D12-01（`.kept-*` 与清除）、R94-D12-02（全文文件的删除范围）。
