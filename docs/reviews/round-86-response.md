## Pi v1.2.0 核实（`packages/coding-agent/src/`，`git show v1.2.0:<path>`）

**stdio MCP 服务器的工作目录与环境**：
- 内置 MCP 扩展以会话的 `ctx.cwd` 为 `sessionCwd`（`extensions/mcp/index.ts:297`、`:1121`），交给每个服务器连接，传输工厂可由选项替换（`:570-571`、`:69-73`）。

- 项目级 `.pi/mcp.json` 只在项目被信任时读（`extensions/mcp/config.ts:145-149`），M1 中恒为不信任（ADR-202）。

**全局根查询**：`runCommandSync` 同步、无超时（`core/package-manager.ts:2752-2765`），异常返回 `undefined`（`:2143-2149`）。资源加载的 `extensionsOverride`（`core/resource-loader.ts:596`）在扩展模块已加载（`:586`）之后运行，不能作为 “只加载清单中的包” 的开关；Pi 没有显式的包允许列表选项。

## R86-D11-01（重要）：stdio MCP 服务器的工作目录

**决定**：Pi 让传输工厂决定 spawn 的工作目录，Tower 在 SDK 下本就提供自己的工厂，所以取评审的 (a)，不推迟 stdio 服务器。

**唯一定义**：`05` §5.3.5 “stdio 服务器的工作目录”（L433）。
- `towerMcpTransport` 以你的主目录（即 Host 的工作目录）为基准：`cwd = resolve(主目录, config.cwd ?? ".")`，`~` 照常展开。
- 结果落在 Agent 可写的位置之下（§5.3.6 规则的集合）时不创建传输、抛出错误，Pi 把该服务器记为 `failed`，文字 `MCP 服务器 <名字> 的工作目录在 Tower 的工作区之下，Tower 不启动它`；静态清单在该条目旁写同一句。
- 服务器得到的 `roots` 仍是卫星（连接单独声明），代码智能类服务器不受影响；`args` 中的相对路径（如 `.`）改为相对主目录，`00` §0.5.1 如实写明。
- HTTP 服务器照常加载。
- 理由与限定写在规则旁：包运行器按工作目录的项目配置与本地依赖选程序；S2 下主目录不是 Agent 可写的位置，S0 见 T23。
- RPC（M2）无法替换传输，须保持同一不变式，随 M2 复审。

**同步**：
- `05` §5.3.6 规则（L445）推广到 “Host 为 stdio MCP 服务器选定的工作目录”；§5.3.1（L277）“与 CLI 完全一致” 补例外；D53 的引文补行号。
- `11` §11.3.4（L221）“以卫星为根运行” 改为 “以 `roots`（Pi 声明为卫星）为根”，相对路径一项改为 “按工作目录还是 `roots` 解析门禁不知道”；§11.8.2 清单行（L607）与残余（L611）；T4（L680）、T16（L692）。
- `00` §0.5.1 新增一行（L99）；README 例外补半句。
- `14` G10（L72）的夹具改为 “以卫星为 `roots`，对卫星运行 `git status`”。

**测试**（只写期望）：
- C21（`05` L1455）补一组：不写 `cwd` 的服务器工作目录是主目录；卫星中出现同名本地依赖或项目级配置后，新会话启动的服务器工作目录与实际执行的程序都不变；`cwd` 落在卫星或 `$GS` 之下的服务器不启动；`roots` 为卫星。

## 后续修订：stdio MCP 服务器的空工作目录（ADR-214 原地修订）

本节取代上文 R86-D11-01 中 “以你的主目录为基准” 的写法，以及 “偏离与未决” 第一条中提到的备选（现已采用）。

**原因**：以主目录为基准时，以 `.` 配置的服务器能触及你的整个主目录。空目录更严，同样不是 Agent 可写的位置。

**规则**（`05` §5.3.5，唯一定义）：
- `config.cwd`（`~` 展开后）是绝对路径时取它；
- 是相对路径或未写时，以 Tower 的空目录 `~/.tower/mcp-cwd/` 为基准求出；
- 结果落在 Agent 可写的位置之下时不启动（同前）。

**这个目录**：
- Tower 创建时为空，之后从不写入、不清空；
- 在 `~/.tower/**` 之下，三种沙箱都拒绝读写（`11` §11.6.2）；
- 沙箱外工具以绝对路径写它列入硬底线（`11` §11.3.3 第 3 条）；
- `06` §6.6.1 目录布局补一行。

**影响**：`args` 中的相对路径（如 `.`）现在指向这个空目录。原先依赖会话目录的服务器，须在 `mcp.json` 中写指向你自己目录的绝对 `cwd`；指向 Tower 工作区的照旧不启动。`roots` 仍为卫星。

**同步**：
- `00` §0.5.1 一行、README；
- `11` §11.3.4、§11.8.2 清单行、T4、T16；
- `14` G10 与 G46 (bk) 的期望（工作目录为 `~/.tower/mcp-cwd/`，且始终为空）；
- C21（绝对 `cwd` 照用，相对的相对空目录）；
- `16` §16.1.13 第 86 轮一行的新说法列；
- ADR-214 与 ADR-133 第 86 轮补记、`14` 增量段与 W6 行的描述文字。
