# 17 · 原型实现

> 本文说明仓库中已构建的原型：用了什么技术、实现了设计的哪些部分、与设计有哪些差异，以及已知的缺口。决定见 `15-decision-log.md` ADR-240。

## 17.1 技术栈

| 层 | 选择 | 理由 |
|---|---|---|
| 桌面外壳 | Tauri 2（Rust） | 安装包与内存比 Electron 小一个数量级；后端逻辑可以全部用 Rust 写 |
| 界面 | SolidJS + TypeScript + Vite | 细粒度响应，没有虚拟 DOM；打包后 JS 约 38 KB（gzip），远低于 `13` 的 250 KB 启动包预算 |
| 状态 | SQLite（rusqlite，WAL） | 单文件、单写者；事件与投影在同一事务中写入 |
| 引擎 | Pi，RPC 模式 | 每个运行中的 Goal 一个 `pi --mode rpc` 子进程，严格按 LF 分帧 |
| 沙箱 | macOS Seatbelt（`sandbox-exec`） | Agent 的 bash 与验证器命令都在 Tower 生成的配置下运行 |
| 字体 | Inter Variable、JetBrains Mono（随应用打包） | 与 `12` §12.3 一致；中文回落到系统字体 |

## 17.2 代码结构

```
crates/tower-core        领域模型（纯逻辑，无 I/O）
  lifecycle.rs           生命周期状态机：唯一的转移函数 apply()
  contract.rs            合同、校验（红灯提示）、范围围栏
  honesty.rs             诚实语法：Fact / Observation / Claim / Human，说法与事实的一致性判定
  event.rs               事件日志的词汇
  review.rs              评审单元：≤300 行、按风险排序
  briefing.rs            重入简报的取舍
  view.rs                给界面的读模型（ts-rs 导出 TypeScript 类型）
crates/tower-store       单写者事件存储与投影
crates/tower-pi          Pi RPC 适配器：分帧、命令与回应的关联、事件解析、关闭与进程组终止
crates/tower-git         卫星克隆、内容寻址的快照、干净检出、封装分支、合入判定、diff 解析
crates/tower-verify      验收命令执行器：进程组、超时、取消、输出截尾与脱敏
crates/tower-supervisor  Supervisor：把以上部分串成 Goal 的生命周期
apps/desktop/src-tauri   Tauri 命令（一一对应 Supervisor 方法）与更新事件
apps/desktop/src         界面：views/、components/、lib/（api、store、nav、keys）、styles/（令牌）
extensions/tower-goal    Pi 扩展：三个工具、门禁、沙箱版 bash
tools/demo-engine        不调用模型的脚本化 Pi，用来演示与测试
```

## 17.3 一个 Goal 的路径

1. **合同**：快速路径（一句话 + 项目检测到的测试命令）或合同编辑器。批准时用与界面同一套校验，错误阻止批准，警告（如没有可执行标准）只提示。
2. **准备**：从你仓库的基线分支克隆出卫星（`~/.tower/work/<goal>`），去掉远端，钩子指向空目录，写入合同与 Seatbelt 配置。
3. **运行**：启动 `pi --mode rpc`，载入 `tower-goal`，把 Goal 的系统段追加到 Pi 的系统提示，第一条消息是合同。所有注入都记入轨迹，标为“Tower 注入”。
4. **观察**：Pi 的事件映射为模式（思考、执行、等你、重试、压缩……）、实况行、工具记录、说法（`log`）、Agent 环境中的观测（运行了与标准相同的命令）和花费。
5. **需要你**：`ask_user` 与门禁审批变成决策卡；你的回答送回等待中的对话框。`log(kind: assumption)` 生成非阻塞的“假设待确认”。
6. **声称**：Agent 调用 `submit` 并停下后，Tower 关闭引擎，Goal 进入“自称完成”。停下却没有提交时先提醒一次，仍不提交则暂停并问你。
7. **验证**：对工作区拍快照（pin），在 pin 的干净检出中运行准备命令与每条机器标准（沙箱中、不带凭据）。每个结果都是一条事实。全部通过 → 待验收；有失败且未达返工上限 → 带着失败输出自动返工；命令无法运行或准备失败 → 验证环境出错，暂停，不返工。
8. **评审**：按风险排序的评审单元；行内批注汇总为“要求修改”，作为转向发回 Agent。
9. **验收**：要求当前快照已通过验证、人工标准已勾选、工作区自验证后没有变化；然后以你的身份写一个提交到新分支 `tower/<goal>-<slug>`。Tower 不推送、不改动你的检出。
10. **合入**：后台每分钟检查已验收的分支是否已进入本地基线（祖先关系，或 squash 后内容一致），进入后标为已合入，24 小时后归档。

退出应用时，运行中的 Goal 以“Tower 退出”暂停；下次启动自动继续。验证中的 Goal 在启动时重新验证。

## 17.4 与设计的差异

| 设计 | 原型 | 原因 / 影响 |
|---|---|---|
| Electron + Pi SDK（进程内），RPC 属 M2 | Tauri + Pi RPC | 后端是 Rust。RPC 模式下 Pi 的扩展 UI 对话框可用，`ask_user` 与审批走这条路 |
| `read`/`edit`/`write` 也在 S2 沙箱中执行（ADR-220） | 只有 bash 与验证器在沙箱中；文件工具由门禁检查路径（含符号链接解析） | 判定与写入之间路径可能被替换，属已知差距 |
| 影子 ref、检查点、bundle 备份 | 一个 `refs/tower/pin`，快照提交内容寻址 | 足以支撑验证与验收；没有回退 UI |
| 卫星分离 gitdir、git 垫片、`GIT_CEILING_DIRECTORIES` 等 | 普通克隆 + 沙箱中 `.git/config` 与钩子只读 + 钩子路径指向空目录 | 防住了最直接的“Agent 改 git 配置让 Tower 执行”路径，其余未实现 |
| 用户扩展经静态清单确认 | 设置中一个开关，默认不加载 | 简化 |
| 依赖缓存与私有依赖存储 | 验证前运行准备命令（按锁文件自动判断，或合同中指定） | 每次验证都要重新安装依赖，慢但干净 |
| 精确的花费与墙钟预算 | 花费取 Pi 的 `get_session_stats`；墙钟只显示，不触发暂停 | 墙钟上限未执行 |
| 哨兵（S1、S5、测试被删等） | 未实现；评审单元的风险排序会把删测试、改快照、改 CI、越界写入排到最前 | 只作为评审提示，不阻断 |

## 17.5 未实现

塑形（Agent 起草合同）、人工编辑检出与检验检出、本地文件清单、项目迁移与清除、记忆与学习闭环、冲突雷达与合并队列、依赖（Goal 之间）、`serve` 远程模式、多机、磁盘满处理、自适应自主度，以及第 99–112 轮围绕写回中断与可达性的全部机制。

## 17.6 已知问题

- 第 112 轮评审（`reviews/round-112.md`）的 6 个次要条目没有修订。它们都属于上面未实现的写回、迁移与可达性机制，实现那些机制时需一并处理。
- 管道命令（如 `npm test | tail`）在 Agent 环境中总是以 0 退出，所以“观测”可能把失败记成通过。这正是观测不计入“已验证”的原因：界面上观测永远是虚线框、不着色。
- 没有 OS 沙箱的平台（Linux、Windows）上只有门禁，界面在设置与环境检查中如实提示。

## 17.7 测试

`pnpm check` 运行全部检查：

- `tower-core`：状态机的不变式（声称不能跳过验证、只有人的验收通向归档、终态不再变化）、合同校验、范围围栏、一致性判定、评审单元。
- `tower-store`：转移经状态机、过期的状态变更被拒绝且整笔回滚、两轨进度只认当前快照、账本判定、收件箱只处理一次、不同 Goal 的说法不互相覆盖。
- `tower-pi`：对脚本化的 Pi 测试分帧（JSON 字符串中的 U+2028 不会切开记录）、关联、对话框往返、错误与退出。
- `tower-git`：真实临时仓库上的完整隔离链路，包括 squash 合并后的合入判定。
- `tower-verify`：退出码、环境故障分类、超时杀掉整个进程组、取消、输出上限、脱敏。
- `tower-supervisor`：真实 Seatbelt 下的配置生效测试；用脚本化引擎与真实 git 跑五条端到端流程（主流程到分支与合入、失败自动返工、提问与回答、停下未提交、暂停继续与放弃）。
- `tower-supervisor` 的 `real_pi` 测试：驱动真实的 `pi`（RPC 模式），模型是脚本化的 OpenAI 兼容服务（不需要凭据）。验证扩展的 `log`、`ask_user`、`submit` 与审批对话框经 Pi 往返；沙箱版 bash 写工作区之外被拒绝、读 `~/.ssh` 被拒绝；Agent 的 shell 中没有 `*_API_KEY`；单向门命令被拒绝后阻断。没有安装 `pi` 时跳过。
- `extensions/tower-goal`：路径模式、范围围栏、自主度矩阵、凭据剥除、沙箱命令的引号。
