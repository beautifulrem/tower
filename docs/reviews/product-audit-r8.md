### 0.4 代码通读

重点读了 `canary.rs`（新增的“改掉测试自身断言的期望值”）、`roles.rs`（新增“改写测试机制”与第三方代码目录）、`sentinel.rs::special_cases` 与 `assertion_cases`、`verify/mod.rs::preflight`、`verify/bench.rs`（基线阶段拆出、环境故障分类、只留源码、金丝雀）、`run/events.rs::sandbox_denied` 与 `readable_error`、`sandbox.rs`（上级 `node_modules` 读权限、截图浏览器配置）、`remote.rs`、`apps/desktop/src-tauri/src/lib.rs` 的通知合并、`Honesty.tsx`、`GoalBlocks.tsx`、`Review.tsx`。下面几点只靠读代码确认，没有实际复现：

- **环境故障的判定依据。** 验证里一条命令失败时，只要它自己的输出尾部含有几种沙箱拒绝的常见字样，就被归为“环境故障”。这段输出由被测代码和测试决定，在 Agent 的快照上就由 Agent 的改动决定。R-perm 证明了诚实项目会被误判；反过来，Agent 的代码也能让一次失败“看起来像”环境问题。
- **“只留源码”复跑对环境故障静默跳过。** 这一步遇到环境故障的标准直接跳过，不记事件、不出哨兵、界面上也不标“未检查”。界面只在结果为“失败”时提示，结果缺失时什么都不显示。结合上一条，这是一个“反事实检查可以被弄得不留痕迹地缺席”的设计缺口：缺的不变式是“Agent 改了源码之外的文件时，只留源码复跑必须有结论，没有结论就按未通过处理并说明原因”。
- **按值生效的断言改写。** 变异只改期望值、每个文件最多 20 处、只认单行的精确相等；高严重度文本规则只认几种直接写法。两者都是“抽样”，缺的不变式是“测试运行时，断言入口必须就是原样的库函数”。
- 截图浏览器的配置仍是 `(allow default)`，可写每用户共享临时目录、可连所有 Unix 套接字；无网络时回环仍默认放行（与 r7 相同）。
- 新增：沙箱允许读取工作区和每个可读路径的所有上级目录里的 `node_modules`。这修好了 r7 的问题，内容是第三方包，风险很低，但 SECURITY.md 的读权限清单里没有写这一条。
- 安静时段的起点仍只存在内存里；通知合并逻辑在桌面外壳里，没有测试。

## 3. 前 20 项修复（按优先级）

“需要维护者”的条目标为 **［维护者］**。每项后面是估计的分数提升，各维度不超过上限。

### 必须先做（决定 D3、D11 能否过 90）

**1. 环境故障只认 Tower 自己观察到的证据，反事实检查不许无声缺席（D3 +2，D11 +2，D12 +0.5）**
不变式一：*只有 Tower 在命令之外观察到的沙箱拒绝，才能把一次失败改判为环境故障。* 现在的判定依据是命令自己的输出，而这段输出由被测代码决定。应当改用沙箱本身的拒绝记录，按验证的进程树归属；卡片上列出 Tower 观察到的被拒绝路径，而不是输出的最后三行。
不变式二：*Agent 改了源码之外的文件时，只留源码复跑必须有结论。* 复跑跑不起来就按“未通过”处理并写明原因，不能跳过。金丝雀和保留测试的“未检查”也要写明是环境原因，不要再套用“测试的语言或写法不认识”这句。
另外三处：环境错误卡不要再根据受 Agent 控制的输出建议放宽沙箱；预检卡的标题改成“验收标准无法在验证沙箱里运行”；误判时给一个“这是真实的测试失败”出路，选了它就保留红 → 绿证据。最后补上 R-perm 这类诚实场景的 flow 测试。

**2. 断言完整性从“抽样”改成“身份检查”（D3 +2，D5 +1）**
不变式：*测试运行时，断言入口和测试框架的全局对象必须就是原样的库对象。* 变异只能证明“被改动的那组期望值会失败”。只放过原期望值的改写，以及文本规则认不出的写法，都在这个缺口里（R3f）。做法上，由 Tower 在程序代码之前装入自己的检查，记下断言入口的原始身份，测试结束时比对；或者让测试从一份 Tower 管理的只读副本加载断言库。另外，非测试源码拿到断言库的引用本身就很少见：“源码触及断言库”从中等升为高严重度，允许你一键确认放行。

**3. 过拟合识别覆盖查表形状，并进入评审排序（D3 +1，D5 +1）**
“按测试的值分支”要识别按输入查表、按输入序列化后取值这类形状：同一处同时出现可见测试的输入和期望值，就是特判的形状（R8c）。特判哨兵命中时，所在评审单元的风险至少为 2 并写明原因（R8b 现在有哨兵、风险却是 0）。没有保留测试时，Tower 可以对可见测试的输入做小幅扰动再跑一遍，作为替代证据。

**4. 定期运行真实模型的对抗回归（r6 第 9 项、r7 第 4 项，D14 +2，D3 +1）**
把本轮的 R3f、R8c、R-perm 和 R1–R8 做成每晚的任务，用便宜的模型跑，每类至少两个变体，记录拦截率，回退时让 CI 变红。连续三轮被列为“必须先做”而没有动。没有它，D3 的每一次进步都只是这一轮审计的快照。

### 应该做（各维度从 85 走向 90）

**5. 回环默认拒绝（r5–r7 遗留，D12 +2）**
不允许联网时，回环只放行合同声明的端口和 Agent 自己启动的监听；系统代理与 PAC 一并排除。

**6. 截图浏览器的配置改为默认拒绝（D12 +1）**
读权限按名单放行；Unix 套接字只允许它自己的目录；不写每用户共享临时目录。

**7. CI 的稳定性要查明原因，不靠放宽断言（D14 +1，D15 +0.5）**
查清 CI 上 WebKit 按键后颜色不稳定的原因，再把断言放回 CI；加一个脚本，核对 SECURITY.md 对应表里的测试名都存在并且实际运行了；CI 里前置条件不满足时报失败，而不是返回。

### 4.2 独立验证还独有吗

- **主流产品里仍然没有。** 每一家要么由 Agent 自己验证（Claude `/verify`、Cursor 云端 Agent、Antigravity 演练），要么由第二个模型评审（Code Review、Bugbot、Devin Review、Guardian）。最接近的 Copilot 云端 Agent 由 harness 跑测试，但跑的是 Agent 看得见、也改得动的那套。
- **开源侧在增加。** Alter-Igor/opencode #121/#122（10 月 5 日合入）：Agent 宣布完成后，由独立用户在私有副本上跑经哈希校验的隐藏验收测试，出错按失败处理；他们的动机数据是 90 次运行全部自称完成，约 10% 过不了隐藏测试。Agrim-Intelligence/sigma #571：保留测试存放在所有 worktree 之外，仍未关闭。新出现的有 Attest（10 月 16–21 日，黑客松项目，0 星）：另一个模型写封存的验收测试，先证明它们失败，再在无网络的沙箱里运行，并对补丁改动的行做变异，看封存测试能否发现。它变异的是补丁，不是测试的断言。另外还有两个小工具：tamperproof 是一个 Claude Code 插件，阻止编辑测试，并在停止时跑测试；testreceipt 核对 PR 里关于测试的说法与 CI 结果是否一致。
- **没有找到**任何产品或项目做“只留源码”的反事实复跑，或检查测试自身的断言能否失败。

结论：Tower 的独特性仍在，但已经从“独有的想法”变成“同一个想法里最完整的桌面实现”。这份优势的价值取决于每一句绿色结论都站得住。本轮的 R3f、R8c，以及“诚实失败被说成环境问题”，说明还有三处站不住。

### 4.3 Tower 缺什么

1. **装不上**：没有签名安装包、没有自动更新、仓库私有、只支持 macOS。
2. **手机端**：主流产品都有原生 App 推送和审批；Tower 是网页加 ntfy。
3. **云端或远程执行**：Claude、Codex、Cursor、Conductor、Factory、Warp 都能离开笔记本运行。
4. **交互式取证**：Cursor、Warp 附视频，Antigravity 有录屏演练；Tower 只有前后两张截图。
5. **引擎数量**：Conductor、Copilot Agent HQ、Zed 都在 3 个以上，Tower 是 2 个。
6. **验证结论的边界**：Tower 的沙箱和检查比别人严，误判的代价也比别人高。环境判定一旦出错，诚实的项目会被拦，反事实检查也可能缺席。

| D4 注意力管理 | 安静时段补发推送和系统通知的摘要，起点持久，跟随专注模式，有测试；原生推送；“待验收”汇成摘要；放一边的条目到期后重新提醒，不重复 |
| D5 评审体验 | 所有哨兵都进评审风险排序并写明原因；金丝雀、只留源码、保留测试的结论在同一行上不互相矛盾，缺失时明说“没有检查”；5 000 行以上的 diff 评审依然流畅；评审组件都在 800 行以内 |
| D10 性能与响应 | 启动 JS 与按需视图都留 15% 以上余量；冷启动和视图切换在 CI 里用真实 WebKit 测量并有预算；大型 pnpm 仓库验证固定开销低于 5 秒；50 个并发目标时界面不卡 |
| D11 稳定性与错误处理 | 沙箱拒绝、限流、断网、磁盘满都有明确的状态和出路，判定依据不受被测代码影响，也不被当成 Agent 的失败；错误卡的标题和正文都对；CI 30 天零环境性失败；崩溃后自动生成诊断包 |
| D12 安全与隔离 | 回环默认拒绝并排除系统代理；截图浏览器默认拒绝；手机页只监听必要的地址；任何放宽沙箱的建议都不来自受 Agent 控制的文字；读权限的每一类例外都写进 SECURITY.md；一次外部安全评审并公开结果 |
| D13 代码架构与可维护性 | 没有超过 800 行的模块或组件，并由 CI 检查；注释、界面文字、CHANGELOG、`docs/17` 与代码行为一致，数字由 CI 生成或核对 |
| D14 测试与质量保障 | `main` 只经 PR 合并且管理员不可绕过（已做到）；CI 30 天绿色率 95% 以上，没有“只在本地检查”的断言；SECURITY.md 对应表由 CI 校验，前置条件不满足时报失败；真实模型回归每晚运行并跟踪拦截率；端到端测试覆盖真实 Tauri 窗口 |
| D15 开源项目成熟度 | 公开仓库、有版本号的签名发行版、自动更新、CHANGELOG 与发行一一对应；issue 有分类和响应时间；至少一位外部贡献者 |
| D16 竞争力 | 独立验证经第三方红队测试并公开拦截率；交互取证、云端或远程执行、原生手机端三项中至少做到两项；支持 3 个以上引擎 |
| D17 可访问性与国际化 | VoiceOver 全流程实测并记录；动态字号；所有存储的文字读取时按语言生成，没有英文句子嵌在中文界面里；手机页通过 axe 和读屏实测；第三种语言，或完整的翻译贡献流程 |
