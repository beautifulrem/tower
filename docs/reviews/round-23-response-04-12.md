# 第 23 轮评审回应 · `04` 与 `12`

依据 `15` ADR-149（取代 ADR-148 补记的“两段准备”）。

| 位置 | 处理 |
|---|---|
| `04` §4.8.11 “正在启动” | 撤回两段写法，改为单一准备阶段（顺序以 `10` §10.3.1 为准）：依赖失败或超过 15 分钟不阻止启动，Run 照常开始，卡片第 5 行与实况行显示 `◇ 依赖准备未完成 · <摘要>`（`prepare{ok:false}`），Agent 开场附失败日志末尾；依赖准备期间 `暂停` 可用（中止安装），`我来改` 提示 `正在启动，稍后重试`；120 秒只计创建或复用工作目录、连接 Pi、组装开场 |
| `04` §4.8.11 启动失败 | 暂停原因改为 `prepare_failed`，卡片 `◆ 启动失败：<原因>`，不自动重试、应用重启后仍暂停；选项 重试（路径冲突时改名重建）/ 我来改（仅工作目录已存在且可用）/ 放弃 |
| `04` §4.8.11 启动期间到达其他原因 | 本次启动中止，目标直接显示那个暂停（例如外部改动），处理后重新排队 |
| `12` §12.6.4 `preparing` 行 | 删除 `依赖准备中` 行；`preparing` 行写明依赖期间可暂停、其余步骤 120 s 内暂停与我来改提示稍后重试、放弃始终可用，以及 `◇ 依赖准备未完成` 的中性显示 |
| `12` §12.6.5 | `engine_crash`（准备阶段失败）行改为 `prepare_failed` 行 |
