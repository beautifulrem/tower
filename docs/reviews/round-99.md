## 1. 总评

**第 98 轮的 8 条次要条目都已按所问关闭**（核对见 §3）。§5 的 9 条观察全部落地。回应 “偏离与未决” 的判断如下：
- 七条接受；
- 两条部分接受：
  - **三要素的收窄**：在合同批准这一时刻接受，理由成立，即一条在一类用户上恒为真、又清不掉的警告会被习惯性地坚持批准。但收窄的安全论证落在 “沙箱外工具的每次调用仍逐次 ask” 上，这句话并不完全成立，带出 R99-D11-01。
  - **写回排除的收窄**：方向接受。但新写的理由 “它们是……的副本，原件在主检出中” 对人在副本中新建的被忽略文件不成立，带出 R99-D13-01。

**对本轮重点问题的回答（三要素）**：
- **是否带回了 ADR-225 修掉的问题**：是，但形态不同。
  - 加载了 MCP 服务器的 Goal 上，不可信内容与对外通信都为真。私有数据一项现在不计沙箱外工具，只在被跟踪的 env 文件命中时为真。所以一个能读取私有数据的 MCP 工具（Willison 的典型情形正是这一类）与外发能力同在时，三要素读为假。
  - 不同之处有三点：
    - 正文现在如实写了 “未知”，并有一行中性的风险说明；
    - §11.3.4 登记了残余；
    - 沙箱外工具的每次调用默认都要人批准，参数中的密钥路径另加只能 “仅这一次” 的 `secrets.access`。
- **“未知” 是否如实**：在合同编辑器这一处如实。
- **与 `11` 的取向是否一致**：不一致，而且这一点被写成了有意的取舍，可以接受。
  - 同一文档中，其他 “无法判定” 都取更严的一边：T7/T26 的 “按能写计”、路径扫描的 “按写处理”、不透明参数的 “至少 ask”。
  - 三要素这一处取了宽的一边，理由是滋扰，回应如实写了。
- **真正没有算完的**：人对一个沙箱外工具选 “本 Goal 内同类” 时，逐次 ask 这道闸被撤掉了，该工具此后为 `notify`（`11` L226）。这一时刻：
  - ADR-201 的 “运行中因授权凑齐” 重算不会因此改变任何一项；
  - 风险说明不在授权卡上；
  - `01` §1.4 #9 也没有登记 “警告不覆盖由沙箱外工具提供的私有数据”。

  见 R99-D11-01。

**ADR-226 的结构性写法成立**（§3.3）：
- **即时投递目录**：按 `hostId` 命名，与 `tmp/<hostId>/`、`mcp-cwd/<hostId>/` 同一生命周期，七处复述一致（`06` L138、L1067，`05` L475，`11` L450、L518，`16` L411、L726）。
- **drain 的 Host 存活分支**：与 §6.1.4 的 drain 协议、卫星丢失在 drain 中的组合规则（`06` L139）以及 `take_over` 的 `E_BUSY` 相容。
- **Host 退出或挂死之后的终止一轮**：写入唯一定义，`10` §10.3.1、`13` §13.11.1、`16` §16.4 都只引用它。
- **准入**：补了检查 d、g 的解除事件；30 s 轮询只在有 Goal 等待刹车时进行。
- **探测缓存键**：补了 Tower 版本与档位模板哈希；探测中崩溃、档位按 Run、翻转的时机都写了。
- **写回排除**：限定为未被忽略、不在清单中的路径；对话框、`04` L668 与带回的提示都已同步。
- **ADR-038 的〔当前值〕与 S0 原因**：已同步，并由 lint (C)、(r) 守住。

**ADR-226 带出、或本轮扫描发现的新问题**：
- **运行中 Host 退出之后那一轮的四个缺口**（R99-D6-01）：
  - 唯一定义的范围是跨 Goal 的并集，而 §6.1.3 写 “该 Host 中各 Run”；
  - “其后尚无新 Run 开始” 没有结束条件；
  - `清理中` 与 `E_BUSY` 只写给了冷启动；
  - 准入的重算时机只写了 “重启清理”。
- **Bedrock 原始密钥的转换**（R99-D5-01）：
  - 照 `11` L518 只传 `AWS_SHARED_CREDENTIALS_FILE` 时，Pi 判 Bedrock 为未配置，G46 (d) 第一组的期望 “模型请求照常成功” 不能成立；
  - 区域与 Vertex 的 location 一类非机密配套变量会被 “其余一律删除” 删掉；
  - `05` L475 引的 Pi 读取位置不对。
- **三要素的收窄**（R99-D11-01）：授权卡上没有告知；ADR-226 的 “每次调用仍逐次 ask” 不实；`01` #9 没有登记这一限制。
- **被忽略的新文件随副本删除**（R99-D13-01）：对话框不列出它们；ADR-226 的理由句对它们不成立；凭据形文件没有交还的途径，对话框给出的办法对它们无效。
- **M3 的日期**（R99-D14-01）：`14` L18 与 L399 仍写 “至 2027-12”。M2 已顺延至 2027-11-12，之后 12–14 周应为 2028-02。
- **G46 的两处**（R99-D14-02）：(bj) 对 MCP 全文文件仍期望 “给出重定向的做法”；(bm) 的手机一组属 M2 而未标出。
- **§6.1.10 的扫描时机**（R99-D15-01）：“只在 settle 终止、重启清理、以及 watcher……” 漏了运行中的一轮。

**排期**：

  - WBS 124.02；角色合计 Agent 26.65、系统 26.35、桌面 28.10、设计 29.29、安全 13.63；

**R99-D5-01｜次要**（云 SDK 原始密钥只以文件变量传入时 Pi 判 Bedrock 为未配置；非机密的配套变量会被删除；Pi 的读取位置引错）

### D6 系统架构与可靠性

**R99-D6-01｜次要**（运行中 Host 退出或挂死之后那一轮：范围、结束条件、接管闸门与准入唤醒）

- **问题**：
  - **(a) 范围**：
    - 唯一定义 `06` L145 把三类令牌并为一个范围：
      - Host 已不存在的未结束 Run；
      - 各 Goal 最近一个以 `crashed` 结束、其后尚无新 Run 的 Run；
      - 有未解决 `bg_process_survived` 的 Run。

      并写明它是 “重启后，以及 Tower 运行中 Engine Host 退出或挂死之后” 的终止范围。
    - 而 `06` L64 写 “对**该 Host 中各 Run** 的令牌做终止的一轮”。
    - 照唯一定义实现，一个 Host 崩溃会对其他 Goal 再做一轮，那些 Goal 在这期间显示 `清理中`、被检查 h 挡住：其他 Goal 的存活者，以及其他 Goal 早先崩溃过、已终止过的 Run。照 L64 实现则不会。两种实现都能从文字读出。
  - **(b) 结束条件**：
    - “其后尚无新 Run 开始” 是唯一的退出条件。有的 Goal 在崩溃之后不再开 Run，例如崩溃 → 接管 → 交还 `reverify` → `in_review` → `accepted` → 归档，或直接放弃。它的令牌就永远在范围内：之后每次冷启动都对它做一轮，期间显示 `清理中 · 残留进程`、`goal.take_over` 返回 `E_BUSY`。
    - 一轮什么也没找到时，是否仍补 `agent_bg_done`、是否在开场中注入 `tower.processes_terminated`，没有写。
    - 回应写的代价 “新 Run 开始之前重启时会再扫描一次（幂等）” 只算到了会再开 Run 的 Goal。
  - **(c) 接管闸门**：
    - `清理中` 与 `goal.take_over` 返回 `E_BUSY`，在 L145 中写在 “它在冷启动之后后台执行” 一句之下；`12` §12.6.4 的实况行也写 “重启后清理……”。
    - 运行中那一轮进行时，Goal 已是 `paused{engine_crash}`，而 `take_over` 允许 `paused(*)`（`06` L907）；检查 h 只挡 Run。
    - 照文字实现，人在这一轮完成之前可以接管。H 以当时的卫星物化，而脱离的后台进程（Host 退出时不随之结束）仍在写卫星。这正是冷启动闸门要避免的情形（ADR-223/224）。
  - **(d) 准入唤醒**：
    - `06` L298 的重算时机写 “某 Goal 的**重启清理**完成终止的一轮”，并称它是检查 h 的解除事件。
    - 检查 h（L320）写 “Engine Host 退出或挂死之后的一轮同此”，但重算时机没有列出这一轮的完成。
    - 照列举实现，自动 “重启并恢复” 会停在 `ready{slot}`，等到某个无关事件。与 R98-D6-03 同类。
- **为什么是次要**：
  - (a)(b) 的多余一轮只对已终止或无法终止的进程再发一次信号，后果是短时的 `清理中` 与 `E_BUSY`；
  - (c) 的写入在交还时按归因表处理：存活进程的写入按 `agent_bg`，来源不明的按外部写入 E 由人选择（`10` L394、L977）。它们不会被记成人的改动；
  - (d) 不丢数据。
- **后果的类别**：
  - 无关 Goal 被短时挡住；
  - 从不再开 Run 的 Goal 在每次冷启动时出现 `清理中`；
  - 人接管的副本与仍在写入的后台进程并存，交还时出现本可避免的外部写入选择；
  - 自动恢复延迟。
- **文档位置**：`06` L64、L145、L196、L298、L320、L907；`10` L394、L431、L437、L977；`12` §12.6.4；`13` L324；`16` L1068；`14` G35c (x)。
- **期望的回答形态**：在 `06` L145 的唯一定义处补三句，并在 L298 的列举中把 “重启清理” 改为 “重启清理或 Host 退出之后的一轮”：
  - Tower 运行中的一轮只取该 Host 中 Run 的令牌；
  - 第二类令牌在它的第一轮完成之后移出范围。仍存活的已按第三类处理。一轮什么也没终止时，不补检查点、不注入；
  - `清理中` 与 `E_BUSY` 对运行中那一轮同样适用，`16` 的 `E_BUSY` 一行同步。

### D11 安全与自主度

**R99-D11-01｜次要**（三要素收窄之后，逐次 ask 被 “本 Goal 内同类” 撤掉的时刻没有任何告知；ADR-226 的安全论证一句不实；原则的限制未登记）

- **问题**：
  - **(a) 授权时刻**：
    - ADR-226 之后，加载了 MCP 服务器的 Goal 上，不可信内容与对外通信恒为真（`11` L545–L546，ADR-032）。私有数据不计沙箱外工具（L544），所以缺的恰好是 “沙箱外工具本身提供的私有数据” 这一项。这是 Willison 致命三要素的典型情形，即一个能读取私有仓库、邮件或数据库的 MCP 工具。
    - 对这类工具，`11` 里实际的人工闸门有两道：
      - 每次调用 ask（`tool.external` 的下限）；
      - 参数中的密钥路径另加只能 “仅这一次” 的 `secrets.access`。
    - 人在审批卡上选 “本 Goal 内同类” 之后，该工具此后为 `notify`（L226）；合同的 `autonomy.grants` 也能带 `tool.external` 的工具名（`02` L322）。
    - 这一时刻，ADR-201 的 “运行中因授权凑齐” 重算（L562）不会因此改变三项中的任何一项。风险说明只在合同编辑器上（L558），不在授权卡上。
    - 结果是，三要素在实际上凑齐的那一刻，界面上没有任何告知。
  - **(b) 安全论证**：
    - ADR-226（`15` L4460）与回应 L30 以 “沙箱外工具的每次调用仍逐次 ask，路径检查照旧” 论证 “不放宽任何访问”。
    - 这句话只在没有按工具名授权时成立。`00` L102 的写法（“每次调用都需要你批准（可选……按工具名授予本目标内的放行）”）才是准确的。
  - **(c) 原则的登记**：
    - `01` §1.4 #9 写 “当 Goal 同时具备私有数据访问 + 不可信内容输入 + 外部通信能力时，合同编辑器给出显式警告”。
    - 收窄之后，由沙箱外工具提供私有数据的情形不在警告之内。这一限制只写在 `11` L228 的残余与 L544 的括注中，`01` #9 与威胁表的 T16 都没有登记。
    - `11` 中其他 “无法判定” 都取更严的一边（T7/T26 “按能写计”、路径扫描 “按写处理”、不透明参数 “至少 ask”），这一处取宽的理由（滋扰）只写在回应中。
- **为什么是次要**：
  - 默认的逐次 ask 仍是有效的闸门；
  - 授权只能由人在本机按一个工具名显式给出（L226 的取舍）；
  - 参数中的密钥路径仍只能 “仅这一次”；
  - 合同批准时的取舍本身可以接受。

  缺的是在撤掉闸门的那一刻告诉人，而不是一条新的阻止规则。
- **后果的类别**：人对一个能读取私有数据的沙箱外工具给出 Goal 级授权之后，被注入的 Agent 可以不经逐次批准，把它与外发能力组合起来，而 Tower 在任何界面上都不提示这一组合。
- **文档位置**：`11` L226、L228、L544–L562、L703（T16）；`02` L322；`01` L77；`00` L102；`04` L1112；`15` ADR-226（L4460）。
- **期望的回答形态**：在 `11` L558 风险说明的唯一定义处加一句，并改 ADR-226 的那句话：
  - 审批卡上对 `tool.external` 的 “本 Goal 内同类” 选项（以及合同编辑器中带 `tool.external` 授权的合同），在不可信内容与对外通信都为真时，于选项上方显示同一行风险说明，并加半句 “授权后该工具的调用不再逐次询问”。中性、不阻止、不计入 E3。
  - ADR-226 的那句改为 “每次调用都 ask，直到人对该工具授予按工具名的授权”。
  - `01` §1.4 #9 或 `11` §11.8 加一句：警告不覆盖由沙箱外工具提供的私有数据，这一面由逐次 ask 与风险说明承担，并说明取宽的理由。

### D13 隔离、git 与并发

**R99-D13-01｜次要**（人在副本中新建的被忽略文件随副本删除而不列出；ADR-226 的理由句对它们不成立；凭据形文件无法交还而对话框给出的办法无效）

  - **(b) 交还凭据形文件的途径**：

  - 但人新建的有意义的被忽略文件（含刚生成的密钥）会在交还时消失而不被列出，所以不只是措辞。
- **后果的类别**：人在副本中新建的被忽略文件在交还或带回后丢失，人事先看不到；人想交还的凭据形夹具被排除，对话框指向一个无效的办法。

- **期望的回答形态**：在 `10` L972 的唯一定义处做以下几处修改：

  - `06` L196 写 “**扫描频率**（……全进程扫描最多每 60 s 一次，且只在 Run 活跃时）：只在 settle 终止、重启清理、以及 watcher 检测到来源不明写入时……扫描”。
  - 这是一个排他的列举。ADR-226 加的 “Engine Host 退出或挂死之后的一轮” 不在其中，而它发生时该 Goal 没有活跃的 Run。
  - 同一节的 L198、`10` L437、`13` L324、`16` L1068 都已包括这一轮。
  - 照 L196 实现，运行中那一轮或者不做，或者受 “每 60 s 一次” 的限制推迟，而检查 h 在它完成之前挡住重启。
- **后果的类别**：自动 “重启并恢复” 被推迟，或残留进程在新 Run 开始时仍在。与 R98-D6-02 要修的正是同一后果。
- **文档位置**：`06` L196、L198；`10` L437；`13` L324；`16` L1068。
- **期望的回答形态**：L196 的列举加 “Engine Host 退出或挂死之后的一轮（§6.1.3）”，并写明它与重启清理一样不受 “每 60 s 一次” 与 “只在 Run 活跃时” 的限制；或把这一句改为引用 `10` §10.3.1 的扫描时机。

### 不扣分的观察

1. **只重启 Supervisor 后对交回 Host 的心跳看门狗**：
   - `08` L370 以 `now - lastHeartbeatAt > 30_000` 判 `unresponsive`，`hostExpected` 没有定义。心跳 Fact 会持久化（`06` L1126）；睡眠唤醒有 60 s 宽限（`06` L109），重新接上没有。
   - 合格的实现者会在重新接上时重新计时，所以记为观察。但 ADR-226 之后 “挂死” 即 SIGKILL：若以持久化的最后心跳为起点，Supervisor 的退避（至多 30 s）就会使存活的健康 Host 被强杀，抵消 ADR-225/226 的 Host 存活路径。
   - 宜在 `08` §8.6.3 写一句 “交回的 Host 自重新接上时起计”，并定义 `hostExpected`。
2. **挂死 Host 的后代树归属**：
   - 打包模式下，以 Host 为根的后代树还含不带令牌的成员：MCP 服务器、扩展的子进程，以及 `13` L195 所说不带 Run 令牌的辅助进程。
   - 逐命令的子进程记录只在 Host 内存中（`10` L430），强杀后不可得。
   - 宜写一句：这些成员照常终止、不列入任何 Goal 的 `tower.processes_terminated`；对该 Host 承载的每个 Goal 各补一次 `agent_bg_done`。
3. **云 SDK 原始凭据没有刷新途径**：
   - 原始值在首次运行时导入一次，“重新读取” 明确不重新提示凭据类变量（`05` L489）；F7 只识别 OAuth 过期与没有凭据。
   - 带有效期的值（如会话令牌）过期后，长寿 Host 一直用旧文件，界面只显示通用的 provider 错误。这是 ADR-226 之前就有的；ADR-226 使 Host 能跨 Supervisor 重启存活，窗口变长。
   - 宜登记为已知限制，或给出重新导入的入口。
4. **远程 `quick_ratify` 不显示风险说明**：`11` L558 只写合同编辑器。`serve` 属 M2，M2 设计手机卡片时宜决定是否列出这一行（与 R99-D11-01 的授权卡一并考虑）。
5. **合同之外的三要素重算**：
   - 由 S2 转为 S0 时 “重算各 Goal 的致命三要素”（`06` L1179），对已批准或运行中的 Goal 结果变为同时为真时显示什么，没有写；
   - 清单确认之后（可能加载 MCP，带入两项）也不是重算时机。
   - 都是 ADR-226 之前就有的；S0 下还有 ADR-022 的授权卡兜底。
6. **安全模式与存活 Host 的 drain**：§6.1.7 没有写安全模式下是否续做存活 Host 的 drain。续做只是收尾、不开 Run，宜写半句。
7. **措辞与登记**：
   - `00` L102 写 “会加载这类工具的目标”，`11` L558 含只注册钩子的扩展，宜一致；
   - `12` 没有风险说明的文案；
   - `06` §6.6.1 的目录树没有 `goals/<G>/logs/`，而 `07` L82、`09` L487、`10` L375、`13` L367 都用它；
   - `04` §4.6.6 第 6 步没有提到带回的新 `E_STATE` 分支（文案在 `06` L917）；
   - `12` L683 写 “新文件”，`10` L972 写 “新建或改过”。人删除 Agent 写出的同类文件时，删除不生效而副本改名保留，宜在对话框中同样列出。
8. **增人备选的前提**：5.5T − 2 的模型还隐含新人从四条全职线各分担约 4.9 人周（各线所需约 28.9，T = 24.01），`14` L16、L401 只写了安全线的 2.43 人周。宜补半句 “并分担各线的非链上工作”。
9. **`04` L1318 的网页端移除**：写 “添加与移除在本机与网页端可用”，而 `16` L1116 写 “`remove` 对 `isSecret` 条目仅本机”。远程能力以 `16` §16.5 为唯一来源（`04` L1260），网页端属 M2，宜补半句。

### 设计是否完成

ADR-226 以已有唯一定义处的一句话关闭了第 98 轮的八条条目：
- 存活 Host 的即时投递文件跨 Supervisor 重启保留，drain 在 Host 存活时续做；
- Host 退出或挂死之后先终止一轮再重启；
- 准入在资源与端口释放、内存压力回落时重算；
- 三要素不再因沙箱外工具在一类用户上恒为真；
- 探测缓存在 Tower 更新之后重新探测；
- 写回的凭据形排除不再盖住复制进来的副本；
- 两处复述同步，并由 lint 守住。

本轮 7 条分三类：
- **新写的规则与已有路径的相遇**：
  - R99-D6-01：运行中的终止一轮遇上唯一定义的并集范围、不再开 Run 的 Goal、`take_over` 与准入列举；
  - R99-D11-01：收窄的三要素遇上按工具名的 Goal 级授权；
  - R99-D13-01：收窄的排除遇上人新建的被忽略文件。
- **对照 Pi 源码的事实**：R99-D5-01（Bedrock 的判定与配套变量）。
- **未同步的复述与过期的数值**：R99-D15-01（§6.1.10 的扫描时机）、R99-D14-01（M3 的日期）、R99-D14-02（G46 的两处）。
