> 本文规定 Tower 的视觉语言：令牌、诚实语法的视觉规格、状态字形、动效契约、注意力阶梯、数据可视化、组件清单、无障碍与简体中文排版。界面结构与交互见 `04-ux-information-architecture.md`。

## 12.1 设计方向：安静的仪表盘（dark cockpit）

一句话：**一切正常时，界面几乎是静止的灰色；颜色和运动只出现在需要人的地方。**

| 原则 | 视觉含义 | 依据 |
|---|---|---|
| 默认是灰的，颜色有含义 | 全产品只有 5 个状态色（§12.4.3）；没有强调色，焦点与选中只靠明度（墨色焦点环、选中底色） | T§A8 ISA-101 灰底 + 例外着色；Airbus dark cockpit；G§5 |
| 琥珀色只表示“需要你” | 要你做决定，或在评审中要你先看这一处（风险依据的 `◆`，§12.9）；从不表示证据。`--st-attention` 是全产品唯一的打扰色；任何其他用途都会稀释它 | R5；T§A9 报警可行动性 |
| 绿色只属于验证器的结论 | 验收前，只有验证器在干净环境中、针对**当前工作区树（指纹）**新鲜得出的通过结果能是绿色（ADR-020、ADR-024）；Agent 环境中的观测、Agent 的说法永不为绿 | R1、R2、ADR-002 |
| 运动是信号，不是装饰 | Agent 的常规活动不触发任何动画；只有进入“需要你”的那一刻有一次性提示 | T§A7 calm technology；G§6.4 |
| 版面稳定 | 看板航班条固定高度（40px）、实况行固定一行；行只在换组时移动，而且是滑过去（220ms），不是跳过去 | T§A11 航班条；G§5 |
| 层级靠字号、字重与灰阶，不靠框和图标 | 图标稀少；边框为 1px 低透明度发丝线；只有浮层有阴影（深色主题的卡片脚下另有一道 1px 阴影，§12.11） | G§5（Linear、Things、Geist） |
| 内容亮于外框 | 侧栏比内容暗一档；决定卡与浮层是最亮的表面（概览是一行一个目标的航班条，§12.12） | G§5（Linear 2026 改版） |
| 键盘优先，键盘打开的东西不做动画 | 面板与列表导航是 0ms；切换视图只做 120ms 交叉淡入，让视线留在原处（§12.7） | G§5（Raycast） |
| 事实、观测、说法、人一眼可分 | 四种排版语域（§12.5） | R1，全产品最重要的视觉规则 |
| 安静但不含糊 | 实况行永远显示可转向的细节（`模式 · 动作 · 对象`），从不显示“工作中…” | R12；L§A.1 Claude Code 折叠反弹 |
| 可逃逸 | Watch 模式是同一套视觉语言下的另一种布局，诚实语法在其中不变 | R12 |
| 不拟人 | Agent 没有头像、名字或表情；说法只标“Agent 称” | R10：更像“同事”的呈现会提高信心而不提高准确度（T§A16 Overseeing Agents） |

## 12.2 令牌架构

三层，组件只能引用语义层：

```
原始层 primitive     --ok-neutral-180, --ok-amber-800 …        仅在 tokens.css 内部出现
语义层 semantic      --bg-app, --text-2, --st-attention …       组件与工具类唯一可用的颜色来源
组件层 component     --row-goal-h, --drawer-w …                 组件内部尺寸常量
```

- 语义令牌是 `tokens.css` 中的 CSS 自定义属性，组件 CSS 直接引用（实现中没有 Tailwind，tokens.css 也直接以 OKLCH 值定义语义令牌，没有单独的原始层令牌）；lint 禁止原始颜色值与原始层令牌出现在组件代码里（G§6.2）。
- 状态色令牌名以 `--st-` 开头，主题系统不可覆盖（§12.15）。
- 每个令牌在 Figma 变量中同名，深浅主题为同一变量的两个模式。
- lint 还检查“文字 × 字号 × 令牌”组合是否满足 §12.13.1 的 APCA 角色表（例如禁止 `text-3` 用于 13px 以下的必读文字）。

## 12.3 排版

### 12.3.1 字体栈

```css
:root {
  --font-ui: "Inter Variable", "PingFang SC", -apple-system, BlinkMacSystemFont, "Segoe UI", "Hiragino Sans GB",
             "Microsoft YaHei UI", "Noto Sans CJK SC", sans-serif;
  --font-mono: "JetBrains Mono Variable", ui-monospace, "SF Mono", "Cascadia Mono", "PingFang SC", monospace;
  --font-features-ui:   "calt" 1, "cv01" 1, "ss03" 1;
  --font-features-mono: "liga" 0, "calt" 0, "zero" 1;              /* 代码、命令、日志、快捷键提示 */
  --font-features-num:  "liga" 0, "calt" 0, "tnum" 1, "zero" 1;    /* mono 中的机器值：哈希、编号、命令、路径（.code-val） */
  --opsz-display: "opsz" 32;   /* Inter 的 display 字形：目标页标题、印章判决词 */
}
```

- 拉丁字符走 Inter，中文回落到平台字体；Inter（含 opsz 轴）与 JetBrains Mono 随应用打包，不内置 CJK 网络字体（每个字重 5–10 MB，G§8）。
- 代码与事实数值走 JetBrains Mono。mono 是证据，按原样显示：关闭连字与上下文替换（`===` 仍是三条横线，`=>` 仍是两个字符），0 带斜线。计数、金额、时长用 UI 字体的等宽数字（`tabular-nums`），不换成 mono。

### 12.3.2 字号角色

基础字号 13px；界面大小设置（紧凑 / 标准 / 大）把整个界面一起缩放为 0.92 / 1 / 1.1，不单独改字号或行高。行高以 px 固定在 `--lh-*` 令牌上（如 `--lh-body` 20px、`--lh-reading` 22px），中英文共用同一行高，不为中文另设一列，避免中英混排时行高抖动（§12.14）。颜色列遵守 §12.13.1 的 APCA 角色表。

| 角色 | 字号 / 字重 | 行高（`--lh-*`，中英文相同） | 字体 | 颜色 | 用途 |
|---|---|---|---|---|---|
| `stamp` | 28 / 580 | 36 | ui（display 字形） | text-1 | 验收面板印章的判决词；界面中最大的字，别处不用这个字号 |
| `display` | 24 / 500 | 32 | ui | text-1 | 仅空状态 |
| `title-goal` | 20 / 500 | 28 | ui（display 字形） | text-1 | 目标页标题 |
| `title-section` | 13 / 500 | 20 | ui | text-1 | 区块标题：与正文同字号，靠 500 字重和 text-1 标出（不用全大写、不加字距） |
| `body` | 13 / 400 | 20 | ui | text-1 | 默认 UI 文本 |
| `body-strong` | 13 / 500 | 20 | ui | text-1 | 强调；600 只给判决（§12.3.3） |
| `reading` | 14 / 400 | 22 | ui | text-1 | 段落、发现、合同正文 |
| `question` | 16 / 500 | 24 | ui | text-1 | 决策卡的一句话问题 |
| `meta` | 12 / 400 | 16 | ui | **text-2** | 时间、计数标签（必读） |
| `live` | 12 / 400（看板行）· 13 / 400（目标页） | 16 · 20 | mono | **text-2** | 实况行 |
| `fact-num` | 12–13 / 400 | 同所在行 | ui + tnum（计数、diffstat、金额）· mono（哈希、编号） | text-1 | 事实数值、哈希、diffstat、金额 |
| `claim` | 13 / 400 | 20 | ui | text-2 | 说法正文（§12.5） |
| `hint` | 11 / 500 | 16 | mono | text-3 | 快捷键提示、分隔符等非必读文字 |
| `code` | 12.5 / 400 | 20 | mono | text-1 | diff、日志 |

### 12.3.3 字重决策

- 界面文字只用 400 与 500。例外只给判决与字标：验收印章的判决词 580（`stamp`）、大号印章的判决词与字标 `Tower` 600，都用 Inter 的 display 字形，且旁边总有自己的图形（印章的实心圆、字标的标记），所以不只靠字重。其余中文环境不使用 600：Microsoft YaHei UI 只有 Light / Regular / Bold 三档，600 会被渲染为 700，500 会回落为 400。macOS 的 PingFang SC 实际包含 Medium 与 Semibold（G§6.1 称其“无真正 Semibold”，与系统字体实际情况不符，但结论“中文强调用 500”不变）。
- 因为 Windows 上 500 可能显示为 400，**任何层级不得只靠字重区分**：强调同时提升一级灰阶（text-2 → text-1）或字号。区块标题与正文同为 13px，靠 500 字重和 text-1 标出；在正文同为 text-1 的地方，二者只差字重与标题所在的位置（区块顶部的发丝线、其下 8px 间距）。
- 说法不使用斜体。中文没有真斜体，合成的倾斜字形难以阅读（§12.16 #9）。

## 12.4 颜色（OKLCH）

### 12.4.1 中性色与焦点（没有强调色）

中性色色相 h≈70（暖灰），极低彩度（Linear 2026，G§6.2）。表面层级靠明度，不靠阴影。

### 12.4.3 状态色：恰好 5 个

```css
:root[data-theme="dark"] {
  --st-attention: oklch(0.800 0.150 75);    /* 琥珀：需要你做决定 */
  --st-danger:    oklch(0.750 0.150 25);    /* 红：验证器失败、哨兵、越界、硬矛盾、已拒绝、无响应 */
  --st-verified:  oklch(0.770 0.130 155);   /* 绿：验证器在当前树上通过；已验证 / 已验收 / 已合入 */
  --st-active:    oklch(0.780 0.120 235);   /* 蓝：运行中、验证中；彩度足以让 10px 的运行弧与中性灰分开 */
  --st-neutral:   var(--text-3);            /* 灰：其余全部状态，含“观测到”与“未经机器验证” */
  --attention-bg: oklch(0.225 0.030 75);    /* 不透明色调底：需要你条目的稳态 */
  --danger-bg:    oklch(0.215 0.030 25);
}
:root[data-theme="light"] {
  --st-attention: oklch(0.600 0.150 65);
  --st-danger:    oklch(0.540 0.190 25);
  --st-verified:  oklch(0.550 0.130 155);
  --st-active:    oklch(0.500 0.130 240);
  --st-neutral:   var(--text-3);
  --attention-bg: oklch(0.962 0.034 85);    /* 白底上的琥珀用 h 85、低彩度，不偏桃色 */
  --danger-bg:    oklch(0.965 0.025 25);
}
```

**状态色只给字形和色调底，不给小字。** 状态上下文里的文字一律用 text-1 / text-2（12–13px 小字需要 Lc ≥ 75，而状态色在深色上只有 55–66）。唯一例外：≥ 16px / 500 的标题可用状态色（Lc ≥ 60）。

| 状态色 | 只用于 | 禁止用于 |
|---|---|---|
| attention 琥珀 | **需要你**：要你做决定，或要你先看一眼（评审单元风险依据前的 `◆`，§12.9）；从不表示证据。用于 Needs-You 条目、`◆`、模式 `waiting_human` / `blocked_guard`（等你批准）/ `budget_capped` / `stalled`、侧栏与 Dock 计数、评论高亮、当场必须决定的内联决策块（致命三要素、S0 授权） | 一般警告、过期、心跳迟到、模型静默、评审积压超上限、按钮 |
| danger 红 | 验证器得出的失败（新鲜时）、哨兵命中、范围越界、**硬**矛盾（`07` §7.8）、审批被拒绝的事件、`unresponsive`、送达失败 | 软矛盾（中性）、观测到的失败（中性）、危险按钮的常态 |
| verified 绿 | 验证器在当前树上的通过；`in_review`、`accepted`、`integrated` **且其验证结论为 `verified` / `verified_qualified`** | 任何说法；任何观测；`claimed`；人工勾选的标准；结论为 `not_machine_verified` 的目标在任何状态（in_review、accepted、integrated、archived）都不着绿（R4-D9-01） |
| active 蓝 | `running`、`verifying` 的生命周期字形；标题栏的运行数仪表 | 文字链接（链接用半透明墨色下划线 `--link-underline`）、选中态 |
| neutral 灰 | 其余所有状态 | — |

界面没有强调色，active 不必再为避开它压低彩度：初稿的 0.06 彩度在 10px 的运行字形上读成灰色，实现取 0.12–0.13（§12.16 #4）；现在的运行字形是一段细弧，比当时的半圆更需要这份彩度。

**“要注意但不需要你决定”的画法**（心跳迟到 15 秒、模型 90 秒无输出、事实陈旧、评审积压超上限）：不用任何状态色。相关文字提到 text-1，字形换成描边圆环加 `i` 的提醒标记 `◇`（§12.6.2）。理由：琥珀一旦用于“可能有问题”，Q1 就失去 3 秒答案（T§A9 cry-wolf 效应）。这些状态若持续，由 Harness 推导为 `stalled` / `unresponsive`，按 `08` §8.6.3 的条目时机生成 Needs-You（`unresponsive` 在自动“重启并恢复”期间不生成），那时才出现琥珀 `◆`。

### 12.4.4 Diff 色

```css
--diff-add-bg:   oklch(0.770 0.130 155 / 0.10);   --diff-add-word: oklch(0.770 0.130 155 / 0.26);
--diff-del-bg:   oklch(0.750 0.150 25  / 0.10);   --diff-del-word: oklch(0.750 0.150 25  / 0.26);
```

- 有评论的行不另设令牌：行号槽画一条 2px 的 `--st-attention` 内阴影（并排视图画在左侧行号上）。
- hunk 作者的线型（human：2px 实线 + 标签“你”；external：2px 虚线 + “外部”；mixed：点线 + “混合”，混合不显示为“你的改动”，ADR-135）目前没有在评审 diff 中绘制，也没有对应令牌；落地时再在这里补令牌。
- Diff 是验证器之外的 git 事实，沿用约定俗成的绿 / 红色调；只用 10% 底色（浅色主题新增 13%、删除 11%，白底上 10% 的行底色会看不见），不会被读成状态。
- 每行都有 `+` / `−` 行号槽符号，不依赖颜色；作者线型落地后同样不依赖颜色。
- **外部写入不进入评审**（ADR-122）：来源不明的写入在评审前就使目标暂停（`04` §4.8.7），因此评审单元中没有“待处置的外部 hunk”状态，也没有对应令牌。
- 设置中提供“色觉友好 diff”：新增 h=250、删除 h=60，仍为 10% 底色。

## 12.5 诚实语法（Honesty Grammar）视觉规格

R1 的视觉落地。**看一眼就知道这句话是验证器测出来的、Agent 环境里观测到的、Agent 说的，还是人决定的。**

### 12.5.1 四种语域与三种派生状态

| 语域 | 来源 | 字体与颜色 | 标识 | 颜色权限 | 交互 |
|---|---|---|---|---|---|
| **事实 Fact**（已验证） | ⚙ 不经 Pi 扩展链的 Harness 组件：验证器、git、记账器（ADR-024） | 数值 mono + tnum，text-1 | 来源栏 `Tower 测得`；行内出处**不加框**：`harness` 标记 + `@9f3e1a · 6分前`（12px，text-2，标记 text-3） | 结果字形可用 verified / danger（仅新鲜时）；来源栏的 `harness` 标记在验证器通过时着绿 | 点击打开证据；`O` |
| **观测 Observation**（ADR-020 第三种语法） | Agent 在自己工作目录中运行的、与标准等价的命令（经扩展链转述，`command_result`） | 数值 mono，text-2 | 来源栏空心圆 + `观测`；行内 `ObsChip`：只有 `观测` 二字带 1px **虚线**框（`--border-strong`，11px，text-2），其后 `@9f3e1a · 2分前` 不加框，无 harness 图标 | **永不着色**：通过 / 失败字形都是 text-2 空心样式（`○✓` / `○✕`） | 点击打开该次命令的轨迹片段 |
| **说法 Claim** | 🤖 Agent | 比例字体，text-2，13px | 来源栏中的 `┆`（text-4）+ `Agent 称`（11–12px，text-3）；正文不加边框 | 永不使用 verified；不带实心 ✓（唯一形式是计划步骤与发现的 `┆✓`：虚线前缀 `┆` 标明它是说法，见下文“计划步骤与发现的字形”，ADR-176） | 点击跳转轨迹；右侧交叉校验徽章 |
| **你的决定 Human** | 🧑 | 比例字体，text-1 | 来源栏 `你`（500，text-2）；`HumanStamp`：`你 · 14:20`（11px，text-2，无框）；需要画线时是一道 2px text-1 **实线**笔划（`chip-you`、已接受的 hunk） | 无颜色 | 不可编辑；只能被新的决定替代 |

四种语域共用来源栏（`ProvenanceFrame`）：每条陈述是三列网格，左边悬挂的来源列（`minmax(6.5em, 8.5em)`，12px，text-3）写出说话者——`Tower 测得`、`观测`、`Agent 称`、`你`——中间是正文（13px），右边是旁注。每行不加框，语域由来源列与墨色区分；唯一带底色的例外是测得的失败（`--danger-bg`，4px 圆角）。它取代了初稿的左边框与带框徽章，避免框中套框（`19` §19.3）。

| 派生状态 | 触发 | 表现 |
|---|---|---|
| **过期 Stale** | 工作区树（指纹）变化（`07` §7.3.3） | 整行 text-4，数值保留；结果字形换为 `⟲`；徽章 `@71c0d2 → 现在 @9f3e1a`；移除所有状态色；`⇧V 重新验证`（只在 `goal.retry_verify` 允许的状态显示；运行中的过期行不显示，由机会式验证重验，`16` §16.3，ADR-208） |
| **失效 Expired** | 非代码前提失效（base 移动、合同修订、超龄） | 整行 text-4 + 删除线，标签 `已失效`，退出所有汇总。删除线只用于失效的事实 |
| **矛盾 Contradicted** | 说法被事实推翻 | 说法保持原样式（不删除线）；**硬矛盾**（`07` §7.8）右侧 `✕ 矛盾`（danger 字形 + text-1 文字）；**软矛盾** `◇ 可能不一致`（中性）；下方缩进一行显示相关事实 |

交叉校验徽章（`02` Claim.crossCheck）：`一致 · 2 条事实`（text-2，一致不等于正确，所以不着绿）· `无依据`（空心框，text-2）· 未校验（无徽章）· `✕ 矛盾`（硬，danger 字形）· `◇ 可能不一致`（软，中性）。

**Tower 注入**（ADR-135）：恢复、返工、交接、`tower.processes_terminated` 等由 Tower 发起的回合，在轨迹与时间轴中以 `⚙ Tower 注入` 标签（`harness` 标记 + 12px text-2 文字，不加框，与事实出处同一标记）开头，正文原样显示注入内容；**不**使用 `HumanStamp`，也不计入“你的转向”。`HumanStamp` 只用于你亲手写的转向与回答。

**系统印章 `⚙ 超时默认`**（ADR-176）：`unattended:"use_defaults"` 下计时器套用的默认（`resolution.by = "timeout"`，`08` §8.7.1；低风险问题的默认就是 Agent 推荐的选项）以 `⚙ 超时默认` 印章（`harness` 标记 + text-2 文字，不加框，与 `⚙ Tower 注入` 同族）开头，后接时间与所套用的选项；**不**使用 `HumanStamp`，不写“你”，也不计入“你的决定”。人之后改判时，改判记录才使用 `HumanStamp`。

**计划步骤与发现的字形**（ADR-176）：`PlanStep` 没有状态字段，“完成”与“当前步骤”来自 Agent 的 `log`（`02` §2.5），是说法。字形集（ADR-180 修订）：`○` 未开始（text-3）· `┆▸` Agent 称正在进行（最近一次 `log` 的 `step`）· `┆✓` Agent 称已完成（text-2，不着色）· `◆` 需要你决定的步骤（`needsDecision`，`04` §4.5）或该步骤上有等你处理的条目（沿用 `◆` 的全局含义）。**没有表示步骤完成的事实字形**：Tower 测不到“完成”——关联标准可能在改动之前就已通过（回归保护）。字形只取一个，优先级 `◆` > `┆▸` > `┆✓` > `○`；其后可加徽章：`关联标准通过`（关联标准 `PlanStep.criteriaIds` 非空且全部由验证器新鲜通过；事实徽章，text-2，不着绿，不表示步骤完成；取代 ADR-178 的事实 `✓`）· `一致 · n 条事实`（交叉校验 X4 一致，只检查触及的文件）· `◇ 可能不一致`（X4 不一致；X4 是启发式，至多是软矛盾，按上方矛盾样式用中性 `◇`，不用 danger 的 `✕`，`07` §7.8）。诊断时间线与轨迹中的发现（Finding）同理：`┆ 发现 n`（说法），交叉校验一致时加徽章 `一致 · n 条事实`，不换成 `✓`（ADR-178）。

### 12.5.2 “已验证”的三种形态（R1-D9-05、ADR-031）

| 形态 | 条件 | 生命周期字形 | 标签 |
|---|---|---|---|
| 已验证 | 至少一条 exec / artifact 标准由验证器执行；全部新鲜通过；无保留条件 | `▲` 绿 | `已验证 @e7a210` |
| **有保留的已验证** | 同上，但满足 `07` §7.10.3 `anyQualified` 的任一条件（唯一定义，本表不复述，ADR-183） | `▲` 绿 + 右下缺角（生命周期字形的圆环在右下留一段缺口，印章的实心圆切去右下角；ASCII 记作 `▲*`） | `已验证（有保留）`。印章旁不加徽章：原因用文字写在印章的提示里、验收面板的判断项里（“仍然验收”要按两次），并以中性药丸出现在对应标准的证据条上：一种保留一个词，与印章提示的措辞相同，不论是哪个哨兵引起的。同一类发现若是高严重度，就不是保留，而是扣留通过（印章写“通过但不作数”），证据条按所做的事命名（如 `运行器被修补`），在通过的标准上以琥珀色出现。每一类只写严重度最高的一条。通过一旦被扣留，就没有“计入的保留”：同一行上本会是保留的发现（含金丝雀未能检查、不稳定）也画成琥珀色，不画中性药丸。目前 supervisor 只计算三项（`progress.qualified`）：`代码触及测试运行器`（`source_patches_tests` / `source_touches_tests` / `runner_patched` 低于高严重度时）、`断言未检查`（金丝雀未能检查）、`不稳定：重跑后通过`。`anyQualified` 的其余条件（既有 flaky、S0 环境、部分标准未执行、Node 版本不同、LFS 改动、延续验收、链接未检查、计数为估计，ADR-184）尚未计算，不会产生这一形态 |
| **未经机器验证** | 没有完成机器验证：只有 human 标准（ADR-031）；或 exec 标准没有执行——S0 授权被拒绝或超时默认拒绝（ADR-068、ADR-077）、M1 中的非 Node 生态（ADR-064）、子模块项目（ADR-071）。后几种情形下 artifact 标准仍会执行，其结果照常以事实显示（R4-D15-02 #9） | `◬` 中性（虚线圆内勾） | `未经机器验证`，按原因加后缀：`（S0 未授权）`、`（S0 超时默认拒绝）`、`（生态未支持）`、`（子模块未支持）`；中性；验收面板逐条列出 human 标准，并列出未执行的机器标准及其观测结果（观测语法） |

`accepted` 若带着保留验收，同样加缺角（`●*`）：生命周期字形的实心圆和目标页头的印章都切去右下角，印章的词仍是 `已验证（有保留）`，提示写明验收时带着哪些保留。合入以后（`integrated`）外环在右下留同样的缺口（`◉*`），读屏标签为“已合入，已验证（有保留）”。已验收或已合入的目标，每一处印章（目标页头、peek、评审头、验证读数）的提示都写“你是带着这些保留验收的”，不再写“验收前先看过它们”。验收延续目前不产生这一形态（见上表）。

**通过但不作数**（必然失败的金丝雀也通过了，`07` §7.10.3）：命令通过，但断言或运行器被改动过，这次通过**不计入 V**。它不是“有保留的已验证”的又一个原因徽章，而是一个独立的结论：印记写 `通过但不作数 @pin`（英文 `Passed, doesn't count`），用琥珀 `◆`（它等你处理，不用绿、不用 `■`）；两轨进度在 V 后另列 `n 项不作数`，进度条为它画一段琥珀；标准行上写“必然失败的测试通过了，这次通过不作数”。措辞统一用“不作数”，不写“不是证据”——在压力下前者一读就懂，后者要先解析一次否定。

**机会式验证的守卫**（ADR-053）：机会式验证的通过结果，若测试路径集、标准命令引用的脚本或测试配置相对 base 有未处置改动，以“有保留”形态显示（`✓` 绿 + 缺角，徽章 `测试定义已变`），并且**不计入 V**。这是唯一一种“绿色但不计入已验证”的情况，所以徽章必须写明原因。

### 12.5.3 组合规则

1. 说法与观测都不得借用事实的颜色。
2. 同一行出现说法与事实时，说法在左、事实在右，中间用 `↔`（账本行，`04` §4.5）。
3. 进度只能由事实与观测构成，并**分两轨显示**：`已验证 V/M · 观测 O/M`（ADR-020）。`M` 只计机器标准（exec + artifact）；human 标准另列 `人工 h/k`，用 Human 语法，**从不进入 V 或 O**（ADR-052）。不再出现单一 `N/M`。Agent 自报的百分比只能以说法出现，从不画成进度条（T§A16 Unreliable Progress Bar）。
4. 置信度只用文字“低 / 中 / 高”，不显示百分比（`02` Claim.confidence；T§C16-10）。
5. 推荐（决策卡）一律以说法样式显示，无论来自 Agent 还是 Harness 规则（Harness 时前缀 `⚙ 规则推荐`，仍是说法的 `┆` 语域，因为推荐不是测量）。
6. 过期、失效的结果两轨都不计入。
7. “原因”区块（ADR-030）= 症状（事实或观测，按来源取语域）+ 原因（说法）。症状与原因上下排列，不合并成一句话。

## 12.6 状态字形

### 12.6.1 生命周期字形（`LifecycleGlyph`）[M1]

10×10px SVG，置于 14px 槽位，1.25px 描边。形状互不相同，灰度与色觉异常时仍可区分。在动的工作会转：运行中与验证中的字形整体旋转（transform，留在合成层），每 1.1 秒一圈（`--dur-spin`）；减弱动效时静止，弧停在右上（§12.7）。

| 状态 | 字形 | SVG 形状 | 颜色 |
|---|---|---|---|
| draft 草稿 | `○` | 空心圆 | neutral |
| ready 就绪 | `◎` | 空心圆 + 中心点 | neutral |
| running 运行中 | `◐` | 淡圆环（28% 不透明）+ 右上四分之一弧，整个字形转动；不再画半实心圆 | active |
| paused 已暂停 | `‖` | 圆环内两条竖杠（保留目标的圆环） | neutral |
| claimed 自称完成 | `△` | 虚线圆（说法的虚线围着一个空目标） | neutral（R2：不是绿色） |
| verifying 验证中 | `◭` | 虚线圆 + 四分之一弧，整个字形转动 | active |
| in_review 已验证 | `▲` / `▲*` | 圆环内勾 / 圆环右下留缺口（§12.5.2） | verified |
| in_review 未经机器验证 | `◬` | 虚线圆内勾 | neutral |
| accepted 已验收 | `●` / `●*` | 实心圆内反白勾 / 有保留时实心圆切去右下角，字形与印章相同（§12.5.2） | verified |
| accepted 人工验收（结论为未经机器验证） | `◍` | 斜线填充圆（形状不同于 `●`） | neutral；标签 `人工验收` + 原因后缀 |
| integrated 已合入 | `◉` / `◉*` | 实心圆 + 外环 / 有保留时外环在右下留缺口（与 in_review 圆环的缺口同角度），实心圆完整（§12.5.2） | verified |
| integrated 已合入（人工验收） | `◉`（中性） | 与已合入同形：细外环 + 实心圆 | neutral；**已知局限**：与验证过的已合入只差颜色，状态词同为 `已合入`（读屏标签也相同） |
| archived 已归档 | `·` | 3px 实心点 | text-4 |
| abandoned 已放弃 | `⊘` | 空心圆 + 斜线 | neutral |

“字形”一列是线框与各文档沿用的记法，界面画的是“SVG 形状”一列（`components/Glyph.tsx`）：圆环是目标，虚线是说法（“说了，未证实”），圆环里的勾是验证器的结论，实心圆是已封存；界面中没有三角形，初稿的三角被这套圆环词汇取代，说法的虚线因此也能出现在生命周期字形上。完成链 `△ → ◭ → ▲ → ●`：虚线圆 → 虚线圆半实心 → 圆环内勾 → 实心圆，颜色只在验证器通过后出现。未经机器验证的链是 `△ → ◬ → ◍`，全程中性；归档列表在 `·` 旁保留结论标记（`●` / `◍`），所以在验收这一步“人验收过但机器没验证过”一眼可辨（R4-D9-01）；合入之后两种结论同形，只差颜色（已知局限，见上表）；放弃列表中从 `integrated` 放弃的 Goal 同样在 `⊘` 旁保留 `◉`（人工验收的为中性色 `◉`），表示改动已在 base 中（由状态事件得出，ADR-196）。

### 12.6.2 叠加标记 [M1]

| 标记 | 形状 | 颜色 | 位置 | 含义 |

**标记族与记法。** 三种叠加标记是同一个家族：16 单位网格上的圆盘，画成 12px，比基线低 2px；符号从圆盘里镂空，每个标记是一条偶奇规则的路径，所以符号是真正的孔，透出标记所在的底色（选中行、浮起的面板都对）。组件里的路径是 `Glyph.tsx` 的 `MARK_PATH`；样式表放在文字前的标记（字段的错误与提醒、提示条、失败的轨迹步骤、评审风险徽章）用同一组路径做 CSS 遮罩（`tokens.css` 的 `--mark-*`），手机页也用同一组路径；一条单元测试保证三处相等。界面上不再有菱形、方块、半圆，也不用任何文字字符或 emoji 表示状态。本文和其他文档里的 `◆` `◇` `■` 只是这三种标记的记号（需要你 / 要注意 / 危险），不是界面画的形状；`◐` `◭` 同理，指运行中与验证中的转动字形。

### 12.6.3 模式徽章（`ModeBadge`）[M1]

模式是封闭集合，由 Harness 推导（R6、`08` §8.6.2）。徽章 = 可选字形 + 2–4 个汉字（两处例外：仓库准备阶段的 `仓库准备中` 与 `软上限 · 收尾中`，ADR-204），12px / 500，**文字一律 text-1 或 text-2**，状态色只在字形与底色上；固定最小宽度 4 个汉字。

| Mode | 徽章 | 字形 | 字形色 | 背景 |

| preparing | 准备中 | — | — | 无 |
| thinking | 思考 | — | — | 无 |
| acting | 执行 | — | — | 无 |
| waiting_human | 等你 | `◆` | attention | `--attention-bg` |
| blocked_guard | 等你批准 | `◆` | attention | `--attention-bg` |
| budget_capped | 软上限 · 收尾中 | `◆` | attention | `--attention-bg` |
| retrying | 重试 2/5 | — | — | 无 |
| compacting | 压缩中 | — | — | 无 |
| queued | 排队 | — | — | 无 |
| verifying | 验证 | — | — | 无 |
| stalled | 卡住 | `◆` | attention | `--attention-bg` |
| unresponsive | 无响应 | `■` | danger | `--danger-bg` |

`blocked_guard` 表示“动作被门禁挂起、等你批准”，与收件箱中的 `approval` 条目是同一件事，所以同为琥珀 `◆`（R1-D9-02）。审批被**拒绝**不是模式：它是一条事实事件，在轨迹与账本中显示为 `■ 已拒绝 · pnpm add stripe@18`，并在实况行对象段停留到 Agent 的下一个动作为止。

### 12.6.5 等待与暂停原因（`02` Goal.waitReason / pauseReason）[M1]

非运行状态的实况行写成 `<状态> · <原因>`，文字 text-2，不加状态色；需要人的原因同时存在一条 Needs-You，由 `◆` 表达。三处例外（ADR-189、ADR-204、ADR-205、ADR-206）：`engine_crash` 在自动“重启并恢复”期间没有条目，写 `◇`，只在 `08` §8.6.3 所列的两种情形下才有条目；`satellite_missing` 同构，自动重建期间没有条目，写 `◇`，重建失败后才有条目（`◆`）；`nested_repo_live` 的条目是 `sentinel`，以危险哨兵的 `■` 表达。

## 12.10 数据可视化

### 12.10.1 验收标准分段条 `CriteriaBar`（两轨，ADR-020）[M1]

```
看板行  ▰▰▱▫  2/4 · 人工 0/1                         每段 9×5px（窄时可压到 5px 宽），间距 2px；文字只写 V/M，有不作数时改写 `n 项不作数`（人工计数随之隐去）
目标页  ▰▰▱▫  已验证 2/4 · 观测 3/4 · 人工 0/1       每段 12×4px（1px 圆角），间距 2px；文字与分段条隔 8px
```

分段条**只画机器标准**（exec + artifact），一共 M 段，**按计数画，不按单条标准画**：先画 V 段，再画不作数段，再画超出这两者的观测段，其余是空段。所以段的顺序不对应合同顺序；失败、过期、验证环境故障在分段条上都是空段，它们的区别只在标准行中显示（§12.5.4）。人工标准不进分段条（ADR-052），也不画方框，只在文字中计数：

| 段状态 | 填充 | 冗余编码 | ASCII（`04` 线框） |
|---|---|---|---|
| 验证器新鲜通过（V） | st-verified 实心 | 实心 | `▰` |
| 通过但不作数（必然失败的金丝雀也通过了，§12.5.2） | st-attention 实心 | 实心；文字写出 `n 项不作数` | `▰`（琥珀） |
| 观测到通过（超出 V 与不作数的部分） | 无填充，1px text-2 虚线描边 | 空心虚线框（虚线 = 观测，与 `ObsChip` 同一线型） | `▱` |
| 其余（未运行、失败、过期、验证环境故障、未知） | 无填充，1px text-4 实线描边（“还没有”要画得和“已完成”一样清楚） | 空心实线框 | `▫` |

- 段数等于机器标准数；看板行中段宽可以收窄到 5px，其他处为 12px（紧凑变体 9px），不改用比例条。
- 旁边的文字为 `已验证 V/M · 观测 O/M`，有不作数时在两者之间插入 `n 项不作数`，有人工标准时追加 `· 人工 h/k`：M = 机器标准数；V = 验证器新鲜通过数（**不含**任何人工勾选，也不含 ADR-053 守卫下的机会式结果）；O = 观测新鲜通过数（ADR-020、ADR-052）。文字一律是 meta（12px，text-2），只有 `n 项不作数` 提到 text-1。没有机器标准的目标不画分段条，显示 `未经机器验证`（看板行为 `无机器标准`），有人工标准时后接 `· 人工 h/k`。悬停提示给出全文和三种计数的说明。
- 人工标准的勾选在目标页的标准行中：一个复选框（`accent-color` 为 text-1，不着绿），旁边写 `你已勾选` / `待你勾选`。

### GoalRow（看板航班条，取代初稿的五行 GoalCard）[M1]

- **结构**：一行固定 40px（`--row-goal-h`），所有行共用一套列，读数逐行对齐（`19` §19.2）：`LifecycleGlyph`（14px 槽）· 标题 + 编号（有重叠时其后是 `◇ 与 G-0004 改动重叠`，写成文字，不只写对方编号——标识列里一个孤零零的 `G-0004` 会被读成本行的编号。提示先于标题、逐步让位，按静止时的行来判断：`◇ 与 G-0004 改动重叠` → `◇ G-0004` → 只留 `◇`，在标题仍能显示完整的短标题、或长标题的 12em 时写得尽量多；收起的部分留在提示和读屏里。悬停或选中时出现的速览按钮可以暂时占标题的位置，提示不随之变化。1241 起标题列的下限都是 16em（1561 以上也一样），留出编号和 `◇` 之后标题仍有约 12em，1560 与 1561 两侧标题列只差十几像素。1240 及以下随标识列一起收进标题的提示）· `LiveLine`（放不下时印章先收起词，再整体让位：绿色的勾不会离开它的 pin 单独出现；文字行用省略号）· `CriteriaBar`（11em，看板尺寸，§12.10.1）· diffstat · 花费 + `BudgetMeter` · 更新时间 · 标识（PR、返工 n/上限、非默认引擎、项目名，靠右对齐，项目名按自己的字宽排。按测量逐步让位，从不裁切：先收引擎名，在项目名需要缩短之前；再让 PR 只留需要你的读数——失败的检查数，已合并或已关闭时的状态词；再收“已静音”（你自己的设置，不是新消息）；再收项目名（可以先缩短，但不短于它自己的字宽和 3.5em 中较小的那个；显示还是收起只看走到了哪一步，不看它被挤得多窄，被 flex 挤成一条缝也算裁切）；再收 PR 的状态词，只留 `PR ■n`；最后整个标识收起，同 1240 及以下，收起后 PR 按钮也不再是 Tab 停靠点。收起的只是不显示，读屏照样读到；标题的提示写全整个标识，PR 写成文字（`PR 已关闭：1 项失败`），返工也在。PR 按钮的名称就是它自己的文字：图形和光秃的计数由一段只给读屏的摘要说成文字，不在它显示的东西上另盖一个标签）。22px 的表头行在第一组内，与条共用一条发丝线。行上不画 `◆`：需要你的事是置顶在目标行上方、同一列网格的决定行。航班条只有一行：初稿卡片第 2 行的内容在实况列；第 5 行的异常与提示不在看板行上（标题格的重叠提示除外），而在目标页与速览抽屉中（§12.6.2）。它取代初稿的五行卡片（132px），因为每个读数落在同一列，十几个目标能像离港屏一样逐行对读。

- **琥珀只说“需要你”**：单独显示的卡（目标页、看板打开的那一条）头部是琥珀条。收件箱队列里每张卡都需要你，琥珀无法再说明“你在哪一张”：队列中的头部一律中性（发丝线 + 一个 `◆`），聚焦卡的头部用中性选中底 `--bg-selected`，与看板选中行同一语言。琥珀从不充当选中色。

- **结构**：头部（种类 · 归属 · 延迟代价 · `CountdownLabel`）→ 问题 → 选项（编号、标签、后果）→ 推荐（`ClaimBlock`；M3 起其下附校准记录，事实语法，`09` §9.8，ADR-180）→ 证据 → 补充说明 → 动作行。
- **状态**：未选择（确认禁用）、已选择、待发送（5 s 倒计时，显示“撤销 / 立即发送”，`05` §5.6.4）、已送达（**不可撤销**；卡片显示 `改判` 按钮，改判以转向送达，R1-D5-11）、已失效（灰显）、已按默认处理；**单向门确认**（`isOneWayDoor` 的审批选中“批准”时：确认按钮改为“按住确认”1.5 s 进度环，或输入目标名后可点（卡片同时显示动作类 id，例如 `system.change`；解析不出目标名时改为输入它，`16` §16.3）；`⌘↩` 不确认，`16` §16.3、`11` §11.2，ADR-183）；**已延后**（`S`，标“已延后至 hh:mm”，留在主列表，时长见 `16` §16.2.4，ADR-183）。
- **紧凑变体**：托盘与手机——后果折叠为一行，证据折叠为计数。
- **无障碍**：选项为 `radiogroup`；推荐项不预选；倒计时 `aria-live="off"`。

### CountdownLabel [M1]

决策卡右上角。**文案直接取 `08` §8.7.1 倒计时文案表的六种情形**（唯一定义在那里，ADR-023/178/182），本组件只规定样式：`unattended:"wait"` 下任何条目一律 `不会超时`（text-2，不显示倒计时）；`use_defaults` 下按条目区分——审批与 S0 执行授权写出默认项“→ 拒绝”，standard/high 风险或推荐项不可逆的问题写“超时后暂停（不自动作答）”，low 风险且推荐项可逆的问题写“N 分钟后 → 采用推荐：<选项>”，检测器 escalate 的停滞写“30 分钟后 → 暂停（仅 use_defaults）”。按分钟替换，不跳秒。

### ReviewUnit [M1]

- **结构**：头部（序号、标题、风险、行数、关联标准、预计时长、`已计入积压`、动作）→ 意图（`ClaimBlock`）→ 风险依据（事实）→ 哨兵 → `DiffView`。
- **状态**：未看、已看、已批准、请求修改、内容已变（重置为未看，显示 `内容已变 · 上次批准于 @…`）。
- **队列项**：风险为中、高时，第二行用 text-2 写出第一条风险依据（最多两行，`--fs-meta`），所以“先读哪一单元、为什么”在队列里就能看到，不只在悬停提示里；首行是标题（mono 12px，text-1）+ 文件数 · 行数（text-2）+ 标记位：风险竖条（高 `▪▪` / 中 `▪` / 低 无，text-2，不着色，读屏为 `风险 n`；不用 `■`——它是 danger 色的阻断哨兵，ADR-178）与已审勾。你把该单元的文件都标为已审后出现已审勾（按文件内容哈希，内容一变就消失）：10px 中性勾，取文字色（text-3），从不用 `--st-verified` 绿，读屏标签为 `已审`。它不会被读成验证器的结论：绿色与实心印章只属于验证器，这个勾既不着色又带 `已审` 标签。本设计系统在这里偏离 ADR-180 的“不用 `✓`”，守卫是颜色加标签（登记于 §12.6.2）。含人或外部改动时显示 `你` / `外部` / `混合`。

### DiffView [M1；就地编辑 M2]

- @pierre/diffs（G§4.2），并排 / 统一；行号槽承载 `+`/`−`、评论琥珀竖条、作者线型。
- 大小分层：≤ 3k 行全高亮；3k–20k 只高亮可见 hunk；> 20k 不着色；生成文件与 lockfile 默认折叠。
- 就地编辑（M2）：CodeMirror 6 合并视图，进入时 hunk 外框为焦点环（`--focus`，界面没有强调色）；保存只写文件，不提交；改动由检查点归因为 `author:"human"`，署名在验收时进入汇总提交的 `Tower-Human-Edit` / `Co-authored-by` trailer（ADR-036、ADR-081）。

### CommentThread（含送达回执）[M1]

- **结构**：作者 · 约束（`requiresChange`：`必须修复` danger 描边小标签 / `建议` text-2）· 送达时机（`立即` / `攒批`）· 正文 · 回执行。
- **回执行**：状态定义以 `05` §5.7.3 为准：`排队 → 已送达（第 37 回合）→ 已读入（seen）→ 已回应（acknowledged）→ 已处理`。`已回应` 由 Agent 的引用产生，写作说法 `┆ Agent 称已回应`；`已处理` 只有事实一个来源：`⚙ hunk 已变 @c41d09`（ADR-176）；非 hunk 锚点的评论没有这一步，回执止于 `┆ Agent 称已回应`（ADR-178）。当前步骤 text-1，已过步骤 text-2。`◇ 未送达：Run 已结束`（无需操作，不是异常，不用 danger：仍在队列中，下一个 Run 开始时随开场送达，`05` §5.7.1，ADR-212）；异常：`过期：hunk 已变` + `重新发送`（`04` §4.6.3）。

### Briefing [M1]

覆盖层；行模板“字形 · 目标 · 一句事实 · → 目的地”；最多 7 行；唯一的说法是“预测”；无动画（0ms）。进度一律写两轨 + 人工（`已验证 0/4 → 2/4 · 人工 0/1`）。

### Palette [M1]

输入框 + 结果列表，每项右侧快捷键 keycap（`hint` 角色）；键盘打开时 0ms 出现，其他方式打开时 160ms 浮起；拼音匹配；合成期间不跳转。宽 600px、10px 圆角、不透明（`--bg-overlay`），行 32px。

## 12.13 无障碍

### 12.13.1 对比度（APCA 角色表）

按 APCA bronze 简化规则，以字号与字重决定目标（R1-D9-01）：

| 角色 | 字号 / 字重 | 最低 Lc | 可用令牌 |
|---|---|---|---|
| 正文与阅读 | 14px / 400 | 90 优先，75 最低 | text-1 |
| 必读小字（实况行、meta、事实数值、标签、说法） | 11–13px / 400–500 | 75 | text-1、text-2 |
| 标题 | ≥ 16px / 500 | 60 | text-1、text-2、状态色（仅此处） |
| 非必读文字（快捷键提示、分隔符、占位、与旁边信息重复的标签） | 任意 | 45 | text-3 |
| 禁用、过期 | 任意 | 30 | text-4 |
| 非文字元素（字形、焦点环、分段条） | — | 45 | 状态色、焦点环 `--focus`、text-3 |

- 实测方法：在 MacBook Pro（XDR，P3）与一台 sRGB 外接显示器（27″ 1440p）上各测一次，用浏览器取色在实际渲染（含亚像素与字体渲染）上复核表中组合；不达标时调整令牌明度而非字号。
- `prefers-contrast: more`：text-2/3/4 各向极端推一档（深色 +0.06 明度，浅色 −0.06），边框透明度 +0.06；过期事实提升到 Lc ≥ 45。
- Windows `forced-colors: active`：状态色映射到系统色，形状编码保证信息不丢失；来源栏的文字标签与虚线 / 实线线型保留。

### 12.13.2 动效

`prefers-reduced-motion: reduce` 时所有动效时长为 0；琥珀一次性提示直接显示为稳态色调。单向门的按住确认 1.5 s 与发送前的 5 s 倒计时是交互阈值，不是动效，不受影响。

### 12.13.3 读屏与 aria-live 政策

| 内容 | 策略 |
|---|---|
| 实况行、计数、计时、分段条、花费 | 不播报 |
| 新的需要你条目（L2–L3） | 单一全局 `polite` 播报区；30 秒内合并为一句 |
| L4 条目 | `assertive` 一次 |
| Watch 模式尾部 | `role="log"`，`aria-live="off"` |
| 你的操作失败（送达失败、验收失败、批准被阻止） | `assertive` 一次 |
| 应用级横幅（§12.8，`06` §6.8 F8） | 出现时 `assertive` 一次；消失时 `polite` 一次，消失时读 `磁盘空间已恢复，Tower 恢复运行`（ADR-233/234/235） |
| 目标页模式变化 | 默认不播报；可开启“朗读当前目标的模式变化” |
| 简报 | 打开时焦点移到标题，按分段标题导航 |
| Diff | 行为 `row`，行号槽符号可读（“新增”“删除”“你的改动”） |
| 终端 | xterm `screenReaderMode` 按需开启 |

### 12.13.4 其他

- 所有动作都可从命令面板到达并显示快捷键；焦点环永远可见（1.5px 墨色描边，§12.11）；最小点击区域：按钮 24px 高（小号），文字按钮 20px 高（Mac 指针目标的下限）。
- 颜色从不单独承载信息（已知例外：已合入的两种结论只差颜色，§12.6.1）：状态有形状、过期有 `⟲`、观测有空心与虚线框、diff 有 `+/−`、作者有线型、必须修复有文字标签。
- 在 VoiceOver 与 NVDA 上测试概览、需要你、评审评论流程（G§8）。

## 12.14 简体中文（zh-Hans）规则

1. **输入法合成**：所有回车提交的处理函数忽略 `event.isComposing === true` 与 `keyCode === 229`；多行输入统一 `⌘↩` 提交、`↩` 换行。端到端测试：输入法输入“修复结账”，用回车选词，断言没有提交（G§8）。
2. **单字母快捷键**：只在焦点不在可编辑元素时生效；每个单字母快捷键都必须有命令面板等价项。
3. **行高**：中英文共用同一套 px 行高令牌（`--lh-body` 20px、`--lh-reading` 22px 等，§12.3.2），不为中文另设行高；中文只把字距设为 0，并把行宽单位从 `ch` 换成 `em`（`--measure` 72ch → 40em）。
4. **中西文间距**：`text-autospace: normal`（Chromium 140+）。消息目录不手写中英文之间的空格，lint 检查 `[一-鿿] [A-Za-z0-9]`。线框中的空格仅为可读性。
5. **标点挤压**：单行标签与标题用 `text-spacing-trim: trim-start`；正文 `normal`。
6. **断行**：中文正文 `line-break: strict`；路径、哈希、命令 `overflow-wrap: anywhere`；不用连字符断词。
7. **截断**：标题末尾省略；路径中间省略保留文件名；按 `Intl.Segmenter` 字素截断。
8. **字重**：只用 400 / 500（判决与字标的 580 / 600 例外见 §12.3.3）；层级不只靠字重。
9. **无斜体**。
10. **引号**：「」表示引用的说法或标题，“”用于一般引号。
11. **数字、时间、货币**：千分位 `3,012`；时间 `14:02`；外周相对时间 `刚刚 / 6分前 / 3时前 / 昨天 / 10月2日`，提示框中 `6 分钟前`；金额 `$1.84`。
12. **排序与搜索**：`Intl.Collator('zh-Hans-u-co-pinyin')`；拼音全拼与首字母匹配。
13. **lang 属性**：用户输入按文字检测设置 `lang="zh-Hans"`；Agent 输出不设，除非检测为中文。
14. **宽度**：不使用固定宽度文本标签；模式徽章最长 4 个汉字（例外见 §12.6.3）；两种语言都测布局。

## 12.15 主题规则

- 浅色、深色、跟随系统、高对比四种；高对比由同一 OKLCH 明度阶梯推到两端生成（G§8）。
- 用户主题只能覆盖中性色色相（彩度上限 0.02）。覆盖后自动按 §12.13.1 角色表复核，不达标时拒绝保存并给出最近的合格值。
- 没有强调色：焦点、选中与主按钮都是墨色与明度（主按钮是反白的墨色），系统强调色不映射到界面。
- **状态色锁定**：`--st-*`、`--attention-bg`、`--danger-bg` 不可被主题覆盖；diff 色只能在“标准 / 色觉友好”两套间切换。
