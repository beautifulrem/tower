# 产品审计评分表（真实用户视角）

审计员以真实用户的身份评估 Tower：一位每天用编程 Agent 干活的中文开发者，同时管理 3–5 个并行任务，用过 Claude Code、Codex、Cursor、Conductor 等工具。每个维度 0–100 分，**全部维度都超过 95 分**才算通过。每轮审计都要和当前主流的 Agent GUI 做对比。

| # | 维度 | 看什么 |
|---|---|---|
| D1 | 上手与引导 | 第一次打开到第一个目标跑起来要多久；环境问题是否给出可执行的修复办法 |
| D2 | 核心流程完整度 | 目标 → 运行 → 验证 → 评审 → 验收 → 推送 / PR 每一步是否可用、出路是否清楚 |
| D3 | 可信度与诚实 | 事实与声明是否分开；验证与哨兵能否挡住“看起来通过”的坏结果 |
| D4 | 注意力管理 | 是否只在需要时打扰；通知、收件箱、跳转是否顺手 |
| D5 | 评审体验 | diff 可读性、批注即转向、增量评审、已看标记、在编辑器中打开 |
| D6 | 视觉美学与原创性 | 是否达到 Linear / Raycast / Things 级别；有没有 AI 味与平庸设计 |
| D7 | 信息架构与布局 | 页面职责是否清楚，信息密度与层级是否合适 |
| D8 | 交互细节与键盘 | 键盘覆盖、焦点、菜单、悬停与反馈、原生感 |
| D9 | 文案与中文排版 | 用词准确、语气一致、中英混排、标点与间距 |
| D10 | 性能与响应 | 启动、切换、长 diff 与长轨迹、后台运行时的流畅度 |
| D11 | 稳定性与错误处理 | 崩溃恢复、错误信息是否可行动、边界情况 |
| D12 | 安全与隔离 | 沙箱、凭据、单向门、扩展信任 |
| D13 | 代码架构与可维护性 | 分层、命名、注释、可测试性 |
| D14 | 测试与质量保障 | 测试覆盖关键路径、CI、真实引擎测试 |
| D15 | 开源项目成熟度 | README、许可证、贡献与安全政策、发布、变更记录 |
| D16 | 竞争力 | 与主流 harness GUI 相比的独特优势与短板 |
| D17 | 可访问性与国际化 | 对比度、键盘可达、读屏标签、英文界面 |
