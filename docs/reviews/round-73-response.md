**收敛规则**（同 ADR-186–200）：只用三种办法关闭条目：

2. 删除或推迟不属于 M1 主循环的机制；

“绝不碰用户的工作现场”（`10` L10）、“不丢人的改动”与全部安全不变式保持。拿不准时取更严格的行为：不加载、终止、保留并列出。安全问题只写到设计层面。

## 偏离指示之处

- **R73-D11-03：没有采用“只加载 base 中已接受的版本”。** 在 Pi v1.2.0 中这无法实现：项目资源只从 cwd（卫星）读取，信任对整个项目一次判定（`resource-loader.ts:520-524`），没有按版本或按文件加载的入口。要做到只能由 Tower 改写卫星，那会覆盖 Agent 的工作。改为更严格的一边：不信任时连 base 版本也不加载，并写明恢复加载的两条途径。也没有采用 M1 中绑定哈希的“是”：它需要新的决定种类、Needs-You kind 与出口，还要在 Host 启动与 Pi 读取之间排除卫星被改写的窗口，超出收敛规则，因此推迟到 M2。
- **R73-D11-03：项目 Pi 配置被改动时不再生成 Needs-You，改为 `◇` 提示。** 这条通知没有可执行的出口。改动本身在验证时由 `protected_path`（severity 3）列出。
- **R73-D11-01：取“只在 pin 时处理”，不改为运行中的哨兵。** 运行中的哨兵需要“恢复这些路径”的新命令，而 pin 时的 `protected_path` 已能阻止改动进入评审。
- **R73-D6-01：结束 drain 后按叠加态重建，而不是把 `satellite_missing` 并入 `reasons`。** 叠加态已能重建卫星，并入只会多一个需要人处理的原因。人的暂停照样保留。
- **R73-D8-01（致命三要素）：不登记 `sentinel` detector，改为在授权生效之前的审批卡片上警告。** 这样更严格，与合同修订后重算三要素的形式一致，也不需要新的 kind 或 detector。
- **R73-D8-01（bash 覆盖）：新增哨兵 id `bash_overridden`。** 现有 kind 中只有 `sentinel` 能承载这类“沙箱被削弱”的提示性条目。它是 detector 注册表中的一行，属 M2。
