# 第 37 轮评审回应 · `04` 与 `12`

依据 `15` ADR-163。

| 条目 | 处理 |
|---|---|
| R37-D15-01（`04` L1099）冻结时机 | §4.10：判定、取槽位、冻结一次完成，冻结在取得槽位时开始、先于依赖与服务准备；补收尾顺序（终止进程 → 清理服务 → 释放槽位 → 解除冻结）与重启时未解除冻结的处理 |
| R37-D11-01 / R37-D6-01 全局冻结 | §4.10：冻结为整机范围，所有启动请求经同一闸口排队，逐项列出显示：`就绪 · …`、`便笺 · …`、`检验 · …`、`人工编辑中 · 依赖准备 · …`、`验证中 · …`（后缀统一为 `等待机密验证结束`），依赖安装与预热同样排队；机密阶段严格串行，`现在运行（接受风险）` 不与另一个机密阶段并行；`12` §12.6.5 冻结行列出全部标签 |
| R37-D11-03 机密输入检查 | §4.10 新增“机密输入检查”，覆盖回答与补充说明、改判、转向、`请求修改` 的评论、交还说明，同一文案与确认（`E_CONFIRM` / `confirmSecret`）；F3 与 §4.5 转向输入框引用它；`12` 同步 |
| R37-D7-01 哨兵与机密标准 | §4.10：普通标准通过但有阻断哨兵时机密标准显示 `因阻断哨兵未运行`；F6 第 5 步与哨兵卡片覆盖选项写 `覆盖后将先运行带机密的标准，通过后进入评审`；“未运行”不算失败、不进验证缓存；`12` 同步 |
