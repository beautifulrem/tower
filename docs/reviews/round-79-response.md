# 第 79 轮评审回应

决策：ADR-207（`15` 末尾，L3307 起）；ADR-206 标题加 “Amended by ADR-207”，其 R78-D13-01 一条加第 79 轮更正注（`15` L3276）；ADR-133 第 79 轮补记（`15` L1324）。本文件关闭 `round-79.md` §4 的 1 条重要条目、4 条次要条目与 §5 的 9 条观察。行号为修改后的位置。

**收敛规则**（同 ADR-186–206）：只用三种办法关闭条目：
1. 把说法改弱，但保证为真；
2. 删除或推迟不属于 M1 主循环的机制；
3. 在已有的唯一定义处加至多一条守卫、一行或一个字段。

本轮的结构性改动只有一处：Tower 快照排除什么，收到 `10` §10.7.1 第 1 步一处定义。该处原本就是检查点树与 pin 树的唯一定义。`10` §10.1.2 只保留本地文件的规则与理由，§10.6、`07` §7.3.2 与 `11` §11.8.1 都引用它。

新增的只有两项：
- 检查点与 pin 提交上的一个 trailer `Tower-Local-Exclude`，与已有的 `Tower-Satellite-Head` 是同一机制；
- `08` §8.8 F7 一行的一个 `obsolete` 出口。

不新增状态、事件类型、表、列、载荷字段、决定种类、Needs-You kind、子类型或 `step` 取值。安全不变式全部保留，有取舍时都取更严格的一侧。安全问题只写到设计层面。

### R79-D13-02（次要）：已解决

**唯一定义**：同在 `10` L735 第 1 步。
- **索引**：(b) 与 (d) 的条目若已在影子索引中，`add` 之前先 `update-index --force-remove`，与 gitlink 相同。因此 `decisive` 与 `full` 一致，`07` L284 的 “与影子索引的历史无关” 重新成立。
- **按快照求值、记在快照上**：
  - 新建检查点或 pin 时，按当时的清单求值 L，以 trailer `Tower-Local-Exclude: <路径>` 记在该提交上（第 4 步提交信息、§10.6 pin）。
  - 与某个检查点或 pin 比较的指纹，用该提交记录的 L。这类比较有：I2、`accept` 与 seal 的 `full` 闸口、归因表第 4 行。
  - 所以清单的增删本身不产生 I2、`external_change` 或 `stat_cache_mismatch`，在该 Goal 的下一个检查点或 pin 生效。

**后果如实写明**（`10` L184；`04` L1313；`06` L890、L891）：
- 加入清单后，Agent 此前写下的该文件从此后的检查点与 pin 中去掉；
- 加入之前已进入某个 pin 的，仍在那份差异中，评审时可见，随它的验收进入 seal；
- 移出清单后，它作为新文件出现在各活跃 Goal 的下一个检查点或 pin 中，作者按收入它的检查点记录（`running` 中为 `agent`）；
- `in_review`/`accepted` 中的 Goal 在下一次生成 pin 之前不受影响。

ADR-206 中 “清单中的路径从不进入检查点” 一句加第 79 轮更正注。

**测试**：G46 (bh)(6) 第六组（`14` L134）。`in_review` 中加入清单：没有 I2，没有 `external_change`，没有 `stat_cache_mismatch`，评审进度不变；返工后的检查点与 pin 不含该文件，影子索引中也没有它的条目，`decisive` 与 `full` 的树相同。

## 偏离与未决

- **L 的记录位置**：指示建议记在已有的 pin/检查点字段（如 `excludedPaths`）中。没有这样做，理由如下：
  - `excludedPaths` 的语义是 “非空即 `nested_repo`，不可覆盖”，`16`、`07`、`10`、`04`、`14` 有十余处依赖这一语义；
  - 把 L 放进去，就要改元素形状，并重写阻断规则。
  - 改为记在检查点与 pin 提交的 trailer `Tower-Local-Exclude` 上，与已有的 `Tower-Satellite-Head` 是同一机制，排除集与它所描述的树在同一个对象里。
  - 这是一个新的 trailer 键，但不是新的表、列、事件或载荷字段。若评审认为它等同新增字段，替代方案是给 `checkpoints` 加一列。
- **移出清单后的作者**：移出后，该文件作为新文件进入下一个检查点，作者按该检查点记录，`running` 中为 `agent`。实际上它是 Tower 播种的、人的文件。
  - 本轮只如实写明，没有新增归因规则。
  - 评审给出的更窄写法（`remove` 在有 `claimed`–`accepted` 的 Goal 时返回 `E_STATE`）没有采用，因为它会阻止 ADR-206 推荐的提交方式。
- **加入清单之前已进入 pin 的文件**：它随该 pin 的验收进入 seal。这与 “清单中的文件不进入汇总提交” 的旧绝对说法不同。`04` 的说法已改为 “加入前已在某个待验收改动中的，仍留在那份改动里，评审时可见”，人可以请求返工。
- **探测的取舍**：没有采用 “认证条目不自动解除”，而是让探测真正刷新令牌。这样保留了 “人在终端登录后自动继续”；代价是探测成功的定类仍是推断，`08` L513 已如实写明。
- **② 的配对**：取 `prepare_failed`，而不是从 `ready` 进入 `provider_unavailable`。后者要改 `03` 的入口状态，并改 lint (s) 的六处来源。
- **观察 6**：F7 沿用 L2 的两个输入。认证过期时，人的处理实际上是恢复的前提；是否改为 `agent_blocked`（L3）没有在本轮改动，保持 ADR-206 的级别。
- **未实现的 lint 建议**：(r′) 补对，理由见 lint 一节。
