# 第 5 轮评审回应 · `04` 与 `12`

一行一条：条目 → 处理位置与方式。依据 `15` ADR-081 – ADR-087。

| 条目 | 处理 |
|---|---|
| R5-D1-01 (a) | `04` §4.6.5 “你的仓库里会出现什么”改为：默认只有验收时的汇总分支 `<branchPrefix>/<目标>-<slug>`；检查点、pin、基线快照只在影子中，pin 永不进入；仅开启“保留审计地标”时才写 `refs/tower/<目标>/cp/<n>`（180 天）。§4.15 项目设置增加“分支前缀”“保留审计地标”，数据设置的清理项改为只在开启地标时出现 |
| R5-D1-01 (b) | ADR-081 / ADR-036：`04` §4.6.4 就地编辑（M2）只写文件、由检查点归因、Tower 不替人提交、署名进入 seal 的 trailer；F5 “我来改”改为在人工编辑检出 `_human/<目标>` 中进行（Tower 模板元数据、IDE 安全、交接前校验、交还时文件级同步写回并删除、人的提交被忽略并提示）；§4.7.3 证据面表同步；§4.6.5 seal 说明加 trailer；`12` `DiffView` 与术语表 |
| R5-D8-01 | ADR-082：`04` §4.6.6 重写：打开前的信任提示框（Agent 代码、沙箱范围、终端内程序不在沙箱、可读密钥本地文件）；脚本与服务在验证器沙箱档位中运行；检验专用端口段与注入渲染后环境变量的终端；S0 未授权只复制文件并提供“授权后检验”；清理时机与 `10` §10.8.3 统一（停止时关服务、目录随工作目录删除），关闭时对检验目录中的修改提示；§4.7.3 表同步 |
| ADR-081 第 2 点 | `04` §4.18.1 第 1 步扩展清单确认卡列出能力差异，包括“依赖 git 的扩展与 MCP 服务器在工作目录中看不到仓库”；§4.15 引擎设置增加能力差异入口 |
