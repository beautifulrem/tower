# 第 19 轮评审回应 · `04` 与 `12`

一行一条：条目 → 处理位置与方式。依据 `15` ADR-145。

| 条目 | 处理 |
|---|---|
| R19-D8-01（`04` L966、L972–973） | `04` §4.8.13：开场在 Run 开始的同一时刻送出；撤回已送出的条目得到 `already_delivered`，该行改为 `已发送，无法撤回`，不显示为撤回成功；`12` `OpeningQueue` 同步（不淡出） |
| R19-D7-01（`04` L946–950，`12` L408） | `04` §4.8.12：rebase 带入的变化（M2）不算你的改动，窗口内只有它时失败卡片写 `包含 base 的变化（rebase）`，两者都有时分两行；`12` §12.6.5 同步 |
| R19-D4-01 窗口次序与“通过” | `04` §4.8.12：按事件先后计，交还写下的检查点早于“交给 Agent 继续”，不在它开启的窗口内；“通过”= 进入待验收（含有保留、未经机器验证）或回到已验收 |
| R19-D6-01 drain 期间再请求接管 / 回退 | `04` F5：`暂停中（等待当前步骤结束）` 时按 `E` / `⌘⇧R` 提示 `等待当前步骤结束后重试`（`E_BUSY`），不排队 |
| R19-D6-01 回退与外部改动 | `04` §4.8.7 与 F5：外部改动未处理时回退与“我来改”同样不可用（`run.rewind` → `E_STATE`），`⌘⇧R`（M2）置灰 |
| R19-D15-01 “知悉”不结束存活期归因 | `04` §4.8.8：选项 2 改为“关闭提醒；进程退出前，它的写入仍记在 Agent 名下”，并补说明：进程全部退出后才恢复正常的外部改动检测 |
| R19-D4-02（`04` L1319）离开暂停后等待 | `04` §4.8.11：要继续运行但无槽位或依赖未满足 → `就绪 · 排队 · 第 n 位` / `就绪 · 依赖 …`，开场队列保留并显示，开 Run 时送出；`12` §12.6.5 `slot` / `dependency` 行同步 |
| 顺带：`mixed` 作者残留 | `04` §4.8.7 采纳一条中“混合路径记 `mixed`”改为 `author:"human"` + `mixedPaths`（ADR-144）；F5“直接重新验证”的“失败不自动返工”改为引用 §4.8.12 |
| R19 其余各项 | 不在 `04`/`12` 中 |
