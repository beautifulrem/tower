本文件关闭 `round-105.md` §4 的 4 条次要条目与 §5 的 12 条观察。行号为修改后的位置。

**收敛规则**（同 ADR-186–232）：只用三种办法关闭条目：
1. 把说法改弱，但保证为真；
2. 删除或推迟不属于 M1 主循环的机制；
3. 在已有的唯一定义处加至多一条守卫、一行或一个字段。

**本轮的取向**：沿用 Pi 自己的做法与已有的恢复出口，不另设开关。
- R105-D5-01 不再自定安装条件，照 Pi 的入口无条件安装同一个分发器。
- R105-D5-02 不订阅、不包装 Pi 的方法（Pi 没有注册事件），只在 Tower 已控制的投递边界读取。
- R105-D6-01、R105-D6-02 沿用 §6.1.6 的 “Run 中崩溃”“settle 中崩溃”“Run 在 drain 中途” 三行与 `10` §10.3.1 “启动恢复”。

新增的只有：
- Host 报告的结论的第三种值与模型选择器的第三种标注 `由扩展处理认证`（只在 Supervisor 内存中，按 Host 保留）；
- Host 内存中 “列出过的扩展 provider” 集合（随 Host 进程结束）；
- `06` §6.2.4 准入的检查 i（可写）；
- `08` §8.10.5 规则 6；
- `12` §12.6.4 磁盘满期间的一行实况、§12.13.3 横幅一行。

不新增状态、暂停原因、事件类型、表、列、命令、决定种类、Needs-You kind、landmark、`wait_reason` 值、锁或常驻进程。

安全不变式全部保留：
- Tower 不会自动把机密交给 Agent 可影响的进程。模型密钥仍只经运行时注入、只在 Host 内存中，Host 环境中仍没有任何模型密钥。
- 扩展注册的 provider 在一次投递之内的窗口里可能收到已注入的导入密钥（如实登记）。扩展本就在密钥的信任边界之内（能经 `ctx.modelRegistry` 读取已注入的密钥），Agent 可影响的进程不因此得到它；后果是用哪份凭据、由谁计费与端点。
- 打包的分组不变，`riskTier=high` 与清单确认之前的 Goal 的模型请求仍不经用户扩展的代码。
- Host 环境不引用 Agent 可写的位置。分发器只读 Host 环境中已有的代理变量；`httpIdleTimeoutMs` 经受保护的设置读取，不进入任何环境。
- 只读启动时，已退出 Host 的即时投递凭据文件改为立即删除，不再推迟到解除。
- 沙箱外的 Tower 进程不在 Agent 可控的 git 元数据上运行 git；Tower 从不自动删除人的工作现场。

安全问题只写到设计层面。

## R105-D5-01（次要）：代理分发器只在有代理变量时安装；选项与空闲超时没有写

取评审的写法。
- **唯一定义** `05` §5.3.6 代理一行（L474）：
  - Host 启动时**总是**（不论 Host 环境中有没有代理变量）在任何模型请求与 MCP 连接之前，安装与 `configureHttpDispatcher` 相同的分发器：`EnvHttpProxyAgent`（没有代理变量时即直连的 agent），`allowH2: false`、`proxyTunnel: true`、连接尝试时限 2 s、`bodyTimeout`/`headersTimeout` 取空闲超时、同一错误监听；以 `setGlobalDispatcher` 安装并调用 `undici.install()`。
  - **空闲超时**取你 Pi 设置中的 `httpIdleTimeoutMs`，经 §5.3.3 的受保护设置读取（`projectTrusted:false` 下只取用户设置；默认 300 000 ms，`disabled` 为不限时）。Host 启动时读一次，之后的改动从下一个 Host 起生效；值无效时与终端中的 `pi` 一样启动失败，按 F4b。
  - **undici 只有一份**：Tower 的代码引用 Pi 所依赖的那一份（v1.2.0 为 8.10.2），不另装；它加载时装上的默认 `Agent`（允许 HTTP/2）由 Tower 的安装在任何请求之前取代。
- **升级复核**：D63（L1449）补选项、空闲超时与 undici 版本；C43（L1505）改为两种情形都断言已安装、选项与 Pi 相同、只有一份 undici，并以 `httpIdleTimeoutMs` 30 s 与 `disabled` 各做一次。
- ADR-232 R104-D5-03 一条加〔ADR-233 更正〕；旧条件登入 `16` §16.1.13 第 105 轮一行（L656）。
- **不取 “空闲超时登记为不读取”**：在终端中关掉空闲超时、使用慢速本地模型的用户在 Tower 中会 300 s 无输出即失败。

## R105-D5-02（次要）：扩展注册的 provider：读取时机、标注、代价一句

**唯一定义** `11` §11.7.1 模型凭据一行（L517）。
- **(a) 读取时机**：
  - Pi 没有 provider 注册的事件可订阅（见上），所以 Host 在每个 Run 的会话创建之后（初次加载时排队的注册此时写入）、第一次请求之前，以及适配器每次调用 `prompt`、`steer`、`followUp`、`inject` 之前（`05` §5.2，Tower 已控制的投递边界）读一次 `getRegisteredProviderIds()`（内存读取）。
  - **列出即不再注入**：某个 provider id 在一个 Host 中被列出过一次，Tower 在该 Host 进程退出之前不再为它注入，扩展随后 `unregisterProvider` 也不恢复。
  - 剩下的窗口如实登记：一次投递之内在事件回调中新注册的覆盖，以及扩展在 `session_start` 中自己发出的请求，可能带已注入的导入密钥，发往扩展配置的端点。它不扩大机密的去向（见文首安全不变式）。
- **(b) 标注**：
  - 结论有第三种 “由扩展处理认证”，模型选择器写 `由扩展处理认证`。
  - Supervisor 按 Host 保留最近一次的结论，Host 退出时丢弃。某个目标的标注取服务它的 Host（正在运行它的，或上一次运行它而仍存活的）的结论，不取各 Host 中最后报告的一次。
  - 还没有这样的结论时，以及设置中不属于某个目标的默认模型，写原有的条件句。
  - `05` §5.3.6 首次运行（L489）、`04` §4.18.1 第 2 步（L1461）同步为 “按服务该目标的 Host 的检查写明”。
- **(c) 代价一句**：以内置 provider 的 id 注册的任何扩展（`registerProvider` 只给 `baseUrl`、`models` 或 `headers` 的也算，`registerNativeProvider` 同样）都使 Tower 不为该 provider 注入导入的密钥；密钥只在 shell 中时它在 Tower 中判为未配置，按 F7。`00` §0.5.1 凭据一行（L112）补半句（观察 7）。
- **测试**：
  - D64（L1450）补依据；C44（L1506）补一组：扩展在 `turn_end` 回调中只给 faux provider 加 `headers`、随后 `unregisterProvider`；
  - G46 (d) 第十组（`14` L134）补标注的断言（打包的两个 Host 分别写 `Tower 用导入的密钥` 与 `由扩展处理认证`、不翻转）与事件回调一组。
- ADR-232 R104-D5-01、R104-D5-02 两条加〔ADR-233 更正〕。
- **不取 “包装运行时的 `registerProvider` 以得到注册时刻”**：那是修改 Pi 的对象，要随 Pi 的每个版本维护；投递边界已由 Tower 控制。

## R105-D6-01（次要）：只读状态启动时的存活 Host、drain 写入失败而 Host 存活、复查的卷集合与推迟的范围

**唯一定义** `06` §6.8 F8（L1199）。
- **(a) 存活 Host 中的 Run**：只读启动时，main 交回的存活 Host 照常接上，Supervisor 让它们中止其中进行中的 Run（`abort`，不写数据库、不 drain）。只读期间因此没有 Run 在运行，“事件缓冲有界” 一句成立。
- **(b) 结果由已有恢复行求出**：
  - 存活 Host 中已中止、而数据库中没有它的 `draining_for` 与 `run.ended` 的 Run——只读启动时中止的，以及 drain 写不进之后 Supervisor 重启、Host 仍存活的（正常启动时同样如此）——按 §6.1.6 “Run 中崩溃”“settle 中崩溃” 两行处理，与 Host 已不存在时相同；
  - 原因取 `app_quit`，`outcome_reason` 写 `disk_full`，因此在解除的集合中，随之按第 5 项继续；
  - `draining_for` 已写进的照 “Run 在 drain 中途” 一行的 Host 存活一支续做。
  - 同步：§6.1.6 “Run 中崩溃” 一行（L148）的 “取哪一个” 加这一例外；`05` §5.5 settle 判定表 “非 draining” 一行（L666）写明这些 Run 不经该表。
- **(c) 推迟的范围**：只推迟会写数据库的中间状态检查。不写数据库的清理照常立即执行：清空不属于存活 Host 的 `tmp/`、`run/`（含已退出 Host 的 `run/<hostId>/` 即时投递凭据文件），终止残留的后台进程（补检查点推迟到解除）。
- **(d) 复查的卷**：`~/.tower` 所在卷与各 Project 的 `<wtRoot>` 所在卷（与 §6.7 自检同一集合；Project 与 `<wtRoot>` 从只读的数据库照常读出），取代 “发生过 `ENOSPC` 的卷”。
  - 复查中求不出剩余空间的卷按不足 2 GB 计，横幅写明该卷（`12` §12.8 L530）。
  - 启动自检中求不出的卷不单独触发只读启动（见 “偏离与未决”）。
  - `16` §16.2.6 磁盘预算一行（L854）同步并登记外接盘的情形。
- **测试**：G35e (q)（`14` L120）补 “`<wtRoot>` 卷不足 2 GB、此前没有 `ENOSPC`，两个 Goal 运行中只杀死 Supervisor” 与 “只读期间卸载外接测试卷” 两组。
- ADR-231 R103-D6-02、ADR-232 R104-D6-01 两条加〔ADR-233 更正〕。

## §5 的观察

1. **F8 并入进行中的 drain**：`06` §6.8 F8 写明 F8 向进行中的 drain 并入 `app_quit` 时，`run.ended` 的 `outcome_reason` 同样写 `disk_full`。
2. **打包时的 Host 预留**：`16` Host 粒度回退规则一行（L879）登记 `h = p95/K` 按满载的 Host 计，未满的 Host 少记至多 (K−1)/K × p95（约 0.1 GB），由内存压力刹车兜底；不改准入记账。
3. **准入闸口**：`06` §6.2.4 补检查 i（L323，可写）：Project 因租约只读时 `waitReason = slot`，卡片注明该仓库正被另一个 Tower 使用；数据库在 F8 的只读状态时不准入、不写数据库，由横幅说明。
4. **多原因一组的卡片**：G35e (q) 的期望写全为 `已暂停 · 磁盘已满 · 另有：硬预算上限`；`12` §12.6.5 叠加原因的示例（L448、L452）与 `04` §4.6.7（L641、L668）的 `预算硬上限` 统一为原因表的 `硬预算上限`。
5. **被压下的覆盖层**：`08` §8.10.5 补规则 6（L696）：被压下的整页或浮层在侧栏顶部以一行入口保留，人点开时显示、不自动补弹；规则 2、4、5 不算被压下。`12` §12.8（L529）只引用，并把 “自动诊断” 改为 “诊断视图”。
6. **只读期间的实况行**：`12` §12.6.4 补一行（L395）：`验证已取消（磁盘已满）· 释放空间后以同一 pin 重跑`、`准备已中止（磁盘已满）`；G35e (q) 断言两者。
7. **`00` §0.5.1 凭据一行**：随 R105-D5-02 (c) 补半句。
8. **卡片条件**：`04` §4.18.3 应用退出一行（L1517）只引用 `12` §12.6.5；`12` §12.6.5（L433）的 `自动恢复` 条件改为 “按第 5 项解除之后没有剩余原因”，含只另有同样解除、没有 `stalled` 条目的 `engine_crash`。
9. **登记**：`03` §3.2.1（L97）`app_quit` 的来源补磁盘满；`10` §10.3.1（L386，唯一定义）、`02` §2.4（L200）、`16` §16.1.1（L26）的 `preparingSince` 注明 F8 的中止保留它。
10. **`models.json` 的 `!` 命令**：`11` §11.7.1 写明每次请求同步执行、至多阻塞 Host 的事件循环 10 s，打包时同一 Host 的其他 Goal 随之推迟，与终端中相同。
11. **模型选择器与读屏表**：`11` §11.7.1 写明模型选择器的位置（设置 › 引擎的默认模型，`04` §4.15；为目标切换模型，`04` §4.18.3 模型服务不可用一行）；`12` §12.13.3 读屏表补横幅一行（L778）。
12. **G46 (d) 第九组 CA 一组**：写明指向 `<wtRoot>` 之下的一次模型请求以 TLS 校验错误失败、按 `06` §6.8 F6 处理（`stalled{engine_error}`）。

## 偏离与未决

- **R105-D5-01**：空闲超时在 Host 启动时读一次，Pi 交互模式中途改设置立即生效，Tower 从下一个 Host 起生效（如实写明）。
- **R105-D5-02**：
  - 一次投递之内在事件回调中新注册的覆盖，到下一个投递边界之前仍可能用已注入的导入密钥（如实登记；扩展在密钥的信任边界之内）。
  - “列出即不再注入” 是按 Host 的单向规则：扩展注销之后，该 Host 中这个 provider 只用你的 Pi 配置，到 Host 退出为止。
  - 设置中的默认模型不属于某个 Host，只写条件句。
- **R105-D6-01，求不出剩余空间的卷**：
  - 按指示，复查（解除）时按不足 2 GB 计，横幅写明该卷。
  - **偏离**：启动自检中求不出的卷**不单独触发**只读启动（取评审的建议）。原因是自检对每次启动都适用，若也按不足计，一个未挂载外接盘上的 Project 会使每次启动都只读，而只读期间不能移除该 Project（会写数据库的命令返回 `E_STATE`），没有出路。
  - 代价（如实登记于 `16` §16.2.6 与横幅）：只读期间外接盘未挂载时，只读要到挂载或重启 Tower 才解除。重启 Tower 能解除这一点使两处规则不完全对称；如要严格对称，须另给只读期间移除 Project 的出路，本轮不做。
- **R105-D6-01，正常启动时的同一规则**：drain 写不进而 Supervisor 重启时空间已释放（正常启动），存活 Host 中已中止、数据库中没有 `draining_for` 与 `run.ended` 的 Run 同样按 “Run 中崩溃” 一行取 `app_quit`/`disk_full`。这一判别按可观察的状态，不按来源；卫星丢失的 abort 与其暂停写入之间崩溃这一双重故障也会落进这条规则（卫星丢失一行在启动时仍会触发），不另判别。
- **未决**：无。
