# 第 18 轮评审回应 · `04` 与 `12`

一行一条：条目 → 处理位置与方式。依据 `15` ADR-144 与 `02`、`03` 的主干修订（归因窗口、`OpeningRef`、非 `pause` 目的的 drain、令牌识别）。

| 条目 | 处理 |
|---|---|
| R18-D4-01（`04` L942–946，`12` L407） | `04` §4.8.12 重写：窗口起点 = 最近一次通过的验证与你最近一次把工作交给 Agent（交还“交给 Agent 继续”、`retry_after_human_change`、`request_changes`）中较晚者；“你的改动” = `author:"human"` 或带 `mixedPaths` 的检查点（不再写 `mixed` 作者）；写明交回 Agent 后自动返工即恢复，“人代为提交”不算交回。失败卡片首行按窗口措辞，混合检查点标 `混合`；`12` §12.6.5 同步 |
| R18-D4-02 硬上限下的验证失败 | `04` §4.8.12：Agent 路径的返工因硬上限不能开始 → `已暂停 · 硬预算上限`，返工证据进入开场队列 |
| R18-D8-01 #1 / ADR-144 开场队列 | `04` 新增 §4.8.13（线框 + 规则）：目标卡片第 5 行、暂停卡片底部、目标页“接下来”显示 `下次运行开场：N 条`；展开逐条写来源（`⚙ <种类>` / `你 · 时间`），`撤回` → `goal.openings.withdraw{goalId, openingId}`（按 ADR-144 补记改为稳定 id、幂等），记 `HumanDecision{withdraw_opening}`，Tower 条目同样可撤回；§4.8.11 引用它；`12` §12.12 组件表新增 `OpeningQueue`（不着色、来源标签同 `Tower 注入`、读屏） |
| R18-D8-01 #2（`04` L880） | §4.8.8 `再次终止` 改为“发信号前再次确认它带有本次运行的标记”（令牌，ADR-142）；补卡片打开期间每 30 s 重扫、进程全部退出时以“已过时”自动关闭（ADR-144） |
| R18-D6-01 / ADR-144 非 `pause` 的 drain | `04` F12：接管、回退、依赖回退在等待当前步骤结束时遇到暂停原因 → 原操作不执行，进入这些原因加 `human`，卡片 `‖ 接管未执行：<原因>；处理后请重新执行`（回退同理，依赖回退离开暂停时重新判定）；`12` §12.6.5 新增对应文案行 |
| R18-D15-01 | 13 项均不在 `04`/`12` 中 |
