## 1. 总评

ADR-170 按第 44 轮的建议关闭了两条问题：
- 判定时机在 `16` L510 有了唯一定义：`add` 时与每次播种前对每个条目重新判定；普通条目命中时写入 `secretBy = content`，不播种并通知；
- `06`、`07`、`10`、`11`、`02` 都改为引用，原先“复制前按内容扫描”与唯一定义方向相反的矛盾已经消除；
- `approve` 不再隐式插入，`unmark_secret` 对 `secretBy = null` 返回 `E_STATE`，DDL 加了 CHECK；
- G46(ac) 的前提改对了，并新增 (ad)(ae)；
- 第 43–44 轮的工时增量已登记，算术全部成立：WBS 121.57，M1 38 周，增人备选 33 周。

但沿着同一条线复查“谁写 `secretBy` / `unmarked`、哪些地方播种”，还有两处与 M1 头号安全不变式直接相关的缺口：
1. **唯一定义列举的播种点漏了人工编辑检出。** `10` L874 规定人工编辑检出照常播种普通本地文件，但 `16` L510 的判定时机与 `seeded` 的作用范围都只列卫星、验证槽位与检验检出。于是在人工编辑检出中，Tower 可能按过期的分类复制一个已写入机密的文件，而界面同时写着“此副本不含本地机密文件”。另外，“判定的内容就是复制的内容”这条不变式没有写明。
2. **`mark_secret` 的效果与谓词不一致。** `06` L877 说标记后“此后不自动播种”，但它只写 `secret_by='user'`。对一个已取消标记的条目，`unmarked` 仍非空，按 `16` 的谓词 `isSecret` 仍为假，文件继续播种。

两条都评为**重要**。另有两条次要：
- 文件不可读时“按命中处理”是否持久改写分类、通知文案是否如实，没有定义；
- `14` L394 残留旧的最长线数值 28.86。

### D11 安全与自主度

**R45-D11-01｜重要**（播种前判定的唯一定义漏列人工编辑检出；“判定字节 = 复制字节”未写明）

- **问题**：
  1. **漏列的播种点**：
     - `16` L510 是唯一定义：判定时机为“每次播种前（卫星创建或重建、验证槽位、检验检出）”；`seeded` 的作用范围也只写“播种到卫星、验证槽位与默认检验检出”。`06` L234 的列举相同。
     - 但 `10` §10.8.4 L874 规定人工编辑检出中“Project 已批准的普通本地文件照常播种”。这一处没有引用判定时机，`16` 的两处列举也都不包含它。
     - 按唯一定义实现时，打开人工编辑检出用的是持久化的分类。若一个已批准的普通文件在上次播种之后被写入机密，而期间没有经过其他播种点，它会被原样复制进人工编辑检出。
     - 同一界面（`04` L604、`10` L863）此时告诉人“此副本不含本地机密文件”，这句陈述不再成立。
  2. **判定与复制的对象**：
     - 判定时机写成“播种前按名字与当前内容重新判定”，然后“从用户检出复制”。两步分别读取文件时，两次读取之间写入的内容不经判定就被复制。
     - 唯一定义没有写明复制的必须是被判定的那一份内容（以及 `unmarked.contentHash`、指纹 `extra` 中的哈希也取自这一份）。
- **为什么重要**：
  - 人工编辑检出是 Agent 写的代码会运行的地方。`10` L861-862 / `04` L599-601 已登记：编辑器打开该目录时会加载其中的工作区任务、lint / 测试扩展的配置、`.envrc` 等，Tower 无法沙箱化；`10` L873 还提供一键“在验证器沙箱中运行准备步骤”，运行的是 Agent 写的脚本。
  - 所以漏列会放进与 R44-D11-01 同一类后果：Tower 自动把机密放进 Agent 可影响代码运行的目录，违反 `11` §11.7.0 的 M1 不变式（G46 的标题）；同时界面给出与事实相反的陈述。
  - 第 2 点是同一不变式的竞态缺口。窗口很窄、写入者是人自己，但修复只需一句话。
  - 两点都只需要文字修订。危险的一侧仍然是“唯一定义”本身的列举，所以评为重要。
- **文档位置**：`16` L510；`06` L234；`10` L367、L814、L861-874；`04` L599-604；`07` L482；`11` L339；`15` ADR-170 第 1 项；`14` G46(x)(ad)。
- **期望的回答形态**：
  - **第 1 点**：在 `16` L510 的判定时机与 `seeded` 作用范围中加入“人工编辑检出”。建议改为“任何把本地文件复制出用户检出的地方”，再列举四处，以免下次漏列。`06` L234、`10` L874 引用。
  - **第 2 点**：在同一处写明“判定与复制针对同一次读取的内容：先读入、判定、再写出这份内容；内容哈希也取自这一份”。
  - **用例**：G46(ad) 的“触发播种”加上“打开人工编辑检出”一组，期望该检出中没有该文件，打开前的提示仍然成立。

### D4 领域模型与生命周期

**R45-D4-01｜重要**（`mark_secret` 不清除 `unmarked`，“此后不自动播种”按谓词不成立；可覆盖 `name`）

- **问题**：
  1. **对已取消标记的条目无效**：
     - `06` L877：`mark_secret` “把该本地文件标记为机密（`secret_by='user'`），此后不自动播种到验证槽位、检验检出或卫星”。`02` L111 把 `mark_secret` 列为 `secretBy` 的写入者；`unmarked` 的写入者只有 `unmark_secret`（写入）与自动恢复（清除）（`02` L113、`16` L510）。
     - 谓词是 `isSecret(f) = f.secretBy ≠ null ∧ f.unmarked = null`。对一个已取消标记的条目（例如 G46(l) 中的 `config/payments.local.json`），人改变主意点“标记为机密”，`secret_by` 变成 `user`，但 `unmarked` 仍非空，`isSecret` 仍为假、`seeded` 仍为真，文件继续播种到卫星。
     - 已取消标记的条目在界面上属于“普通”一栏，按 `04` L1289 的线框，这类行提供 `[标记为机密]`。
     - 自动恢复只在内容哈希变化且再次命中模式时发生。人按自己的判断标记（`user` 依据，内容不一定命中模式），或内容没有变化时，这次标记不会生效。
  2. **覆盖 `name`**：
     - `mark_secret` 没有前置守卫。对 `secretBy = name` 的条目执行它，会把依据改写为 `user`，此后 `unmark_secret` 就被允许了。
     - 这绕开了“按文件名判定的不可取消（保守）”（ADR-165 补记，`16` L510）。两步都是本机的人工操作，危害有限，但领域规则出现了一条没有定义的路径。
- **为什么重要**：
  - 人显式撤回对某个文件的暴露授权，是用户能直接操作的安全控制。按唯一定义实现，这个控制会静默失效：Tower 继续把一个被人标记为机密的文件自动复制到 Agent 可读的卫星，违反 M1 不变式。
  - `06` 的效果列给出了与谓词相反的结论，属于与 R44-D11-01 同一结构的矛盾：引用方写了安全的结果，唯一定义推出危险的结果。
- **文档位置**：`06` L877；`02` L111、L113；`16` L510、L884；`04` L1289、L1297；`14` G46(l)(p)。
- **期望的回答形态**：
  - 在 `16` L510 写明 `mark_secret` 的效果，`06` L877、`02` L113 引用：
    - 写入 `secretBy = 'user'`，**同时清除 `unmarked`**（`unmarked` 的写入者因此增加 `mark_secret`）；
    - 对已是 `isSecret` 的条目为幂等的无操作（或返回 `E_STATE`），**不覆盖** `name`（也不把 `content` 改写成 `user`，以保留判定依据）。
  - **用例**：G46 加一组：(l) 中已取消标记的 `config/payments.local.json` 被人重新“标记为机密”并触发播种，期望 `isSecret` 为真、不播种；对 `.env.local` 执行 `mark_secret`，期望依据仍为 `name`、`unmark_secret` 仍返回 `E_STATE`。

**R45-D4-02｜次要**（“文件不可读按命中处理”的持久化、事件与文案未定义）

- **问题**：
  - `16` L510 写“文件不可读时按命中处理（失败关闭）”，紧接在“写入 `secretBy = content`、发事件、通知‘现在含有机密形态的内容’”之后。字面上，不可读也会持久改写分类，并发出命中的事件与文案。
  - 而 `04` L1299 只写“文件不可读时同样不复制并通知”，没有说改写分类。
  - 没有定义的有三件事：
    - 清单中的文件在用户检出里**不存在**（开发者临时删除或重新生成 `.env.local`）是否算“不可读”；
    - 是否持久写入 `secretBy = content`，以及之后文件恢复可读时如何回到普通（若写入了，只能由人以 `unmark_secret` 恢复，而那需要确认“将被复制到 Agent 可读的工作目录”并绑定内容哈希）；
    - 通知与事件是否沿用“现在含有机密形态的内容”。
  - 已取消标记的条目不可读时是否适用同一规则，也没有写。
  - 另外，新事件的 `producer`（`06` L391，NOT NULL）没有给出取值。
- **为什么重要**：
  - 安全一侧已经成立：不可读就不复制。缺的是领域与诚实两侧：
    - 一次暂时的读取失败可能永久改变分类；
    - 设置页“机密”列会显示 `■ 内容`；
    - 通知把 Tower 没有观测到的内容当作事实陈述，与 `07` 的 Fact / Claim 纪律不符。
  - 若选择不持久写入，又需要说明每次播种是否重复通知。
- **文档位置**：`16` L284、L510；`04` L1299；`06` L234、L391、L407；`10` L1241；`11` L339。
- **期望的回答形态**：
  - 在 `16` L510 一处写明，建议：
    - 不可读或不存在时，这次不复制；**不改写** `secretBy`；
    - 发一条独立的 L1 通知，如“`<路径>` 无法读取（或不存在），本次未复制”，按条目去重，恢复可读后自动消失；
    - 只有内容真正命中时才写 `content` 并发 `project.local_file_secret_detected`。
  - 若坚持持久写入，则改用独立的依据或事件名，并给出如实的文案与恢复路径。
  - 同时给出该事件的 `producer`（例如由执行播种的服务记录，或统一记为 `sm`）。

## 5. 结论

- **是否所有维度为 100：否。**
  - D1–D3、D5、D6、D8–D10、D12、D13、D16 为 100，这十二个维度上没有可追问的实质问题。
  - D4 98、D7 99、D11 95、D14 99、D15 98。
- **是否还有可追问的问题：有。** 新增共 **4** 条：阻断 0、**重要 2**、次要 2。
  - **第 44 轮核验**：已解决 2，部分 0，未解决 0。
  - **其他核对**：
    - lint 全部通过（exit 0）；
    - Pi v1.2.0 源码复核成立，Pi 依赖面不变；
    - 排期算术全部成立：WBS 121.57；各线 26.03 / 26.35 / 27.41 / 28.38 / 13.40；余量 0.81 / 0.12 / 0.83 / 1.08 / 0.62；38 周；增人 33 周。`14` 与 `15` 一致，只有 L394 一处旧值。
  - **不扣分的观察**：
    - **网页端的 `[添加]` 串联**：`add` 在网页端可用、`approve` 不可用。建议一句话写明：网页端的建议 `[添加]` 只发 `add`，结果不是 `isSecret` 时该行显示 `需在本机批准`，不尝试发 `approve`。远程能力属于 M2（`serve`），不扣分。
    - **`inspect_with_secrets` 与新近命中**：按字面“这次不播种”，人选择带上机密时，新近命中的文件这次也不带入（人在第 0 步看到的机密清单中没有它）。这是保守的一侧，与人同意的范围一致；若希望一致，可在 `10` §10.8.3 第 0 步之前先做判定，使开关的说明包含它。
    - **未批准条目的通知文案**：未批准的普通条目命中时，通知中的“不再播种”并不准确（它从未播种）。可在修 R45-D4-02 时顺手按 `approved` 区分文案。
- **设计是否完成：否。**
  - ADR-170 干净地关闭了第 44 轮的两条问题。判定时机与守卫写定后，“谁写 `secretBy` / `unmarked`、哪些地方播种”第一次可以逐项检查。
  - 正是这种逐项检查暴露了两处遗漏：一个播种点、一个写入者。两处都触及 M1 头号安全不变式，修复只需文字，但必须在冻结设计前写定。
- **下一轮建议按以下顺序修订**：
  1. **R45-D11-01**：`16` L510 的判定时机与 `seeded` 作用范围加入人工编辑检出（建议写成“任何复制出用户检出的地方”）；写明“判定的内容即复制的内容”；`06` / `10` 引用；G46(ad) 加一组。
  2. **R45-D4-01**：`mark_secret` 清除 `unmarked`，对已是机密的条目不覆盖依据；`06` L877、`02` L113 同步；G46 加一组。
  3. **R45-D4-02**：不可读 / 不存在只本次不复制，不改写分类，使用如实的文案；补事件 `producer`。
  4. **R45-D14-01**：`14` L394 改为 28.88。

  **工时与排期**：上述修订估计合计约 0.03 人周。
