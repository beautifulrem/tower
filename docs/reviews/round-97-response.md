# 第 97 轮评审回应

决策：
- ADR-225（`15` 末尾，L4395 起）；
- ADR-224、ADR-223、ADR-201、ADR-167 标题加 “Amended by ADR-225”；
- ADR-133 第 97 轮补记（`15` L1463）。

本文件关闭 `round-97.md` §4 的 5 条次要条目与 §5 的 11 条观察。行号为修改后的位置。

**收敛规则**（同 ADR-186–224）：只用三种办法关闭条目：
1. 把说法改弱，但保证为真；
2. 删除或推迟不属于 M1 主循环的机制；
3. 在已有的唯一定义处加至多一条守卫、一行或一个字段。

**本轮的取向**：五条都在已有的唯一定义处各加一句关闭，引用处只改为引用：
- 交还与带回的写回集合（`10` §10.8.4 第 5 步）另排除一类路径；
- 文件工具与 bash 的路径分类先判第 3 条硬底线（`11` §11.3.3）；
- 准入的重算时机（`06` §6.2.4）、重启清理的终止范围（`06` §6.1.6）与探测的规格（`06` §6.7）各加一句；
- 超时证据的标签（`07` §7.2.2）；
- 复述改为与唯一定义一致。

不新增状态、事件类型、表、列、命令、决定种类、Needs-You kind、landmark、`wait_reason` 值或常驻进程。新增的只有探测结果在自检日志中的一个缓存键。

安全不变式全部保留：
- Tower 不会自动把机密交给 Agent 可影响的进程；
- 回退后权限与默认位置相同；
- Agent 的三种沙箱与安装器安装阶段都拒绝创建硬链接与钥匙串查找；
- 探测未能确认拒绝时不以路径规则不完整的 S2 运行；
- Pi 的输出文件对 Agent 读写都拒绝，并且最迟随 Host 退出删除。

取更严的一边：
- 写回集合多排除一类路径；人工编辑检出中有这类改动时改名保留，不删除；
- bash 中路径能求出的硬底线读写在 S0 下也直接 forbid（此前为 ask）；
- 三要素在加载了任何沙箱外工具时计私有数据为真（Tower 无法判定它们是否写文件系统）；
- 探测失败的结果不跨 Tower 启动沿用。

本轮没有放宽。安全问题只写到设计层面。

## R97-D11-01（次要）：卫星之内放宽的理由漏算两条路径

**(a) 人工编辑交还与检验带回**：取评审的结构性写法。

**唯一定义**：`10` §10.8.4 第 5 步，即写回集合（L972）。名字形如凭据、且在该 Goal 的 base 中未被跟踪的路径，与含机密的本地文件同样排除。
- **名字**：按 `11` §11.3.1 密钥路径表的无锚定模式，以 `16` §16.1.12 的名字规则比较。
- **做法**：
  - 人在人工编辑检出（带回为检验目录）中新建或改过的这类文件不进入 T1，不写回卫星；
  - 路径保持 T0（带回为 T_pin）中的版本；
  - 在交还（或带回）结果中与第 7 步跳过的路径一同列出。
- **留在原处**：其中有这类路径与 T0（T_pin）不同时，第 8 步删除前的比较按“不同”处理。该目录按 §10.2 改名保留，不删除。这样人放进去的凭据不随目录删除而丢失。
- **引用**：§10.8.3 带回的排除列举（L923）引用这一条。

结果：Tower 自己的路径（不播种 + 不写回）不再把人的真实凭据放进写允许范围，ADR-165 的前提对人一侧成为真。评审担心的遍历成本不存在，写回集合本来就逐路径已知。

**(b) 沙箱外工具**：取“如实写出”，并按评审的结构性写法计入三要素。
- `11` §11.3.1 作用范围 (ii)（L167）：理由改为“Tower 自己的路径不把真实凭据放进这里”。这里名字形如凭据的文件由 Agent 与它运行的程序写入，沙箱外工具（用户扩展与 MCP 服务器）以你的权限写进来的除外。
- `11` §11.3.4 路径检查一条（L228）登记残余：
  - 这类工具写进写允许范围的文件不受 S2 与路径检查约束，可能含真实凭据；
  - Agent 运行的程序之后读取它们不经分类，只有文件工具与 bash 的直接读取出卡。
- `11` §11.8 私有数据（L544）限定为：本 Goal 加载了沙箱外工具时除外，私有数据为真。
  - 不按“能写文件系统”细分：Tower 无法判定这一点，按能写计，取更严的一边。
- `00` §0.5.1 沙箱外工具一行（L102）补一句。

**测试**：G46 (bl)（`14` L134）。
- **设置**：人在人工编辑检出中新建 base 未跟踪、不在本地文件清单中也不被忽略的 `certs/dev.key`，并改动一个普通文件，然后交还；另一组在检验目录中做同样的改动后带回。
- **期望**：
  - 普通文件照常写回；
  - `certs/dev.key` 不在卫星、`human_edit` 检查点与 pin 中，结果中列出；
  - 该目录改名保留。

## R97-D11-02（次要）：bash 读 Pi 的全文文件出读取凭据卡

**唯一定义**：`11` §11.3.3 第 3 条的“分类的先后”（L219）。文件工具与 bash 中路径能求出的读写，先判第 3 条硬底线，再查密钥路径表。
- **范围**：bash 一侧是 §11.3.2 按参数路径分类的命令与重定向；第 3 条硬底线含各 Host 的临时目录。
- **命中时**：带 `hardFloor`，forbid、不出审批卡、不可授权，不再追加 `secrets.access`。
- **返回文字**：
  - 写明“该路径属于 Tower 不向 Agent 开放的位置，批准也不会改变”；
  - 路径在 Host 临时目录中时，另加必然拒绝返回文字中的重定向一句（需要全文时把输出重定向到 `$TMPDIR` 下的文件）；
  - S2 与 S0 相同。
- **代价**（取更严的一边）：此前第 3 条对 bash 只“由 S2 保证”。S0 下 bash 读写主检出、其他 Goal 的卫星等位置是按分类询问的，现在也直接 forbid。

**引用同步**：
- §11.3.1 的“先后”（L164）改为引用这一条；
- `05` §5.3.6 临时目录一行（L473）写明先于密钥路径表判定，且 `Full output: <path>` 提示对 Agent 不可用；
- §11.7.1 残余同步；
- `00` §0.5.1（L105）补“工具结果末尾的 `Full output: <路径>` 提示不可用，S0 下同样如此，Agent 按它读取时被直接拒绝、不出审批卡”。

**测试**：G46 (bj) 的 ADR-224 一组改为以 `read` 与 bash 的 `cat` 各读一次全文路径。期望两者都 forbid、不出读取凭据卡，返回文字给出重定向的做法。

**没有采用**评审的第二种写法（在 `tool_result` 钩子中改写 `Full output:` 一行）：它改动 Pi 交回的文字，只对 bash 的结果有效，而分类的先后对一切按路径的访问都成立。

## R97-D6-01（次要）：启动闸门的唤醒；只重启 Supervisor 时的范围

**(1) 唤醒**：`06` §6.2.4 准入的重算时机（L298）加两项，即检查 h 的两个解除事件：
- 本次启动的硬链接探测有结果；
- 某 Goal 的重启清理完成终止的一轮。

这是一行事件触发的列举，检查 h 本身不变。SP6a A3 补期望：探测有结果后无需其他事件即开 Run。

**(2) 只重启 Supervisor**：
- **终止范围**：`06` §6.1.6 后台进程一行（L145，重启后终止范围的唯一定义）改为“**Host 已不存在**的未结束 Run 的令牌，以及未解决 `bg_process_survived` 的令牌”。
  - 只重启 Supervisor 时，main 交回的存活 Host 重新接上（§6.1.3），其中进行中的 Run 不在此列：不终止，不显示 `清理中`，检查 h 对它们所属的 Goal 照常满足。
  - §6.1.10 崩溃恢复（L198）与检查 h 的注释（L322）同步。
- **探测的缓存**：`06` §6.7（L1179）。
  - 结果连同键（本机、开机会话、Supervisor 所用沙箱运行时的版本）记入自检日志。
  - 只重启 Supervisor 时沿用本次启动的结果，不重新探测。存活 Host 中的沙箱档位与之对应：Host 中的沙箱在 Host 启动时按这一结果施加。
  - Tower 再次启动时，键相同且上次结果为“已拒绝”的直接沿用；键不同、或上次未能确认拒绝时重新探测。所以“失败不重试，下次启动重新探测”保持不变。
  - 只重启 Supervisor 而键已不同时同样重新探测，新结果只用于此后启动的活动；存活 Host 中进行中的 Run 保持它启动时的档位直到结束。这一情形实际上只在 Tower 运行中被就地更新时出现。
  - `13` §13.11.1（L325）同步。

**测试**：G44 (c)（`14` L132）补一组。在另一个 Goal 的 Run 运行中、其 Host 存活时杀死 Supervisor。期望：
- 该 Run 照常进行，工具进程与后台服务未被终止；
- 不显示 `清理中`；
- 本次不重新探测。

## R97-D7-01（次要）：超时与中止命令的证据标签

**唯一定义**：`07` §7.2.2 `fullOutput` 注释（L87–L89）。超时、中止与无退出码时，证据只是 Pi 截断后的尾部（≤ 50 KB / 2000 行）加状态行。错误文本带 `Full output:` 一行（即曾被截断）时：

## §5 观察

## 偏离与未决

- **R97-D11-01 (a) 取结构性写法，并比评审的写法多一步**：评审只要求排除并列出。本轮另规定，人工编辑检出（检验目录）中有这类改动时改名保留、不删除。否则人在检出中生成的凭据（如开发证书私钥）会随目录删除而丢失，“留在检出中”也就不为真。
  - 代价：人删除了 Agent 写出的同类文件（如 `id_test`）时，这一删除不写回卫星，检出也会被保留，需要人自行清理。
- **R97-D11-01 (b) 只如实写出，没有封闭**：沙箱外工具写进卫星的凭据仍可被 Agent 运行的程序读到。封闭它需要在加载沙箱外工具时把写允许范围之内的凭据形文件编入 S2，这会重新带来第 96 轮去掉的测试夹具失败。本轮取三要素计为真、在 `11` §11.3.4 登记残余，与 T7 的分档同口径。
  - 三要素按“加载了任何沙箱外工具”计，不区分是否写文件系统：Tower 无法判定这一点，按能写计。所以加载了用户扩展或 MCP 服务器的 Goal，在其余两项为真时都会出现警告，比评审的写法更常出现。
- **R97-D11-02 在 S0 下更严**：bash 中路径能求出的硬底线读写（如 `cat` 主检出中的文件）在 S0 下由询问改为 forbid，与文件工具一致。这是先后规则对 bash 生效的直接结果。如实写在唯一定义中。
- **R97-D6-01 的探测缓存**：任务方向是“按开机会话与本机缓存、只在 Supervisor 的沙箱运行时变化时重测”。本轮另加一条限定：上次“未能确认拒绝”的结果不跨 Tower 启动沿用。否则一次偶发超时会让本机在整个开机会话中都不使用 S2，与第 96 轮“下次启动重新探测”的承诺相反。只重启 Supervisor 时，不论结果如何都沿用。
- **R97-D7-01 的标签以“曾被截断”为条件**：没有被截断的超时命令，错误文本就是它的全部输出，标为截断不为真。所以标签的条件是错误文本中有 `Full output:` 一行，不是 `outcome` 本身。
- **观察 9 没有为 Host 另设 jiti 缓存位置**：等 SP2 的数据。jiti 默认缓存的位置本地未逐行核实（jiti 未安装），正文写“通常”。
- **排期**：顺延按 ADR-224 写定的规则执行，没有用观察的 0 计数去抵消增量。顺延之后桌面线与设计线余量 1.10，其余 1.12。增人备选已在 33 周的边界上：再多约 0.03 人周（合计超过 130.02）就是 34 周。
