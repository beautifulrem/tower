## Pi v1.2.0 核实（`packages/coding-agent/src/`；`git show v1.2.0:<path>`）

| 问题 | 核实结果 | 出处 |
|---|---|---|
| 用户终端中的 `pi` 用哪个 agentDir | `getAgentDir()` 读**本进程**的 `process.env[ENV_AGENT_DIR]`，有值时 `expandTildePath`，否则 `join(homedir(), CONFIG_DIR_NAME, "agent")` | `config.ts:605-611` |
| 变量名 | `ENV_AGENT_DIR = \`${APP_NAME.toUpperCase()}_CODING_AGENT_DIR\``，即 `PI_CODING_AGENT_DIR` | `config.ts:585` |
| `~` 的展开 | `expandTildePath` 就是 `normalizePath` | `config.ts:588-590` |
| 显式路径是否绕过 `getAgentDir()` | 是。`AuthStorage.create(authPath = join(getAgentDir(), "auth.json"))` 只在未传入时求默认值 | `core/auth-storage.ts:348-351` |
| `ModelRuntime.create` 的默认值 | `DefaultAuthStorage.create(options.authPath)`；`modelsPath` 缺省为 `join(getAgentDir(), "models.json")` | `core/model-runtime.ts:217-220` |

结论：只要 Tower 显式传入 `authPath` 与 `modelsPath`，Host 进程自己的环境就不影响凭据路径。所以只需 Tower 用与 Pi 相同的规则求出用户 agentDir（观察 2）。

### R81-D7-01（次要）：已解决（取法与派工方向有偏离，见下）

**唯一定义**：`10` L742（§10.7.1 第 1 步 “移出清单的路径的归属”），改写如下。

- **判定**：取本 Goal 最近一个记录的 L 含该路径的检查点或 pin S。同时满足以下三条时，按人的改动记录：
  - 本次 L 不含该路径；
  - 它出现在本次快照的树中；
  - S 之后本 Goal 的检查点与 pin 的树都没有收入过它。

  这就是 “移出清单之后首次进入本 Goal 的快照”。它与移出时文件是否仍被 git 忽略、之后何时解除忽略无关，覆盖评审的 (b)。
- **记法**：
  - 检查点：记入它自己的 `mixedPaths`。
  - pin：覆盖评审的 (a)。先以同一棵树写一个 `safety` 非回合检查点，并记入它的 `mixedPaths`，再生成 pin。settle 的 pin 已由 `agent_bg_done` 检查点处理。所以归因窗口（`03` §3.2.1 只数检查点）、评审作者推导（`16` L212）与 `Tower-Human-Edit` 的既有规则都不必改。
  - 收入之后它不再特殊。
- **不加字段**：判定只读已有的 trailer 与快照树。
- **残余**（如实写明，同时关闭观察 1）：本 Goal 还没有记录 L 的检查点或 pin 时，没有记录可比。窗口从卫星创建起，含检出完成后在 `ready` 中排队的时间，到第一个检查点或 pin 为止。

**引用处与 “先移出” 的补充**：
- `10` L184：同步为检查点或 pin，并补 “让它在该 Goal 中不再被 git 忽略（只经 `info/exclude` 忽略的，在下一次刷新后生效）”。
- `10` L776：`Checkpoint.mixedPaths` 注释。
- `06` L587：DDL 注释。
- `06` L891：`project.local_files.remove`。
- `04` L508：`混合` 的定义，同时关闭观察 6 的一项。
- `04` L658：“先移出，并让它不再被 git 忽略”。
- `04` L1313：同上，并改称 “可能是你的文件”。

**测试**：G46 (bh)(6) 第八组改写（`14` L134），见 R81-D14-01。

**偏离说明**：派工方向是以 `project.local_files.remove` 的事件或决定（带 seq）为依据。逐处核对后：
- 这条命令不是 HumanDecision，也不产生事件：`06` L891 写明 “不是 HumanDecision”；`16` §16.1.14 的 `project` 前缀下只有 `trust_changed` 与两种机密判定事件。
- 清单行在移除时删除。

所以 “已有的移除记录” 并不存在。新增事件类型违反收敛规则；而每个快照上已记录的 L 就是本 Goal 视角下的移除记录（之前在 L 中、现在不在）。因此改用 trailer 回看，派工方向要的性质都成立：
- 检查点与 pin 都适用；
- 与移出时是否被忽略无关；
- 进入快照后即不再特殊。

代价是上面那个窗口仍是已知限制。事件方案能关闭这个窗口，但要新增事件类型。

## 偏离与未决

- **R81-D7-01 的依据**：派工方向假定 `project.local_files.remove` 有带 seq 的事件或决定。核对后两者都没有，所以改用已有的 trailer 回看，理由见该条。
  - 代价：“本 Goal 还没有记录 L 的快照” 这一窗口仍是已知限制。
  - 要关闭它，需要新增 `project.local_files.removed` 事件，或在卫星创建时记录播种所用的清单（新字段）。本轮都没有做。
- **pin 的落点**：取 “pin 之前写一个 `safety` 检查点”，没有给 pin 另加归属记录。
  - 好处：窗口、作者推导与 `Tower-Human-Edit` 都不改。
  - 代价：`safety` 的用途从 “恢复前的记录” 扩展到这一种。landmark 集合不变。
- **R81-D8-02 的取法**：取 “加一条命令”，没有取 “删除按钮”。M1 中 `00` §0.5.1 的能力差异行与 G37 都依赖它，删除后人只能在不受沙箱保护的终端里自行运行 Agent 写的准备脚本，会弱化 “不自动在人的权限下执行 Agent 代码” 这条保护。
- **R81-D13-01 中 L254 的处理**：L254 是目录守卫，不改为 “打开期间”，而是写明目录存在的两种来源及各自的出口。
- **观察 2 的时机**：取值在首次运行时读取，读取时机与 PATH 相同。用户之后修改该变量时，不会自动重新读取；设置页显示所用路径，供人核对。没有新增重新检测的命令。
- **G46 第八组的前提**：“检查 base” 只对远端引用 base 执行获取（`06` `goal.base.check`），所以这一组限定 base 为远端引用。本地 base 下影子 `info/exclude` 的刷新时机，本轮没有另行定义。
- **未实现的 lint 建议**：两条，理由见 lint 一节与 `round-81-lint.md`。
