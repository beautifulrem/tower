## R99-D5-01（次要）：Bedrock 只以文件变量传入时判为未配置；非机密的配套变量被删除；Pi 的读取位置引错

**唯一定义**：`11` §11.7.1 “云 SDK 凭据链”行（L518）。
- **传入什么**：Host 环境只有两类变量，都不进入 bash：
  - 指向文件的变量；
  - **非机密的配套变量**，原样传入：`AWS_REGION`、`AWS_DEFAULT_REGION`、`GOOGLE_CLOUD_PROJECT`/`GCLOUD_PROJECT`、`GOOGLE_CLOUD_LOCATION`。
- **AWS 的 profile**：凡以凭据文件提供 AWS 凭据，Host 环境中总带 `AWS_PROFILE`：
  - 你设了的，取你的值；
  - 没设的（例如只有 `AWS_SHARED_CREDENTIALS_FILE`），取 SDK 的默认值 `default`；
  - Tower 为原始密钥写入的投递文件，取写入时所用的 profile 名。

  这样只有文件变量的配置也能被 Pi 识别（`amazon-bedrock.ts:54-79`）。
- **区域**：环境变量与该 profile 的配置中都没有区域时，Tower 补 `AWS_REGION=us-east-1`，与 Pi 在没有 profile 时的回落相同（见上方 Pi 核实）。
- 写明 Pi 的判定路径：`models.ts:757` → 各 provider 的 `resolve` → `:865-866`。

**同步**：

## R99-D6-01（次要）：运行中 Host 退出或挂死之后那一轮的范围、结束条件、接管闸门与准入唤醒

**唯一定义**：`06` §6.1.6 “Agent 后台进程”一行（L145）。
- **(a) 范围**：Tower 运行中的一轮只取**该 Host 承载的 Run**：
  - 该 Host 中的 Run，打包模式下即该 Host 上各 Goal 的 Run；
  - 这些 Goal 有未解决 `bg_process_survived` 的 Run。

  其他 Host 的 Goal 不在这一轮中，不显示 `清理中`。冷启动的范围不变。
- **(b) 结束条件**：第二类令牌（各 Goal 最近一个因 Host 退出或挂死而以 `crashed` 结束的 Run）在**带它 `runId` 的 `agent_bg_done` 检查点**写入后移出范围。
  - 为此，每一轮完成时对范围内每个 Goal 都补这一检查点，什么也没终止时同样补。它不受 `10` §10.7.1 “树相同即不建” 的限制（L735 去重例外加这一项）。
  - 第一轮之后仍存活的进程，已按第三类（`bg_process_survived`）处理。
  - 已归档、没有卫星的 Goal 不在第二类中。
  - 什么也没终止时，不注入 `tower.processes_terminated`。
  - 用已有的检查点作持久化的标记，不新增列。所以不再开 Run 的 Goal（崩溃 → 接管 → 交还 → 验收）在之后的冷启动中不再出现 `清理中`。
- **(c) 接管闸门**：`清理中` 的实况行与 `goal.take_over` 的 `E_BUSY` 对运行中的一轮同样适用。同步：
  - `06` §6.1.3 Engine Host 一行（L64），改为引用；
  - `06` `goal.take_over` 一行（L907）：不论源状态；
  - `12` §12.6.4 实况行（L390）；
  - `16` `E_BUSY` 一行（L293）。
- **(d) 准入唤醒**：`06` §6.2.4（L298）的重算时机写 “某 Goal 的重启清理或 Engine Host 退出或挂死之后的一轮完成”，检查 h 的解除事件写 “探测与终止的一轮”。

观察 2（挂死 Host 的后代树中不带令牌的成员）在同一行写明，见 §5 观察。

**测试**：G35c (x) 补一组（`14` L118）。另有 Goal B 在另一个 Host 中运行，期望：
- B 不显示 `清理中`、不被挡住；
- A 在一轮完成之前显示 `清理中`、“我来改” 返回 `E_BUSY`；
- 完成时补带 `runId` 的 `agent_bg_done`，准入随即重算；
- A 经接管、交还、验收之后，冷启动不再对它做一轮。

## R99-D11-01（次要）：按工具名授权撤掉逐次 ask 的时刻没有告知；ADR-226 的安全论证一句不实；原则的限制未登记

按任务指示，取 “不提供” 一支，不只加告知。

**唯一定义**：`11` §11.3.4 “按工具名授权的条件”（L226）。
- **条件成立**：本 Goal 的不可信内容与对外通信都为真时，`tool.external` 不提供 “本 Goal 内同类”。
  - 加载了 MCP 服务器的 Goal 恒如此（ADR-032）；私有数据对沙箱外工具至少是 “未知”。
  - 审批卡只有 “仅这一次”，该工具的每次调用都 ask。
  - 已有的这类授权（运行时 `Grant` 与合同 `autonomy.grants` 中的 `tool.external` 项）在这一条件下不编入 `policy.json`。条件中途成立时（例如另一类授权使对外通信变为真），于下一次编入时失效。
- **条件不成立**：照常提供。选项上方显示 §11.8 的沙箱外工具风险说明，并加半句 `授权后该工具的调用不再逐次询问`；合同编辑器对带 `tool.external` 授权的合同同样加这半句。
- **理由**：
  - 私有数据一项对沙箱外工具无法判定，按本节其他 “无法判定” 的取向取更严的一边；
  - 合同批准处仍不因此警告（ADR-226 的取舍不变），这一面由逐次 ask 承担；
  - 所以三要素的另外两项都成立时，不让逐次 ask 被撤掉。

## R99-D13-01（次要）：人新建的被忽略文件随副本删除而不列出；凭据形文件的交还途径无效

**(a) 唯一定义**：`10` §10.8.4 第 5 步（L972）。

- **人新建的被忽略文件**：H 中被 git 忽略、而卫星工作目录与主检出中都没有同一路径的条目，没有原件。

## §5 观察

1. **心跳看门狗的起点**（`08` §8.6.1 L363–L364、§8.6.3 L391）：
   - 定义 `hostExpected`：本 Supervisor 进程 spawn 了该 Host，或重新接上了 main 交回的存活 Host；
   - `lastHeartbeatAt` 以 `hostExpected` 置位的时刻为起点，持久化的心跳 Fact 只作诊断；
   - 补 “挂死” 的唯一定义：进程仍在，且自该起点或最后一次心跳起超过 30 s 没有心跳。Supervisor 的退避不计入；睡眠期间冻结，唤醒后另有 60 s 宽限（`06` §6.1.5）。`06` §6.1.3 的 SIGKILL 以它为前提；
   - G35c (x) 补只杀 Supervisor 一组：Host 不被判为挂死、不被强杀。
2. **挂死 Host 的后代树**（`06` L145）：不带令牌的成员（MCP 服务器、扩展的子进程、文件辅助进程，`13` §13.8.3）照常终止，不列入任何 Goal 的 `tower.processes_terminated`；范围内每个 Goal 各补一次 `agent_bg_done`（随 R99-D6-01）。
3. **云 SDK 原始凭据没有刷新途径**（`11` L518）：如实登记为已知限制。
   - 原始值只在首次运行时导入，带有效期的值过期后，用它的 Host 的请求以 provider 错误失败（F7 不识别这一类）；
   - M1 没有重新导入的入口，有效期短的凭据请改用 profile。
4. **远程 `quick_ratify` 不显示风险说明**（`11` L558）：写明随 M2 的手机卡片设计决定（`serve` 属 M2）。
5. **合同之外的三要素重算**（`11` §11.8 L562、`06` §6.7 L1180）：
   - 启动自检由 S2 转为 S0 时重算；已批准或运行中的 Goal 由此变为同时为真时标红并显示 `■ 致命三要素`，不暂停、不另生成 Needs-You；S0 下另有 ADR-022 的授权卡；
   - 清单确认不是重算时机：两项按 MCP 服务器是否配置判定，不按是否已确认。

## 偏离与未决

- **R99-D11-01 取 “不提供”，而不是评审建议的 “只加告知”**：
  - 评审建议在 “本 Goal 内同类” 上方显示风险说明（中性、不阻止）。本轮按任务指示更严：不可信内容与对外通信都为真时根本不提供按工具名的授权，已有的这类授权也不编入，只在条件不成立时显示说明；
  - 代价：加载了 MCP 服务器的 Goal 中，MCP 工具每次调用都要人批准，不能再按工具名放行。需要大量调用同一 MCP 工具的工作流会更吵。这是对 ADR-186 “可以授予按工具名的 Goal 级授权” 的有意收窄，与 ADR-226 在合同批准处取宽的取舍互补：那里不警告，这里不撤闸；
  - 限制同时登记在 `01` §1.4 #9 与 `11` §11.3.4 残余、T16。`01` #9 是调研引出的修订表，不是残余登记表，所以两处都写。
- **R99-D13-01 (b) 取 “如实写明途径”，没有采用对话框逐个 “按普通文件交还”**：
  - 后者要给 `goal.hand_back` 新增一个参数（`humanCheckout.params` 的形状随之改变，`02`、`16` 与 lint (o) 都要动）；
  - 后者还要为名字形如凭据、base 未跟踪的文件新开一条由人确认后进入卫星的路径，需要单独论证它与 “Tower 不会自动把机密交给 Agent 可影响的进程” 的关系；
  - 本轮只写明真实可行的两条途径（让 Agent 生成，或在仓库中提交、供之后新建的目标使用）。若自用中凭据形夹具常见，可在 M2 再评估逐个交还。
- **R99-D13-01 (a) 只对人工编辑检出保留副本，检验目录只列出**：检验目录用于运行，被忽略的新文件多是构建产物，逐次保留会让每次检验都留下目录。带回结果如实写明它们随目录删除。
- **R99-D6-01 的结束条件以 “带 `runId` 的 `agent_bg_done` 检查点” 持久化**，而不是评审建议的 “一轮什么也没终止时不补检查点”：
  - 不新增列时，需要一个跨冷启动可见的 “第一轮已完成” 标记；
  - 每一轮完成时都补这一检查点，代价是什么也没终止时多一个只带 landmark、引用同一棵树的检查点；
  - “不注入” 照评审所写。
- **R99-D5-01 的区域补齐是评审没有点出的连带后果**：设 `AWS_PROFILE` 会关掉 Pi 的 `us-east-1` 回落（`bedrock-converse-stream.ts:193-205`），所以多写了 “都没有区域时补 `us-east-1`” 半句，使行为与 Pi 自身在没有 profile 时相同。
- **排期**：R99-D5-01 的落点按 WBS 行归 W16（首次运行与凭据导入，设计线），评审写的是 W10/W6；合计 +0.04 在余量之内，M1 维持 39 周，增人备选仍为 34 周。最长线由桌面变为设计（28.95）。
- **未决**：无。
