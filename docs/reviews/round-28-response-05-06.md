# 第 28 轮评审回应：`05`、`06`

以 ADR-154 为准。每条一行：条目 → 修订位置。

- R28-D11-01（配置不经命令行与环境）→ `06` §6.2 GitService 行：`-c` 改为 `0600` 临时配置文件（`[include]` 用户全局配置 + 白名单键）与 `GIT_CONFIG_GLOBAL=<路径>`，argv/env 只出现路径，命令结束即删除；userinfo 只在文件中、不进诊断日志与卡片。`05` C29 增加 (b)：LFS 获取期间 `ps` 与进程环境不含 URL 或键值，结束后文件已删除。
- R28-D13-01（远端选择）→ 同一行：`branch.<base>.remote` → `remote.lfsdefault` → 唯一远端 → `origin`。
- 排除对象在所有检出中一致 → 同一行：卫星、验证槽位、人工编辑检出、检验检出都保持指针；验证证据附 `lfs_excluded`，失败卡片提示排除数。
- 被拒绝的配置值 → 同一行：卡片写“LFS 配置被拒绝：<键>（不支持的协议）”。
- 措辞 → 同一行：“输入只来自用户主检出的配置与 base 提交，Agent 在卫星中的写入不参与”；“不读镜像中的任何配置（`HEAD` 指向占位引用）”。
- ADR-154 补记 → `06` GitService 行：base 为 `refs/remotes/<r>/<b>` 时远端取 `<r>`；被白名单拒绝的值记 Fact `lfs_config_ignored{keys}`（提示与卡片列出）；在用户主检出上下文中求出 `credential.*`、`http.<url>.*`、`url.<base>.insteadOf` 的有效值写入同一 0600 临时文件，使按目录的 `includeIf` 生效。
