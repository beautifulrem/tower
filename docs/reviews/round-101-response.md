## R101-D11-01（次要）：确认框的 git 求值不在唯一加固清单中

`10` §10.1.2 表加一行 “已脱离副本的求值”（L53），只用于 `goal.delete_kept` 的确认框：
- **文件差异与被忽略的条目**：只对人工编辑检出与检验目录求。影子上下文，`GIT_WORK_TREE=<该目录>`，临时索引从检查点的树起 `add -A`，与 §10.8.4 第 5 步同一取法。目录自带的 `.git` 排除，不写影子 ref，不在其上运行 git。
- **H/.git 中人做的提交数**：不运行 git。由 §10.1.3 “读取 gitdir” 的同一解析器在隔离 worker 中只读求出，不读 `config`、`include`、`alternates`。从 `refs/heads/tower-human/<goalId>` 沿父链只数 H/.git 自己对象库中的提交，遇到不在其中的对象即停：Tower 写出的检查点提交在影子中，所以数到的就是人做的提交。
- **卫星的 `.kept-*` 与 `_gitdirs/*.kept-*`**：由 Agent 写过，不求任何 git 信息，只列大小与 `其中的一切随之删除`。

同步：§10.1.3 “读取 gitdir” 一行注明同一解析器的这一用途；`10` §10.2 与 `06` §6.4.3 `goal.delete_kept` 一行（L911）改为引用。

## R101-D13-01（次要）：已脱离的副本比影子与记录活得久

- **(a) H/.git 的对象**：取登记，不在脱离时重新打包。
  - `10` §10.2 “人的工作现场不自动删除”（L259）写明：影子删除之后（归档或放弃 180 天后；隐私清除时立即），H 中的 git 命令因缺少对象而失败，文件完整；人做的提交对象仍在 H/.git 中，但不能完整读出。
  - Goal 页与存储面板对这类 H 注明 `git 历史已不可用（文件完整）`。
  - 告诉人：如需保留历史，可在影子删除前自行执行 `git repack -a -d` 并删去 alternates，磁盘代价写明；Tower 不替人做。
  - §10.3.2 检查点保留的 180 天一条同步。
- **(b) 确认框没有比较对象**：影子已删除或 Goal 已清除时，确认框写 `无法与检查点比较：其中的一切随之删除`，并列出文件数与大小。提交数只读 H/.git 自己的对象，照常求出，读不出时写 `无法读取`。
- **(c) 清除之后的列出**：
  - **列出的来源**：存储面板按每个已知 Project 的 `<wtRoot>`（默认与回退位置）扫描按名字属于各 Goal 的目录，不依赖 Goal 的其他记录。已清除的 Goal 标为 `（已清除）`，`goal.delete_kept` 对它照常可用（路径按名字属于它）。
  - **清除一个 Project 与清除全部之后**：这些目录不再列出（再次添加同一项目且位置不变时按名字重新列出）。
  - **`09` §9.12.4（L560）**：清除结果给出完整路径。清除一个 Goal 时仍写 “不需要时在设置的存储面板中删除”，注明确认框只有文件级信息；清除 Project 与清除全部时改写为 “存储面板之后不再列出它们，不需要时请自行删除”，确认框在执行之前同样列出这些路径。
  - `04` §4.15 同步。

## R101-D5-01（次要）：Bedrock 区域第 ③ 步与 Pi 不同；`ANTHROPIC_AUTH_TOKEN` 的头部类型

**唯一定义**：`11` §11.7.1 “云 SDK 凭据链” 行（L518）与 “模型凭据” 行（L517）。

- **(a) 区域**：
  - **第 ③ 步**：只在 Host 环境中带 `AWS_PROFILE`（凡以凭据文件提供）时补 `us-east-1`。
  - **只有 `AWS_BEARER_TOKEN_BEDROCK` 时**：它按 API Key 运行时注入（`:184-189`、`model-runtime.ts:692`），不补区域，由 Pi 按模型端点取区域，与终端相同。这一支照任务方向 “不设 `AWS_PROFILE` 与区域” 做到了。
  - **删去的断言**：“这与终端中的 Pi 相同” 中不成立的部分。
  - **如实登记两处差别**：
    - 只有 profile 而没有区域时，Tower 补 `us-east-1`（原有）；
    - 只有原始密钥、没有区域时，终端中的 Pi 取模型端点的区域（`:201`；`eu.*` 为 `eu-central-1`，测试 `:113-120`）。Tower 只能经投递文件与 `AWS_PROFILE` 提供原始密钥：Pi 的判定只认环境或存储凭据中的 `AWS_PROFILE`，或环境中的原始密钥对（`amazon-bedrock.ts:65-73`），而原始密钥从不进入 Host 环境。环境中的 `AWS_PROFILE` 又使 Pi 不固定端点（`:167`、`:1239-1249`），所以请求发往 `us-east-1`，这类模型在 Tower 中失败。用这类模型请设区域。
  - **首次运行**：确认卡片写明 `只有原始密钥、没有区域：Tower 中的请求发往 us-east-1；使用 eu.* 等模型请设区域`（`05` §5.3.6 首次运行检测同步）。
- **(b) 以头部发送的令牌**：登记为已知限制。
  - Pi 只从进程环境读取 `ANTHROPIC_AUTH_TOKEN`（`anthropic.ts:34-40`、`auth/context.ts:23-28`）。令牌不能放进 Host 环境，运行时注入只按 API Key 发送（`anthropic.ts:30-31`、`model-runtime.ts:621-629`），所以 M1 不提供这一类。
  - 首次运行时不导入；模型选择器标 “该凭据只在你的终端中可用，Tower 中不可用”，并提示改用 `ANTHROPIC_API_KEY` 或 `pi /login`。
  - Anthropic 工作负载身份联合（`:49-69`）同样不提供。
  - ADR-049 类型表下补〔ADR-229 补记〕。
- **同步**：`05` §5.3.6 首次运行检测与 D62（Pi 位置补 `:162-173, 184-205, 1225-1250`、测试 `:113-120`、`anthropic.ts:28-47`）；`16` 云 SDK 凭据一行（L724）。
- **测试**：G46 (d) 补第七组。
  - 只有原始密钥、没有区域、选 `eu.*`：期望 Host 中 `AWS_PROFILE=tower-<hostId>` 与 `AWS_REGION=us-east-1`，确认卡片写明差别，请求以 provider 错误失败；
  - bearer 令牌带与不带区域：期望环境中没有 `AWS_PROFILE` 与令牌，不带区域时不补，请求发往 `eu-central-1` 并成功；
  - 只有 `ANTHROPIC_AUTH_TOKEN`：期望不导入、标注，任何进程环境中都没有它。

## 偏离与未决

- **R101-D10-01 (a) 没有采用 severity 2 的收件箱条目**，改为复用设置入口的 `◇`（任务方向允许的 “复用 M1 中已有的呈现面”）：
  - 收件箱条目需要新的 Needs-You kind、去重键与出口分类，这正是 ADR-186 以来避免新增的一类；
  - 设置入口的 `◇` 是 M1 中不属于任何 Goal 的通知的现成呈现面（ADR-174/175），条件成立期间一直显示，比一次性的 L2 条目更不容易被看漏；
  - 代价：它不计入 Dock 角标，人不打开 Tower 时看不到。磁盘满时 F8 另有 L3 横幅。
- **R101-D10-01 (b) 不改变磁盘压力的自动回收顺序**：Tower 的非永久证据与依赖目录仍先被回收，因为回收必须立即发生，不能等人。通知把人的工作现场列在第一行，并如实写出压力主要来自它们时回收解决不了。
- **R101-D5-01 (a) 没有照任务方向对 “只有原始密钥” 一支不设 `AWS_PROFILE` 与区域**：
  - Pi 的判定只认环境或存储凭据中的 `AWS_PROFILE`，或环境中的原始密钥对（`amazon-bedrock.ts:65-73`）。存储凭据的 `env` 由用户的 `auth.json` 给出，请求级 `env` 在会话路径上不传（`model-runtime.ts:671-675`），Tower 没有不经进程环境给出 profile 的途径。
  - 不设 `AWS_PROFILE` 就只能把原始密钥放进 Host 环境，这违反 “原始密钥从不进入 Host 环境”。
  - 所以按评审的第一种写法如实登记差别。照方向做到的只有 bearer 令牌一支，它不设 `AWS_PROFILE`、不补区域。
- **R101-D5-01 (b) 没有照任务方向把 `ANTHROPIC_AUTH_TOKEN` 按 Pi 读取的环境变量传入**：
  - Pi 只从 `process.env` 读它（`auth/context.ts:23-28`），传入就是把令牌放进 Host 进程环境；
  - 同一用户的进程（包括 Agent 的沙箱进程）能读到非 Apple 二进制的环境（`11` §11.6.2、T33）；
  - 这违反 “Tower 不会自动把机密交给 Agent 可影响的进程” 与 ADR-158 “模型凭据不进入任何环境”。
  - 所以登记为已知限制，首次运行如实标注。
- **R101-D13-01 (a) 取登记，不在脱离时重新打包 H/.git**：对每个已脱离的 H 自动 `repack` 会让每次交还多写一份被跟踪内容的打包对象，而多数副本最终会被删除。磁盘代价写明，需要时由人自行执行。
- **R101-D13-01 (c) 没有在清除时留下清单文件**：结果与确认框已列出完整路径，清单文件会是 Tower 在 “清除” 之后仍保留的又一份记录。
- **R101-D13-02 不新增锁**：以 “正在本进程中执行” 判定 `E_BUSY`，与 “写回进行中” 同一写法。崩溃之后留下的半物化目录按 “中断的接管留下的目录” 处理，可以删除。
- **lint (d) 的严格匹配同时修正了第 100 轮一组**：它原先被自身的 “删除” 豁免，实际上不起作用。改为严格匹配后，第 93 轮增量句中的 2 处历史文字被报出，处理方式是把 `14` §14.3.4 的逐轮增量段整段视为历史。
- **观察 7 不改比较对象**：只写明偏保守。
- **未决**：无。
  - 人的工作现场仍是唯一没有上限、只由人清理的磁盘消耗者。它已有 M1 呈现面、磁盘压力与磁盘满的指向、周度计量与复审线，以及 M2 决定点。
  - 只有原始密钥、没有区域的 `eu.*` 一类 Bedrock 用户与 `ANTHROPIC_AUTH_TOKEN` 用户在 Tower 中不可用，已登记并在首次运行时如实提示。
