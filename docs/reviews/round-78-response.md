## 条目

### R78-D13-01（次要）：已解决

按指示推广为一条按路径的规则，以 `10` L184（§10.1.2 “本地文件按路径排除”）为唯一定义，`16` `ProjectLocalFile` 行引用它。

**规则**：Tower 的每一次快照 `add` 都对该 Project 本地文件清单中的**全部**路径加 `:(exclude)`。
- 不论条目是否机密、是否批准、复制时的判定如何。
- 与 `.gitignore`、`info/exclude`、`core.excludesFile` 的状态无关。
- 快照包括：检查点、pin 与 seal、验收与 seal 时的全新临时索引、§10.5 的基线快照、检验带回、交还的 T1 与人工编辑的差异。
- 指纹与外部写入判定同样不含这些路径。
- 被排除的路径不记入 `excludedPaths`，不是检测器。

**唯一的例外**：路径在该 Goal 的 base 树中被跟踪时，它对这个 Goal 是仓库文件。
- Tower 不复制它，也不排除它，Agent 对它的改动照常进入快照。
- 这样 Agent 对仓库文件的修改不会被悄悄丢弃。
- 含机密的本地文件在交还时仍一律排除（ADR-167），不受这一例外影响。

**复制前**（`16` `ProjectLocalFile` 行）：`check-ignore` 复核改为 “路径在该 Goal 的 base 树中是否被跟踪”。
- 被跟踪的这次不复制，按 “不可读或不存在” 一条处理。
- 通知文案为 “`<路径>` 在这个目标的代码中已被跟踪，本次未复制”。
- 验证记录与 `envHash` 中记 `not_copied`（`07` L486、L744）。
- 评审情形 4（槽位内容偏离 pin）因此不再出现。

**`add`**：
- 保留 `check-ignore` 守卫（`E_STATE`）。它现在只让人自己的 `git status` 与提交不收录个人文件，不再决定快照的成员。
- 另拒绝在 `Project.defaultBaseRef` 当前提交中被跟踪的路径，提示 “在仓库中被跟踪，不是本地文件”。
- 提示文案去掉 “影子” 与节号（观察 7）。

**人有意提交这样的文件时**：先 `project.local_files.remove`。此后它是普通的未跟踪文件，按忽略规则处理。写明的位置：
- `06` L891 `remove` 一行；
- `04` §4.15.1；
- `04` §4.6.7 交还对话框：列出 `已排除：<路径>（本地文件）`。

**覆盖范围**：评审列出的四种情形与卫星重建时的播种都由这一条覆盖。“进入检查点后再 `mark_secret`” 的问题也随之消失，因为清单中的路径从不进入检查点。ADR-205 登记的残余加更正注、删除。

### R78-D8-01（次要）：已解决

取 “`stalled{engine_error}`” 一种写法，沿用已登记的 kind 与子类型，不新增 `auth_expired` 子类型。

**唯一定义**：`08` L210（§8.4 一行）。
- 去重键为 `st:{goalId}:auth`，按 Goal 去重：预检失败时还没有 Run。
- 三种检测键与之后的再次失败并入同一条目。
- 级别同 `engine_error`（L2）；不参与 provider 根因合并。
- Run 因此以 `error` 结束时进入的暂停是 `provider_unavailable`，与它成对。

**定类**：`08` §8.8 一行。
- “重试”（`goal.resume`）→ `actionable`。
- 探测成功、暂停自动解除 → `actionable`。Tower 不代管认证，恢复通常是人已在终端登录；无法区分其他原因时统一这样计。
- “放弃” → `informative`。

**同步**：
- `16` L195：`provider_unavailable` 一格写出 F6、F7 两种条目；
- `12` L438：理由改为 “进入这一暂停时总有一条 `stalled{engine_error}` 条目”；
- `06` L1183：F7 的用户可见一列；
- `05` C39 (c)(d)：原来写 “不生成 F6 的 `stalled{engine_error}`”，改为 “条目即 F7 的 `stalled{engine_error}`，不进入 F6 的合并”。
