**ADR-200 的主干成立**：
- **drain 恢复行**（`06` L146 唯一规则）：
  - `pause`：`run.ended` 已提交而状态转移未提交时，照 `reasons` 进入 `paused`，成立。
  - `take_over`：物化 H 中途中断后进入 `paused(human)`。`paused(*)` 是 `goal.take_over` 的源状态（`10` L912），再按 “我来改” 得到 ADR-199 的 `E_STATE` 与 “移到一边”，不再 `E_BUSY`。成立。
  - `dependency`：按 `reasons` 是否为空进入 `paused(reasons ∪ {human})` 或 `ready{dependency}`，成立。
  - “Run 已结束时不再写 `run.ended`”，以及 S0 授权已在 `run_end` 时失效（L148 末句），都不产生重复事件。
  - L147、L148 都要求 `draining_for` 为空，与本行互斥。
  - 但本行与 L139 “卫星丢失” 都能对同一个 Goal 触发，见 R73-D6-01。
- **会话删除覆盖年度归档包**（`06` L941；`09` L562；`06` L142 续做行）：
  - 写新包后原子替换；续做只按事件中的 `sessionIds` 定位；包中已没有该会话时不再改动，因此重放幂等。
  - 崩溃在替换之前时旧包仍完整，续做重写；崩溃在替换之后时续做发现会话已不在包中。两种情况都成立。
  - G46 的期望（“包中其余会话逐字节不变，再次续做不再改动该包”）与规则一致。
  - 归档包有三个写者（180 天移入、“清除一个 Goal”、“彻底忘记”），它们之间的串行化见 §5 观察 3。
- **检验临时目录**（`10` L871–L873）：第 7 步停止服务时一律删除，“保留目录，稍后决定” 时同样删除。保留下来的检验目录之后只能带回、丢弃或自行移走（`10` L253），不会重新起服务，因此不再需要临时目录。清除清单不必列出它。成立。

  - 前缀 `G-0145.kept-` 含点号，不会与 `G-01450` 混淆。
  - 高水位丢失、编号被复用时，旧 Goal 的 `.kept-` 目录不会被列到新 Goal 名下。成立。

    - 没有对应的 `HumanDecision.kind`，`06` §6.4.3 也没有对应命令（`project.set_trust` 作用于整个 Project，禁止远程，L943）。
  - **所放进的后果类别**：实现者若自行补上 “是 = 下一个 Run 传 `--approve`”，又没有把同意绑定到所列文件的内容，那么 Agent 在人同意之后、下一个 Run 之前改动的扩展代码，会在宿主中以用户权限、沙箱之外运行。这正是 `11` L563 末句与 T4/T16 防范的后果。`11` §11.8.2（L574、L578）对用户扩展已有 “人确认的是哪些代码（哈希）” 的不变式，项目侧这一问没有对应规则。
- **为什么是次要**：保守的实现（“否” 或不提供 “是”）不越界，正文也没有授权不加绑定的加载。但这是沙箱外执行的入口，正文给出了一个无法照做的选项，实现者自行补全时可能补错。
- **文档位置**：`11` L563、L574、L578、T4/T16（L659）；`05` L479；`06` L943；`08` §8.4、§8.8；`16` L144、L193。
- **期望的回答形态**：在 `11` L563（唯一定义）改一句，二选一：
  - **绑定内容**：“是” 记 `HumanDecision`（已有种类或新增一个），载荷为所列文件的路径与内容哈希。下一个 Run 启动时，只有当前内容与载荷逐一相同时才视为信任，并走 §11.8.2 的静态清单确认；否则重新询问。同时登记 kind 与出口；

- **是否还有可追问的问题：有。** 新增共 **7** 条：阻断 0、重要 0、**次要 7**。
  - **D6**：R73-D6-01、R73-D6-02；**D8**：R73-D8-01；**D11**：R73-D11-01、R73-D11-02、R73-D11-03；**D15**：R73-D15-01。
  - **第 72 轮核验**：2 条全部解决；§5 的观察全部落地。
  - **其他核对**：
    - lint 全部通过（exit 0；ADR 200，section_refs 6141，(v) 96 条命令，(e) 186 对，(D) 210 个短语，(z′) 35 处，(T) 9 种，(H) 77 个提示键，(J) 134 对，(C) 19 行并覆盖 §14.8，(M) 1 个，(B) 1 条，(O) 31 行）。

    - 排期结论成立：WBS 122.90；余量 0.12 / 0.26 / 0.37 / 0.84 / 0.20；依赖链 19.91；增人 128.81、T 23.78、33 周；M1 38 周（2027-07-30）。
  - **不扣分的观察**：
    1. **回退（M2）中途终止后的卫星**：ADR-200 让 drain 恢复行覆盖 “回退恢复检查点的中途”，结果为 `paused(human)`。`restoreCheckpoint` 第 2–3 步就地改写卫星（`10` L826–L828），中途终止后卫星是混合的树。重启后监视重建时的决定性检查会把 Tower 自己写了一半的路径判为来源不明的写入，叠加 `external_change`；此后重做回退会因守卫返回 `E_STATE`，与 G35e(m) 回退组 “由人重做回退” 的期望不同。外部改动卡片也会把 Tower 自己的写入说成来源不明。回退在 M1 没有入口（`04` L686、`14` L190），所以只影响 M2。建议 M2 实现回退时在 drain 恢复行写明：`target = rewind` 且 Run 已结束时，先以第 0 步的 `safety` 检查点 `restorePaths` 还原卫星（作为 Tower 的写回窗口）再进入 `paused(human)`；同时把 G35e(f)(m) 的回退组标为 M2。
    2. **整理后的检验目录**：`inspect.bring_back` 在清除 `human_checkout` 的事务之后才删除检验目录（`06` L913，`10` L901）。在两者之间终止时，目录留下，按 “已打开的检验” 处理（`10` L253），关闭时与 T_pin 比较，会把已经带回的改动再列为 “被修改”。T_pin 的记录位置没有写明（自然的落点是 `inspect.opened` 事件）。重新带回会因卫星树已不等于 T_pin 被拒，丢弃即删除，不丢数据。可在 `10` §10.8.3 写明 “带回事务提交后若检验目录仍在，直接删除”。
    3. **年度归档包的写者**：180 天移入、“清除一个 Goal” 与 “彻底忘记” 都会重写 `sessions-<年>.tar.zst`。若两次重写并发，后写者可能把先写者删掉的会话写回。实现者自然会以一把锁串行化，建议在 `06` §6.6.4 写半句。
    4. **“Trace 打开时按需解压” 的位置**（`06` L1118）：没有写解压到哪里。解压到 `~/.tower/tmp/`（启动时清空）或只在内存中时，与清除规则相容；解压到其他持久位置则不在 `09` §9.12.4 的清单中。建议写明位置。
    5. **归档清理的崩溃**（`10` L442）：最终 bundle、删除卫星、删除分支三步与 `archived` 转移的先后没有写明，§6.1.6 也没有对应行。删除前已有 `safety` 检查点与 bundle，分支删除以 CAS 守卫，不丢数据。另外，`integrated` 宽限期内卫星丢失时，情形 E 的叠加态列表（`10` L1231）不含 `integrated`。可各补半句。
    6. **文案中的例子**：`04` L587 以 “自动 rebase” 举例说明检验期间工作目录可能离开 pin。自动 rebase 属于 M2，且检验期间暂停（`10` L893）；`10` L895 的例子是 “有进程写了卫星”。建议同步。
    7. **历史文字**：`14` L395 依赖链口径句逐轮列出的增量只列到第 69 轮（第 70–72 轮都是 0），属历史记录，结论 19.91 正确。
    8. **清除后的审计地标**：开启 “保留审计地标” 时，地标在归档 180 天后删除（`10` L717）；清除结果却说 “Tower 未改动你的仓库……需要时请自行删除”（`09` L554）。已清除的 Goal 是否仍按计划删除地标，没有写明。两种做法都不伤数据，建议写明。
    9. **`app_quit` 的自动解除**：`06` L146 写 “`app_quit`/`engine_crash` 在启动时自动解除”，没有带上 `resumeOnLaunch` 的条件（`06` L101 第 5 项带了）。只在 `reasons` 中没有其他原因、且该设置关闭时有差别，建议引用第 5 项。
- **设计是否完成：ADR-200 的主干已收敛，第 72 轮的两条都在唯一定义处关闭。** 本轮没有阻断或重要问题。七条次要问题都是全范围扫描中发现的老问题，不是 ADR-200 的回归，可归为三类：
