# 第 32 轮评审回应：07 / 08 / 09

依据 ADR-158。

| 决策 | 处理 | 位置 |
|---|---|---|
| ADR-158（机密注入） | “带机密的标准”改为默认**文件注入**：机密写入 Tower 数据目录下的私有 `0600` 文件，以 `<NAME>_FILE` 传路径，标准结束（含超时、取消）即删除。<br>• 只有声明 `secretsVia:"env"` 时才以普通环境变量注入，并在合同编辑器与结果中标“机密以环境变量注入：运行期间同一用户的其他进程可能读到”（`11` T33b）。<br>• 脱敏规则：精确匹配集合含注入的机密值，与注入方式无关。<br>• 残余风险：补上 `env` 注入时被同用户观察的残余。<br>• `envHash` 计入 `secretsVia`，排除 `_FILE` 路径。<br>• `criterion_check` 增加 `secretsVia` 字段 | `07` §7.4.3、§7.4.4 |
| ADR-158（进程身份） | settle 第 3 步：macOS 上本 Run 的进程 = 进程树（`exec` 记录的直接子进程，以 `proc_listchildpids` 递归）∪ 令牌，两者都参与终止。<br>• 平台二进制只能靠进程树识别。<br>• 环境读取为空与读取失败都视为“无法确认”。<br>• 已登记窗口改为“脱离进程树且读不到含令牌环境的进程”：它们不被终止，也不进入 `bg_process_survived`，其后的写入按来源不明处理（`paused(external_change)`），不记为 Agent 或人的改动 | `07` §7.4.1 |

`08`、`09` 无涉及。lint `--checks rstuvwxyzck`：退出码 0。工时：0.05 人周（文件注入与删除、并集识别的规格对齐；实现量计在 `05`/`06`/`11`）。
