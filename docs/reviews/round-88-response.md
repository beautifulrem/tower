## R88-D11-01：并发 Host 之间共用的空目录

**决定**：取评审的第一种做法——**每个 Host 进程一个空目录**。

**唯一定义**：仍在 `11` §11.3.4 “stdio MCP 服务器的空工作目录与相对路径” (a)（L222）。
- 路径 `~/.tower/mcp-cwd/<hostId>/`，由 Tower 拥有。
- 创建：Supervisor 在 `host.spawn` 时、Host 进程启动之前建为空目录（已存在时先删除，删除不跟随符号链接），并把路径交给该 Host。所以该 Host 启动任何 MCP 服务器之前，目录已经存在且为空。
- 删除：该 Host 进程退出（含崩溃）后由 Supervisor 删除；Supervisor 启动恢复时删除不属于存活 Host 的残留目录。Host 是 main 的子进程，Supervisor 重启时可能仍在运行（`06` §6.1.1），所以只删除不属于存活 Host 的目录。
- 从不在 Host 之间共享，也从不在其他 Host 启动时被删除或重建。所以：
  - 别的 Goal 开 Run 不影响本 Host 中正在运行的服务器；
  - 删除与重建之间的启动失败窗口不再存在。
- 各 Host 的这一目录都在第 3 条硬底线（写）之内，三种沙箱都拒绝读写。
- 界限改写为：留在其中的东西只影响同一 Host 进程中之后启动的服务器（交接与恢复时的新会话；打包模式下含同一 Host 的其他 Goal），不越过该 Host 进程的生命周期。

**同步**：

- `06` §6.6.1 目录布局（L1060）、§6.6.4 清理表新增一行（L1133）；
- `11` §11.3.3 第 3 条（L212）、§11.3.4 路径检查 (1)（L221）、§11.8.2（L608）、T4（L681）、T16（L693）；

## R88-D11-02：相对路径的硬 forbid 波及非路径参数

**决定**：取 “缩小规则”。

**唯一定义**：`11` §11.3.4 (b)（L222）。
- 相对路径以 `roots`（卫星）为基准解析；`mcp.json` 为该服务器写了绝对 `cwd` 时，再以该目录为基准解析。
- **Tower 的空目录不作基准**。未写 `cwd` 的服务器，`owner/repo`、分支名、MIME 类型这类参数不会因此被拒绝，与其他相对路径一样至少 ask（即 ADR-215 之前的行为）。
- 任一结果落在硬底线仍 forbid、不可授权覆盖；绝对路径照旧检查。例如绝对 `cwd` 在主检出之内时，相对路径落在主检出之内仍 forbid。
- **残余**（写明）：一次经人批准的相对路径调用可以写进本 Host 的空目录。按 (a)，它只影响同一 Host 进程中之后启动的服务器，Host 退出时删除，从不跨 Host。

**同步**：
- `11` §11.3.3 第 3 条改为 “相对路径不以它为基准，残余见 §11.3.4”（L212）；
- `00` §0.5.1 的代价改写（L99）：删去 “代码智能类服务器须写绝对 `cwd`” 与 “一律被拒绝”；改为相对路径按项目根（与你写的绝对 `cwd`）解析，受保护位置被拒绝，其余需要批准；
- G46 (bk) 的 ADR-215 一组改为：`sub/x` 与 `owner/repo` 出现审批卡，主检出中的 `src/a.ts` 仍被 forbid。

## R88-D4-01：`pendingHandBack` 期间置灰的范围

**唯一定义**：移到转移规则的唯一来源 `03` §3.2.1，新增一条 “`pendingHandBack` 等待期间的选项”（L74）。`16` `Goal.pendingHandBack`（L45）、`06` §6.4.3、`04` §4.6.7（L664）与 §4.8.9（L933）引用。

- **置灰并返回 `E_STATE` 的只有两个**，两者都另选去向：
  - `我来改`（`goal.take_over`，ADR-214/215 已有）；
  - 预算硬上限卡片的 `按当前状态送去验证`（`goal.claim_on_behalf`，`06` L902 本轮补守卫）。
- **解除保留原因的命令一律可用**：

  - `override_sentinel`（被保留的 `input_mutated_after_gate`）；
  - `keep`/`revert`、`rebuild_satellite`。
  - 它们对继续目标的改写照常写入、不改变结果：第 ① 步先执行 `pendingHandBack`。
- **`reverify` 模式下的附转向**（取 “取消待执行的重新验证、交给 Agent” 一支）：
  - `pendingHandBack.mode = reverify` 时，附转向解除 `nested_repo_live` 的 `resume` 在同一事务把 `mode` 置为 `continue_agent`（`06` `goal.resume`，L882）。

  - 原因全部解除时开 Run 交给 Agent，不再先以必然停在 `sentinel_high` 的树验证。
  - 与 ADR-143 不冲突：这条路径不经过 `verify_new`，不涉及 `returnTo`。

## R88-D6-01：墓碑行与部分由事件承载的 JSON 列

**唯一定义**：`06` §6.2.1（L221），补两句。

- **(a) 墓碑行**：
  - 载荷已墓碑化、无法重放的行——隐私清除留下的 Goal 墓碑行与决定墓碑行，含 “彻底忘记” 墓碑化的决定——从被重建的库原样沿用，不重放；
  - 所以 `parent_id`、`resurrected_from`、`goal_deps`、沿用表中的 `decision_id` 等外键仍然成立；
  - 投影版本迁移同样沿用它们；迁移改动这两张表的列时，墓碑行只经迁移对旧行所做的同一列变换。
- **(b) 字段粒度**：
  - 清单 (1) 的表按事件重放，以字段为粒度与被重建的库合并；
  - 重放只写 Projector 由事件载荷求出的字段（含由事件置空的）；
  - 其余字段按主键取被重建的库中的值：不由事件载荷承载的列，以及 JSON 列中不由事件载荷承载的键，如 `human_checkout` 的 `syncState`/`written`/`targetTree`/`rebuiltTree`/`params` 与 `counters`。

**被取代的写法**：“清空后按事件重放”，以及以列为粒度的 “按主键逐行沿用”。

**场景**：G35e 补 (o)(p)，只写期望（`14` L120）：
- (o) 清除一个被另一个 Goal 以 `parent_id` 引用的 Goal 之后做投影版本迁移，另一组做 `doctor --rebuild`；
- (p) 交还写回中途崩溃后做 `doctor --rebuild`。

## 偏离与未决

- **R88-D11-02 保留了 `roots` 一侧的基准**：
  - 指示是：未写 `cwd` 的服务器，相对路径一律不解析、回到 ask。
  - 本轮只去掉空目录这一个基准；以 `roots`（卫星）解析、落在硬底线即 forbid 这一侧，对所有经 `towerMcpTransport` 启动的 stdio 服务器保留。
  - 理由：这是 ADR-215 引入的不变式，挡的是代码智能类服务器以 `../` 越出卫星、进入主检出或其他 Goal 的卫星。卫星本身不在硬底线内，所以 `owner/repo` 这类参数解析进卫星后仍是 ask，误判的来源（空目录在写入硬底线中）已经去掉。
  - 这一侧比指示更严，没有新的误判类别；唯一的例外是参数恰好以 `..` 越出卫星、或在卫星中形成 `.git` 等价条目。
- **R88-D4-01 的唯一定义放在 `03` 而不是评审建议的 `16`**：指示允许 `03` §3.2.1 或 `06`。`03` §3.2.1 是转移规则的唯一来源，`16` 改为引用。
- **`claim_on_behalf` 改为 `E_STATE`**：ADR-215 的写法是 “照常写入、但不改变结果”，但它实际上会解除 `budget_hard_cap`，并非无效。本轮改为与 `take_over` 相同的守卫，规则因此简化为 “置灰 ⇔ `E_STATE`”。代价：交还后仍暂停于硬上限时，人须先提高预算再 `resume`；交还时的选择随后执行。
- **重建的字段粒度没有逐列清单**：规则以 “Projector 是否由事件载荷写出该字段” 判定，正文只举例（`runs` 的非事件列、`human_checkout` 的五个键、`counters`）。完整性由构造保证，与 R87-D6-01 的两份清单同一思路。
- **评审 §3.1 的 lint 建议未采用**：置灰的命令只有两个，都以 `06` §6.4.3 的 `E_STATE` 守卫落地；`16` 与 `04` 只引用 `03`，没有第二份清单可比对。
