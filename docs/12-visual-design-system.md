>
> 起点是 `research/gui.md` §5–8 的令牌草案（v0）。本文沿用其大部分取值，修正了与主干原则冲突或未达对比度目标的部分，取舍记录在 §12.16。所有 APCA 数值由脚本按 APCA 0.0.98G 公式从 OKLCH 换算 sRGB 后计算，实现后须在目标屏幕上复核（§12.13.1）。

> 分工：注意力阶梯的级别与投递以 `08` 为准；新鲜度语义以 `07` §7.3.3 为准；两轨进度以 ADR-020 为准；致命三要素判定以 `11` §11.8 为准；标识符、默认数值、快捷键与刷新节奏以 `16-registry.md`（ADR-039）为准。本文只规定视觉形态。第 1 轮评审的逐条回应见 `reviews/round-1-response-04-12.md`。

## 12.1 设计方向：安静的仪表盘（dark cockpit）

一句话：**一切正常时，界面几乎是静止的灰色；颜色和运动只出现在需要人的地方。**

| 原则 | 视觉含义 | 依据 |
|---|---|---|
| 默认是灰的，颜色有含义 | 全产品只有 5 个状态色（§12.4.3）；强调色只用于焦点与选中，从不表示状态 | T§A8 ISA-101 灰底 + 例外着色；Airbus dark cockpit；G§5 |
| 琥珀色只表示“需要你做决定” | `--st-attention` 是全产品唯一的打扰色；任何其他用途都会稀释它 | R5；T§A9 报警可行动性 |
| 绿色只属于验证器的结论 | 验收前，只有验证器在干净环境中、针对**当前工作区树（指纹）**新鲜得出的通过结果能是绿色（ADR-020、ADR-024）；Agent 环境中的观测、Agent 的说法永不为绿 | R1、R2、ADR-002 |
| 运动是信号，不是装饰 | Agent 的常规活动不触发任何动画；只有进入“需要你”的那一刻有一次性提示 | T§A7 calm technology；G§6.4 |
| 版面稳定 | 卡片固定高度、实况行固定一行、位置只由人改变 | T§A11 航班条；G§5 |
| 层级靠字号、字重与灰阶，不靠框和图标 | 图标稀少；边框为 1px 低透明度发丝线；只有浮层有阴影 | G§5（Linear、Things、Geist） |
| 内容亮于外框 | 侧栏比内容暗一档；概览卡片是最亮的表面 | G§5（Linear 2026 改版） |
| 键盘优先，键盘打开的东西不做动画 | 面板、列表导航、切换视图都是 0ms | G§5（Raycast） |
| 事实、观测、说法、人一眼可分 | 四种排版语域（§12.5） | R1，全产品最重要的视觉规则 |
| 安静但不含糊 | 实况行永远显示可转向的细节（`模式 · 动作 · 对象`），从不显示“工作中…” | R12；L§A.1 Claude Code 折叠反弹 |
| 可逃逸 | Watch 模式是同一套视觉语言下的另一种布局，诚实语法在其中不变 | R12 |
| 不拟人 | Agent 没有头像、名字或表情；说法只标“Agent 称” | R10：更像“同事”的呈现会提高信心而不提高准确度（T§A16 Overseeing Agents） |

## 12.2 令牌架构

三层，组件只能引用语义层：

```
原始层 primitive     --ok-neutral-180, --ok-amber-800 …        仅在 tokens.css 内部出现
语义层 semantic      --bg-app, --text-2, --st-attention …       组件与工具类唯一可用的颜色来源
组件层 component     --card-goal-h, --criteria-seg-w …          组件内部尺寸常量
```

- 通过 Tailwind 4 `@theme` 暴露语义令牌，lint 禁止原始颜色值与原始层令牌出现在组件代码里（G§6.2）。
- 状态色令牌名以 `--st-` 开头，主题系统不可覆盖（§12.15）。
- 每个令牌在 Figma 变量中同名，深浅主题为同一变量的两个模式。
- lint 还检查“文字 × 字号 × 令牌”组合是否满足 §12.13.1 的 APCA 角色表（例如禁止 `text-3` 用于 13px 以下的必读文字）。

## 12.3 排版

### 12.3.1 字体栈

```css
:root {
  --font-ui: "InterVariable", "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI",
             "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei",
             "Noto Sans CJK SC", "Noto Sans SC", "Source Han Sans SC", sans-serif;
  --font-mono: "JetBrains Mono", ui-monospace, "SF Mono", "Cascadia Mono",
               "PingFang SC", "Microsoft YaHei UI", "Noto Sans Mono CJK SC", monospace;
  --font-features-ui:  "liga" 1, "calt" 1, "ss02" 1;
  --font-features-num: "liga" 1, "calt" 1, "tnum" 1, "zero" 1;   /* 所有计数、计时、diffstat、金额 */
}
```

- 拉丁字符走 Inter，中文回落到平台字体；不内置 CJK 网络字体（每个字重 5–10 MB，G§8）。
- 代码与事实数值走 JetBrains Mono；用户可换 Berkeley Mono，或 2:1 宽度的 Maple Mono NF CN / Sarasa Mono SC（G§8）。

### 12.3.2 字号角色

基础字号 13px（紧凑密度相同，舒适密度 14px）。行高以 px 固定在行令牌上，避免中英混排时行高抖动（§12.14）。颜色列遵守 §12.13.1 的 APCA 角色表。

| 角色 | 字号 / 字重 | 行高（拉丁 / 中文） | 字体 | 颜色 | 用途 |
|---|---|---|---|---|---|
| `display` | 24 / 500 | 32 / 36 | ui | text-1 | 仅空状态 |
| `title-goal` | 20 / 500 | 28 / 32 | ui | text-1 | 目标页标题 |
| `title-section` | 14 / 500 | 20 / 22 | ui | text-2 | 区块标题（不用全大写、不加字距） |
| `body` | 13 / 400 | 20 / 21 | ui | text-1 | 默认 UI 文本 |
| `body-strong` | 13 / 500 | 20 / 21 | ui | text-1 | 强调；中文文本不用 600 |
| `reading` | 14 / 400 | 22 / 24 | ui | text-1 | 段落、发现、合同正文 |
| `question` | 16 / 500 | 24 / 26 | ui | text-1 | 决策卡的一句话问题 |
| `meta` | 12 / 400 | 16 / 18 | ui | **text-2** | 时间、计数标签（必读） |
| `live` | 12 / 400（卡片）· 13 / 400（目标页） | 16 / 18 · 20 / 21 | mono | **text-2** | 实况行 |
| `fact-num` | 12–13 / 400 | 同所在行 | mono + tnum | text-1 | 事实数值、哈希、diffstat、金额 |
| `claim` | 13 / 400 | 20 / 21 | ui | text-2 | 说法正文（§12.5） |
| `hint` | 11 / 500 | 16 | mono | text-3 | 快捷键提示、分隔符等非必读文字 |
| `code` | 12.5 / 400 | 20 | mono | text-1 | diff、日志 |

### 12.3.3 字重决策

- 只用 400 与 500。中文环境不使用 600：Microsoft YaHei UI 只有 Light / Regular / Bold 三档，600 会被渲染为 700，500 会回落为 400。macOS 的 PingFang SC 实际包含 Medium 与 Semibold（G§6.1 称其“无真正 Semibold”，与系统字体实际情况不符，但结论“中文强调用 500”不变）。
- 因为 Windows 上 500 可能显示为 400，**任何层级不得只靠字重区分**：强调同时提升一级灰阶（text-2 → text-1）或字号。
- 说法不使用斜体。中文没有真斜体，合成的倾斜字形难以阅读（§12.16 #9）。

### 12.4.1 中性色与强调色

中性色色相 h≈70（暖灰），极低彩度（Linear 2026，G§6.2）。表面层级靠明度，不靠阴影。

| text-4 | 31 / 31 / 29 / 32 | 47 / 49 / 35 / 42 | 禁用、过期（APCA 允许的禁用文字下限约 30） |
| accent | 58 / 58 / 56 / 59 | 77 / 79 / 65 / 72 | 焦点环、下划线；不作为小字文字色 |
| st-attention | 66 | 66 | 字形、色调底；不作为小字文字色 |

### 12.4.3 状态色：恰好 5 个

```css
:root[data-theme="dark"] {
  --st-attention: oklch(0.800 0.150 75);    /* 琥珀：需要你做决定 */
  --st-danger:    oklch(0.750 0.150 25);    /* 红：验证器失败、哨兵、越界、硬矛盾、已拒绝、无响应 */
  --st-verified:  oklch(0.770 0.130 155);   /* 绿：验证器在当前树上通过；已验证 / 已验收 / 已合入 */
  --st-active:    oklch(0.740 0.060 230);   /* 低彩度蓝灰：运行中、验证中（正常态，故意安静） */
  --st-neutral:   var(--text-3);            /* 灰：其余全部状态，含“观测到”与“未经机器验证” */
  --attention-bg: oklch(0.225 0.030 75);    /* 不透明色调底：需要你条目的稳态 */
  --danger-bg:    oklch(0.215 0.030 25);
}
:root[data-theme="light"] {
  --st-attention: oklch(0.600 0.150 65);
  --st-danger:    oklch(0.540 0.190 25);
  --st-verified:  oklch(0.550 0.130 155);
  --st-active:    oklch(0.540 0.070 230);
  --st-neutral:   var(--text-3);
  --attention-bg: oklch(0.965 0.030 75);
  --danger-bg:    oklch(0.965 0.025 25);
}
```

**状态色只给字形和色调底，不给小字。** 状态上下文里的文字一律用 text-1 / text-2（12–13px 小字需要 Lc ≥ 75，而状态色在深色上只有 55–66）。唯一例外：≥ 16px / 500 的标题可用状态色（Lc ≥ 60）。

| 状态色 | 只用于 | 禁止用于 |
|---|---|---|
| attention 琥珀 | **需要你做决定**：Needs-You 条目、`◆`、模式 `waiting_human` / `blocked_guard`（等你批准）/ `budget_capped` / `stalled`、侧栏与 Dock 计数、评论高亮、当场必须决定的内联决策块（致命三要素、S0 授权） | 一般警告、过期、心跳迟到、模型静默、评审积压超上限、按钮 |
| danger 红 | 验证器得出的失败（新鲜时）、哨兵命中、范围越界、**硬**矛盾（`07` §7.8）、审批被拒绝的事件、`unresponsive`、送达失败 | 软矛盾（中性）、观测到的失败（中性）、危险按钮的常态 |
| verified 绿 | 验证器在当前树上的通过；`in_review`、`accepted`、`integrated` **且其验证结论为 `verified` / `verified_qualified`** | 任何说法；任何观测；`claimed`；人工勾选的标准；结论为 `not_machine_verified` 的目标在任何状态（in_review、accepted、integrated、archived）都不着绿（R4-D9-01） |
| active 蓝灰 | `running`、`verifying` 的生命周期字形 | 文字链接（用 accent 下划线）、选中态 |
| neutral 灰 | 其余所有状态 | — |

强调色 accent（h=285）与 active（h=230）色相相距 55°，active 彩度只有 0.06，二者不会混淆（§12.16 #4）。

**“要注意但不需要你决定”的画法**（心跳迟到 15 秒、模型 90 秒无输出、事实陈旧、评审积压超上限）：不用任何状态色。相关文字提到 text-1，字形换成空心菱形 `◇`（§12.6.2）。理由：琥珀一旦用于“可能有问题”，Q1 就失去 3 秒答案（T§A9 cry-wolf 效应）。这些状态若持续，由 Harness 推导为 `stalled` / `unresponsive`，按 `08` §8.6.3 的条目时机生成 Needs-You（`unresponsive` 在自动“重启并恢复”期间不生成），那时才出现琥珀 `◆`。

### 12.4.4 Diff 色

```css
--diff-add-bg:   oklch(0.770 0.130 155 / 0.10);   --diff-add-word: oklch(0.770 0.130 155 / 0.26);
--diff-del-bg:   oklch(0.750 0.150 25  / 0.10);   --diff-del-word: oklch(0.750 0.150 25  / 0.26);
--diff-comment:  var(--st-attention);   /* 有评论的行：行号槽琥珀竖条 */
--diff-human:    var(--text-2);         /* hunk author=human：行号槽 2px 实线 + 标签“你” */
--diff-external: var(--text-2);         /* author=external（运行中收尾回合内的外部路径，采纳或撤销前不会进入评审）：2px 虚线 + “外部”；mixed：点线 + “混合”——混合不显示为“你的改动”（ADR-135） */
```

- Diff 是验证器之外的 git 事实，沿用约定俗成的绿 / 红色调；只用 10% 底色，不会被读成状态。
- 每行都有 `+` / `−` 行号槽符号，不依赖颜色；作者用线型区分，不依赖颜色。
- **外部写入不进入评审**（ADR-122）：来源不明的写入在评审前就使目标暂停（`04` §4.8.7），因此评审单元中没有“待处置的外部 hunk”状态，也没有对应令牌。
- 设置中提供“色觉友好 diff”：新增 h=250、删除 h=60，仍为 10% 底色。

## 12.5 诚实语法（Honesty Grammar）视觉规格

R1 的视觉落地。**看一眼就知道这句话是验证器测出来的、Agent 环境里观测到的、Agent 说的，还是人决定的。**

### 12.5.1 四种语域与三种派生状态

| 语域 | 来源 | 字体与颜色 | 标识 | 颜色权限 | 交互 |
|---|---|---|---|---|---|
| **事实 Fact**（已验证） | ⚙ 不经 Pi 扩展链的 Harness 组件：验证器、git、记账器（ADR-024） | 数值 mono + tnum，text-1 | `FactChip`：`⚙ @9f3e1a · 6分前`（11px mono，text-2，**实线**发丝线框） | 结果字形可用 verified / danger（仅新鲜时） | 点击打开证据；`O` |
| **观测 Observation**（ADR-020 第三种语法） | Agent 在自己工作目录中运行的、与标准等价的命令（经扩展链转述，`command_result`） | 数值 mono，text-2 | `ObsChip`：`观测 @9f3e1a · 2分前`（11px，text-2，**虚线**发丝线框，无 harness 图标） | **永不着色**：通过 / 失败字形都是 text-2 空心样式（`○✓` / `○✕`） | 点击打开该次命令的轨迹片段 |
| **说法 Claim** | 🤖 Agent | 比例字体，text-2，13px | 左侧 2px **虚线**边框（`--border-strong`）+ 前缀 `Agent 称`（11px，text-2） | 永不使用 verified；不带实心 ✓（唯一形式是计划步骤与发现的 `┆✓`：虚线前缀 `┆` 标明它是说法，见下文“计划步骤与发现的字形”，ADR-176） | 点击跳转轨迹；右侧交叉校验徽章 |
| **你的决定 Human** | 🧑 | 比例字体，text-1 | `HumanStamp`：`你 · 14:20`（11px，text-2）；左侧 2px **实线**边框 text-3 | 无颜色 | 不可编辑；只能被新的决定替代 |

| 派生状态 | 触发 | 表现 |
|---|---|---|
| **过期 Stale** | 工作区树（指纹）变化（`07` §7.3.3） | 整行 text-4，数值保留；结果字形换为 `⟲`；徽章 `@71c0d2 → 现在 @9f3e1a`；移除所有状态色；`⇧V 重新验证`（只在 `goal.retry_verify` 允许的状态显示；运行中的过期行不显示，由机会式验证重验，`16` §16.3，ADR-208） |
| **失效 Expired** | 非代码前提失效（base 移动、合同修订、超龄） | 整行 text-4 + 删除线，标签 `已失效`，退出所有汇总。删除线只用于失效的事实 |
| **矛盾 Contradicted** | 说法被事实推翻 | 说法保持原样式（不删除线）；**硬矛盾**（`07` §7.8）右侧 `✕ 矛盾`（danger 字形 + text-1 文字）；**软矛盾** `◇ 可能不一致`（中性）；下方缩进一行显示相关事实 |

交叉校验徽章（`02` Claim.crossCheck）：`一致 · 2 条事实`（text-2，一致不等于正确，所以不着绿）· `无依据`（空心框，text-2）· 未校验（无徽章）· `✕ 矛盾`（硬，danger 字形）· `◇ 可能不一致`（软，中性）。

**Tower 注入**（ADR-135）：恢复、返工、交接、`tower.processes_terminated` 等由 Tower 发起的回合，在轨迹与时间轴中以 `⚙ Tower 注入` 标签（11px，text-2，实线发丝线框，同 `FactChip` 的框线）开头，正文原样显示注入内容；**不**使用 `HumanStamp`，也不计入“你的转向”。`HumanStamp` 只用于你亲手写的转向与回答。

**系统印章 `⚙ 超时默认`**（ADR-176）：`unattended:"use_defaults"` 下计时器套用的默认（`resolution.by = "timeout"`，`08` §8.7.1；低风险问题的默认就是 Agent 推荐的选项）以 `⚙ 超时默认` 印章（11px，text-2，实线发丝线框，与 `⚙ Tower 注入` 同族）开头，后接时间与所套用的选项；**不**使用 `HumanStamp`，不写“你”，也不计入“你的决定”。人之后改判时，改判记录才使用 `HumanStamp`。

**计划步骤与发现的字形**（ADR-176）：`PlanStep` 没有状态字段，“完成”与“当前步骤”来自 Agent 的 `log`（`02` §2.5），是说法。字形集（ADR-180 修订）：`○` 未开始（text-3）· `┆▸` Agent 称正在进行（最近一次 `log` 的 `step`）· `┆✓` Agent 称已完成（text-2，不着色）· `◆` 需要你决定的步骤（`needsDecision`，`04` §4.5）或该步骤上有等你处理的条目（沿用 `◆` 的全局含义）。**没有表示步骤完成的事实字形**：Tower 测不到“完成”——关联标准可能在改动之前就已通过（回归保护）。字形只取一个，优先级 `◆` > `┆▸` > `┆✓` > `○`；其后可加徽章：`关联标准通过`（关联标准 `PlanStep.criteriaIds` 非空且全部由验证器新鲜通过；事实徽章，text-2，不着绿，不表示步骤完成；取代 ADR-178 的事实 `✓`）· `一致 · n 条事实`（交叉校验 X4 一致，只检查触及的文件）· `◇ 可能不一致`（X4 不一致；X4 是启发式，至多是软矛盾，按上方矛盾样式用中性 `◇`，不用 danger 的 `✕`，`07` §7.8）。诊断时间线与轨迹中的发现（Finding）同理：`┆ 发现 n`（说法），交叉校验一致时加徽章 `一致 · n 条事实`，不换成 `✓`（ADR-178）。

### 12.5.2 “已验证”的三种形态（R1-D9-05、ADR-031）

| 形态 | 条件 | 生命周期字形 | 标签 |
|---|---|---|---|
| 已验证 | 至少一条 exec / artifact 标准由验证器执行；全部新鲜通过；无保留条件 | `▲` 绿 | `已验证 @e7a210` |
| **有保留的已验证** | 同上，但满足 `07` §7.10.3 `anyQualified` 的任一条件（唯一定义，本表不复述，ADR-183） | `▲` 绿 + 右下 2px 缺角（ASCII 记作 `▲*`） | `已验证（有保留）` + 中性原因徽章，与 `anyQualified` 的条件一一对应：`2 个既有 flaky` · `计时 flaky` · `S0 环境` · `部分标准未执行` · `Node 版本不同` · `运行器被修补` · `哨兵已覆盖` · `LFS 改动` · `延续验收` · `链接未检查`（M2）· `计数为估计`（ADR-184） |
| **未经机器验证** | 没有完成机器验证：只有 human 标准（ADR-031）；或 exec 标准没有执行——S0 授权被拒绝或超时默认拒绝（ADR-068、ADR-077）、M1 中的非 Node 生态（ADR-064）、子模块项目（ADR-071）。后几种情形下 artifact 标准仍会执行，其结果照常以事实显示（R4-D15-02 #9） | `◬` 中性（空心三角 + 中心点） | `未经机器验证`，按原因加后缀：`（S0 未授权）`、`（S0 超时默认拒绝）`、`（生态未支持）`、`（子模块未支持）`；中性；验收面板逐条列出 human 标准，并列出未执行的机器标准及其观测结果（观测语法） |

`accepted` 若经验收延续或有保留，同样在 `●` 上加缺角（`●*`）。

**机会式验证的守卫**（ADR-053）：机会式验证的通过结果，若测试路径集、标准命令引用的脚本或测试配置相对 base 有未处置改动，以“有保留”形态显示（`✓` 绿 + 缺角，徽章 `测试定义已变`），并且**不计入 V**。这是唯一一种“绿色但不计入已验证”的情况，所以徽章必须写明原因。

### 12.5.3 组合规则

1. 说法与观测都不得借用事实的颜色。
2. 同一行出现说法与事实时，说法在左、事实在右，中间用 `↔`（账本行，`04` §4.5）。
3. 进度只能由事实与观测构成，并**分两轨显示**：`已验证 V/M · 观测 O/M`（ADR-020）。`M` 只计机器标准（exec + artifact）；human 标准另列 `人工 h/k`，用 Human 语法，**从不进入 V 或 O**（ADR-052）。不再出现单一 `N/M`。Agent 自报的百分比只能以说法出现，从不画成进度条（T§A16 Unreliable Progress Bar）。
4. 置信度只用文字“低 / 中 / 高”，不显示百分比（`02` Claim.confidence；T§C16-10）。
5. 推荐（决策卡）一律以说法样式显示，无论来自 Agent 还是 Harness 规则（Harness 时前缀 `⚙ 规则推荐`，仍是虚线框，因为推荐不是测量）。
6. 过期、失效的结果两轨都不计入。
7. “原因”区块（ADR-030）= 症状（事实或观测，按来源取语域）+ 原因（说法）。症状与原因上下排列，不合并成一句话。

### 12.6.3 模式徽章（`ModeBadge`）[M1]

模式是封闭集合，由 Harness 推导（R6、`08` §8.6.2）。徽章 = 可选字形 + 2–4 个汉字（两处例外：仓库准备阶段的 `仓库准备中` 与 `软上限 · 收尾中`，ADR-204），12px / 500，**文字一律 text-1 或 text-2**，状态色只在字形与底色上；固定最小宽度 4 个汉字。

| Mode | 徽章 | 字形 | 字形色 | 背景 |
|---|---|---|---|---|
| preparing | 准备中 | — | — | 无 |
| thinking | 思考 | — | — | 无 |
| acting | 执行 | — | — | 无 |
| waiting_human | 等你 | `◆` | attention | `--attention-bg` |
| blocked_guard | 等你批准 | `◆` | attention | `--attention-bg` |
| budget_capped | 软上限 · 收尾中 | `◆` | attention | `--attention-bg` |
| retrying | 重试 2/5 | — | — | 无 |
| compacting | 压缩中 | — | — | 无 |
| queued | 排队 | — | — | 无 |
| verifying | 验证 | — | — | 无 |
| stalled | 卡住 | `◆` | attention | `--attention-bg` |
| unresponsive | 无响应 | `■` | danger | `--danger-bg` |
| settled | 已停 | — | — | 无（收尾等待期的实况行见 §12.6.4） |

`blocked_guard` 表示“动作被门禁挂起、等你批准”，与收件箱中的 `approval` 条目是同一件事，所以同为琥珀 `◆`（R1-D9-02）。审批被**拒绝**不是模式：它是一条事实事件，在轨迹与账本中显示为 `■ 已拒绝 · pnpm add stripe@18`，并在实况行对象段停留到 Agent 的下一个动作为止。

### 12.6.4 实况行格式（`LiveLine`）[M1]

`[ModeBadge] · 动作 · 对象 [事实后缀] ……… 活跃度`（R6、R12、`01` §1.4 #1）

| 模式 | 动作 | 对象 | 示例 |

## 12.7 动效契约

令牌：

```css
:root {
  --dur-0: 0ms;       /* 键盘触发、面板、列表导航、切换视图 */
  --dur-1: 100ms;     /* 按压反馈（仅透明度）、字形交叉淡入 */
  --dur-2: 160ms;     /* 抽屉、弹出层（用户触发） */
  --dur-3: 220ms;     /* 进入 / 退出评审与诊断全屏（空间性说明） */
  --dur-attn: 700ms;  /* 一次性注意提示，永不循环 */
  --ease-out: cubic-bezier(0.2, 0.8, 0.2, 1);
  --ease-inout: cubic-bezier(0.4, 0, 0.2, 1);
}
@media (prefers-reduced-motion: reduce) {
  :root { --dur-1: 0ms; --dur-2: 0ms; --dur-3: 0ms; --dur-attn: 0ms; }
}
```

## 12.8 注意力阶梯的视觉处理

级别定义、基础级别映射、断点、令牌桶、洪泛、覆盖层优先级以 `08` 为准。severity 是“后果严重度”，L0–L4 是“投递强度”，二者经 `08` §8.3.1 映射。

| **L1 外围** | 第 5 行 `AnomalyChip`（`◇` 或 `■`，依来源） | —（不进入收件箱；侧栏的 `+n 稍后` 只计 `ratify` 聚合条目，`08` §8.5.1） | 不计 | 进入简报与站会摘要 | — | — | 无 |

规则：
- Dock 角标、侧栏数字、菜单栏数字的口径相同（`08` §8.7.3），只计需要你。

决策卡右上角。**文案直接取 `08` §8.7.1 倒计时文案表的六种情形**（唯一定义在那里，ADR-023/178/182），本组件只规定样式：`unattended:"wait"` 下任何条目一律 `不会超时`（text-2，不显示倒计时）；`use_defaults` 下按条目区分——审批与 S0 执行授权写出默认项“→ 拒绝”，standard/high 风险或推荐项不可逆的问题写“超时后暂停（不自动作答）”，low 风险且推荐项可逆的问题写“N 分钟后 → 采用推荐：<选项>”，检测器 escalate 的停滞写“30 分钟后 → 暂停（仅 use_defaults）”。按分钟替换，不跳秒。

### ReviewUnit [M1]

- **结构**：头部（序号、标题、风险、行数、关联标准、预计时长、`已计入积压`、动作）→ 意图（`ClaimBlock`）→ 风险依据（事实）→ 哨兵 → `DiffView`。
- **状态**：未看、已看、已批准、请求修改、内容已变（重置为未看，显示 `内容已变 · 上次批准于 @…`）。

## 12.13 无障碍

### 12.13.1 对比度（APCA 角色表）

按 APCA bronze 简化规则，以字号与字重决定目标（R1-D9-01）：

| 角色 | 字号 / 字重 | 最低 Lc | 可用令牌 |
|---|---|---|---|
| 正文与阅读 | 14px / 400 | 90 优先，75 最低 | text-1 |
| 必读小字（实况行、meta、事实数值、标签、说法） | 11–13px / 400–500 | 75 | text-1、text-2 |
| 标题 | ≥ 16px / 500 | 60 | text-1、text-2、状态色（仅此处） |
| 非必读文字（快捷键提示、分隔符、占位、与旁边信息重复的标签） | 任意 | 45 | text-3 |
| 禁用、过期 | 任意 | 30 | text-4 |
| 非文字元素（字形、焦点环、分段条） | — | 45 | 状态色、accent、text-3 |

- 实测方法：在 MacBook Pro（XDR，P3）与一台 sRGB 外接显示器（27″ 1440p）上各测一次，用浏览器取色在实际渲染（含亚像素与字体渲染）上复核表中组合；不达标时调整令牌明度而非字号。
- `prefers-contrast: more`：text-2/3/4 各向极端推一档（深色 +0.06 明度，浅色 −0.06），边框透明度 +0.06；过期事实提升到 Lc ≥ 45。
- Windows `forced-colors: active`：状态色映射到系统色，形状编码保证信息不丢失；虚线 / 实线左边框保留。

### 12.13.2 动效

`prefers-reduced-motion: reduce` 时所有动效时长为 0；琥珀一次性提示直接显示为稳态色调。单向门的按住确认 1.5 s 与发送前的 5 s 倒计时是交互阈值，不是动效，不受影响。

### 12.13.3 读屏与 aria-live 政策

| 内容 | 策略 |
|---|---|
| 实况行、计数、计时、分段条、花费 | 不播报 |
| 新的需要你条目（L2–L3） | 单一全局 `polite` 播报区；30 秒内合并为一句 |
| L4 条目 | `assertive` 一次 |
| Watch 模式尾部 | `role="log"`，`aria-live="off"` |
| 你的操作失败（送达失败、验收失败、批准被阻止） | `assertive` 一次 |
| 应用级横幅（§12.8，`06` §6.8 F8） | 出现时 `assertive` 一次；消失时 `polite` 一次，消失时读 `磁盘空间已恢复，Tower 恢复运行`（ADR-233/234/235） |
| 目标页模式变化 | 默认不播报；可开启“朗读当前目标的模式变化” |
| 简报 | 打开时焦点移到标题，按分段标题导航 |
| 概览 | React Aria GridList |
| Diff | 行为 `row`，行号槽符号可读（“新增”“删除”“你的改动”） |
| 终端 | xterm `screenReaderMode` 按需开启 |

### 12.13.4 其他

- 所有动作都可从命令面板到达并显示快捷键；焦点环永远可见；最小点击区域 24×24px。
- 颜色从不单独承载信息：状态有形状、过期有 `⟲` 与斜线、观测有空心与虚线框、diff 有 `+/−`、作者有线型、必须修复有文字标签。
- 在 VoiceOver 与 NVDA 上测试概览、需要你、评审评论流程（G§8）。

## 12.14 简体中文（zh-Hans）规则

1. **输入法合成**：所有回车提交的处理函数忽略 `event.isComposing === true` 与 `keyCode === 229`；多行输入统一 `⌘↩` 提交、`↩` 换行。端到端测试：输入法输入“修复结账”，用回车选词，断言没有提交（G§8）。

5. **标点挤压**：单行标签与标题用 `text-spacing-trim: trim-start`；正文 `normal`。
6. **断行**：中文正文 `line-break: strict`；路径、哈希、命令 `overflow-wrap: anywhere`；不用连字符断词。
7. **截断**：标题末尾省略；路径中间省略保留文件名；按 `Intl.Segmenter` 字素截断。
8. **字重**：只用 400 / 500；层级不只靠字重。
9. **无斜体**。
10. **引号**：「」表示引用的说法或标题，“”用于一般引号。
11. **数字、时间、货币**：千分位 `3,012`；时间 `14:02`；外周相对时间 `刚刚 / 6分前 / 3时前 / 昨天 / 10月2日`，提示框中 `6 分钟前`；金额 `$1.84`。

## 12.15 主题规则

- 浅色、深色、跟随系统、高对比四种；高对比由同一 OKLCH 明度阶梯推到两端生成（G§8）。

- 强调色约束：与 5 个状态色色相距离 ≥ 30°，彩度 ≤ 0.16。系统强调色只映射到 `--accent`。
- **状态色锁定**：`--st-*`、`--attention-bg`、`--danger-bg` 不可被主题覆盖；diff 色只能在“标准 / 色觉友好”两套间切换。
