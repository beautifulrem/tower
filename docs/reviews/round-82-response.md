|---|---|---|

### R82-D11-01（重要）与 R82-D11-02（次要）：已解决（删除，推迟到 M2）

删除 `human_checkout.run_prepare` 与人工编辑面板的 “在验证器沙箱中运行准备步骤” 按钮。

**M1 的如实写法**：Tower 不在人工编辑检出中运行任何准备步骤，也不提供这样的按钮。生成产物需要时，由人在自己的终端中运行。这是在 Tower 沙箱之外、以人的权限运行 Agent 可能改过的代码，是否运行由人判断。各处的落点：
- `00` L85（§0.5.1 能力差异行）：写明 “M1 中 Tower 也不在人工编辑检出中运行准备步骤：需要时由你在自己的终端中运行……是否运行由你判断；在沙箱中运行准备步骤属 M2”。
- `10` L943（§10.8.4 第 2 步，唯一定义）：
  - 提示文案改为 “需要时请在你自己的终端中运行准备步骤（不在 Tower 沙箱中，以你的权限运行 Agent 可能改过的代码）”；
  - 写明 M2 重新引入的两个前提：
    - 不能写 H/.git，也不能在 H 中任意深度造出名字折叠后为 `.git` 的条目，即第 3 步 “该 gitdir 的全部内容来自 Tower，Agent 从未可写”；
    - H 中含机密的本地文件按检验检出的显式开关（`inspect_with_secrets`）处理。
- `04` L623（§4.6.7）：面板只显示提示，没有按钮。
- `14` L137（G37）：预期改为 “Tower 也不提供在检出中运行它们的按钮……Prisma 客户端未生成”。
- `11` L707（T31）：威胁列补 “人在人工编辑检出中自行运行 Agent 可能改过的准备脚本”。
