### R80-D5-01（次要）：已解决

取评审的第一种写法。**唯一定义**：`05` L459（§5.3.6 “隔离 agentDir 的凭据来源”）。
- 隔离 agentDir 时凭据**不**隔离。`ModelRuntime` 仍以用户 agentDir 中的 `auth.json` 与 `models.json` 创建，与非隔离模式、用户自己的 `pi` 是同一个路径字符串。
- API 密钥照常只经 `setRuntimeApiKey` 写入内存覆盖层。
- 隔离的只是传给 `createAgentSessionServices` 的 `agentDir`，即扩展、技能、提示模板、settings 与 MCP 的加载目录。

**这样 “登录后自动继续” 成立**：
- 锁按路径字符串加，同一路径共用一把锁。
- 刷新在锁内复查并落盘，多个进程只刷新一次。
- 人在终端 `/login` 后，隔离 Goal 的探测与 Run 读到的是同一份凭据。
- 不会出现两把锁造成的误报 F7，也不会因只在内存中刷新而使用户自己的登录失效。

**同步**：
- `11` L607（§11.8.2）：“只链接” 改为引用 `05` §5.3.6；
- `11` L449、L507；`05` L1469（C29 (a)）、L1417（D57）、L1310；`14` G46/G46b (a)：去掉内存存储。

**M2**：RPC 的凭据路径随 `PI_CODING_AGENT_DIR` 改变，与用户 `auth.json` 的锁共享在 M2 复审（`05` L460）。

### R80-D8-02（次要）：已解决

**命令**：`06` L914 新增 `inspect.close{goalId, modified?: "discard" | "keep"}`，它是 `10` §10.8.3 第 7 步清理的命令。
- 关闭时停止服务、回收端口段，比较目录与 T_pin。
- 没有修改 → 删除目录。
- 有修改而未带 `modified` → `E_STATE`，并列出被修改的文件。
- `discard` → 删除目录。
- `keep` → 保留目录，检验就此关闭。
- 产生已登记的 `inspect.closed`。不是 HumanDecision：检验目录不是 Goal 的工作区，关闭不改变 Goal 的状态、卫星、指纹或证据。
- 仅本机：`16` L1100 §16.5 单列为 ✗；`06` L990 禁止远程清单同步。

**保留目录之后的出口**：再次 `inspect.close{modified:"discard"}`，或 `inspect.bring_back`（照常要求 `in_review`/`accepted`）。`inspect.open` 的 `E_STATE` 指向这两个出口（`06` L895）。同步：`10` L902；`04` L585、L587。

**`⇧V`**：只在 `goal.retry_verify` 接受的状态显示，运行中的过期行不显示，由机会式验证重验。同步：`16` L973、`12` L228；`04` L303 线框改为 “待重验”。

## 偏离与未决

- **新增一条命令**：收敛规则倾向不加新机制。`inspect.close` 是唯一的新增：M1 界面已有三个动作，事件 `inspect.closed` 已登记，却没有产生它的命令，无法用已有命令表达。它不是 HumanDecision，所以不新增决定种类。
- **R80-D7-01 的残余**：第一个检查点之前没有记录的 L 可比，这一窗口内移出的路径仍按收入它的检查点记录。要关闭它，需要在卫星创建时记录播种所用的清单（新字段），或者生成一个初始检查点（新机制），本轮都没有做。窗口很短，评审中该文件照常可见。
- **R80-D7-01 的取法**：用 `mixedPaths`（评审建议的第一种），没有取 “`author:"human"` + `Tower-Human-Edit`”。所以 seal 不写 `Tower-Human-Edit`，与 “`mixed` 不作为你的改动” 的既有规则一致；失败去向按人的改动处理，这是条目的核心。
- **R80-D5-01 的取法**：取 “共用用户凭据文件”，没有取 “隔离模式不支持 OAuth”，以保留首次运行（清单未确认）时 OAuth 用户的可用性。这意味着高风险 Goal 的 Host 读写用户的 `auth.json`；Host 不在沙箱中，非隔离模式本来就如此，没有新的读者。M2 RPC 的凭据路径未决，已注明复审。
- **R80-D8-03 的取法**：在 `08` 的路由规则中直接把单向门审批映射到 L4，没有改 `07` 中审批的 severity。severity 仍为 2，只有级别由路由决定，避免改动精度统计与 `07` 的生成规则。
- **探测的边界**（观察 2）：被吊销的 API 密钥会让 F6 的探测反复解除再失败。这是 ADR-207 之前已有的行为，本轮只如实写明，没有改动。
- **未实现的 lint 建议**：(z′) 补登与批次覆盖检查，理由见 lint 一节。
