**R52-D11-02｜次要**（远程矩阵中“改变验收依据”的命令与字段没有封闭清单）

- **问题**：`11` L578 规定“改变安全边界或**验收依据**的命令……只能在本机执行”；`06` L976 的理由同样写“改变安全边界、验收依据或不可逆”。但 `16` §16.5 中有三处由示例或开放措辞决定：

### D13 隔离、git 与并发

**R52-D13-01｜次要**（撤销合入后再次验收，新 seal 以被撤销的 seal 为父，会被判为 `integrated`，而 base 不含被撤销的内容）

- **问题**：
  - 撤销合入后，Goal 留在 `accepted(reverted)`，出口沿用 `accepted`（`03` L61）。被撤销的 seal S 仍在 base 的历史中；人合并 revert 草案后，base = …S…R。
  - 之后经 `request_changes` 等路径再次验收时，按重新 seal 的规则，“本地分支顶端仍是上一次的 seal → 新 seal 以它为父提交”（`06` L915、`10` L597–611）。新 seal S′ 的父提交就是 S。
  - 人在自己的检出中合并 S′ 时，按 git 的三方合并，合并基为 S，只带入 S..S′ 的差异；R 撤掉的内容不会回来。
  - 但 `integrated` 的判定是 `merge-base --is-ancestor <seal> <base>`（`10` L1096），S′ 是 base 的祖先，又是最近一次验收的 seal，于是 Goal 进入 `integrated`，界面显示“改动已进入 base”（`03` L61），而 base 实际上不含 Goal 的全部内容。
- **为什么是次要**：路径很窄：撤销、合并 revert、再验收、再合并。内容仍在分支中，不丢失。但 `integrated` 是 Tower 对外的事实性陈述，这里它与 base 的实际内容不符。
- **文档位置**：`03` L61；`06` L915、L917；`10` L597–611、L1096–1102。
- **期望的回答形态**：
  - 写明带 `integration_reverted_seal` 的 Goal 再次 seal 时不以被撤销的 seal 为父，按首次 seal 的规则以当前 base 为父（或写入 `-v<k>`）。
  - 或者 `integrated` 的判定对这类 Goal 另加树级条件（base 中包含 seal 相对其父的全部改动）。

### D14 路线图与可验证性

**R52-D14-01｜次要**（G46(an) 的期望结果与 `11` §11.9 的失效时点不一致）

- **问题**：
  - `11` L578 规定，经远程批准的 S0 授权“有效至本 Goal 当前 Run 结束；在没有 Run 的阶段批准的，有效至该 Goal 下一个 Run 开始”。

  - 按规则，Run 中批准的授权在**该 Run 结束时**就失效。S0 授权的用途之一是“验证器在 S0 下运行该 Goal 的代码使用同一 grant”（`11` L106），所以该 Run 提交后紧接着的验证就已经没有授权，会进入 `paused(s0_grant_pending)`，需要再次批准。
  - 用例没有覆盖这一步，期望写的失效时点也与规则相反。规则的这一后果（远程在运行中批准的 S0 授权覆盖不到随后的验证，人会被打扰两次）也没有在 `04` 或 `11` 中说明。
- **为什么是次要**：规则本身唯一。但这是安全用例组，测试作者照期望写断言，会与正确的实现相冲突。
- **文档位置**：`14` L133 G46(an)；`11` L106、L578；`16` L889。
- **期望的回答形态**：G46(an) 的期望改为“该 Run 结束时失效；随后的验证进入 `paused(s0_grant_pending)`，再次批准（本机或远程）后以同一 pin 验证”。在 `11` §11.9 或 `04` 的 S0 授权卡片中如实说明这一后果；如果这不是本意，就把规则改为“有效至本 Run 提交的那次验证结束”。

## 5. 结论

- **是否所有维度为 100：否。**
  - D1、D2、D3、D10、D12、D16 为 100，这六个维度上没有可追问的实质问题。
  - D4 96；D5 99；D6 99；D7 98；D8 99；D9 99；D11 92；D13 99；D14 99；D15 99。
- **是否还有可追问的问题：有。** 新增共 **16** 条：阻断 0、重要 1、次要 15。
  - **第 51 轮核验**：16 条全部已解决；ADR-177 的五项中 Go 一项为部分（并入 R52-D11-01）。
  - **其他核对**：
    - lint 全部通过（exit 0；ADR 177，(v) 96 条命令，(e) 145 对，(r′) 34 对）；
    - Pi v1.2.0 复核约 95 条，没有被源码否定的断言；
    - 排期结论成立：WBS 121.86；各线 26.15 / 26.35 / 27.55 / 28.39 / 13.42；余量 0.67 / 0.12 / 0.67 / 1.07 / 0.58；依赖链 19.7；增人 127.68、T 23.58、33 周；M1 38 周（2027-07-30）。
  - **不扣分的观察**：
    - **Pi 的措辞**：
      - D58 与 `06` L1169 括注中的“只会发出一条普通消息”，在认证已过期时实际是预检直接报认证错误；C39(a) 只在已认证的 faux provider 下成立。可改为“不触发登录（认证失效时直接报认证错误）”。
      - `11` L273 的 `shellPath`（第 51 轮观察）仍在。
    - **恢复前 safety 检查点的归因**：
      - 该检查点记录的是来源不明的内容，而 `Checkpoint.author` 只有 `agent`/`human`，也没有像 drain 检查点那样记 `externalPaths`。
      - M1 中回退到非回合检查点属于 M2（`06` L904、`04` L713），所以“可再撤销”在 M1 中的含义是“内容保留在影子中”。
      - M2 实现回退时，应让这个检查点带上 `externalPaths`，避免来源不明的内容恢复后被当作 Agent 的内容。
    - **`03` L78 的接管入口**未列 `ready`（`03` L54、`06` L890、`16` L42 都允许），读法唯一。
    - **人工编辑检出丢失时的选项**：“交给 Agent 继续（`goal.resume`）”（`06` L141）在 `takeoverFrom ∈ {in_review, accepted}` 时实际回到评审（继续目标为 `review`）。可改为按 `takeoverFrom` 显示文案。
    - **`03` L85** 中“撤销人的改动（回退到人编辑前的检查点）后 `retry_verify`”依赖回退到非回合检查点（M2），可加 M2 标注。另外 `run.rewind` 在 `03` §3.2 中没有转移边，M2 实现回退时宜补上。
    - **事件类型**没有集中登记。`16` 的开头没有声称登记事件类型，保留与哈希链按前缀（`engine.*`、`audit.*`）规定，不构成冲突；`06` L403 只登记“本文新增的”。可考虑在 `16` 中增加事件类型索引。
    - **`run.requested` 的发出时点**：`06` L851 写在准入之前，`07` L1581 写“准入通过时才发”。实现时取后者即可，可统一措辞。
    - **`contract.trial_criterion`** 的 `verify.requested{trial:true}` 没有对应的 `VerifyTrigger`。试运行不生成 pin、不改状态（`03` L125），可注明它不经 `verify(goal, trigger)`。
    - **密钥路径表**（`11` L156）没有列出 `~/.git-credentials`、`~/.cargo/credentials.toml` 等。S2 下用户主目录本来就是读允许列表之外的默认拒绝，所以只影响 S0 的分类与技能路径排除，可顺带补全。
    - **`06` L976** 的禁止远程清单没有列 `project.merge`/`split`，但 `06` L898 与 `16` L924 都已标为仅本机，`06` L976 也声明以 `16` 为准。
    - **`Grant.expiresAt`** 是时间戳，而远程授权按事件失效（Run 结束 / 下一个 Run 开始）。实现时可加一个事件型失效字段，读法唯一。
    - **其他文案**：
      - `04` L1071–1072 的“✓ 红灯，可证明完成”（第 51 轮观察）仍在；
      - `04` L1290 对只做过模式扫描的条目在“机密”列写“无”，可改为“未检出”；
      - `04` L1026、L1030 的简报行只写“已验证”一轨，与 `04` L1020“进度一律写两轨”不一致。
- **设计是否完成：主干已收敛，剩下的是边角与文案。**
  - 第 51 轮的三条重要安全问题与十三条次要问题都已按所选方案落地，没有发现回退。
  - 本轮唯一的重要问题（R52-D11-01）是 ADR-177 推广白名单时漏掉的一行，修复只需改一行。
  - 15 条次要问题都可以用一条规则、一处登记或一处文案关闭，不需要改变架构：
    - 远程规则的封闭清单；
    - 两处副本的内容判定；
    - 低频路径（settle 重跑、手动重建、合同修订、撤销后再合入）的唯一去向；
    - 交还参数的落盘时点；
    - 界面文案与语法的残留。
