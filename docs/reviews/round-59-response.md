1. 把说法改弱，但保证为真；
2. 删除或推迟不属于 M1 主循环的机制；
3. 在已有的唯一定义处加至多一条守卫、一行或一个字段。

本轮不新增状态、事件或表，也不新增命令与决定种类。安全不变式全部保持，拿不准时取更严格的行为。安全问题只写到设计层面。

## Pi v1.2.0 引用

都已用 `git -C research/pi-mono show v1.2.0:packages/coding-agent/<path>` 核实：

- `src/core/extensions/runner.ts:636-646`：`getAllRegisteredTools()`，“first registration per name wins”。
- `src/core/resource-loader.ts:778-781`（`loadFinalExtensionSet`）：先按 `extensionPaths` 排列文件型与 builtin 扩展，再 `push(...inlineExtensions)`，所以 inline 扩展排在最后；`:1145`：inline 扩展的路径为 `<inline:<name>>`，tower-goal 即 `<inline:tower-goal>`。
- `src/core/agent-session.ts:3529-3553`（`_refreshToolRegistry`）：先写内置工具（`builtin:<name>`），再按 `[...扩展工具, ...customTools]` 的顺序 `set`，后写者胜。因此 `customTools`（`<sdk:<name>>`）压过同名扩展工具，而扩展工具压过同名内置工具。
- **结论**：用户扩展先于 tower-goal 注册同名工具时，生效的是用户的工具。tower-goal 要作为最后一个 `tool_call` 处理器（`05` §5.6.5 第 7 步），不能先加载。因此选择 Run 开始前的来源自检。
