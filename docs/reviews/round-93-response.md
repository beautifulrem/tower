# 第 93 轮评审回应

决策：
- ADR-221（`15` 末尾，L4114 起）；
- ADR-220、ADR-199、ADR-125 标题加 “Amended by ADR-221”；
- ADR-133 第 93 轮补记（`15` L1429）。

本文件关闭 `round-93.md` §4 的 7 条次要条目与 §5 的 14 条观察。行号为修改后的位置。

**收敛规则**（同 ADR-186–220）：只用三种办法关闭条目：
1. 把说法改弱，但保证为真；
2. 删除或推迟不属于 M1 主循环的机制；
3. 在已有的唯一定义处加至多一条守卫、一行或一个字段。

**本轮的取向**：七条都是 ADR-220 新机制的规格缺口或连带后果。每条都先找可以复用的已有限额、路径与命名，不新增机制：
- 辅助进程的内存不另立预算行，改为按次启动的一次性子进程，归入已有的进程树预留；
- “必然被拒的审批”复用 `hardFloor`（`decide` 首行）；
- 写回失败处理的崩溃窗口复用情形 E 的“旁路目录 + `renameat`”与 ADR-199 的 `.kept-<时间>` 命名；
- Pi 的完整输出文件如实登记为 S2 下不可读，不把 Host 的临时目录交给 Agent。

不新增状态、事件类型、表、列、命令、决定种类、Needs-You kind、landmark 或常驻进程。安全不变式全部保留：
- 文件工具的访问仍在访问那一刻由 S2 判定；
- 硬底线、密钥路径表与上下文文件名的写拒绝不变；
- 新的 forbid 只会更严（判定与 S2 不一致时访问仍由 S2 判定）；
- “经批准的目标”只改告警级别，拒绝本身不变。

安全问题只写到设计层面。

## R93-D5-01（次要）：文件辅助进程的上限、超时与崩溃

**唯一定义**：`11` §11.3.1 使用时强制（L160）；取值登记在 `16` §16.2.8（L895）。

- **形态与生命周期**：每次文件操作一个一次性子进程。
  - 在与沙箱 bash 同一包装、同一档位中执行系统自带命令：`cat`；`head -c 4100`；经 `sh` 重定向写入，内容走标准输入、路径作参数；`mkdir -p`；`test`。
  - 都在 S2 允许执行的系统路径中，不加载 Pi，不另设运行时或构建目标。
  - 图像类型由 Host 对前 4100 字节按 Pi 的纯字节判定求出（移植 `utils/mime.ts:3-23`，C42 与 Pi 比对）。
  - 原文的 “以 Electron 自带的 Node 运行一个脚本” 不采用：该可执行文件不在 S2 读允许列表中，要用它就得放宽档位。
- **上限**：单次读取的回复与写入的请求 ≤ **16 MB**。
  - Pi 的 `read`/`edit` 整读整写，所以上限按 Host 承受得起的单文件大小取，不按 Pi 截断后的 50 KB。
  - 超出时工具结果写 “文件超过 16 MB，Tower 的文件工具不读写它；请用 bash 分段处理（如 `sed -n`、`head -c`）”。
- **超时**：每次操作 10 s。超时时先杀掉该进程、等它退出，再报失败，所以报告为失败的写入不会在之后落盘。
- **崩溃**：
  - 启动失败、崩溃或回复不合规都只使这一次操作失败，工具结果写明原因，不重试，之后的操作照常各起一个进程；
  - 反复失败由 `07` §7.7.1 的循环/停滞检测处理，不另设规则（`engine_error`/`stalled` 路径不需要）。
- **停止顺序**：Pi 的 `edit`/`write` 在中止时也等文件操作结束才返回，所以 settle 终止进程时没有仍在写的辅助进程。评审期望的 “在 settle 第 3 步之前停止” 与 “下一次操作时重启” 因按次启动而不再需要。

**同步**：
- `05` §5.3.5 骨架注释（L386）；
- `16` §16.2.8 一行；
- `00` §0.5.1 内置工具一行写明 16 MB 的限制与改用 bash；
- C42 (g)：17 MB 失败并返回分段提示；挂起 10 s 后失败、进程已不在、之后照常；图像判定与 Pi 逐项相同。

## R93-D5-02（次要）：Pi 的完整输出文件在 S2 下读不到

**决定**：登记为限制，并改正 `11` L522。没有采用 “把 Host 的 `TMPDIR` 设为 S2 可读的 Tower 目录”，理由有三：
- Pi 没有改变输出目录的选项，只能改整个 Host 进程的 `TMPDIR`；
- 打包模式下一个 Host 承载多个 Goal，同一目录对它们都可读，Goal 之间互相可见；
- 放到 `~/.tower` 之下（S2 读拒绝）时，Agent 按 Pi 的提示用 bash 读取会产生 `tower_data` 类的 severity 2 告警；而系统临时目录的拒绝只是 `system` 类的 severity 1。

**改动**：
- `11` §11.7.1 残余（L523）：
  - 全文文件在 Host 的系统临时目录（你自己的 `TMPDIR`，0600），不在 S2 读允许列表中，S2 下 Agent 读不到；
  - `read` 按 R93-D8-01 直接 forbid，返回的文字说明 “在 bash 中把输出重定向到 `$TMPDIR` 下的文件，再分段查看”；
  - 观察器把它复制为证据之后删除它；
  - MCP 二进制资源与 codemode 图像文件，Pi 与 Tower 都不删除。
- `05` L465 的唯一定义（Host 环境不引用 Agent 可写的位置）不变。两处的矛盾以 `11` 改为真而消除。
- `07` §7.2.2：删去不成立的 “Pi 的临时文件会被清理”，改为观察器复制之后删除它（不跟随链接）。
- `09` §9.12.4 “清除一个 Goal” 如实列出：清除不覆盖 MCP 与 codemode 的这类文件（不能按 Goal 区分，由系统清理）。
- `00` §0.5.1：这些文件与 Pi 文档目录 S2 下读不到。
- C42 (f)：读取 Host 临时目录中的全文文件，不出审批卡、直接返回说明。

## R93-D6-01（次要）：写回失败处理自身的崩溃窗口；“改名保留”的定义

**唯一定义**：`06` §6.4.3 `inspect.bring_back` 行的 “写回在本进程中失败”（L914）。
- **①**：在同一父目录的旁路目录中物化，完毕后以 `renameat` 改名到原路径（与情形 E 相同）。中途崩溃时原路径仍不存在、`syncing` 仍在；`06` §6.1.6 续写之前丢弃旁路目录（L144），续写再失败时重做 ①。残缺的目录不会被当作人的副本。
- **②**：还原**整个**写回集合（当前内容已等于还原目标的跳过，幂等），不只 `written`。崩溃前已写而未记入 `written` 的路径同样被还原，“完成” 因此有定义。
- **③**：
  - 还原没有完成时，仍在原位的卫星**先在事务之前**改名保留（工作目录与 gitdir 各自改名），再在事务中置 `satellite_rebuilding=1`；
  - 改名之后、事务之前崩溃时 `syncing` 仍在，续写因卫星已不在而失败，再进入 ③；
  - `06` §6.1.6 卫星重建中途崩溃一行（L140）写明：原路径上只可能是重建自己 `rename` 到位的目录，`.kept-*` 不在此列——旧卫星不会被删除。
- **④**：Needs-You 在 ③ 的同一事务中生成（观察 9）。

**“改名保留” 的定义**：`10` §10.2 新增 “Tower 自动改名保留”（唯一定义，L256）。
- 只有两处：删除来源目录之前的比较不同（R93-D6-02）；写回失败转入重建时仍在的卫星。
- 做法与 `moveAside` 相同：同一父目录内不覆盖地改名为 `<原名>.kept-<时间>`（重名加序号）。
- 改名后的目录：从不删除、不再管理；删除卫星与清除都不认领；Goal 页与下一条通知按 `<goalId>.kept-*` 列出；编号分配跳过（`02` §2.2 同步）；S2 与验证器沙箱照常拒绝。
- §10.2 原句 “Tower 也不自行改名” 限定为 “不为新建而自行改名”。

**验收**：G31（`14` L107）补一组：① 物化到一半时杀掉 Tower、续写再失败——重启前原路径只有旁路目录，之后以 T1 重新建立检出、旁路目录已删除，人的改动不丢，条目写明。

## R93-D6-02（次要）：“删除前比较” 的适用范围与口径

**决定**：推广到所有删除来源目录的路径，不收窄。

- **带回删除检验目录时中断的重启规则**（`10` §10.8.3）由 “直接删除” 改为按同一比较处理（T1 取该决定的 `targetTree`）。残缺的目录因此改名保留，不会删掉写回之后才保存的改动。

## R93-D8-01（次要）：S2 必然拒绝的访问仍出审批卡；批准之后又以 severity 2 告警

**唯一定义一**：`11` §11.3.1 新增 “S2 必然拒绝的访问不询问”（L162）。
- **判定**：S2 下，文件工具求出的路径按 “比较的规范形式” 对照本 Run S2 档位的同一份路径数据（随 `policy.json` 下发）：
  - 拒绝一侧任一形式命中即算，允许一侧以 `real` 判定；
  - 读取在读允许列表之外或命中读拒绝（含密钥路径表），写入在写允许列表之外或命中写拒绝（含上下文文件名）。
- **处理**：该调用带 `hardFloor`（forbid）：不出审批卡、不可授权、不发生访问、不记 `sandbox_violation`。返回给模型的文字说明沙箱不允许，并给出 `ask_user` 与重定向输出的替代做法。
- **不一致时**：访问仍由 S2 判定。误判为允许的，回到 “批准后被拒绝”；误判为拒绝的，只少一次本可成功的读写。两种都不越权。
- **bash 不适用**：一条命令的读写只能启发式求出，审批卡照旧。

**唯一定义二**：`11` §11.6.2 新增 “经批准的目标”（L372）。
- 被拒绝的访问来自经人批准的调用、且目标在该次批准所列的路径之中时，不论类别都记 severity 1 的 chip、不生成 Needs-You，不再以 “可能表明提示注入” 告警；
- 目标不在所列路径之中的照常按类别分级；
- 这不是规则 F 的降级，ADR-125 的 “凭据读取永不降级、不入良性清单” 不变。

**引用**：`07` §7.10.1 severity 1 一行、`16` §16.1.6；`04` §4.10.2 写明凭据审批卡只在批准能起作用的地方出现；`00` §0.5.1。

**验收**：
- C42 (f)；
- G46 `~/.aws` 一组：`read` 直接 forbid；另以 bash 读取、人批准，只有一条 severity 1 提示。

## §5 观察

1. **`withFileMutationQueue` 的 `realpath`**：`11` §11.3.1 改为 “求出的绝对路径只经它们读写文件内容；`operations` 之外只有两处元数据访问”。残余 (ii) 合写两处，“只涉及元数据”，写明错误原样成为工具错误、不记 `sandbox_violation`，以及打包 Host 中单一登记链的延后效应。D61 同步并补行号。
2. **`write` 的前像**：`05` gate 第 3 步（L1040）写明 Host 按 `10` §10.1.3 读取（逐级不跟随、只接受普通文件、带上限与超时），超出或不是普通文件时省略 `prevSha256`（该字段本就可选）。
3. **`read` 的图像缩放**：骨架传入 `autoResizeImages: settingsManager.getImageAutoResize()`，与内置 `read` 同源；`00` §0.5.1 写明照常生效。
4. **降级哨兵的名字**：`05` §5.3.5 自检一条（L444）写明文件工具来源不符用同一哨兵 `bash_overridden` 与同一文案；只可能在 RPC 下出现，SDK 下四个工具的检查都只是回归保护。
5. **Pi 文档目录**：`00` §0.5.1 写明 S2 下读不到（按 R93-D8-01 直接拒绝）。
6. **`04` 带回一侧的措辞**：重建提示补 “完成后可再次带回或关闭检验”，另写明原来的工作目录改名保留的路径。
7. **`write_back_failed` 的关闭条件**：`08` §8.4（L211）改为按条目生成之后的事件关闭（交还或带回成功、放弃改动、放弃 Goal、检验关闭），不按 `human_checkout` 是否为空。
8. **出口与验收组**：`08` §8.8（L516）补 “放弃 Goal” → `informative`；G31 不可写一组补断言出现 `write_back_failed`。
9. **条目与 ③ 同一事务**：随 R93-D6-01，④ 的 Needs-You 在 ③ 的事务中生成。
10. **重建来源的措辞**：
    - `06` §6.4.3 ③ 写明告知为 “检查点 n 的改动未进入工作目录，仍在检查点 n 中”，不写 “无法恢复”；
    - `10` §10.8.4 第 6 步改为 “接管期间只用第 1 步的检查点 k”，写回失败时 k 不一定是链上最新的。
11. **带回重建期间**：`06` §6.4.3 带回出口写明：重建进行中返回 `E_STATE`；重建树不等于 pin 时情形 E 触发 I2、转入验证，回到评审之后再带回才按冲突处理。删去 “此时前置条件都成立”。
12. **`00` L104 的措辞**：改为 “S2 读允许列表之外的文件（工作目录、系统与工具链路径、Pi 资源目录与 Tower 提供给 Agent 的文件之外的一切）”。
13. **README 与扫描名单**：
    - README L19 补 `read`/`edit`/`write` 被取代、`grep`/`find`/`ls` 不提供（改用 bash 中的同名命令）；
    - `05` §5.10 扫描名单补 `powershell`；
    - `04` §4.18.1 确认卡补其他内置工具名的写法。
14. **放弃时的询问**：`10` §10.8.4 放弃 Goal 一条在重建进行中把 “先交还” 置灰，并写明 “工作目录正在重建，完成后才能交还”。

## 偏离与未决

- **R93-D5-01 的形态由 “Tower 随附的 Node 小程序” 改为 “档位中执行的系统命令”**：
  - 前者的可执行文件不在 S2 读允许列表中，要用它就得放宽档位；`$SH/tools` 中的 Node 随项目的 `VerifyProfile.node` 下载，不一定存在，不能依赖。
  - 代价是图像类型的纯字节判定要由 Host 移植 Pi 的约 100 行（C42 比对，与 D60 的 `piResolve` 同一做法）。
  - 评审期望形态中的 “退出或超时后在下一次操作时重启” 与 “在 settle 第 3 步之前停止”，因按次启动而不再需要。
- **16 MB 低于 Pi 的能力**：Pi 自身不设上限。超过 16 MB 的文件在 Tower 中只能经 bash 处理，已在 `00` §0.5.1 登记。取值是假设值（⚫），E7 回填。
- **R93-D5-02 取 “登记为限制”**：Agent 在 S2 下读不到 Pi 的完整输出文件。MCP 二进制资源与 codemode 图像文件留在系统临时目录、清除不覆盖它们，已在 `09` §9.12.4 如实写出，这是一处隐私上的弱化。bash 的全文文件由观察器复制为证据后删除，仍随 Goal 清除。
- **R93-D8-01 的 forbid 只用于文件工具**：bash 的审批卡照旧。S2 下 bash 读取凭据的审批仍是 “批准也不起作用” 的决定，只是批准之后不再告警。按命令的启发式判定去 forbid，可能挡掉命令的其余部分，这里取不改。
- **R93-D10-01 没有找到可合并的已有进程**，按 “并入已有类别” 关闭；没有采用 “单列一行”，因为常驻进程会使打包的 15 MB/Goal 不成立。
- **自动改名保留会留下目录**：`.kept-*` 由人自行删除，与 ADR-199 相同。删除检验目录中断后的残缺目录也会被改名保留（宁可多留，不删改动）。
- **排期**：估计按真实实现计；M1 维持 38 周，各线余量为正。
- **未决**：无。
