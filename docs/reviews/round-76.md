**ADR-203 的主干成立**：
- **名字集合**：与 Pi v1.2.0 的候选清单一致。
- **比较规则**：取 `10` §10.1.2 的名字比较规则。它比 APFS 的大小写不敏感更宽，多出来的只是多报，不会漏报。
- **非 ASCII 等价变体由复核与验证兜底**：
  - 复核对完整差异按名字规则筛选，`protected` 与验收标记引用同一行。Seatbelt 只覆盖 ASCII 大小写，这一残余已写明。
  - Pi 在 APFS 上实际会加载的非 ASCII 变体（Unicode 大小写折叠的等价字符），NFKC 加大小写折叠同样能识别。
- **项目系统提示改传内容**：经 `systemPromptOverride`/`appendSystemPromptOverride` 传入，与 Pi 源码一致（见文首）。复核与加载之间文件消失的退化随之消除。
- **M2 的 RPC 备忘**（`11` L596）：如实记下了 `runMigrations` 与 `--system-prompt` 两点。
- **新 lint 条目**：能拦下三种旧写法。它只按字面比较，所以 R76-D13-01、R76-D12-01 所述的两处不在它的范围内（见 §3.1）。

**关于 “大小写折叠后的写拒绝是否误拒合法写入”**：
- 会误拒。S2 下，路径最后一个分量折叠后形如 `agents*.md` 或 `claude.md` 的文件（例如 `docs/agents.md`、`agents-guide.md`），在任意深度都会被 bash 写拒绝。
  - 文件工具改它们走 `edit.protected`（ask）；
  - 验证时按 `protected_path` 列出，合同放开保护后至少为 severity 2；
  - 合同放开 `protected` 不解除 Seatbelt 的写拒绝。
- 这一过宽在 ADR-203 之前就有（大写的 `AGENTS-*.md`），折叠后扩展到常见的小写文档名。
- 取舍本身可以接受：在大小写不敏感的卷上，`docs/agents.md` 对在 `docs/` 中运行的 Pi 确实是上下文文件；代价也只是多一次批准。
- 但 `00` §0.5.1 的限制清单没有写，记为 §5 观察 1。

### D5 Agent 架构与 Pi 集成

**R76-D5-01｜次要**（由 Tower 显式传入的祖先 `.agents/skills`：范围写作 “与 Pi 相同” 但不同；策略门不认这些路径）

- **问题**：
  - **正文的规则**（`11` L584–L585，ADR-202 起）：
    - 第一组含 cwd **任意祖先目录**中的 `.agents/skills`，“与 Pi 在信任下的收集范围相同（`trust-manager.ts` L196–207）”。
    - Tower 在批准信任时记录 worktree 所有祖先目录（直到文件系统根）中存在的 `.agents/skills` 及其内容哈希；每个 Run 重新枚举，出现新目录或哈希变化 → 以不信任启动。
    - 复核为信任时，这份清单中的普通文件以 `additionalSkillPaths` 传入。
  - **Pi v1.2.0 的实际行为**：
    - 被引的 `trust-manager.ts:185-207` 是 `hasTrustRequiringProjectResources`，只用来判定要不要询问信任，它确实一直走到根，但只做判定。
    - 实际收集在 `package-manager.ts:474-491` 的 `collectAncestorAgentsSkillDirs`：从 cwd 向上，**止于最近的含 `.git` 的祖先目录**（`findGitRepoRoot`，`:459-472`）。
    - 调用处排除用户级 `~/.agents/skills`（`:2464-2468`）；被引的 `trust-manager.ts` 同样排除它。
    - 因此用户在自己的检出中运行 Pi 时，只收集到仓库根为止，仓库根以上的 `.agents/skills` 一概不加载；卫星中没有 `.git`，信任下的 Pi 才会走到根（或走到某个含 `.git` 的上层目录）。
  - **两处后果**：
    1. **范围**：正文没有写排除用户级目录。卫星默认在 `<checkoutParent>/.tower-wt.noindex/…` 下，通常位于 `$HOME` 之内，`~/.agents/skills` 就是它的一个祖先 `.agents/skills`。照字面实现会把它记进清单：
       - 用户级技能会经显式路径再传一次，与 Pi 自己加载的用户级技能重名；
       - 用户此后每次增改自己的用户级技能，都会使所有受信任项目的复核为不信任。第一组不再传入，卡片显示 `◇ 项目 Pi 配置已被修改`，列出的却是用户级文件。
       - 此外，Tower 传入的仓库根以上的技能是用户自己运行 Pi 时看不到的。`09` §9.11 与 `10` §10.4.3 所立的 “Agent 看到的与你本地 Pi 一致” 对技能不成立，正文也没有说明这是有意的超集。
    2. **读取分类**：Pi 在系统提示中列出技能，并要求模型用 `read`（或 bash）读取技能文件（`system-prompt.ts:172-180`）。
       - S2 读允许列表有 “Host 实际枚举到的已启用技能 `baseDir`”（`11` L349，`05` L446），bash 读这些文件不受阻。
       - 策略门的 `read.pi_resources`（`16` L251 为 “单一来源”，`11` L30 同）不含祖先 `.agents/skills`，也不含 “Host 枚举到的技能 `baseDir`”。
       - 按 `11` L146，worktree 之外、不命中 Pi 资源目录的读取归 `read.external`，在多数预设中为 ask（`11` L79）。
       - 结果：一个经人批准、由 Tower 有意传入的技能，模型每次按 Pi 的约定读取它时都要人批准；bash 读同一文件却是静默的。
- **为什么不是观察**：
  - 第 1 点：正文写明 “与 Pi 相同” 并给出引文，照引文（排除用户级目录、走到根）与照字面（所有祖先、不排除）会得出两种实现，用户可见的后果不同（复核反复变为不信任）。
  - 第 2 点：两份 “唯一/单一来源” 的允许范围（S2 读允许与 `read.pi_resources`）对同一组路径不一致。
- **文档位置**：`11` L30、L79、L146、L349、L584–L585；`16` L251；`05` L446；`09` L460；`10` §10.4.3。
- **期望的回答形态**：
  - 在 `11` L584 写清祖先 `.agents/skills` 的范围，二选一：
    - 与用户在检出中运行 Pi 相同：止于仓库根，此时祖先检查只剩卫星根本身，已在 base 树中，可以删去；
    - 或保留到根的超集，写明这是有意的，并说明理由。
  - 两种写法都须排除用户级 `~/.agents/skills`，改正引文（`package-manager.ts:459-491`、`:2464-2468`）。

### D8 注意力与交互

**R76-D8-01｜次要**（`engine_crash` 的 Needs-You 何时生成，四份文档不一致）

- **问题**：
  - `16` L195（`pauseReason` → Needs-You kind 的登记，lint (w′) 的依据）：`engine_crash` → `stalled`（子类型 `crashed`），**一次自动恢复失败后**才生成。

  - `08` L385：心跳迟到超过 30 s 时，崩溃与挂死**都生成** `stalled{unresponsive|crashed}`（severity 2，`agent_blocked`，基础级别 L3，即断点打扰）。没有提到自动恢复。

  - `06` L64、`08` L385 改为引用；`12` L430 补上 “自动恢复失败后 `◆`”，或在 L406 的例外中列出 `engine_crash`。

### D11 安全与自主度

**R76-D11-01｜次要**（名字比较规则只用于上下文文件；`.pi/**`、`.agents/**` 等受保护名字在 `protected` 与验收标记中仍区分大小写）

- **问题**：
  - **ADR-203 的范围**：
    - `16` L287 只为上下文文件规定了名字比较规则。`02` L308 的注释、`11` L210 的括注、`07` L1275 的 “大小写变体同样标记”，都只挂在上下文文件上。
    - 同一默认 `protected` 列表中的 `.pi/**`、`.agents/**`、`.mcp.json`、`.envrc`、`.npmrc`、`.husky/**`（`02` L307）与 `.pnpmfile.cjs`（`11` L210），`07` L1275 的 `.pi/**`、`.agents/**`、`SYSTEM.md`、`APPEND_SYSTEM.md`，以及 `07` §7.6.3 的配置路径集合（含 `.npmrc`、`.env*`），都没有比较规则。
    - 默认语义是区分大小写的 glob：`07` L1249 的 `matches(path, fence.protected)`，`11` L150 的 `match(scope.protected)`。
  - **ADR-203 同时让 Seatbelt 对 `.pi`、`.agents` 两个目录名折叠**（`11` L350），并称 “与 §11.3.3 一致，形成双保险”。对这两个目录，双保险的另一半（`protected` 与验收标记）并不按同一规则识别。
  - **这些名字在 macOS 默认卷上都按大小写不敏感解析**：
    - 读取它们的工具都以固定名字打开文件，在大小写不敏感的卷上，只差大小写的变体会被当作原名读取。例如合并后用户自己的 Pi（项目受用户信任时）、包管理器、direnv、其他读取 `.mcp.json` 的客户端。
    - 这与 R75-D11-01 中 Pi 读上下文文件是同一机制。
  - **照字面实现**：base 中没有某个受保护名字时，Agent 新建一个只差大小写的同名条目：
    - 写入时不触发 `edit.protected` 的 ask；
    - 验证时不按 `protected_path`（severity 3，阻止进入 `in_review`）列出；
    - 验收面板不标为 “给 Agent 的指令文件”；
    - 它只以普通新文件出现在差异中。
  - **适用范围**：
    - S2 下，`.pi`/`.agents` 的变体已被 Seatbelt 拒绝，其余名字不在 Seatbelt 规则内；
    - S0 下全部适用。
    - 已存在的同名条目不受影响：写入落到原文件，差异中显示的是原名。
- **所放进的后果类别**：
  - 这些路径被列为受保护，理由是它们 “影响后续 Run 的上下文、信任或执行”（`11` L208）；ADR-201 起，事后发现的受保护写入又统一交给验证时的 `protected_path` 处置。
  - 名字变体让一类会影响执行或配置的文件绕过这道专门的人工关口，以普通改动的身份并入仓库，在用户本机生效。例如项目级包管理器配置与安装钩子、项目级 Pi 配置。
  - 危害有界：文件仍在差异中，验证仍在沙箱中运行，部分读取方另有自己的批准。所以记为次要。
- **为什么不是观察**：
  - ADR-203 已确立 “按名字识别受保护路径时，名字须按文件系统可能视为同名的规则比较” 这一原则，并对 `.pi`/`.agents` 的 Seatbelt 规则照此做了。`protected` 与验收标记对同一组名字却仍区分大小写，同一不变式在两道防护中语义不同。
  - 实现者没有依据判断其余名字该不该折叠。
- **文档位置**：`02` L307–L308；`11` L150、L208、L210、L350；`07` L1249、L1273、L1275；`16` L287；`15` ADR-201、ADR-203。
- **期望的回答形态**，二选一：
  - 在 `02` §2.5（或 `11` §11.3.3）的 `protected` 处写一句：`protected` 模式与 `07` §7.6.3 的路径集合按路径分量用 `10` §10.1.2 的名字比较规则匹配（与上下文文件同一规则）；`07` L1275 的 “大小写变体同样标记” 扩到整句；G 用例补一组（例如 S0 下新建只差大小写的 `.pi` 目录与包管理器配置文件，期望 `protected_path` 列出）。

### D12 记忆与学习（隐私）

**R76-D12-01｜次要**（“导出到 AGENTS.md” 的目标选择不符合 Pi 每个目录只取第一个候选的规则）

- **问题**：
  - `09` L468：取条目 `appliesTo.paths` 的公共前缀目录，“该目录下已有 `AGENTS.md` 就用它，只有 `CLAUDE.md` 就用 `CLAUDE.md`，都没有就新建 `AGENTS.md`”。
  - 同一节的事实句（`09` L450，ADR-203 改写）与 `16` L287 写明：Pi 在每个目录中按 `AGENTS.override.md`、`AGENTS.md`、`AGENTS.MD`、`CLAUDE.md`、`CLAUDE.MD` 的顺序**只取第一个存在的文件**，大小写不敏感的卷上任何变体都算存在。
  - 选择规则因此会把补丁写进 Pi 在该目录中不加载的文件，或与已有文件冲突：
    - 目录中有 `AGENTS.override.md` 时，补丁写进同目录的 `AGENTS.md`，Pi 在该目录只加载前者；

  - 导出之后，`09` L472 询问是否把这些条目退役（`retiredReason:"exported"`）。
- **为什么是次要**：
  - 第一种情形下，人照流程操作，结果是这些规则既不再由 Tower 注入，也不被 Pi 读到。人以为它们已进入仓库约定，实际从 Agent 的上下文中消失，没有任何提示。
  - 第二种情形改变了仓库原有指令文件的生效与否。
  - 都限于少数目录形态，导出与退役也都是人的显式动作，所以是次要。ADR-203 改写了同一节的事实句，没有同步这一步。
- **文档位置**：`09` L450、L465–L472；`16` L287；`04` 记忆管理器的导出入口。
- **期望的回答形态**：
  - 目标文件取 “Pi 在该目录实际加载的那个候选”：按 `16` L287 的顺序与比较规则取第一个存在者；都不存在时新建 `AGENTS.md`；
  - 或者在目标不是 Pi 在该目录实际加载的文件时提示，并不提供退役。
  - 一句话即可。

### D13 隔离、git 与并发

**R76-D13-01｜次要**（回退位置的祖先上下文差异仍按 `AGENTS*.md/CLAUDE.md` 通配识别）

- **问题**：
  - `10` L525（§10.4.3 位置选择第 3b 步）：“列出 checkout 祖先目录（仓库根以上）中的 `AGENTS*.md`/`CLAUDE.md`，与回退路径祖先中的同类文件比较”；有差异时显示警告，并在项目受信任时把缺失的祖先上下文文件注入简报（L526–L527）。
  - `09` L460–L463 描述同一步骤时用的是 `contextFiles(checkout)` 与 `contextFiles(worktree)`，即 Pi 将加载的集合；缺失文件中位于用户检出之外的，内容快照写入 `contract.md` 的 `## Imported context`。
  - `16` L287 说 “凡按名字识别上下文文件之处” 都用该行的集合与比较规则，但它的 “用到它的四处” 没有列这一步，`10` L525 也不引用它。
  - 照 `10` L525 字面实现，与 Pi 实际加载的集合在三处不同：
    1. 区分大小写的通配会漏掉 Pi 在大小写不敏感的卷上实际加载的变体（例如祖先目录中小写的 `claude.md`）。漏掉的文件既不提示也不导入，Agent 看到的上下文与用户本地 Pi 不同，界面却不提示。
    2. `AGENTS*.md` 会把 Pi 不加载的文件（例如 `AGENTS-notes.md`）也算作上下文文件，并导入 `contract.md`。
    3. 不按 “每个目录只取第一个候选” 判定：同一目录同时有 `AGENTS.md` 与 `CLAUDE.md` 时，两者都会被比较、被导入，而用户本地 Pi 只读前者。
- **为什么是次要**：
  - 只在回退位置发生，影响的是给 Agent 的指令内容是否与用户本地 Pi 一致，以及 “Agent 看到的上下文文件与你本地 Pi 不同” 这一提示是否可信，不涉及沙箱。
  - 两份文档对同一步骤的写法不同，实现会分化。
- **文档位置**：`10` L514、L525–L527；`09` L460–L463；`05` G31 L1297；`16` L287。
- **期望的回答形态**：
  - `10` L525 改为引用 `09` §9.11 的 `contextFiles()`，并在 `16` L287 写明 `contextFiles()` 按该行的集合、顺序与比较规则求值。
  - 把 “用到它的四处” 改为列出全部用途（含 “生效上下文” 面板与导出），或改写为 “凡按名字识别上下文文件之处”，不计数。

### D15 文档一致性与可执行性

**R76-D15-01｜次要**（`16` 检测器表的 `symlink_escape` 一行是已登记为被取代的旧规则）

- **问题**：
  - `16` L176 的 “子类型 / 规则” 列：“`pinSafetyCheck`：pin 中**新增或改变**的符号链接……终点为绝对路径或越出仓库根（ADR-112）”。
  - `16` L430（§16.1.13 被取代的说法）登记的正是这条旧说法：“`symlink_escape` 只检查新增或改变的链接；解析经过 tree 中不存在的分量时结论未定义；……”，现行规则为 “pin 中全部链接整链解析；不存在的分量与 `.git` 分量视为逃逸”（ADR-116）。
  - 现行定义在 `10` L188（§10.1.2 规则 (b)），比 `16` L176 多三项：
    - 在 pin 中解析不安全、而在 base 中安全或解析结果不同的未改动链接也命中（例如路径中的目录被换成链接，R12-D11-01）；
    - 经过 tree 中不存在的分量视为不安全；
    - 经过 `.git` 等价分量视为不安全。
    - 另有 base 豁免（ADR-124）。
  - (D) 只做短语比较，两者措辞不同，没有拦下。
- **为什么是次要**：
  - `16` 是登记处。照 `16` L176 写检测器或写测试清单，会重新打开 ADR-112/116 已关闭的逃逸路径（例如经由被替换为链接的目录逃出仓库根）。
  - 该行注明了出处 `10` §10.1.2，实现者多半会去读，危害有界。
  - 但这是同一份登记文档自相矛盾，而且矛盾的正是一条安全检测规则。
- **文档位置**：`16` L176、L430；`10` L186–L188；`07` L1509；`15` ADR-112、ADR-116、ADR-124。
- **期望的回答形态**：
  - `16` L176 的规则列改为现行规则的一句摘要（全部链接整链解析；不安全的四种情形；命中条件含 “base 中安全或解析结果不同”；base 豁免），或只写 “见 `10` §10.1.2 (b)”；
  - (D) 补一个能命中旧说法的短语。
