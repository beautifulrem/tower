决策：
- ADR-220（`15` 末尾，L4009 起）；
- ADR-219、ADR-190、ADR-189、ADR-188 标题加 “Amended by ADR-220”；
- ADR-133 第 92 轮补记（`15` L1421）。

本文件关闭 `round-92.md` §4 的 3 条重要条目与 §5 的 14 条观察。行号为修改后的位置。

**收敛规则**（同 ADR-186–219）：只用三种办法关闭条目：
1. 把说法改弱，但保证为真；
2. 删除或推迟不属于 M1 主循环的机制；
3. 在已有的唯一定义处加至多一条守卫、一行或一个字段。

**本轮的取向**：三条都是 “判定的对象与实际发生的事不一致” 或 “一个本不该长期存在的状态”。所以优先采用让整类问题不可能出现的结构性改动与删除，不再给分类器加路径检查规则：
- **R92-D11-01**：判定与访问之间的窗口不靠更多的判定关闭，而是把文件工具的访问放进已有的边界（S2）。
- **R92-D11-02**：只按一个点分类的目录型工具直接删除。
- **R92-D6-01**：“写回失败而仍在 `syncing`” 的状态整体消除，复用已有的情形 E 重建。

复用的已有机制：
- 沙箱 bash 的 `customTools` 注入、来源自检与 S2 档位（ADR-041/066）；
- `excludeTools` 白名单（ADR-189）；
- `10` §10.16.2 情形 E 的重建、`10` §10.2 的改名保留；
- `stalled` 子类型（同 ADR-211 的 `human_checkout_lost`）。

新增的：
- 一个 Tower 自己的 `operations` 实现与它的文件辅助进程；
- 依赖清单一行（D61）、一项契约测试（C42）；
- 一个 `stalled` 子类型 `write_back_failed`；
- `11` §11.3.1 的两条定义：使用时强制、比较的规范形式。

不新增状态、事件类型、表、列、命令、决定种类、Needs-You kind 或 landmark。安全不变式全部保留：
- 第 3 条硬底线、`edit.outside_worktree` 在各预设 forbid、密钥路径表都不变；
- 有取舍处都取更严格的一侧：文件工具的权限收紧到不超过沙箱 bash；受保护位置按两种形式比较，任一命中即命中。

安全问题只写到设计层面。

## R92-D11-01（重要）：分类之后、执行之前文件系统可变

**决定**：文件工具实际访问的位置由访问那一刻的 OS 沙箱判定，分类只决定审批分级（forbid / ask / notify / silent）。

**唯一定义**：`11` §11.3.1 新增的 “使用时强制”（L160）。
- **做法**：Tower 以包入口导出的 `createReadToolDefinition`、`createEditToolDefinition`、`createWriteToolDefinition` 构造三个工具，与沙箱 bash 一样以 `customTools` 注入，并传入 Tower 自己的 `operations`。
- **辅助进程**：S2 下每个文件操作（`readFile`、`access`、`detectImageMimeType`、`writeFile`、`mkdir`）由一个文件辅助进程执行。它的约束：
  - 与沙箱 bash 同一包装、同一档位；
  - 每个 Run 一个，由 Tower 启动与终止，不带 Run 令牌、不算 Agent 进程；
  - 只做这几种文件操作，内存计入该 Goal 的 Engine Host（`13` §13.8.1）；
  - 回复当作不可信数据，带大小上限与超时。
- **强制的方式**：操作系统在打开的那一刻按读写允许列表判定真实路径。分类之后换上的符号链接、路径分量或 `..` 都不能把访问带出 S2 允许的范围；被拒绝时该工具报错，并记 `sandbox_violation`。
- **权限**：文件工具的权限从此不超过沙箱 bash。S2 拒绝的访问即使经批准也失败（与 bash 相同）：
  - 读允许列表之外的 `read.external`；
  - 密钥路径表；
  - 卫星中 `.pi`、`.agents`、`AGENTS*.md`、`CLAUDE.md` 的写入。
- **残余**（如实登记）：
  - (i) 改向 S2 允许范围之内另一路径（如卫星中受保护的文件）的写入。这与 bash 本来就能做到的相同，由事后检测与验证时的 `scope_breach` 兜底（`11` §11.4 已补一句）。
  - (ii) `read` 的名字变体探测在 Host 中进行，只透露存在与否；读取本身仍经辅助进程。
  - (iii) **S0 下没有沙箱**：同一 `operations` 在 Host 中直接执行，分类是唯一的防线，窗口不封闭。

**评级**：
- T3（`11` L684）的主防线由 “S1 路径守卫” 改为 “S2 写允许列表在访问时强制（bash 与文件工具）+ 硬底线”，S1 只决定审批分级；
- T3 评级改为 **低（S2）；高（S0，含 Windows v1）**，并写明 S0 的窗口；
- T26（L707）补 “文件工具的访问同样在 S2 中执行”，评级不变。

**同步**：
- `05` §5.3.5：
  - 骨架加 `createSandboxedFileOperations` 与 `sandboxedFileTools`，`customTools: [sandboxedBash, ...sandboxedFileTools]`；
  - 启动自检扩展到 `bash`、`read`、`edit`、`write` 四个 `<sdk:…>`，不符时降为 S0（回归保护）；

## R92-D6-01（重要）：写回失败后保留 `syncing` 的状态

**决定**：消除这一长期状态。写回在本进程中失败时，任何分支都不留下 `syncing`：
- 还原没有完成，就转入已有的情形 E 重建；
- 来源目录（人工编辑检出或检验目录）一律保留；
- 生成一条 Needs-You，写明交还没有完成、你的副本保留。

**唯一定义**：`06` §6.4.3 `inspect.bring_back` 行的 “写回在本进程中失败”（L914）。
1. **来源目录已不存在时**（T1 是人的改动仅剩的副本），先在原路径以 T1 重新物化它：交还按 `10` §10.8.4 第 2–3 步（内容取 T1，索引仍取 T0），带回按 `10` §10.8.3 第 1 步（不重新播种、不执行脚本与服务）。
2. **还原已写路径**：
   - 交还取写回之前最近的检查点（第 6 步 safety 或第 7 步 `agent_bg_done`，都没有时为 B）中的版本（观察 4）；
   - 带回为 T_pin；
   - 勾选删除的 `.git` 等价条目不还原。
3. **退回写回之前的状态**：一个事务完成（交还 `idle`；带回清除 `human_checkout`）。还原没有完成（出错，或卫星已不在）时，同一事务置 `satellite_rebuilding=1`，按 `10` §10.16.2 情形 E 重建：
   - 仍在的卫星先按 `10` §10.2 改名保留；
   - 接管期间只用检查点 k，带回时为最新检查点 → pin → base；
   - 重建失败按情形 E 升级为 `satellite_missing`。
4. **报告**：返回 `E_INTERNAL`，并生成 Needs-You `stalled{write_back_failed}`。启动续写失败时只有后者。

**出口**：人工编辑检出或检验目录保留。
- 交还：再次 `goal.hand_back`（重建进行中按已有的卫星守卫返回 `E_STATE`）或 `goal.discard_human_edits`；
- 带回：再次 `inspect.bring_back`，此时它的前置条件都成立（检验目录存在、无 `human_checkout`、卫星树等于 pin 的树）。这样不必加新命令，也不必豁免前置条件；或者 `inspect.close`；
- `goal.abandon` 在两种情况下都照常可用。
- 所以 `syncing` 只存在于本进程中正在写的有限时间内（`E_BUSY`）与崩溃到重启之间（§6.1.6 在接受命令之前续写）。命令与自动转移（I2、外部写入检测、重建失败的升级）从不在 “写回已不在进行而 `syncing` 仍在” 的状态上执行，DDL 的 CHECK 不需要改，只改注释（L500）。

**续写删除前比较**（`06` §6.1.6 人工编辑检出一行，L144）：
- 启动续写完成之后、删除来源目录之前，以临时索引比较它与 T1（与关闭检验时的比较相同）；
- 不同时（崩溃之后人仍在编辑器中改动过它）不删除，按 `10` §10.2 改名保留并列出；
- 来源目录只在写回成功、且内容仍等于 T1 时删除。
- 失败通知不再留下 `syncing`，所以 “失败提示之后人改动目录、重启后被删除” 的路径已不存在；这条比较补上崩溃到重启之间同一类的窗口。

**删除**：
- `10` §10.8.4 第 6 步的 `syncing` 分支（交还命令不再遇到它；观察 5 随之消失）；
- `goal.discard_human_edits` 的 “写回失败后保留的 `syncing` 返回 `E_STATE`”；
- `goal.abandon` 的 “带回写回失败后保留 `syncing`” 一句；
- `04` §4.6.7 的 “恢复也失败时……重启 Tower 后也会自动续写”。

**同步**：
- `06` §6.1.6 与 DDL 注释（观察 2）；
- `10` §10.8.3 第 7 步补失败的引用，§10.8.4 检出丢失一条改为 “无法完成时按写回失败处理——先以 T1 重新物化 H”；

## 偏离与未决

- **文件工具不再能写上下文文件**（更严）：辅助进程与沙箱 bash 用同一档位，所以 S2 对卫星中 `.pi`、`.agents`、`AGENTS*.md`、`CLAUDE.md` 的写拒绝同样作用于 `edit`/`write`。
  - 此前 `00` §0.5.1 写 “Agent 改这些文件须用文件工具并经你批准”；现在改为只能由人在 “我来改” 中修改，`00` 如实登记。
  - 未采用 “辅助进程用去掉这条拒绝的变体档位”：分类之后被改向这些名字的写入会因此绕过 `edit.protected`，正是本条要关闭的窗口。
  - 同理，S2 读允许列表之外的 `read.external` 与密钥路径表中的凭据，经批准也读不到（与 bash 已有的行为相同）。分类与审批卡照旧，不为 “注定被沙箱拒绝” 另加分类规则；这类审批之后的失败由工具结果中的沙箱解释说明。
- **R92-D11-02 取删除，没有采用评审期望形态中的 “目录型调用按子树相交判定”**：三个工具在 M1 中没有用途，删除比给分类器加子树规则更简单，也不留下 “子树中的符号链接” 一类后续缺口。评审的第二部分（规范形式）照期望加了一条。
- **R92-D6-01 没有采用评审期望形态中的 “保留 `syncing` 时命令一律 `E_STATE`”**：按指示消除这一状态本身，复用情形 E 重建。
  - 带回的重试出口复用 `inspect.bring_back`，不加新命令；
  - 代价：还原没有完成时要重建整个卫星，比逐路径还原重；
  - 来源目录不在时 Tower 以 T1 重新物化它，是一处新的物化入口，复用两种检出已有的物化步骤；
  - 新增一个 `stalled` 子类型 `write_back_failed`（按指示要求的 Needs-You），没有新增 kind。
- **重新物化也失败时**（来源目录被删除、写回失败、物化再失败的三重失败）：条目如实写 “你的改动未能保留在目录中”，交还随后按 `06` §6.1.6 检出丢失处理。这是登记的残余，T1 只留在影子对象中（`human.decision` 的 `targetTree` 记有它）。
- **S0 下的窗口**：R92-D11-01 只在 S2 下结构性关闭。S0（含 Windows v1、SP6a 不通过时的 B 分支）中文件工具的分类与访问之间的窗口仍在，T3 的 S0 评级为高，并已写明原因。S0 本就是 “只有策略层” 的档位，其 M1 门槛另有书面的残余风险接受记录（`14` §14.3.5）。
- **排期**：R92-D11-01 的估计按真实实现计（0.14 人周），没有压低；M1 维持 38 周，但桌面线与设计线不再有余地默认吸收下一轮的实现性增量。
