## R95-D11-02（次要，本轮分量最重）：S2 的路径规则与同卷硬链接

**唯一定义**：`11` §11.6.2 S2 配置表新增 “硬链接” 一行（L359）。
- **范围**：与钥匙串一行同一范围的沙箱，即 Agent 的 S2（含文件辅助进程）、验证器（§11.6.3）、检验检出的服务与生命周期脚本。
- **规则**：拒绝创建硬链接，不论源与目标在哪里（不按源路径区分，最严格，也最容易写对）。
  - 理由：本表的读写规则都以路径表达，而卫星、验证槽位与用户主检出、主目录通常同卷（ADR-008）。
  - 卫星中原有的文件由 Tower 检出、复制或以写时复制物化，从不硬链接（ADR-021）。所以 §11.3.1 的 “经链接原地写” 只能经符号链接到达，由 S2 在打开时按真实路径判定。
- **写法**：macOS 以 Seatbelt 的硬链接操作（`file-link`）或等价规则写入档位，确切写法以 SP6a A3 的探测为准。Linux S2（M2）的手段与 `.git` 名字一行同列为 M2 决定点。
- **影响**（如实写出）：
  - pnpm 默认的 `package-import-method=auto` 先试写时复制，APFS 上成功，不受影响；
  - 在不支持写时复制的卷上本会硬链接，这时退回逐文件复制，安装变慢、多占磁盘；
  - git 写对象时链接失败即改用改名（git 自身的回退）。
- **验证**：
  - SP6a A3 补 “硬链接一组”（`14` L53）：在 Agent 的 S2 中于卫星内对用户主检出中的文件、密钥夹具与卫星内另一文件各建一次硬链接；在验证器沙箱中对用户主检出文件建一次；另在不支持写时复制的卷上以 pnpm 安装一次。期望创建全部被拒绝，pnpm 退回复制后安装成功。
  - `06` §6.7 启动自检（L1174）在后台以同一档位做一次同样的探测，完成之前不启动使用沙箱的 Run 与验证。
- **回退**（已有规则）：创建未被拒绝时本机不使用 S2。各 Goal 按没有可用的 OS 沙箱处理，走 S0 与 ADR-022 的授权路径（`04` §4.8.5，原因 `本机没有可用的 OS 写入沙箱`），验证结果带 “S0 环境” 限定。SP6a 中出现这一结果时，该 macOS 版本按 §14.3.5 安全门槛的 “SP6a = B” 一列。
- **T 表**：`11` T3 的残余（L687）补一句：S2 的 “低” 依赖这一条；沙箱之外建立的硬链接（T16 一类的沙箱外代码或人自己）不在此列。

## R95-D11-01（次要）：读取凭据例外的适用范围

- **(1) 卫星内的凭据**：`11` §11.3.1 伪代码（L154）改为一条与卫星内外无关的规则：“`read` 或 `edit` 的读取一侧命中密钥路径表 → 追加 `secrets.access`”。卫星之外一支的括注随之删除。
  - 卫星中未跟踪的 `.env`、`*.pem`、`id_*` 因此与 bash 的 `cat .env` 出同一张卡。L163 的 “照常归 `secrets.access`” 现在由伪代码保证。
  - 副作用（更严）：S0 下读取卫星内这类文件由 silent 变为审批卡。这类文件在 M1 卫星中只会是 Agent 或构建工具自己生成的（ADR-165 不播种含机密的本地文件），打扰有限。
  - C42 (f)（`05` L1500）补两组：读取卫星中未跟踪的 `.env` 出同一张卡；读取用户主检出中未跟踪的 `.env` 按第 3 条硬底线直接返回说明、不出卡。
- **(2) 与第 3 条硬底线的先后**（L163）：第 3 条硬底线先于本例外，例外只撤去本条所加的 `hardFloor`。命中第 3 条的调用照常 forbid、不出卡，例如影子、`$TI`、`$VS` 中的文件（它们在 `~/.tower/**` 之下，也命中密钥路径表）。
- **(3) 卡上的 S2 句子**（L163，新的唯一定义 “卡上的 S2 句子”，`04` §4.10.2 与 `12` §12.12 引用）：
  - 只在这次求出的读取路径都落在 S2 读拒绝范围（必然拒绝的同一份路径数据）时，才写 “S2 下批准也不会让沙箱允许这次读取（M1）”。文件工具的这类调用都满足；bash 中路径能求出的读取命令（如 `cat ~/.aws/credentials`）同样满足。
  - 其余 bash 的 `secrets.access` 不写这一句，改写批准之后实际发生什么：
    - `printenv`、`env`、`set` 读到的是 bash 的白名单环境（`05` §5.3.6 `bashEnv`）；
    - `security find-*` 与钥匙串存储的 `gh auth token` 在 S2 中查找钥匙串被拒绝。A8 回退取消该拒绝时，只受钥匙串条目的访问控制与系统授权提示约束；文件存储的 `gh` 令牌在 `~/.config/gh/hosts.yml` 中，读取同样被 S2 拒绝；
    - `op read`、`vault read` 经进程间通信或网络取值，不受 S2 文件读拒绝约束，网络仍只经沙箱代理。
- **同步**：`04` §4.10.2（L1135）：卫星内外相同，硬底线位置中的凭据直接拒绝，S2 句子按条件出现；`12` L681 见观察 10。

## R95-D8-01（次要）：带回一侧的 `write_back_failed` 在检验目录不存在之后无法关闭

- **`08` §8.8 该行**（L516）：“知悉” 由 `needs_you.dismiss`（人按 `X` 关闭）承载，定为 `informative`。
  - 条目不对应任何暂停原因，不是阻塞类（L530 的唯一定义），所以检验目录或副本已不在、再次带回与关闭检验都返回 `E_STATE` 时也可用。

  - 补 “此后成功执行的 `goal.resume`、`goal.take_over` 及 §8.4 所列其他不经本条目出口的事件 → `obsolete`”。

## §5 观察

1. **按调用的缓存**：`11` §11.3.1（L161）写明缓存按调用作用域：Tower 包装三个工具的 `execute`，每次调用以新的 `operations` 构造该次的工具定义。同一批中对同一路径的两次 `read` 各自启动、不共用，中止或结束时随调用丢弃。`05` 骨架注释（L389）同步，`13` 的回退引用同一条。
2. **错误的映射与上限的落点**（`11` L161）：
   - `cat` 的其他失败映射为 Pi 默认实现在同一情形下给出的错误码（如 `EISDIR`），不一律映射为 `EACCES`；
   - 超时、启动失败、崩溃、回复不合规与 16 MB 的失败以不带 `code` 的错误抛出，所以 `edit` 的工具结果保留承诺的文字；
   - S2 下 16 MB 上限在交回的字节流上执行，超出即杀进程；
   - S0 下以有上限的读取循环判定，大小为 0 的特殊文件与读取期间增长的文件同样受限；FIFO 在 S0 下没有时限，如实写出。
   - C42 (g) 补三项断言：目录报 `EISDIR`；`edit` 17 MB 文件时保留文字；两次 `read` 各一个进程。
3. **回退方案的按调用语义**：`13` §13.11.1 文件辅助进程一行（L320）写明：
   - 10 s 上限对共用进程计，它被杀或失败时同批读取一并失败、各自写明原因；
   - `sandbox_violation` 按被拒路径对应到请求它的调用；
   - 缓存仍按调用；
   - C42/G46 的钩子在共用进程启动之前执行。
   - 基线为不经包装的同一命令，`14` A3 同步。
4. **情形 E 的触发处**：`10` §10.16.2 情形 E（L1264）引用 `06` §6.1.6 卫星丢失一行的三条排除。
5. **③ 的部分改名**（`06` L914）：
   - 只有一半改名成功时按改名成功处理：置标记、重建，仍在原位的另一半在重建开始之前同样改名，再失败时按情形 E 升级；
   - 带回时 ③ 的事务提交之后解除对 I2 的抑制、按提交后的状态重新求指纹，卫星停在半写的状态时照常触发 I2。
6. **`syncing` 期间的其他事件**：`06` §6.1.6 卫星丢失一行（L139）改为 `syncing` 期间的任何文件系统事件都不触发本行。清除 `syncing` 的事务提交之后（③，或带回转入 `verifying`、交还完成的事务）按提交后的状态重新判定；卫星在这期间被别的原因删除的，这时触发。
7. **重启清理的顺序与文案**：`06` §6.1.6 “Agent 后台进程” 一行（L145）写明它是 “在接受 UI 命令之前” 的例外：
   - 在冷启动之后后台执行；
   - 完成之前实况行为 `清理中 · 残留进程 · <剩余>/<总数>`（`12` §12.6.4 新增一行，L390；原文案不含对象，与 §12.6.4 “禁止出现不含对象的文字” 不符，所以按该表改写）；
   - 该 Goal 的 Run（含启动时自动解除后的继续目标）在清理结束之后才准入，`goal.take_over` 返回 `E_BUSY`。恢复开场因此总含 `tower.processes_terminated`。
   - `13` L324 改为引用这一行。
8. **`04` L667 的两个罕见分支**（L669）：
   - ③ 改名失败：`写回失败：<原因>。工作目录未能恢复，也未重建；你的副本保留在原路径`；
   - ① 也失败：`写回失败：<原因>。你的改动未能保留在目录中，此后不可恢复`，不写 “你的副本保留”。
9. **`保留的目录` 的位置**：
   - `04` §4.5.2 右栏定义（L354）列入它；
   - §4.5.3 表后（L374）注明各列末尾另有这一行；
   - §4.6.7 的范围改为 `10` §10.2 所列各处（副本、原来的工作目录与它的 gitdir、重新建立副本时的旁路目录），各状态（含评审与终态）都显示。
10. **`12` L680 的措辞**（现 L681）：改为 “注入机密的 `secrets.access` 批准卡片及其风险行属 M2”，并登记 M1 读取凭据卡上的 S2 条件句与改写的后果句（以 `11` 为准）。
11. **`13` L329 的子状态词**：改为验证时 `验证 · 预取 · …`、Goal 启动时并入 preparing 的 `依赖`、人工编辑检出的依赖后台准备中为 §12.6.5 的阶段词 `预取`。`07` §7.4.3（L614）的 “Goal 启动时在 preparing 下” 同样改为真。
12. **`04` L1282 设置页**（现 L1284）：确认框补 “改名保留的 `.kept-*` 目录（含卫星与 gitdir 的）”。
13. **无锚定模式的作用范围**：`11` §11.3.1 密钥路径表（L166）写明这些模式只在卫星工作区中按跟踪状态匹配，在 Pi 资源目录中不论跟踪状态匹配，编入 S2 档位与必然拒绝的路径数据时同样如此；不作用于系统路径、`$SH` 与镜像 `objects/`，其中的 CA 证书包须可读。

## 偏离与未决

- **R95-D11-02 的规则取 “拒绝一切硬链接创建”**，不取评审写法中的 “以写允许范围之外的文件为源”。前者更严，也不依赖平台按哪个名字判定源；代价只是包管理器在不支持写时复制的卷上退回复制。范围按钥匙串一行扩到验证器与检验检出的服务：它们同样运行 Agent 可影响的代码，读写拒绝也以路径表达。
- **R95-D11-02 的平台行为未实测**：Seatbelt 的确切写法（`file-link` 或等价规则）与 macOS 各版本的行为由 SP6a A3 确认。平台做不到时的结果不是缺口，而是本机不使用 S2（S0 + ADR-022）；对使用者而言这是一个很重的降级，如实写出。启动自检多出一次沙箱内的探测，在后台执行，没有另列预算（一次进程启动，量级与文件辅助进程一行相同）。
- **R95-D11-01 (1) 在 S0 下更严**：卫星内的凭据读取由 silent 改为审批卡。接受这一打扰，换取两种工具、两种档位同一规则。
- **观察 13 是收窄**：无锚定的密钥模式不再作用于系统路径、`$SH` 与镜像 `objects/`。这些位置原本就只读，内容来自系统或 Tower 自己；不收窄会拒绝 CA 证书包、破坏 TLS。Pi 资源目录取更严的一边：不论跟踪状态都匹配。
- **观察 7 给 `goal.take_over` 增加了一种 `E_BUSY`**（清理残留进程期间）。这是已有错误码，没有新增命令或状态；`goal.resume` 不报错，只是 Run 的准入排在清理之后。
- **R95-D8-01 用 `needs_you.dismiss` 而不是 `signal.acknowledge`**：前者不改 `06` §6.4.3 的任何命令；后者是其他几类 “知悉” 的承载者，两种写法的类别相同（`informative`）。
- **排期**：W4 按 0.02 计（评审估 0.01–0.02），取上界，因为本轮就写了显式规则与启动探测。M1 维持 38 周，各线余量为正。
- **未决**：无。
