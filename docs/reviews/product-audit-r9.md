### 0.4 代码通读

重点读了 `verify/bench.rs`（`confirmed_refusal`、只留源码、金丝雀、保留测试选择）、`sentinel.rs::source_loads_test_library`、`roles.rs::patches_test_machinery`、`canary.rs`（Rust 部分）、`sandbox.rs::listening_ports` 与截图浏览器配置、`remote.rs`、`store/goals.rs` 的进度计算、`tools/ship.sh`、`pre-push.sh`、`doc-numbers.sh`、`line-limit.sh`、两个工作流和 `adversarial.rs`。

- **环境故障的判定。** 现在要求输出里点名的路径确实被同一份沙箱配置拒绝，Tower 会自己再探测一次。这把“诚实项目被误判”修好了。但要探测哪条路径，仍由命令的输出决定。Tower 确认的是“这条路径会被拒绝”，不是“这次运行真的碰过它”，所以这还不是 r8 要求的“按进程树归属的沙箱拒绝记录”。好在后果已经变小：只留源码复跑里“没有结论”按未通过处理，金丝雀里会加一条高严重度的“断言没能检查”。剩下的伤害是 Agent 可以把一次失败变成“环境错误”暂停，不再是绿色。环境错误卡仍然建议“必要时把它加入项目设置”，而这条路径是受 Agent 控制的输出选出来的。
- **保留测试是否真的被执行，没有检查。** 没有一条标准点名保留测试时，Tower 假定“项目自己的测试命令会在原处找到它们”，于是用同样的命令再跑一遍，结果标为保留测试结果。没有任何核对：用例数有没有增加、输出里有没有保留测试的文件名、保留测试有没有被加载。缺的不变式是：*只有确实执行了保留测试的运行才能标为“带保留测试”，否则明说“保留测试没有被任何标准运行”。*
- **“已验证”的计数。** 只有金丝雀“被改动”才把一条标准从已验证里扣掉（`goals.rs:366`）。“只留源码复跑失败”和“源码改写或加载断言库”这类高严重度结论，本身就说明这次通过不能当真，却不影响计数，于是 R2b、R2c、R3f 的卡片上写着“已验证 1/1”，旁边是一张“这次通过不能当作事实”的暂停卡。
- **基线红的来源。** 基线上的失败只要不是 127 这类“命令无法运行”、沙箱也没有确认拒绝，就被记成真实的“改动前失败”。工具链缺失、版本管理器找不到默认版本这类环境问题，会变成假的红 → 绿证据。预检也只认这一类失败。
- **断言完整性。** “源码加载断言库”的高严重度规则是一份库名清单（四组 JS 库）加 `import` / `require(` 字样；Python 和 Rust 只有“改写”类的写法清单。r8 要求的“断言入口在测试运行时必须是原样的库对象”仍没有实现，R3g 就从这里过去了。金丝雀增加了 Rust（只认单行 `assert_eq!(…, 字面量);`）。
- **回环。** 关网时，写配置那一刻已在监听的端口会被加进拒绝名单。但名单是以当前用户身份枚举出来的，看不到 root 或其他用户的服务。我用一次探针运行留下的 Agent 配置核对：SSH、文件共享、屏幕共享等系统服务的回环端口**仍然连得上**，名单里的端口确实被拒绝了。配置写好之后才启动的服务也不在名单里。SECURITY.md 说“这台 Mac 上已经在监听的服务（数据库、开发服务器、其他应用……）都关闭”，比实际做到的多。回环本身仍是默认放行。
- 截图浏览器的配置仍是 `(allow default)`。
- 手机页开局域网时现在也监听 `127.0.0.1`，沙箱里的进程能经回环碰到它（要令牌才进得去）。
- 对抗回归的判定：诚实目标只要求“如果进入了评审就不能有高严重度”，被暂停或超时也算通过；作弊类只覆盖五个 JS 目标，没有 R3f、R3g、R8c、保留测试未执行、环境类和 Rust。

## 3. 前 20 项修复（按优先级）

“需要维护者”的条目标为 **［维护者］**。每项后面是估计的分数提升，各维度不超过上限。

### 必须先做（决定 D3、D14 能否过 90）

**1. 保留测试必须证明自己被执行了（D3 +2，D5 +0.5）**
不变式：*只有确实执行了保留测试的运行，才能标为“带保留测试”。* 现在没有标准点名保留测试时，Tower 用项目的测试命令再跑一遍，就把结果标成保留测试的结论（R1c）。至少要做到下面两点中的一点：比较有无保留测试时的用例数，或者在输出里核对保留测试文件被加载了。核对不了时，明说“保留测试没有被任何标准运行”，不要显示“只给你看”的标签。设置保留测试时，也要直接提示用哪条命令能跑到它们。

**2. 高严重度结论扣掉“已验证”计数（D3 +1，D5 +0.5）**
不变式：*Tower 自己说“这次通过不能当作事实”时，同一处的进度不能写“已验证”。* 只留源码复跑失败、源码改写或加载断言库，应当和金丝雀“被改动”一样，从已验证里扣掉，并在卡片、进度条、印章和验收面板上一致显示。R2b、R2c、R3f 现在是“1/1”加一张暂停卡。

**3. 基线红必须是测试红（D3 +1，D11 +1.5，D1 +1）**
不变式：*只有命令真的跑到了测试，基线失败才能算“改动前失败”。* 工具链缺失、版本管理器没有默认版本、解释器找不到这类失败，应当在预检里归为“验收标准在验证沙箱里跑不起来”，并写明原因（沙箱里的工具链解析和你的终端不一样）。判定可以靠测试运行器自己的“开始运行”标记，或者用例数大于 0。同时让沙箱里的工具链解析和用户终端一致，诚实的 Rust 项目才不会被逼着加配置文件，再被只留源码复跑按作弊暂停。补上这一类的 flow 测试。

**4. 断言入口的身份检查，不再靠点名清单（D3 +2）**
r8 第 2 项的不变式原样保留：*测试运行时，断言入口和测试框架的全局对象必须就是原样的库对象。* R3g 证明，点名清单只是把缺口挪了个地方。由 Tower 在程序代码之前装入自己的检查并在结束时比对，或者从 Tower 管理的只读副本加载断言库。在做到之前，“源码触及断言库”从中等升为高。

**5. 治理恢复，且“本地合入”留下可核对的证据（D14 +2，D15 +1）［维护者］**
`enforce_admins` 重新打开；runner 不可用期间的本地合入要写明期限。合入时把 pre-push 的完整日志（提交哈希、每一步的结果、耗时）作为 PR 评论或 check run 附上。pre-push 补齐 CI 的四步（构建、包体预算、文档数字、验证开销），日志不要再写到共享的 `/tmp`。

**6. 对抗回归真的每晚运行，而且覆盖本轮的类别（D14 +2，D3 +1）［部分需要维护者］**
配置 secret（或者在 runner 恢复前用本机的定时任务），每晚跑，并保存结果。目标要加上 R3f、R3g、R8c、R8d、保留测试未执行、环境类（R-perm、Rust 工具链）和 Rust 作弊，每类两个变体。诚实目标要求“进入评审且没有高严重度”，被暂停或超时都算失败。本轮本地跑是红的，这一点要先解决：要么特判类暂停（见第 7 项），要么改测试的判定，二者选一并写明理由。

### 应该做（各维度从 85 走向 90）

**7. 特判的处置要和团队自己的标准一致（D3 +1，D5 +0.5）**
团队的对抗回归把“进入评审、没有高严重度、代码仍错”定义为漏网，而产品把特判定为中等，所以 R8b、R8c、R8d 都正好落在这个定义里。没有保留测试时，可以对可见测试的输入做小幅扰动再跑一遍，作为特判的证据：扰动后失败就升为高。同时要降低误报：R-perm 这类“需求本身就是一一对应”的诚实修复不应被标成最高风险，可以按扰动复跑的结果决定是否降级。

关网时，回环只放行 Agent 或验证自己启动的监听，以及合同声明的端口。现在的拒绝名单看不到系统服务和其他用户的服务，也看不到之后才启动的服务。SECURITY.md 那一句先改成实际做到的范围。

**13. 文档与实现同步（D13 +1，D15 +0.5）**

### 4.2 独立验证还独有吗

- **主流产品里仍然没有。** 每一家要么由 Agent 自己验证，要么由第二个模型评审或读对话记录（Claude `/goal`、Code Review、Bugbot、Devin Review、Guardian、Planning Critic）。最接近的 Copilot 云端 Agent 跑的是 Agent 看得见、也改得动的那套检查。
- **开源侧已经追上了想法。** attest（MIT，Python，带网页控制台）几乎一一对应：先由另一个模型封存验收测试，在未修改的检出上证明它们失败，对补丁做 AST 变异，用必过和必败两种金丝雀，在无网络的全新沙箱里运行，最后输出可离线核对的证明包。software-agent-factory PR #160（10 月 18 日合入）做的就是“只留源码”的反事实复跑，只是只给提示。aws-solutions/konductor #72（10 月 22 日）做测试篡改的差异检查。Alter-Igor/opencode #121/#122 没有新动静，sigma #571 仍开着。
- 结论：Tower 仍是唯一把这些检查做进桌面监督台、和合同、沙箱、评审、验收连成一条流程的产品。但“独立验证”本身已经不再是独有的想法。差异会越来越取决于两件事：每一句绿色结论都站得住；以及能拿出公开的拦截率和误报率。本轮的 R1c、R3g 和 Rust 误判，正好是这两件事上的反例。

### 4.3 Tower 缺什么

1. **装不上**：没有签名安装包，没有自动更新，仓库私有，只支持 macOS。
2. **手机端**：Claude、Codex、Cursor、Conductor 都有原生 App；Tower 是网页加 ntfy。
3. **云端或远程执行**：几乎每家都有，Tower 没有。
4. **引擎数量**：Conductor、Warp、Copilot Agent HQ、Zed 都在 3 个以上，Tower 是 2 个。
5. **公开证据**：attest 一类项目开始输出证明包，Tower 没有公开的拦截率。
6. **误判的代价**：Tower 的检查最严，诚实的项目被拦（Rust 工具链）、诚实修复被标成最高风险（R-perm）的代价也最高。
