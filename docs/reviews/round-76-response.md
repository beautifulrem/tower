## 条目

### R76-D11-01、R76-D13-01（次要）：已解决

**唯一定义**：`16` §16.1.12“上下文文件名与受保护名字”一行（L287，原“上下文文件名”一行推广）。
- **比较规则**：凡按名字识别上下文文件或受保护路径之处，名字都按 `10` §10.1.2 的名字比较规则比较。
- **适用范围**：`protected` 的全部模式（ADR-204），即 `02` §2.5 的默认值与 `11` §11.3.3 的补充项，含 `.pi/**`、`.agents/**`、`.mcp.json`、`.envrc`、`.npmrc`、`.husky/**`、`.pnpmfile.cjs`，以及合同中写的模式；另加 `07` §7.6.3 的路径集合。
- **匹配方式**：模式的字面分量与路径分量按该规则比较，通配部分匹配处理后的分量。`scope.include`/`exclude` 不在此列。
- **`contextFiles(dir)`**：Pi 以 dir 为 cwd 时加载的文件，每个目录按候选顺序取第一个存在者，在该目录所在的卷上求值。
- “用到它的四处”改为不计数的写法。

**各匹配处引用该行**：
- `02` L308 注释；
- `11` L208（§11.3.3 导言一句，覆盖全部模式）、L150（§11.3.1 伪代码 `match(scope.protected)`）；
- `07` L1249（`matches(path, fence.protected)`）、L1273（§7.6.3 路径集合）、L1275（“给 Agent 的指令文件”，大小写变体同样标记的范围扩到整句）；
- `10` L514、L525（回退位置的祖先差异改为比较 `contextFiles(checkout)` 与 `contextFiles(回退路径)` 中仓库根以上的部分，与 `09` §9.11 同一函数）；
- `09` L460。

**信任复核**同样改为对完整差异按规则筛出 `.pi`、`.agents` 之下的路径，不再用区分大小写的 pathspec（`11` L584，`05` L491）。

**“双保险”改为真**（`11` L350）：`protected` 按同一比较规则识别 Seatbelt 写拒绝的四个名字；非 ASCII 等价变体只由 `protected` 与复核识别。

**测试**：G46 (bh)(4)（`14` L134）。
- S2 一组：bash 新建 `.NPMRC` 不被沙箱拒绝，验证时 `protected_path` 列出。
- S0 一组：新建 `.PI/prompts/p.md`、`.NPMRC`，并用文件工具新建 `.Mcp.json`。写入时询问；验证时三者都列出；`.PI/…` 标为指令文件。

**没有采用**“只折叠上下文文件与 `.git`、其余登记残余”：推广一处规则即可，多出来的只是多报，与 ADR-203 的取舍相同。

### R76-D5-01（次要）：已解决

**范围**（`11` L584）：与用户在自己的检出中运行 Pi 时相同，即从 cwd 向上、止于最近的含 `.git` 的目录、排除用户级目录。
- Run 的 cwd 是主 binding 的卫星根（`05` RunSpec），对应用户检出的仓库根，正是这一范围的终点。
- 所以第一组只含卫星根自己的 `.agents/skills`。它在 base 树中，已由信任复核的差异覆盖。
- 仓库根以上的 `.agents/skills` 不传入。卫星中没有 `.git`，所以不能照搬 Pi 在卫星中的收集：那样会一直走到根。
- 评审给出两种写法，这里取第一种（止于仓库根）。

**删除**：批准信任时记录各级祖先 `.agents/skills` 与哈希、每个 Run 重新枚举（原 `11` L584 的祖先检查，以及 L585 的“取批准时记录的清单”）。由此：
- 用户级技能不会再经显式路径重复传入；
- 用户改动自己的技能不再使复核为不信任；
- Agent 看到的技能与用户本地 Pi 一致。

**不变式保留**：Agent 可写、未经人批准的项目资源仍不加载。Tower 只从 base 树枚举，worktree 之外的目录不再传入。

**引文改正**：`package-manager.ts:459-491`、`:2464-2468`、`:2556-2567`；`trust-manager.ts:185-207` 只作为“是否询问信任”的出处。

**读取分类**：`16` L251（§16.1.10 `read.pi_resources` 单一来源）补一项“每个 Run 启动时 Host 实际枚举到的已启用技能 `baseDir`”。
- 它与 `11` §11.6.2 S2 读允许中的集合相同，含以显式路径传入的项目技能。`11` L30 同步。
- 经批准的技能被 `read` 读取时不再询问，与 bash 一致。

**测试**：G46 (bh)(5)。
- 只传入 `.agents/skills/s`，父目录的 `p` 不传入；
- `u` 只由 Pi 作为用户级技能加载一次；
- 改动 `u` 后复核仍为信任；
- `read` 读取 `s/SKILL.md` 不需要批准。

### R76-D8-01（次要）：已解决

取“只在自动恢复不进行或失败后生成”。这与 `06` F4、`16` §16.1.7 原有的写法一致，也与 `provider_unavailable`、`satellite_missing` 先自动处理、失败才打扰的模式一致。

**唯一定义**：`08` L386（§8.6.3）。
- 自动“重启并恢复”进行期间不生成条目，实况行与卡片写 `◇ 将自动重试 1 次`。
- 自动恢复不进行（10 分钟内重复崩溃、`autoResume` 为假）或失败时，才生成 `stalled{unresponsive|crashed}`（severity 2，L3）。
- 恢复成功不生成条目，所以没有要随自动恢复关闭的条目，也不影响 §8.8 的精度。

**引用**：
- `06` L64（§6.1.3 Engine Host 一行）、L1179（F4）；
- `16` L195（子类型补 `unresponsive`）；
- `12` L430：自动恢复期间 `◇`，不进行或失败后 `◆`；
- `12` L406：例外由两处改为三处，补 `engine_crash`。

### R76-D12-01（次要）：已解决

`09` L468 改写目标选择：
- **目标**：Pi 在 Run 的 cwd（主 binding 的仓库根）实际加载的那个文件，即 `contextFiles(用户检出)` 中仓库根那一项，以磁盘上的实际名字写入；仓库根没有任何候选时新建 `AGENTS.md`。
- **不再取 `appliesTo.paths` 的公共前缀目录**。核对 Pi 源码时发现，这比评审指出的“每个目录只取第一个候选”更根本：Pi 不加载 cwd 子目录中的上下文文件（`resource-loader.ts:232-274`）。原规则选出的子目录文件，Pi 在任何情况下都不会自动加载。
- 条目的路径范围改为写进文字。

`09` L472：只在目标是 Pi 会加载的那个文件时询问退役；人改选其他文件时提示“Pi 不会自动加载这个文件”，不提供退役。评审给出的两种写法这里都采用了。
