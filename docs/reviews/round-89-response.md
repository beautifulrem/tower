## R89-D11-01：门禁不以服务器实际的工作目录为基准

**决定**：取评审的第一支——以服务器实际的工作目录为第二个基准，工作目录是本 Host 空目录时只检查越出它的结果。

**唯一定义**：`11` §11.3.4 “stdio MCP 服务器的空工作目录与相对路径” (b)（L222）。
- 相对路径以两个基准各解析一次：
  - `roots`（卫星）；
  - 该服务器**实际的工作目录**，即 `05` §5.3.5 求出的 spawn `cwd`：绝对 `cwd` 照用；相对 `cwd`（含 `..`）以本 Host 的空目录为基准求出；未写时就是本 Host 的空目录。
- 任一结果落在第 3 条硬底线即 forbid、不可授权覆盖；命中密钥路径表的归 `secrets.access`；其余至少 ask。
- **唯一的例外**：工作目录是本 Host 的空目录时（未写 `cwd` 或写 `.`），以它为基准求出、仍在该目录之内的结果，不因该目录在第 3 条中而 forbid。
  - 所以 ADR-216 的取舍保留：`owner/repo`、分支名只 ask，R88-D11-02 的误判不回来（不以 `..` 开头的值求出的结果都在空目录之内）。
  - 以 `..` 越出它的结果照常判定：落在影子目录、安装器私有目录、其他 Host 的空目录或主检出的 forbid。
- **残余因此成立**：经批准的调用只能写进本 Host 的空目录，按 (a) 只影响同一 Host 进程中之后启动的服务器；其他 Host 的空目录都在硬底线之内，所以从不跨 Host。

**相对的 `config.cwd`**（`05` §5.3.5，L439）：
- 一律以本 Host 的空目录为基准求出（含 `..`）。
- `.` 求出空目录本身；不含 `..` 的其他值求出其中不存在的子目录，按原文字不启动。
- 含 `..` 的值求出的目录，除原有集合（Agent 可写位置、任一 `<wtRoot>`、`~/.tower/` 之下，本 Host 的空目录本身除外）之外，还不得落在第 3 条硬底线之内（如主检出）；落在其中的不启动，文字 `MCP 服务器 <名字> 的相对工作目录落在受保护的位置，Tower 不启动它；请写绝对路径`。
- 其余照常启动，与写成绝对路径的同一目录相同，门禁以它为基准——两种写法的保护不再不同。
- “相对的 `config.cwd` 实际只有 `.` 可用” 删去。

**同步**：
- `11` §11.3.3 第 3 条（L212）：“以它为基准解析的相对路径只在越出它时按硬底线判定”；§11.3.4 路径检查 (3)（L221）注明例外见 (b)；
- `00` §0.5.1（L99）与 README L19：相对路径按项目根与服务器的工作目录检查；相对 `cwd` 的启动规则；
- C21（`05` L1461）补含 `..` 的相对 `cwd` 三组：求出各 Host 空目录的上一级目录的、求出主检出的都不启动，求出你主目录中另一个目录的照常启动；
- G46 (bk)（`14` L134）补一组：不写 `cwd` 的服务器以 `..` 越出空目录，分别写向另一个 Host 的空目录、影子目录与主检出——三次都被 forbid、不出现审批卡，即使已授予 “本 Goal 内同类”；`sub/x` 仍出现审批卡。原 ADR-215/216 一组的说明改为 “以空目录解析的结果仍在该目录之内，不 forbid”。

## R89-D11-02：路径扫描不认 `file:` URI

**唯一定义**：`11` §11.3.4 “沙箱外工具的路径检查” (1)（L221）。
- `file:` URI 按 RFC 8089 取路径部分（`file:///p`、`file://localhost/p`、`file:/p`），解码百分号转义后视为绝对路径，照 (1) 的硬底线与 (2) 的密钥路径表检查。
- 主机部分是其他名字的不是本地路径，视为不透明参数、至少 ask。
- 其他 scheme 的 URI 照旧不视为路径；(3) 的 `<scheme>://` 排除只对它们成立。

**契约测试**：C21 补一组（`05` L1461）：
- 夹具服务器的资源以 `file:` URI 标识；
- 资源工具以 `file:` URI 读取 `~/.ssh/` 中的私钥文件 → `secrets.access` 的审批卡，只有 “仅这一次”；
- 以百分号转义写出、指向主检出中文件的 `file:` URI → forbid，即使已授予该工具 “本 Goal 内同类”；
- `https://` 形状的参数不按路径检查。

## R89-D4-01：置换后的 `resume` 不移动归因窗口的起点

**决定**：取 “列入”。

**唯一定义**：`03` §3.2.1 “验证失败是否自动返工”（L75）。

## §5 观察

1. **`hostId` 与每个 Host 进程一个**：`11` §11.3.4 (a)（L222）取 “先后规则”，不改目录名：
   - 路径随 `host.spawn` 的启动参数交给 Host；
   - 启动恢复的残留清理在 main 交回存活 Host 的端口之后（`06` §6.1.3）；
   - 同一 `hostId` 的下一个 Host 进程（崩溃后的 “重启并恢复”、挂死后强杀再启动）只在上一个进程确认退出、其目录已删除之后才 spawn，所以退出清理从不删除后继进程的目录。
2. **交接时自检失败的出口**：
   - `03` `prepare_failed` 行的 `running` 入口（L98）与 `06` F4b（L1185）补 “上下文交接时运行时重建、Host 的来源自检不通过（新会话不创建）”；
   - `05` “内置 MCP 的来源自检” 末句（L434）：按运行中途停止的一种进入 `paused(prepare_failed)`，`重试` 是开新的运行；
   - `04` §4.8.11（L974）卡片写 `◆ 运行已停止：…`；C21 交接一组补卡片的期望。
3. **`继续` 按钮的改名**：`04` §4.6.7（L664）注明 `nested_repo_live` 附说明的 `继续` 例外。
4. **硬上限卡片的列举**：`04` §4.18.3（L1508）与 `12` §12.6.5（L439）注明 `claim_on_behalf` 在交还后仍暂停期间置灰；`04` §4.6.7 的置灰提示另写 `先扩展预算，再继续`。
5. **G32 区分不出新守卫**：G32（`14` L108）不再检验 `claim_on_behalf`；G33（L110）的步骤补 “尝试 `claim_on_behalf`”，期望 `E_STATE`、置灰并提示先扩展预算。
6. **`HumanDecision.handBack` 缺 `mode`**：`02` §2.7（L528）补 `mode?: "continue_agent" | "reverify"`，取自 `Goal.humanCheckout.params`，只在 `take_external` 时省略。
7. **被清除 Goal 在其他重放表中的行**：`06` §6.2.1（L221）补：
   - 这些行已随清除删除、事件载荷已墓碑化，重放跳过这些事件，不重新产生这些行，也不因 “由事件产生而旧库中没有该行” 中止；
   - 迁移改动清单 (1) 中其他行的非事件列时，其值同样来自旧行经同一列变换。
8. **最后一次由非事件写入的字段**：同处补 “最后一次写入不是事件的字段同样取被重建的库中的值”，例子是 §6.1.6 检出丢失时清除 `human_checkout`——被重建的库中为 NULL 时取 NULL，不由 `human_checkout.created` 重新写出。
9. **`inspect.bring_back` 期间的并发命令**：`06` §6.4.3 `inspect.bring_back`（L914）补：写回进行中（写入 `syncing` 的事务到转入 `verifying` 的事务之间），该 Goal 上其他会改写状态或 `human_checkout` 的命令（如 `goal.abandon`、`goal.request_changes`、`contract.amend`、`goal.accept`）返回 `E_BUSY`。
10. **Pi 引文**：ADR-216（`15` L3821）的 `runtime.ts:342` 更正为 `:343`，“在该会话中保持 `failed`” 限定为首次连接失败、工具从未注册的服务器，并写明资源工具经 `getClient()` 重新打开（`:237-243`、`:278-300`）。`round-88-response.md` 与 `round-88-lint.md` 是历史记录，未改。
11. **Host 被强杀后的 stdio 服务器**：`11` §11.3.4 (a) 登记为残余：
    - 各在自己进程组中的服务器可能比 Host 活得久；
    - stdin 随 Host 关闭、不再收到请求，多数随即退出，其工作目录照常删除；
    - 仍在运行的属 §11.8.2 “用户确认的那段代码的行为”。
12. **`GIT_CEILING_DIRECTORIES` 的旧写法**：`11` §11.6.2（L359）、T16（L693）、T29（L706）中 Host 一侧改为 `<全部 wtRoot>`；Agent 环境一侧（L363）仍为本卫星的 `<wtRoot>`，与 `05` §5.3.6 一致。

## 偏离与未决

- **相对的 `config.cwd` 多了 “不得落在硬底线之内”，绝对 `cwd` 没有**：
  - 评审只要求把 “只有 `.` 可用” 改为与规则一致的说法。本轮按指示对含 `..` 的相对值另加硬底线一条（例如求出主检出的不启动），而绝对 `cwd` 仍可指向你自己的目录（含主检出，`00` §0.5.1 只劝 “不要这样做”）。
  - 理由：相对值以 Tower 拥有的目录为基准，以 `..` 求出受保护位置的写法几乎只能是误写或被构造的配置，取更严格的一侧；写成绝对路径时是人明确的选择，门禁对落在其中的相对路径照样 forbid。
  - 代价：两种写法在 “能否启动” 上仍不完全相同；在门禁的保护上已相同（都以求出的目录为基准）。
- **例外只给 “工作目录是本 Host 空目录” 的服务器**：评审写的是 “结果在本 Host 的空目录之内的不因此 forbid”，未限定基准。本轮限定为以空目录为工作目录、并以它为基准求出的结果；以卫星或其他工作目录为基准、经 `..` 落进本 Host 空目录的结果仍 forbid（更严，没有新的误判类别——不以 `..` 开头的值不会落进那里）。
- **观察 1 取 “先后规则”，不改目录名**：改成 `<hostId>-<hostEpoch>` 要改动 `00`、README、`05`、`06`、`11`、`14`、`16` 与 lint (d) 中的全部路径写法；先后规则只在唯一定义处加一句，且与已有的 “已存在时先删除” 相容。代价：重启并恢复须等上一个进程确认退出、目录删除之后才开始，这本来就是检测退出之后的步骤。
- **观察 8 只举一例**：“最后一次写入不是事件的字段” 没有逐列清单，正文只点名 §6.1.6 清除 `human_checkout`。评审只发现这一处；其余非事件写入的字段已按 ADR-216 (b) 取旧库的值。
- **评审 §3.1 的 lint 建议未采用**：起点列表只留在 `03`，`16` 与 `07` 不再复述；`06` 的逐字引文已由 (q) 比对，并在本轮实际报出过一次不一致（见 `round-89-lint.md`）。
- **未决**：无。
