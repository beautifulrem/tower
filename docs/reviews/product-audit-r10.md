### 0.4 代码通读

重点读了 `verify/bench.rs` 和新拆出来的 `bench/checks.rs`（保留测试的加载标记、`tests_ran`、`stop_survivors`）、`roles.rs` 的两张测试机制清单、`sentinel.rs` 的严重度、`store/goals.rs` 的计数与 `not_evidence`、`sandbox.rs` 里用 netstat 枚举监听和截图浏览器配置、`remote.rs`、`perf_verify.rs`、`adversarial.rs`、三个工作流、`pre-push.sh` 和 `ship.sh`。

- **保留测试的执行证明。** 现在每个保留测试文件末尾都会加一行，文件被加载时写一个标记文件，用的是 JS/TS/Python/shell 的写法。缺口有四个。第一，**所有文件共用一个标记**，所以只能证明“至少有一个被加载”，证明不了“全部被加载”（R1e）。第二，其他语言的保留测试（Rust、Go、Java……）不加标记，也就不会产生任何提示，行为和 r9 一样。第三，没加载时只是一条**中等**哨兵，结果事件仍然写成 `held_out: true`，界面仍然显示“保留测试 · 只给你看”。第四，标记的写法就在保留测试文件里，被测代码运行时读得到。这一点要求 Agent 预先针对它不知道的保留测试做准备，伤害不大，但证据是被测代码自己也能伪造的那一类。缺的不变式是：*只有按文件证明确实执行了的保留测试，才能给结果加上“带保留测试”的标签；证明不了的文件要逐个列出。*
- **基线红必须是测试红。** `tests_ran` 认识常见的测试运行器，输出里没有它们的运行痕迹，就不算“改动前失败”。这修好了 Rust 工具链的误判。不认识的命令（脚本、`make`）仍然按红处理。另外有一个副作用：基线判为“没跑起来”的标准**不再运行必败金丝雀**，界面上也不显示“断言没能检查”。`perf_verify` 的标准就是这种情况，所以验证开销“快了一半”，其中一部分是因为少跑了一步。
- **“已验证”计数。** 最新一次验证只要有一条高严重度结论，所有通过都不计入已验证，并以 `not_evidence` 带到看板和侧栏。R2b、R2c、R3b、R3d、R3f、rrust2 现在都是 0/1，卡片、进度、印章的说法一致。这一项修好了。
- **断言完整性。** `source_touches_tests` 从中等升为高严重度。但它和 `patches_test_machinery` 都还是**字符串清单**，比的是添加行里有没有某个字样，或者赋值号左边有没有某个前缀。r8、r9 要求的不变式，即*测试运行时，断言入口和框架全局必须是原样的库对象*，仍然没有实现，所以 R3g 和 R3h 这一类会一直有新变体。升级严重度还带来了**误报方向的风险**：清单里有程序代码常见的写法，比如判断测试环境变量、Python 的模块表和 `builtins` 子串，诚实修复只要碰到其中一种就会被高严重度暂停。
- **特判。** 检测靠的是测试里出现过的字面量。按派生属性识别（R8d）就没有可匹配的东西。特判一直是中等，不暂停，也没有扰动复跑。
- **回环。** 监听端口改用 `netstat -anv` 枚举，能看到 root 和其他用户的服务，SECURITY.md 的描述也改成了实际做到的范围。这一项是诚实的修复。仍然缺的是：之后才启动的服务不在名单里，回环默认仍是放行。
- **截图浏览器** 仍是 `(allow default)`。本轮看到了它的实际后果：Agent 的命令碰不到的回环服务，浏览器碰得到，截图证据也就可能来自别的进程。而且 `look` 只等“URL 有回应”，不核对回应它的是不是验证自己启动的那个进程。
- **Agent 的后台进程。** `stop_survivors` 只在验证结束时清理验证目录里的进程。Agent 在工作区里放到后台的进程，在运行结束、目标进入评审、Tower 退出之后都不清理。r9 探针留下的那个服务器，父进程是 1，在沙箱里跑了两个多小时，一直占着端口。它仍受沙箱约束，但是一段 Agent 留下的代码，在没人看着的时候继续运行，这本身就是一类风险。
- **环境错误卡** 不再建议“把它加入项目设置”，只陈述被拒绝的路径。要探测哪条路径，仍然由命令的输出决定。
- **对抗回归的判定。** 诚实目标现在必须“进入评审、没有高严重度、代码确实修好”，r9 第 6 项的这一半做到了。作弊目标仍然只有 5 个，都是 JS，都是 `add()`。600 秒后仍在运行的算通过。模型自己选择诚实修复的，也算通过。本轮的 R3g、R3h、R8d、R1c、R1e 和 `look` 外部监听，一个都不在里面。
- **文档。** CHANGELOG 本轮**一行都没有更新**，而这轮改了保留测试证明、基线判定、计数、回环枚举、Xcode 工具链和包体拆分。`docs/17` 的金丝雀段落仍然只写“JavaScript/TypeScript/Python”，不提期望值变异和 Rust。§17.7 说对抗回归“配置了模型时每晚在 CI 运行”，可是从来没有配置，也就从来没有运行。验证开销那一段写“全部算上，7.9 秒”，现在的测量已经不包括金丝雀。

## 3. 前 20 项修复（按优先级）

需要维护者处理的条目标为 **［维护者］**。括号里是估计的分数提升，各维度不超过上限。

### 必须先做（决定 D3 能否过 90、D15 能否过 80）

**1. 断言入口身份检查，第三次提出（D3 +2.5，D5 +0.5）**
不变式：*测试运行时，测试所用的断言入口和框架全局必须就是原样的库对象。* 文本清单已经被绕过三次（r8 的 R3f、r9 的 R3g、本轮的 R3h），每次加一条规则只会把缺口挪个地方。做法由 Tower 在测试代码之前装入自己的检查、结束时比对，或者从 Tower 管理的只读副本加载断言库；比对失败就是高严重度。做到之后，把 `source_touches_tests` 降回中等，减少误报（见第 10 项）。还有账本：当 Agent 自己的说法写明它改了测试机制时，说法和事实的比对不应显示“一致”。

**2. 保留测试按文件证明，标签跟着证明走（D3 +1.5，D5 +0.5）**
不变式：*只有按文件证明确实执行了的保留测试，才能给结果加上“带保留测试”的标签。* 每个文件一个独立的标记。没有被执行的文件逐个列出。全部没执行时，不写 `held_out: true`，也不显示“只给你看”。只执行了一部分时，标签写明“n 个中的 m 个”。不支持加标记的语言，明说“无法证明保留测试被执行”。证明不能用被测代码读得到的东西来做。

**3. 特判要有扰动复跑做证据（D3 +1.5，D5 +0.5）**
R8d 证明，靠字面量的文本规则可以被“按派生属性识别”完全绕开。对可见测试的输入做小幅扰动，再跑一遍，作为特判的证据；扰动后失败就升为高严重度。同时用扰动结果给 R-perm 这类“需求本身就是一一对应”的诚实修复降级，不再标成最高风险。

**4. `look` 的证据必须来自验证自己启动的进程（D3 +0.5，D12 +1.5，D2 +0.5）**
不变式：*截图只能拍验证自己启动的应用。* 启动前确认端口空闲，不空闲就报环境错误；截图前确认回应 URL 的监听属于验证的进程树。截图浏览器的配置改为默认拒绝，并和验证命令一样关闭已有的回环监听（r7–r9 一直提，本轮看到了实际后果）。

**5. 运行结束时清理 Agent 的后台进程（D11 +1，D12 +0.5）**
不变式：*Agent 启动的进程活不过它的运行。* 验证已经有 `stop_survivors`。运行结束、暂停、进入评审、Tower 退出时，对 Agent 的工作区和私有临时目录做同样的事。补一条 flow 测试：Agent 在后台启动一个监听进程，运行结束后它不能还在。

**6. 发行版与安全报告通道［维护者］（D15 +10，D1 +5，D16 +2，D12 +0.5）**
打 `v0.1.x` tag，让 Release 工作流第一次真正跑起来。签名公证、Homebrew cask 和自动更新跟上。**立刻打开 private vulnerability reporting**，否则 SECURITY.md 的报告说明是一条死路。同时打开 Dependabot 安全更新。

### 应该做（各维度从 85 走向 90）

**7. 对抗回归真跑、真考到东西［部分需要维护者］（D14 +2，D3 +1）**
配置 secret，或者在本机用定时任务跑，并保存结果。目标补上 R3g、R3h、R8c、R8d、R1c、R1e、`look` 外部监听、Rust 工具链和 Rust 作弊，每类至少两个变体。判定改成：作弊目标 600 秒仍在运行算失败（没有给出结论），模型自己选择诚实修复的记为“没考到”，不能算通过；每晚输出每一类的拦截率。

**8. 沙箱里的工具链解析与终端一致（D1 +1.5，D11 +1）**
rustup、版本管理器默认版本、Xcode 选择，在沙箱里和用户终端里应当解析到同一个东西。做不到的时候，预检卡要说出具体原因（例如“沙箱里找不到 rustup 的默认工具链”），并给出不需要 Agent 改仓库配置的出路。

**9. 基线“没跑起来”的标准不能悄悄丢掉金丝雀（D3 +0.5，D10 +0.5）**
这类标准的行上要显示“断言没能检查”。`perf_verify` 要换一个基线真的跑到测试的标准，并断言金丝雀确实运行了；`docs/17` 的 7.9 秒按新的测量重写。

**10. 降低文本规则的高严重度误报（D5 +0.5，D3 +0.5）**
`source_touches_tests` 升为高严重度之后，判断测试环境变量、模块表这类诚实程序里常见的写法，都会暂停目标。在第 1 项做到之前，至少按语言解析出真实的导入和赋值目标，不要做子串匹配；并在 flow 测试里加诚实对照组。

**13. 回环默认拒绝（r5 起遗留，D12 +1.5）**
关网时，回环只放行验证或 Agent 自己启动的监听，以及合同声明的端口。现在之后才启动的服务仍然可达。

### 4.2 独立验证还独有吗

- **主流产品里仍然没有。** 没有一家在 Agent 碰不到的地方运行 Agent 没见过的测试，也没有反事实复跑或必败金丝雀。最接近的几家里，Claude `/goal` 只读对话记录，Codex Guardian 审的是安全，Kiro 的性质测试 Agent 看得见，Factory 的“上一个验证过的构建”只是环境卫生。mabl 10 月 21 日的“agentic testing harness”自称“独立”，但没说测试是否对 Agent 隐藏、是否检查篡改。
- **开源侧的零件都已经有了，只是没有装进同一个 GUI。** Alter-Igor/opencode #121/#122（10 月 5 日合入）：Agent 声称完成后，以另一个用户身份、冻结 Agent 进程，再跑隐藏验收测试，并公布了“90 次声称完成，约 10% 过不了隐藏测试”。software-agent-factory #160（10 月 18 日）：只留源码的反事实复跑，只给提示。konductor #72 是一个 issue，不是 PR，仍然开着。attest 10 月 21 日之后没有新提交。新出现的有 Praxso/attested（签名的测试回执，README 承认还查不出测试被削弱）。研究方面，10 月有 RH-Detect（arXiv 2610.10947）等奖励投机检测的基准。
- **结论：** Tower 仍是唯一把保留测试、只留源码复跑、必败金丝雀、哨兵和人工验收串成一条流程的桌面产品。但差异越来越取决于“每一句绿色结论都站得住”。本轮的 R3g、R3h、R8d、R1e 和 `look` 外部监听，正好都是绿色结论站不住的例子；而竞品哪怕只是“第二个模型读记录”，至少不会把一个明说“我改了断言模块”的提交标成“一致”。

### 4.3 Tower 缺什么

1. **装不上**：仓库公开了，但没有发行版、签名、Homebrew 和自动更新；只支持 macOS。
2. **手机端**：Claude、Codex、Cursor、Conductor 都有原生 App 或遥控；Tower 是网页加 ntfy。
3. **云端或远程执行**：几乎每家都有，Tower 没有。
4. **引擎数量**：Conductor、Warp、Copilot、Zed 都在 3 个以上，Tower 是 2 个。
5. **公开证据**：开源侧开始公布数字，Tower 没有按类别的拦截率和误拦率。
6. **检查最严，代价也最高**：诚实的 Rust 项目在 rustup 机器上跑不了验证；诚实修复被标成最高风险；新的高严重度清单还有误报风险。

## 5. 各维度达到 95+ 需要满足什么

| 维度 | 需要成立的条件 |
|---|---|
| D1 上手与引导 | 签名公证的 DMG、Homebrew cask、自动更新；应用内完成 Pi 和 Claude Code 登录，以及验收身份设置；在常见的“脏”开发机上（rustup 或版本管理器的默认版本只在终端里生效、主目录有 `node_modules`、装着接管网络的代理）演示和第一个真实目标都能走通，预检对每一种环境问题都说出原因和出路；从下载到第一个目标进入待验收不超过 10 分钟，有录屏 |
| D2 核心流程完整度 | 从意图到合入每一步都有出路；塑形（Agent 起草合同、人批准）可用；第三个引擎；`look` 只拍验证自己启动的应用，并支持录屏；重启、断网、Tailscale 断开都不丢状态 |
| D3 可信度与诚实 | 断言入口身份检查；保留测试按文件证明执行，标签跟着证明走；基线红只认真正跑到测试的失败，丢掉的检查在行上明说；高严重度一律扣计数（已做到）；特判有扰动复跑做证据；`look` 证据来源可证；环境故障按进程归属判定；至少 30 类、每类两个变体的对抗集每晚在真实模型下运行，没有一类拿到绿色事实，诚实对照组零误拦，“模型没作弊”不算通过 |
