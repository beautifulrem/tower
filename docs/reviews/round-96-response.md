## Pi v1.2.0 与 Node 核实（`git show v1.2.0:<path>`，`packages/coding-agent/src/` 下）

- **Pi 的全部输出文件经同一个函数写在 `os.tmpdir()`**（R96-D12-01 的依据）：
  - `utils/output-files.ts:17-20`：`createOutputFilePath` 返回 `join(tmpdir(), <prefix>-<16 位十六进制><扩展名>)`（`:19`）；`:23-28` `writeOutputFile`（0600、`wx`）；`:31-34` `createOutputFileStream`。
  - 调用者只有四处：
    - bash 的累加器 `core/tools/output-accumulator.ts:249`（前缀取 `core/tools/bash.ts:424` 的 `pi-bash`，扩展名 `.log`）；
    - MCP `extensions/mcp/tools.ts:70-71`（`pi-mcp`；截断全文与二进制资源，`:180-199`）；
    - codemode `extensions/codemode/execute.ts:338-341`（溢出文本 `pi-codemode-*.txt`）与 `:369`（图像）；
    - 交互模式的 `core/bash-executor.ts:66`（SDK 宿主不用）。
- **Node 的 `os.tmpdir()`**：每次调用时读取进程环境，POSIX 上依次取 `TMPDIR`、`TMP`、`TEMP`，都没有时为 `/tmp`。依据是 Node 文档，另在本机 Node v26.10.0 实测：
  - `TMPDIR=/tmp/xyz/` 得 `/tmp/xyz`；
  - 去掉 `TMPDIR`、设 `TMP` 得 `TMP` 的值；都没有时得 `/tmp`；
  - 进程中改写 `process.env.TMPDIR` 后立即生效。

  所以 Host 环境的 `TMPDIR` 决定 Pi 全部输出文件的位置。
- **bash 子进程不继承 Host 的 `TMPDIR`**：Pi 以 `getShellEnv()` 的整个 Host 环境起步（`core/tools/bash.ts:193`），再交给 `spawnHook`（`:211`）。Tower 的 `bashEnv` 只输出白名单与 `16` §16.8 角色 A 的变量，`TMPDIR` 显式取 Agent 的 `$TMPDIR/tower-<goalId>/`；本轮在 `05` §5.3.6 把它写成单独一行，不再放在“白名单”一行中笼统透传。
- **最终 `details` 与临时文件的条件**：
  - 最终 `details` 只在截断时带路径（`bash.ts:342-343`）；
  - 临时文件按原始字节数、解码后字节数或行数任一超限即建立，可以在 `finish()` 中才建立（`output-accumulator.ts:64-89, 239-243`）；
  - 超时、中止、无退出码时抛错，没有最终 `details`（`bash.ts:371-388`）；错误文本中状态行在最后，其前是命令自己的输出，截断时两者之间另有一行 “Full output: <path>”。

  评审指出的两种 Pi 一侧边缘成立。本轮之后它们只影响“是否复制为证据”，不影响删除。

`@anthropic-ai/sandbox-runtime` 的源码仍不在本地，所以硬链接与安装阶段的档位仍只写到设计层面，确切写法以 SP6a A3 的探测为准。

## R96-D11-01（重要）：回退位置下，卫星内的每次读取都归 `secrets.access`

**唯一定义**：`11` §11.3.1 密钥路径表的 `~/.tower/**` 一项（L167），新增 “**回退位置下本 Goal 的卫星工作区除外**”。
- **范围**：`<wtRoot>` 回退到 `~/.tower/worktrees/…` 时，本 Goal 的卫星工作区（§11.6.2 回退位置例外中 Agent 读写项的第一项）不因这一项命中。对本 Goal 的一切工具都如此：
  - 文件工具的分类（伪代码的读取凭据一行）；
  - bash 命令按参数路径的分类（§11.3.2）；
  - 沙箱外工具的路径检查（§11.3.4 (2)）。

  结果与默认位置相同，即 “回退后权限与默认位置相同”（§11.6.2）。
- **限定**：
  - 只对本 Goal 的调用；其他 Goal 的卫星照常命中，且在第 3 条硬底线之内；
  - 表中其他条目（如其中 base 未跟踪的 `.env`）与第 3 条硬底线照常适用。
- **不除外的项**（更严，如实写出）：回退位置下 Agent 的其余读写项（`_gitdirs/<goalId>`、`_stores/<goalId>/`、`$SH`、`_stores/_shim/`）。文件工具与 bash 按路径读取它们时，比默认位置多归一次 `secrets.access`。日常工作流经 git、包管理器与环境变量访问它们，不经路径参数，所以 A3 “日常工作流与默认位置相同”的期望仍成立。

## R96-D11-03（次要）：无锚定密钥模式的作用范围

**唯一定义**：`11` §11.3.1 密钥路径表的“这些无锚定模式的作用范围”（L167），以 Agent 的写允许范围（§11.6.2 写允许一行）为界分两侧。

**(1) 写允许范围之外**：撤回 ADR-223 的收窄。
- **规则**：处处匹配、不论跟踪状态，编入 S2 读拒绝与必然拒绝的路径数据。范围含主目录与其中的其他仓库、外接卷、Pi 资源目录、`$SH`、系统路径等。
- **唯一的除外是 CA 证书包允许清单**：
  - 系统的 `/etc/ssl/cert.pem` 与 `/etc/ssl/certs/**`（macOS 上为 `/private/etc/ssl/…`）；
  - Homebrew 的 `<前缀>/etc/ca-certificates/cert.pem` 与 `<前缀>/etc/openssl@*/cert.pem`（`<前缀>` 为 `/opt/homebrew` 或 `/usr/local`）；
  - `$SH` 中由 Tower 写入的 `cacert.pem`、`cert.pem`、`ca-bundle.pem`。
- **写法上更严的两处**：
  - 不写成 `/etc/ssl/**`：Linux 的 `/etc/ssl/private/` 存放私钥；
  - 钥匙串文件不在清单中。
- **其他**：
  - Linux 的清单与 `.git` 名字一行同列为 M2 决定点；
  - 镜像 `objects/` 的文件名是对象哈希与 `pack-*`，不命中这些模式，不需要除外；
  - 清单之外命中的文件读拒绝；A3 的日常工作流因此缺文件时补录，只收 CA 证书包。
- **结果**：卫星之外的凭据形文件重新归 `secrets.access`。
  - S2：出带 S2 句子的单向门卡（不再只得到 forbid chip）；
  - S0 与沙箱外工具：按单向门询问，spike 与调研预设下 forbid。

  评审 (1) 列出的四种后果都消失。

**(2) 写允许范围之内**（本 Goal 的卫星工作区与 gitdir、`_stores/<goalId>/`、`$TMPDIR/tower-<goalId>/`）：只作分类、不编入 S2。
- **跟踪状态的来源**：本 Goal 的 base 树（各 binding 的 `baseCommit` 树）。
  - 生成 `policy.json` 时，列出 base 树中名字命中这些模式的被跟踪路径，这些路径按普通文件处理（含 ADR-078 的已跟踪 env 文件）；
  - 不取卫星索引（Tower 从不读它）、检查点或 pin；
  - Run 中新建或新提交的这类文件按未跟踪处理。
- **后果**：
  - 文件工具与 bash 读取命令读它们归 `secrets.access`：spike、依赖升级与调研三种预设下 forbid，其余预设出单向门卡；
  - S2 允许读取，所以卡上按已有条件不写 S2 句子，批准即读到；
  - 不产生 `sandbox_violation`，也就没有误报的凭据哨兵；
  - Agent 运行的程序（如测试读取 `node_modules` 中的 `*.pem` 夹具）不经分类，照常成功。
- **理由**：卫星中不播种含机密的本地文件（ADR-165）。名字形如凭据的未跟踪文件只会由 Agent、它运行的工具或人交还时写入。S2 对它们的读拒绝只拦住 Agent 读自己写的东西，却使依赖这类夹具的测试失败。

**同步**：
- `11` §11.3.1 “卡上的 S2 句子”的条件补写允许之内一句；先后的括注改为用户主检出与 `_human`、`_inspect` 中的 `.env` 也命中密钥路径表、按第 3 条 forbid；
- §11.6.2 读拒绝一行写明模式只在写允许之外编入；
- §11.8 致命三要素的“私有数据”同步；
- `04` §4.10.2 卡片说明、`00` §0.5.1 一行同步；
- C42 (f) 补三组：卫星中 base 未跟踪的 `.env` 与 Agent 写出的 `id_test` 出卡但无 S2 句子、批准后读到；被跟踪的 `id_fixture.pem` 不出卡；主目录 `Downloads/x.pem` 出带 S2 句子的卡；
- A3 补 “`node_modules` 中的 `*.pem` 夹具可读”与 Node、git、curl 的 TLS 连接。

## R96-D6-01（次要）：启动闸门不在准入之中，探测失败没有去向

**并入唯一的启动点与准入**，不新增 `wait_reason`：

  - 验证、安装器、检验检出与人工编辑检出的依赖准备留在各自的队列中，与等待槽位相同。

  - 不满足时 `waitReason = slot`，卡片注明“等待启动自检”或显示 `清理中 · 残留进程`。这与检查 d 的“机器资源”同形。
  - 启动时自动解除与 `goal.resume` 照常执行，Goal 在 `ready{slot}` 中等待。这样它有合法状态：`ready` 的 `wait_reason` CHECK 成立，没有借用不实的“等待槽位”文案。
  - `12` §12.6.5 新增一行 `就绪 · 等待启动自检`（L413），其他排队的启动用同一后缀。

**探测的规格**：`06` §6.7（L1177）。
- 以 Agent、验证器、检验检出与安装阶段四种档位模板各建一次硬链接，与 SP6a A3 的硬链接一组相同（观察 9）。

- 出错、超时或任一档位无法启动，都按“未能确认拒绝”处理，与创建未被拒绝同一去向：
  - 本次启动不使用 S2，各 Goal 走 S0 与 ADR-022 的授权路径；
  - 不重试，下次启动重新探测。

  方向与 “不以路径规则不完整的 S2 运行” 相同。`11` §11.6.2 硬链接一行引用此处。

**“清理结束”的含义**：`06` §6.1.6 后台进程一行（L145）。
- 指终止的一轮完成：逐个发信号、等待清空、到时 `SIGKILL`；
- 仍存活的按 `bg_process_survived` 照常处理，不再阻挡准入。所以杀不掉的进程不会使 Goal 一直不能开 Run，`goal.take_over` 的 `E_BUSY` 也只持续这一轮。

## R96-D13-01（次要）：只丢了一半的卫星

**唯一定义**：`10` §10.16.2 情形 E（L1264）的 “**另一半**”。
- **做法**：工作目录与 gitdir 之一仍在原位时，在置 `satelliteRebuilding` 的事务之前，先按 §10.2 “Tower 自动改名保留”把它改名为 `<原名>.kept-<时间>`。自动重建、人发起的重试与写回失败的 ③ 相同。
- **从不删除**：其中可能有未解除的外部写入，所以取“改名保留”，不取“移入旁路目录、成功后删除”。
- **改名失败**：不重建，按重建失败升级为 `satellite_missing`。
- **排在置标记的事务之前的理由**：这样重建与崩溃续做的原路径上只会有重建自己的目录，`06` §6.1.6 重建中途崩溃一行的“原样移入旁路目录、续做成功后删除”不会删到原有的另一半。

**引用同步**：
- `10` §10.2（L256）“只有三处”改为四处，(d) 为这一条；它的结果写在重建的结果与 `satellite.recovered` 的告知中；
- `06` §6.4.3 ③（L916）的单独规则与 §6.1.6 重建中途崩溃一行改为引用这一条。

## R96-D12-01（次要）：观察器依赖可合并、可丢弃的流式更新

**唯一定义**：`05` §5.3.6 新增 “临时目录” 一行（L473）。
- **目录**：每个 Host 进程一个 Tower 拥有的临时目录 `~/.tower/tmp/<hostId>/`（0700），经 Host 环境的 `TMPDIR` 交给该 Host。
- **生命周期**：与 stdio MCP 空目录同一规则（唯一定义在 `11` §11.3.4 (a)，ADR-216/217/218）：
  - `host.spawn` 时、Host 进程启动之前新建为空；
  - Host 进程退出（含崩溃）后删除；
  - 启动恢复时删除不属于存活 Host 的残留；
  - 同一 `hostId` 的后继进程在删除之后才 spawn，删除失败时不 spawn；
  - 从不在 Host 之间共享。
- **Agent 一侧**：`bashEnv` 显式设 Agent 的 `TMPDIR`（`$TMPDIR/tower-<goalId>/`，S2 可写）；本文档集中 `$TMPDIR` 写法指你的系统临时目录，不是 Host 的。
- **保护**：
  - 它在 `~/.tower/**` 之下，三种沙箱都拒绝读写（`11` §11.6.2 读拒绝一行写明）；
  - 列入第 3 条硬底线（读写，`11` §11.3.3，L219），所以文件工具在 S0 下也直接 forbid，不出卡；
  - Host 派生的 MCP 服务器、扩展子进程与全局根查询继承同一 `TMPDIR`，它们的临时文件同样随 Host 删除。
- **与已有清理的衔接**：`06` §6.1.6（L138）、§6.6.1 与 `10` §10.1.2 的“每次启动清空 `~/.tower/tmp/`”改为保留存活 Host 的目录：在 main 交回存活 Host 之后，只删除不属于存活 Host 的，与 stdio MCP 空目录相同。

**观察器**：`07` §7.2.2（L84）。
- **路径来源**：只取该调用 `tool_execution_end` 的最终 `details.fullOutputPath`。`tool_execution_end` 立即转发、永不丢弃（`13` §13.2 ②、`05` §5.4.7）。
- **校验**：路径是承载本 Run 的 Host 的临时目录的直接子项、名字为 `pi-bash-<16 位十六进制>.log`；复制与删除共用同一次不跟随链接的打开。这回答了“是哪个进程的 `os.tmpdir()`”。
- **超时、中止与无退出码**：不复制，全文取错误文本。

## 偏离与未决

- **R96-D11-03 (2) 是一处放宽**：卫星（以及 Agent 写允许范围之内）中 base 未跟踪的凭据形文件，S2 不再读拒绝，只经 `secrets.access` 分类。这改变了 ADR-078/082 自第 4–5 轮起的“卫星中未跟踪 env 不可读”。
  - **取这一边的理由**：当初那条拒绝保护的是播种进卫星的含机密本地文件，而 ADR-165 之后这类文件不再播种。现在这条拒绝只拦住 Agent 读自己与它的工具写出的东西，并使 `node_modules` 中带 `*.pem` 夹具的测试在 S2 下失败、产生误报的凭据哨兵。
  - **代价**：名字恰好命中的普通新文件（如 `id_utils.ts`）每次经文件工具或 `cat` 读取都要批准，spike、依赖升级与调研三种预设下被拒绝。按评审给出的另一种选择，也可以“如实写出保守行为”；没有采用，因为保守行为会使常见的测试夹具失败。
  - **待你确认**：若要保留沙箱层的读拒绝，另一种做法是在 Run 开始时把卫星中已存在、base 未跟踪的凭据形文件逐路径编入 S2（Run 中新建的不编入）。代价是每个 Run 都要遍历卫星中的未跟踪文件，超出本轮的收敛规则，所以没有采用。
- **CA 证书包允许清单是枚举**：系统与 Homebrew 的位置之外，用户或工具自带的 CA 包（如 `NODE_EXTRA_CA_CERTS` 指向主目录中的文件）在 S2 下本来就读不到；`$SH` 中其他名字的 CA 包由 A3 发现后补录，只收 CA 证书包。
- **R96-D11-01 不除外 Agent 在回退位置下的其余读写项**：比评审写法中的“读写项”更窄，与 ADR-218 的取舍相同。回退位置下按路径读取 gitdir、`_stores/<goalId>/`、`$SH` 的文件，比默认位置多一张卡。这是更严的一边，如实写在唯一定义中。
- **Host 临时目录的位置取 `~/.tower/tmp/<hostId>/`**：沿用已有的 0700、备份排除与 Spotlight 设置。代价是“启动时清空 `~/.tower/tmp/`”在三处改为保留存活 Host 的目录。另一种写法是单独的 `~/.tower/host-tmp/` 一级目录，未采用。
- **观察器不再为超时与中止的命令复制全文**：这些命令的证据只取错误文本，即截断后的尾部与状态行。这是去掉流式更新来源的直接代价。若需要，可由 Host 在转发 `tool_execution_end` 时附上它见过的路径（评审的第一种写法），但这又引入一个按调用的 Host 侧状态，未采用。
- **硬链接探测失败即本次启动不使用 S2，不重试**：一次偶发的超时会让整次启动退回 S0，对使用者是很重的降级。按“未能确认即不使用”的同一方向取舍。S0 卡片的原因与诊断让这一来源可见，下次启动自动恢复，`s0_grant_pending` 随之解除。
- **排期正好落在阈值上**：四条全职线的 M1 剩余都恰为 26.25（未舍入余量 0.125）。按 ADR-136 的口径这仍是“在阈值上”，所以不顺延。若本轮估计再多 0.01（例如 W16 的无锚定模式一项按 0.03 计），设计线会降到 0.11，按同一规则就须顺延到 39 周。删去流式更新路径的节省已按“不足 0.01 计 0”处理，没有用它抵消增量。已写成下一次增量的预设顺延，不再保留可改派的余量。
- **未决**：无。
