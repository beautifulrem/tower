# 对抗评审评分表（Rubric）

每轮评审由一个**独立的对抗 Agent** 执行：它没有参与写作，目标是找出设计中的漏洞、矛盾、未论证的断言与不可实现之处。每个维度 0–100 分。

**100 分的含义**：评审者在该维度上已经找不到任何值得追问的实质问题——每个可预见的问题都已在文档中被回答、被论证、或被明确记录为带有验证计划的已知风险。措辞偏好、可选的锦上添花不扣分。

**Goal 达成条件**：所有维度均为 100，且评审者明确声明“没有可再追问的问题”。

| # | 维度 | 评审者要问的问题 |
|---|---|---|
| D1 | **原论述契合度** | 原论述 P1–P10 的每一条核心观点是否被忠实实现？偏离之处是否给出了证据与理由？是否偷偷回到了 Chat/Session 中心？ |
| D2 | **Pi 哲学契合度** | 是否尊重极简、透明、可扩展、“等特性被证明”？对 Pi 的依赖面是否最小？Pi 事实是否与源码一致？ |
| D3 | **论证与证据** | 关键主张是否有调研支撑？反例是否被正视？竞争格局与差异化是否站得住？ |
| D4 | **领域模型与生命周期** | 实体、字段、写入者、状态机、不变量是否完整、一致、无歧义？边界情形是否有定义的转移？ |
| D5 | **Agent 架构与 Pi 集成** | Engine Adapter、tower-goal 扩展、钩子、事件映射、返工/压缩/交接是否可实现？与 Pi API 是否逐项对得上？ |
| D6 | **系统架构与可靠性** | 进程模型、单写者、持久化、协议、崩溃恢复、退出/休眠、迁移是否严谨？ |
| D7 | **诚实与验证** | 事实/声明分离是否贯彻到数据、算法与 UI？验证器、哨兵、交叉校验的规则是否具体且可证伪？误报如何处理？ |
| D8 | **注意力与交互（UX）** | 信息架构、视图、流程、快捷键、重入、Needs-You 纪律是否回答了北极星问题？是否可逃逸？边界情形？ |
| D9 | **视觉设计与美观** | 设计语言、令牌、动效契约、状态语义、中文排版是否一致、可实现、且服务于原则？ |
| D10 | **性能** | 预算是否具体、可测、可达？关键路径（流式、diff、终端、启动）是否有方案与降级策略？ |
| D11 | **安全与自主度** | 威胁模型、动作分类、沙箱、密钥、信任、单向门是否完备？残余风险是否诚实？ |
| D12 | **记忆与学习** | 作用域、来源、批准、注入预算、可迁移、隐私、学习闭环是否完备且防投毒？ |
| D13 | **隔离、git 与并发** | worktree、检查点、冲突、合并队列、多仓库、恢复是否严谨？ |
| D14 | **路线图与可验证性** | MVP 范围是否清晰可交付？实验是否有假设、方法、指标、阈值？风险登记是否诚实？ |
| D15 | **文档一致性与可执行性** | 文档之间是否有矛盾？术语、类型、编号是否统一？工程师能否据此直接开工？ |
| D16 | **创新与差异化** | 是否有真正新颖、可防御的东西，而非现有产品的拼装？ |

## 输出格式

每轮评审写入 `docs/reviews/round-N.md`：

1. 总评（≤ 200 字）
2. 评分表（16 维度，每维分数 + 一句理由）
3. 追问清单：按维度编号，每条包含 **问题**、**为什么重要**、**文档位置**、**期望的回答形态**；标注严重度（阻断 / 重要 / 次要）
4. 结论：是否所有维度 100、是否还有可追问的问题

作者回应写入 `docs/reviews/round-N-response.md`：逐条说明如何修订（文件与章节）或为何不修订。
