## R108-D13-01（次要）：多附着点下的必需路径

**按指示改为按 Goal 判定**。唯一定义在 `06` §6.1.6 Project 不可达一行（L139）。
- **该 Goal 的必需路径**有三类：
  - 它每个 binding 的附着检出；
  - 它有未删除的卫星、检验检出或验证目录记录（`WorktreeRecord`）时，这些记录所在的 `<wtRoot>`；
  - 它的人工编辑检出。`<wtRoot>` 经 `project.relocate` 改变之后，人工编辑检出仍按原路径计，所以迁移不会把未交还的改动判为丢失。
- **只有该 Goal 冻结**：同一 Project 中附着在其他检出、`<wtRoot>` 在别处的 Goal 不受影响。删掉一个旧克隆或一个 linked worktree，不再使整个 Project 停下。
- **终态 Goal**（`integrated`、`archived`、`abandoned`）不判定、不冻结，因为它们没有待执行的动作。路径不可访问时，它们只在存储面板（`04` §4.15）注明 `不可访问`；对这些路径的删除与丢失判定推迟到可访问。
- ①②③④ 的作用对象随之改为该 Goal：
  - 作用于该 Goal 的命令返回 `E_STATE`；
  - Project 级命令不受本行限制，要访问的路径不可访问时同样返回该 `E_STATE`。
- **`<wtRoot>` 的取法统一**：`10` §10.4.3（L522）改为按附着检出计算、记入 `WorktreeRecord`，与 §10.1.1（L40）一致。“记入 Project 设置” 删除。

## R108-D6-01（次要）：单线程排队；`~/.tower` 所在卷读不出

**按指示，可达性检查按挂载点隔离**（`13` §13.5，L130）。
- **线程分配**：每个挂载点一个 `worker_thread`。挂载点按路径在系统挂载表中的最长前缀求出：只读挂载表、不访问该路径，只决定由哪个线程执行，不作为可达的判据。
- **计时**：5 s 从该次调用开始执行时计。
- **超时**：
  - 该路径按不可访问计；
  - 该线程被放弃（不再向它派发，调用返回后退出），同一挂载点另起一个线程，继续其他路径的检查；
  - 每个挂载点至多有一个被放弃而尚未退出的线程。再次超时时，该挂载点上的全部路径按不可访问计，不再另起，直到被放弃的线程退出。
- **效果**：一个挂起的挂载只影响它上面的路径。
- **符号链接**：经符号链接指向别的卷的路径，按链接所在的挂载点分组。目标卷挂起时，只多占该组一个线程（如实登记）。
- **存在性检查**：`10` §10.16.1 的存在性检查（`turn_end` 前与 10 分钟的定期检查）经同一组线程（L1254、L1256），不再在事件循环中同步调用。
- **`~/.tower` 所在卷读不出剩余空间**：F8 的这一项按未知计（`06` F8 L1202、§6.7 L1186、`16` §16.2.6）。
  - 不因此进入只读（启动时同此），也不因此停在只读，按其余各卷判定；
  - 显示存储提示，`08` §8.1（L38）增一类条件，“四类” 改为 “各类”；
  - 它若确实已满，下一次写入的 `ENOSPC` 再按 F8 进入只读。

## §5 的观察

1. **`idle` 模式的缓存预热**：
   - `11` §11.7.1（L517）的窗口改写：压缩与摘要止于下一次 `turn_start`；缓存预热在默认 `streaming` 模式下止于 settle，在 `idle` 模式下 settle 之后继续，至多到启动它的请求之后 30 min 或会话 `dispose`。
   - `06` §6.2.5（L353）写明：`idle` 模式下 settle 之后的预热用量只在同一会话之后的某次对账中出现，Goal 进入 `in_review` 或终态后不再出现（金额很小，有 US$0.05 的节省门槛）。
   - “每次会话请求之后” 改为 “请求发出之前”。不在受保护设置中固定（D2）。
2. **`retry.ts` 的引文**：`05` §5.3.6 与 D63 改引 `core/agent-session.ts:1204, 3795`。`retry.ts:198, 218` 标为压缩与摘要的 `retryAssistantCall`。
3. **`!` 命令的缓存**：`06` §6.1.4 第 5 项（L101）限定为 `auth.json`。`models.json` 中的 `!` 命令每次 `getAuth` 都执行，与每次模型请求相同。
4. **探测的摘要**：
   - `03` L96、`08` L419、`12` L444、`04` L1516、`16` L29、`05` L486 改为 “同组已存活的空闲 Host”；
   - `06` §6.1.4 删去 “Host 的运行时不能代它判定”。
5. **F13**（`06` L1207）：`tool_call` 处理器出错时阻断工具；`turn_start` 处理器出错时这一次请求照常发出，按 `event` 区分。两者都计入连续 3 次。
