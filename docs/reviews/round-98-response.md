决策：
- ADR-226（`15` 末尾，L4451 起）；
- ADR-225、ADR-224、ADR-201、ADR-159 标题加 “Amended by ADR-226”；
- ADR-133 第 98 轮补记（`15` L1470）；ADR-038 决策行的〔当前值〕（`15` L271）。

本文件关闭 `round-98.md` §4 的 8 条次要条目与 §5 的 9 条观察。行号为修改后的位置。

**收敛规则**（同 ADR-186–225）：只用三种办法关闭条目：
1. 把说法改弱，但保证为真；
2. 删除或推迟不属于 M1 主循环的机制；
3. 在已有的唯一定义处加至多一条守卫、一行或一个字段。

**本轮的取向**：
- 第 97 轮有两条规则放得过宽，带来了评审指出的后果。本轮把它们**收窄**，不再叠加规则：
  - 三要素的私有数据不再因加载了沙箱外工具而计为真，改为一行不阻止批准的风险说明（R98-D11-01）；
  - 写回集合的凭据形排除与改名保留只针对未被忽略、不在本地文件清单中的路径（R98-D13-01）。
- 其余六条各在已有的唯一定义处加一句，引用处只改为引用。

不新增状态、事件类型、表、列、命令、决定种类、Needs-You kind、landmark、`wait_reason` 值或常驻进程。新增的只有合同编辑器上的一行中性说明与探测缓存键的两项。

安全不变式全部保留：
- Tower 不会自动把机密交给 Agent 可影响的进程；存活 Host 的即时投递文件仍只有该 Host 可用，三种沙箱照旧拒绝读取 `~/.tower/**`；
- 回退后权限与默认位置相同；
- Agent 的三种沙箱与安装器安装阶段都拒绝创建硬链接与钥匙串查找；
- 探测未能确认拒绝时不以路径规则不完整的 S2 运行。缓存键加入 Tower 版本与档位模板哈希之后，这一条在 Tower 更新之后也由探测保证；
- Pi 的输出文件对 Agent 读写都拒绝，并且最迟随 Host 退出删除。

三要素一项的收窄只改变警告何时出现，不放宽任何访问：沙箱外工具的每次调用仍逐次 ask，路径检查照旧，§11.3.4 的残余照旧登记。安全问题只写到设计层面。

## R98-D6-01（次要）：只重启 Supervisor 时即时投递目录被清空；drain 一行没有 Host 存活的去向

**(a) 唯一定义**：`06` §6.1.6 检查点写入中途一行（L138），这里已经定义 `tmp/` 的启动清理。用户指示放在 `06` §6.1.6，没有按评审的建议放在 `11` §11.7.0。
- **命名**：交给 Engine Host 的投递以该 Host 的 `hostId` 为 `deliveryId`，即 `run/<hostId>/`。
- **生命周期**：与 `tmp/<hostId>/`、`mcp-cwd/<hostId>/` 相同。`host.spawn` 之前建立，该 Host 进程退出后删除；同一 `hostId` 的下一个进程在上一个目录删除之后才 spawn。
- **启动清理**：在 main 交回存活 Host 之后，只删除不属于存活 Host 的投递，其余投递（安装器第 1 阶段）一律删除。所以只重启 Supervisor 时，存活 Host 的云 SDK 凭据文件仍在。
- 用 `hostId` 命名，是因为它不需要另外持久化 “投递属于哪个 Host” 的映射，与另外两个按 Host 的目录同一套实现。
- **引用同步**：
  - `06` §6.6.1 目录树（L1067）；
  - `05` §5.3.6 凭据一行（L475）；
  - `11` §11.7.0（L450）与 §11.7.1 云 SDK 凭据一行（L518）；
  - `16` 即时投递目录一行（L726）与 §16.1.13 的现值（L411）。

**(b) drain 一行**（`06` L146）：
- 原有的崩溃规则限于 **Host 已不存在**，即 main 退出，或只重启 Supervisor 而该 Run 的 Host 已不存在。
- **Host 存活时**：重新接上后由 Supervisor 继续这次 drain，从 §6.1.4 drain 协议尚未完成的一步续做。
  - Run 未结束时，重新发 `abort` 并等到 `agent.settled`（期间的事件经 `replay` 补齐）；之后与正常结束的 drain 相同：写 `run.ended`，按 `draining_for.target` 执行原目标，`reasons` 非空时同样放弃原目标。
  - Run 已结束时，只执行原目标。
- 不会在 Run 仍活跃时把 Goal 置为 `paused`。

**测试**：G44 (c) 补两组断言（`14` L132）：
- 存活 Host 使用写入即时投递文件的云 SDK 凭据：Supervisor 重启后 `run/<hostId>/` 与文件仍在，之后的模型请求照常成功；
- 人暂停、Run 尚在 drain 中时杀死 Supervisor：Run 结束之后才进入 `paused(human)`。

## R98-D6-02（次要）：Host 崩溃而 Tower 仍在运行时，崩溃 Run 的进程不在终止范围内

采用评审的第一种写法：包括这些 Run 并终止，不是删去 “或 Host” 再登记窗口。

**唯一定义**：`06` §6.1.6 “Agent 后台进程”一行（L145）。
- **范围**加一项：各 Goal 最近一个因 Host 退出或挂死而以 `crashed` 结束、其后尚无新 Run 开始的 Run 的令牌。
  - 用 “其后尚无新 Run 开始” 划定范围，不新增列。
  - 这一轮完成之前，检查 h 挡住新 Run。之后 Tower 再重启时重做一次也无害，因为终止是幂等的。
- 该行写明它也是 **Tower 运行中 Host 退出或挂死之后**的终止范围。

**`06` §6.1.3 Engine Host 一行**（L64）：Host 退出或挂死之后，不论随后是否自动重启：
- 挂死的 Host 先以 SIGKILL 终止，终止之前以它的 pid 为根取后代进程树；
- 再对该 Host 中各 Run 的令牌做终止的一轮，按 ADR-158 取进程树与令牌的并集。已退出的 Host，其后代已被收养，只能按令牌，同 `10` §10.3.1 ②；
- 补 `agent_bg_done` 检查点；
- 重启（自动，或人发起的继续）经准入，检查 h 等到这一轮完成。

**同步**：
- §6.1.10 崩溃恢复（L198）；
- 检查 h 的注释（L320）；
- `10` §10.3.1 ②（L431）与扫描时机、“由此” 一句（L437），后者现在引用范围，不再列举；
- `13` §13.11.1 与 `16` 令牌扫描一行的复述改为只引用（观察 5）。

**测试**：G35c 补 (x)，分 Host 被杀与 Host 挂死两组。期望：
- 两个后台进程都在 “重启并恢复” 之前被终止；
- 新 Run 在这一轮完成之后才开始；

## R98-D6-03（次要）：准入的重算时机缺检查 d 的解除事件

`06` §6.2.4 准入（L298）的重算时机加三项，它们是检查 d、g 的解除事件：
- 资源预留或端口段释放：验证槽位结束、检验服务停止、`inspect.close` 回收端口段；

## R98-D11-01（次要）：三要素在配置了 MCP 的 Goal 上恒为真

按任务指示**收窄 ADR-225**。取最简单且一致的规则：不另设按 Goal 的确认。

**唯一定义**：`11` §11.8 私有数据一行（L544）。
- 沙箱外工具不改变这一项。它们能否读取本地文件、能否把凭据写进卫星，Tower 无法判定：
  - Tower 不按注解分类（§11.3.4）；
  - 静态清单只有路径、哈希与命令行，没有可核实的能力声明（`05` §5.10）。
- 所以这一项对它们记为 “未知”，不计入私有数据。
- 只有可核实地标明能读取本地文件或用户数据的沙箱外工具才计为真。M1 中没有这样的来源；是否由静态清单提供，列为 M2 决定点。

**沙箱外工具风险说明**（唯一定义，表下新增一段，L558）：
- **何时显示**：按静态清单，本 Goal 会加载任何用户扩展或 MCP 服务器时。只注册钩子的扩展也算，它同样以你的权限在 Host 中运行，这回答了评审的 “判定依据” 一问。
- **显示什么**：合同编辑器在 “批准” 上方显示一行中性说明，不用琥珀色。
- **它不是致命三要素警告**：
  - 不使 “批准” 不可用，也不需要理由；
  - 不影响远程 `quick_ratify`；
  - 不计入 E3 的触发率与采纳率。
- 清单确认之前与 `riskTier=high` 时这些工具不加载，所以不显示。

**触发率测算表**按判定规则恢复：
- S2 下私有数据为 “仅当被跟踪的 env 文件密钥扫描命中”。ADR-224 之后，“未忽略 `.env`” 的说法已经不准。
- 用户扩展不改变三项。
- 配置了 MCP 时，警告只在私有数据为真时出现。

由此，表格、`quick_ratify` 的可用性与 ≤ 10% 的目标都重新成立，不需要分层统计。

**同步**：
- §11.3.1 作用范围 (ii) 的括注（L167）；
- §11.3.4 路径检查的残余（L228）；
- `00` §0.5.1 沙箱外工具一行（L102）；
- `04` §4.10.2 致命三要素一条（L1112）；
- T7、T26 与 §11.3.4 末句的分档改为 “是否加载了沙箱外工具”（是否写文件系统无法判定，按能写计），与 “Tower 无法判定” 的说法一致。

**测试**：G46 (bm)（`14` L134）。设置：用户级 `mcp.json` 中有一个服务器，另有一个只注册钩子的扩展；仓库中没有被跟踪的 env 文件。期望：

## §5 观察

1. **硬底线命中的告知强度**：`11` §11.3.3 分类的先后（L219）如实登记。
   - 直接尝试的读取只记 severity 1 的 `policy_block`；同样的读取若经混淆、由 S2 拒绝，记 severity 2。直接尝试的信号反而较弱。
   - M1 不改。按受保护类别提升级别需要另一条守卫，而且必须排除 Host 临时目录，否则会重新带回 R97-D11-02 的误报。
2. **截断标签**：`07` §7.2.2（L86–L89）。
   - 按状态行之前的 `[Showing … Full output: <path>]` 后缀匹配，不按子串；
   - 标签按是否得到全文推导：正常结束且截断、但全文文件未通过校验或已不在时，同样标为 `截断的输出（尾部）`；
   - `00` §0.5.1（L106）同步。
3. **返回文字与作用范围**：
   - 分类的先后对 MCP 与 codemode 的全文文件，改用 §11.3.1 已有的 “以更窄的参数重新调用该工具” 一句；
   - `00` L106 写 “Agent 环境中的 `$TMPDIR`”；
   - 写明本条的作用范围是 Goal 的 Run，Scratch（M2）的真实检出读允许在 M2 限定；
   - 镜像 `objects/` 之外的读取不在第 3 条之内，按密钥路径表的 `~/.tower/**` 一项归 `secrets.access`。S2 与 S0 都出读取凭据卡，S2 下批准也读不到。
4. **只重启 Supervisor 的边缘情形**：
   - **存活 Run 与旧 Run 的存活者**：当前 Run 在存活 Host 中进行的 Goal，其旧 Run 的未解决 `bg_process_survived` 令牌同样不在终止范围，存活期间的复查与归因照常（`06` L145）。所以不出现 `清理中` 与 `E_BUSY`，和崩溃前的行为一致。
   - 探测进行中崩溃、按 Run 的档位、翻转处理的时机：见 R98-D11-02。
   - **Trace 解压文件**：取最小的真实写法（`06` §6.6.4，L1127）。只重启 Supervisor 时，正在打开的解压文件同样被清空，Trace 抽屉提示重新打开、按需再解压。
   - **情形 E 的告知**：如实登记（`10` §10.16.2，L1264）。崩溃落在改名与置标记之间时，告知仍写 “随工作目录丢失”；Goal 页的 `保留的目录` 一行照常列出该 `.kept-*`。
5. **终止范围的复述**：`10` L437、`13` L324、`16` L1068 改为只引用 `06` §6.1.6（随 R98-D6-02）。
6. **措辞**：
   - `00` L106 理由栏改为 “Pi 只在错误文本中给出路径、没有最终 `details`，Tower 不从错误文本取路径”；
   - `14` L216 第 97 轮 W4 摘要补 “运行时版本”；
   - ADR-225 Pi 核实中 “会使该 Host 的工具调用失败” 一句，在 ADR-226 的 Pi 核实中更正为 “更可能使 Host 进程崩溃”。ADR-225 原文作为历史保留。
7. **增人备选的取整**：`14` §14.3.4 写明取整规则：T 先按十进制半进位取到 0.01，再加 2 周缓冲，向上取整为工作周数。本轮的增量正好越过台阶，见下文 “排期”。
8. **存储与隐私清单**：
   - `13` §13.11.3 补命令全文副本一行（L367）。单个副本没有上限，也不在磁盘压力的回收顺序之内，如实登记，按 E6 的实测决定；
   - `09` §9.12.1 补 `~/.tower/tmp/<hostId>/` 一行：未经脱敏的原文，随 Host 退出删除，打包模式下与长寿 Host 同寿；
   - 命令与验证日志一行写明全文副本没有上限、默认进入系统备份。

## 偏离与未决

- **R98-D6-01 的唯一定义位置**：评审建议放在 `11` §11.7.0，本轮按任务指示放在 `06` §6.1.6 检查点写入中途一行。`tmp/` 的启动清理本来就在这里，`11` §11.7.0 改为引用。

- **R98-D6-02 取 “包括并终止”**，没有取 “删去 ‘或 Host’ 并登记窗口”。
  - 范围以 “各 Goal 最近一个以 `crashed` 结束、其后尚无新 Run 开始的 Run” 划定，不新增列。代价是 Tower 在这一轮完成之后、新 Run 开始之前重启时会再扫描一次（幂等）。
  - 已退出的 Host 的后代只能按令牌识别，进程树已不可得；脱离进程树且读不到环境的进程仍是 ADR-158 登记的窗口，没有变化。
- **R98-D11-01 收窄 ADR-225，而不是如实写出或按 Goal 确认**：
  - 对配置了 MCP 的用户，致命三要素警告不再恒出现，只在私有数据由其他来源成立时出现；
  - 沙箱外工具可能把真实凭据写进卫星的残余仍登记在 §11.3.4，并在合同编辑器上以一行说明告知，但不阻止批准；
  - 这是对第 97 轮 “取更严的一边” 的有意回退：一条在一类用户上恒为真、又无法清除的警告，会使人习惯性地坚持批准，削弱的正是这条警告存在的理由；
