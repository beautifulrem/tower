# 第 104 轮评审回应

决策：
- ADR-232（`15` 末尾，L4804 起）；
- ADR-231、ADR-212、ADR-079 标题加 “Amended by ADR-232”；
- ADR-231 的 R103-D5-01、R103-D6-02 两条与 Pi 核实 R103-D5-02 一条补〔ADR-232 更正〕；
- ADR-133 第 104 轮补记（`15` L1513）。

本文件关闭 `round-104.md` §4 的 7 条次要条目与 §5 的 12 条观察。行号为修改后的位置。

**收敛规则**（同 ADR-186–231）：只用三种办法关闭条目：
1. 把说法改弱，但保证为真；
2. 删除或推迟不属于 M1 主循环的机制；
3. 在已有的唯一定义处加至多一条守卫、一行或一个字段。

**本轮的取向**：用最简单的约束代替新机制。
- R104-D5-01 不另起只做检查的进程，标注只取 Host 已有的检查。
- R104-D5-02 不在会话结束时注销扩展的 provider，改为一条打包的分组约束。
- R104-D6-01、R104-D6-02 沿用已有出口：§6.1.4 第 5 项、§6.1.6 `verifying` 一行、`10` §10.3.1 “启动恢复”。

新增的只有：
- Host 向 Supervisor 报告的检查结论（每个有导入密钥的 provider 一项，只在 Supervisor 内存中）；
- 模型选择器的两种标注文字与尚无结论时的一句；
- Host 启动时安装的代理分发器（Tower 的代码）；
- `05` §5.11.1 的依赖行 D63、D64 与契约测试 C43、C44；
- `06` §6.7 自检剩余空间一项覆盖的卷（加上各 `<wtRoot>` 所在卷）。

不新增状态、暂停原因、事件类型、表、列、命令、决定种类、Needs-You kind、landmark、`wait_reason` 值、锁或常驻进程。

安全不变式全部保留：
- Tower 不会自动把机密交给 Agent 可影响的进程。模型密钥仍只经运行时注入、只在 Host 内存中，Host 环境中仍没有任何模型密钥。`auth.json` 中的 `!` 命令只在 Host 中执行。扩展注册的 provider 不再收到导入的密钥。
- 打包的分组使 `riskTier=high` 与清单确认之前的 Goal 的模型请求从不经过用户扩展的代码：“高风险 Goal 不加载扩展” 在模型请求的路径上同样成立。
- Host 环境不引用 Agent 可写的位置。代理分发器只读 Host 环境中已有的代理变量，不新增变量；`NODE_EXTRA_CA_CERTS` 的排除不变。
- 沙箱外的 Tower 进程不在 Agent 可控的 git 元数据上运行 git。
- Tower 从不自动删除人的工作现场，也不删除另一个 Tower 安装正在使用的目录；租约过期而未接管的一段同样不删除。

安全问题只写到设计层面。

## R104-D5-01（次要）：首次运行与模型选择器的标注由哪个进程求出

取评审的第二种写法（标注只取 Host 已有的检查），不另起只做检查的进程。

- **唯一定义** `11` §11.7.1 模型凭据一行（L517）补 “标注取自 Host 的检查”：
  - 判定只在 Host 中求出；`auth.json` 中的 `!` 命令也只在 Host 中执行，Tower 的其他进程不求值、不执行它们。
  - Host 把每次检查的结论（每个有导入密钥的 provider 一项：凭据是否来自你的 Pi 配置）交给 Supervisor，Supervisor 只在内存中保留最近一次。
  - 模型选择器按它写 `已有你的 pi 配置中的凭据，Tower 用它` 或 `Tower 用导入的密钥`。
  - 还没有结论时（首次运行在任何 Host 之前，或 Tower 启动之后还没有 Host 检查过），写 `第一次运行时由 Pi 判定：你的 pi 配置中已有凭据时 Tower 用它，导入的密钥只在没有时使用`。
- **同步**：`05` §5.3.6 首次运行（L489）、`04` §4.18.1 第 2 步（L1461）改为这一写法；ADR-231 R103-D5-01 一条加〔ADR-232 更正〕。
- **测试**：G46 (d) 第八组的期望改为首次运行写上一句、第一个 Run 之后模型选择器写 `已有…`；第九组 `$VAR` 与 `!` 命令两组的期望改为模型选择器写 `Tower 用导入的密钥`，`!` 命令只在 Host 中执行。
- **不取 “短时的探查进程”**：它要另起一类进程，并在 Host 之外再执行一次你的 `!` 命令（可能再次触发密码管理器的提示），而真实的 Host 仍可能因进程缓存得到不同的结果。

## R104-D5-02（次要）：扩展注册的 provider

- **(a) 探查看不到它们**：`11` §11.7.1 补 “扩展注册的 provider”：
  - Host 运行时 `getRegisteredProviderIds()` 列出的 provider（扩展新建的，或以同名覆盖内置 provider 的），Tower 不注入导入的密钥、已注入的移除，认证由该扩展自己处理；
  - 每次检查都跳过它们；Host 的第一个会话创建之后（扩展在此时注册）、第一次请求之前再做一次这一步；
  - 代价如实登记：只覆盖 `baseUrl`、依赖 shell 中密钥变量的扩展在 Tower 中判为未配置，按 F7 处理；请把密钥写进 `pi /login` 或 `models.json`。
- **(b) 生命周期**：**唯一定义** `06` §6.1.1 “打包的分组”（L42）：
  - 只把加载同一扩展集合的 Goal 放进同一 Host：`noExtensions` 相同，且为假时已确认清单的哈希相同；
  - 所以 `riskTier=high` 与清单确认之前的 Goal 从不与加载用户扩展的 Goal 共用 Host；
  - Host 的扩展集合在它的第一个会话时确定；之后集合不同的 Run（清单重新确认、`riskTier` 改变）不在该 Host 上开会话，改在相符的或新起的 Host 上开（专用模式下即先让旧 Host 按 §6.1.8 退出）。
- **同步**：
  - `05` §5.3.6 “Pi 运行开关” 一行（L481）的 “Host 不因它们重启” 改为 “Host 环境不因它们变化”，并引用打包的分组；
  - `06` §6.1.1 代价一句（L44）：高风险与确认之前的 Goal 另占 Host，节省的内存随之变小，设置页同一句注明；
  - `11` §11.7.1 范围一句、`16` Host 粒度回退规则一行（L878）引用；
  - `05` §5.11.1 D64（L1450）与契约测试 C44（L1506，锁定 “会话结束不注销” 的现状）。
- **测试**：G46 (d) 第十组：扩展以自己的密钥覆盖 Anthropic；打包模式下高风险 Goal 与加载该扩展的 Goal 同时就绪；暂停不足 5 分钟期间清单重新确认。
- **不取 “会话结束时注销该会话的扩展 provider”**：Pi 没有这条路径，Tower 要自己记录并逐个注销；打包模式下并行的会话仍会互相看到。

## R104-D5-03（次要）：SDK 嵌入的 Host 中，代理变量不使模型请求经过代理

- **唯一定义** `05` §5.3.6 代理一行（L474）补 “模型请求怎样经过代理”：
  - Pi 的 `configureHttpDispatcher` 只在 CLI 入口调用、不从包入口导出，SDK 嵌入的 Host 不经过它，Node 的全局 `fetch` 默认不读代理变量；
  - 所以 **Host 启动时，Host 环境中有代理变量的，在任何模型请求与 MCP 连接之前，以 Tower 自己的代码安装同一做法的分发器**：undici 的 `EnvHttpProxyAgent` + `setGlobalDispatcher`，同样替换全局 `fetch`，undici 取 Pi 所依赖的同一版本；
  - 模型请求与 HTTP 类 MCP 连接因此与终端中的 `pi` 一样经过代理、遵守 `NO_PROXY`；
  - Pi 设置中的 `httpProxy` 不读取，代理请设在登录 shell 的环境变量中（如实登记，`00` §0.5.1 同一行）。
- **升级复核**：`05` §5.11.1 D63（L1449，C 类）；契约测试 C43（L1505）：只能经代理出网的测试网络中模型请求与 HTTP 类 MCP 连接都经过代理，并断言 Pi 的函数仍不导出、选项与 Tower 的副本相同。
- **测试**：G46 (d) 第九组的 CA 一组改在只能经代理出网的网络中进行，并连接一个 HTTP 类 MCP 服务器。
- ADR-231 Pi 核实 R103-D5-02 一条加〔ADR-232 更正〕。
- **不取 “在 Host 环境中加入让 Node 读代理变量的开关”**：它依赖 Node 版本，且与 Pi 自己的做法不同。

## §5 的观察

1. **`!` 命令的同步阻塞与失败缓存**：`11` §11.7.1 写明同步执行，第一次检查时至多阻塞该 Host 的事件循环 10 s（低于 30 s 的挂死判定，打包时其他 Goal 的心跳随之推迟）；失败的结果同样缓存到 Host 退出；`models.json` 中 `!` 形式的 `apiKey` 每次请求都执行、不缓存。
2. **探查运行时的副作用**：`11` §11.7.1 写明构造时在锁内同步重读（至多约 200 ms 的忙等），`auth.json` 不存在时建出 `{}`，与 Host 自己的运行时相同；不联网、不刷新 OAuth、不加载扩展。
3. **没有 `key` 的存储条目**：`11` §11.7.1 “少见配置” 登记：Bedrock 只带 `env.AWS_PROFILE` 的条目判为 `stored credential`、不注入，终端在 shell 有令牌时用令牌、Tower 用该 profile；Vertex 的存储 ADC 配置同理；`/login amazon-bedrock` 存下的条目不带 `env`，只在手工编辑时出现。
4. **`!` 命令在 Tower 中失败、终端中成功**：随 R104-D5-01，模型选择器写 `Tower 用导入的密钥`；`11` §11.7.1 写明它包括这一情形，两边可能是不同的账户。
5. **D57 的标签依赖**：D57（`05` L1443）的复核范围补列没有 `models.json` 覆盖的内置 provider 自己的 `resolve` 给出的标签（`helpers.ts:21`、`anthropic.ts:31`、`amazon-bedrock.ts:62, 69`、`google-vertex.ts:72, 85`、`cloudflare-auth.ts:50`，经 `models.ts:679-680`）。Pi 升级的复核清单另增 D63、D64。
6. **`models.json` 的 `$VAR`**：`11` §11.7.1 写明 `apiKey` 写为 `$VAR` 而 Host 环境中没有该变量时判为没有（`provider-composer.ts:447-449`），照 ADR-049 导入并注入，与终端结果相同。
7. **残留与措辞**：
   - `05` §5.3.6 凭据一行（L475）删去 “Azure 配置目录等”，改为 “只有这几个”；原句登入 `16` §16.1.13 第 104 轮一行（L655），由 (D) 检查，变异检查起作用。
   - `05` §5.10 的确认卡片（L1354）把 MCP 服务器与扩展分开写：工具链变量列六个，“扩展另看到 PNPM_HOME”，并注明 `mcpBaseEnv` 不含 ④。
8. **CA 的两个边缘**：`00` §0.5.1 S2 的 CA 一行（L114）登记：
   - S0 下代理变量透传给 bash 而 `NODE_EXTRA_CA_CERTS` 不进入；
   - 根证书只在钥匙串中时 Node 需要另一个开关，它不在 Host 环境的列表中，请导出为文件并设 `NODE_EXTRA_CA_CERTS`；
   - 补 “指向 Agent 可写的位置时不传入”，以及 Pi 的 `httpProxy` 不读取。
9. **租约过期而未接管的窗口**：`10` §10.2（L259）的只读条件改为 “本机尚未接管，含租约已过期而人尚未确认接管的一段”；`06` §6.1.9（L184）写明人确认接管之前照只读处理、目录照样标注、不删除。
10. **F8 的几处呈现**：
    - `12` §12.8 横幅文字改为 `…；释放空间后自动恢复可写`，说的是 Tower 自己的可写与准入，`resumeOnLaunch` 关闭时同样成立；
    - `04` §4.18.3 只引用 `12` §12.6.5；

## 偏离与未决

- **R104-D5-01 取 “标注只取 Host 的检查”**，不取短时的探查进程。代价：首次运行时不能告诉你结论，只写条件句；Tower 重启之后到第一个 Host 检查之前，模型选择器同样只写条件句。
- **R104-D5-02 取 “打包的分组”**，不取会话结束时注销。代价：
  - 打包模式下高风险 Goal 与清单确认之前的 Goal 另占 Host，节省的内存变小（设置页注明）；
  - 只覆盖 `baseUrl`、依赖 shell 中密钥变量的扩展在 Tower 中不可用（如实登记，出路是 `pi /login` 或 `models.json`）。
  - “扩展注册的 provider 不注入” 是按方向执行的取舍：终端中同一扩展会用 shell 的密钥，Tower 不交给它。
- **R104-D5-03**：
  - 分发器是 Tower 对 Pi 未导出代码的一份副本，随 D63 与 C43 在 Pi 升级时复核；
  - Pi 设置中的 `httpProxy` 不读取：读取它要在 Host 环境的封闭列表之外再引入一个来源，代理请设在登录 shell 中（如实登记）。
- **R104-D6-01 中间状态检查在只读启动时推迟**：其间 UI 可用，会写数据库的命令返回 `E_STATE`。
- **R104-D6-02**：`ENOSPC` 之前已写入的失败结论按标准失败计，不另判别（如实登记）。
