# 第 36 轮评审回应：`05`、`06`

以 ADR-162 为准。每条一行：条目 → 修订位置。

- R36-D15-01（`05` L974）→ `05` §5.6.5：`secrets.access` 动作类在 M1 照常分类凭据读取类命令，只有注入部分推迟到 M2。
- Agent 简报与钥匙串 → `05` §5.3.6 读允许列表行：简报写明 M1 不提供任何密钥库机密；S2 的 Seatbelt 配置拒绝钥匙串服务查找（设计层，规则唯一在 `11` §11.6.2，SP6a A8 测量）。`06` §6.6.1 “密钥”行：钥匙串条目以 ACL 限定为 Tower 的代码签名身份，`secrets.enc` 为回退。
- R36-D6-01（机密阶段）→ `06` VerifierScheduler 行按 `07` §7.4.1 改写：先跑不带机密的标准并释放槽位；失败或阻断哨兵 → 跳过机密阶段；否则不持槽等待“无 Agent 活动” → 取槽位 → 冻结 → 注入前完成准备（depcache 只读、不回写）→ 逐个注入运行 → 终止进程、释放、解冻；冻结上限；`run_now` 只跳过等待，`as_file` 走普通槽位不冻结。“Agent 活动”改为按原则引用 `11` §11.7.0。
- R36-D11-01（冻结清单）→ `06` §6.2.4 与 VerifierScheduler 行：冻结清单加入“其他验证”。
- `ask_user` 机密提示 → `06` `needs_you.answer` 行：文本匹配机密模式时返回 `E_CONFIRM{reason:"looks_like_secret"}`，人确认后带 `confirmSecret:true` 重发；`ProtoError.code` 加入 `E_CONFIRM`。
