# 第 15 轮评审回应 · `04` 与 `12`

一行一条：条目 → 处理位置与方式。依据 `15` ADR-134 – ADR-136、`02` `Continuation` / `StopCondition.id` 与 `03` §3.2.1 “离开 `paused` 的唯一规则”。

| 条目 | 处理 |
|---|---|
| R15-D4-01 / ADR-134 唯一规则 | `04` 新增 §4.8.11 “暂停之后去哪里”：继续目标在第一次暂停时写下、叠加原因不改；全部原因解除时先执行交还选择，再执行继续目标；守卫——树 ≠ pin 时一律重新验证。凡写“回到 X”处都指向 §4.8.11 |
| R15-D4-01 #take_external（`04` L645） | §4.6.7 `放弃你的改动`：不记 `pendingHandBack`，去向选择置灰；对话框写明“目标继续因外部改动暂停；采纳或撤销后回到接管前要做的事” |
| R15-D4-01 #keep（`04` L860） | §4.8.7 `采纳`：暂停前在运行 / 收尾 → 继续运行或收尾；在验证 / 评审 → 以你的改动重新验证；有其他原因时只解除本项 |
| R15-D4-02（`04` L861） | §4.8.7 `撤销`：不改写继续目标，只有树 ≠ pin 时才重新验证；之后只检查 E 中的路径，Agent 在收尾回合改的其他文件不算新的外部改动 |
| R15-D4-01 #detectedIn | §4.8.7 导语删去 `externalChange.detectedIn`；卡片头部“检测时：待验收”改为“之后：回到待验收”，并说明选中“采纳”时预览为“以你的改动重新验证”；`12` §12.6.5 `external_change` 文案改为“之后：<继续目标>” |
| R15-D4-01 #discard（`04` L648） | §4.6.7 `放弃改动`：去掉“检测时状态”；其余情形按 §4.8.11；外部改动已存在时路径并入同一张卡片，基线与继续目标不变 |
| R15-D4-01 #nested_repo_live（`04` L892） | §4.8.9 线框删去“消失后自动解除”；新增条目：条目自行消失时卡片改为 `‖ 条目已消失，确认后继续`（`paused(human)`），不自动继续；`12` §12.6.5 增加对应文案行 |
| R15-D8-01 / ADR-135 stop_condition | `04` 新增 §4.8.10 卡片：继续 → `goal.resume`；修订合同后继续 → `contract.amend` → `goal.resume`；这里不该停 → `goal.resume{feedback:"stop_condition_false_positive"}`；去重键 `stc:{goalId}:{conditionId}`；`12` §12.6.5 `stop_condition` 行指向该卡片 |
| R15-D5-01 / ADR-135 Tower 注入 | `04` §4.7.2：Tower 发起的回合（恢复、返工、交接、`tower.processes_terminated`）一律标 `Tower 注入`，不显示为你；`12` §12.3 新增 `⚙ Tower 注入` 标签规则（不用 `HumanStamp`），并加入 §12.16 第 26 行 |
| R15-D7-01 / ADR-135 mixed | `04` §4.6.4 hunk 作者：`混合`（`Checkpoint.mixedPaths`）不显示为“你的改动”、不计入 Agent 统计；§4.7.2 与 `12` `TimelineScrubber` 的采纳检查点把混合路径单列；`12` §12.4.4 `--diff-external` 注释同步 |
| R15-D11-01 / ADR-136 known_hosts | `04` §4.8.6 与 §4.6.5 示例：`~/.ssh/**` 属于 `credential`，默认良性条目写作 `(credential, write, ~/.ssh/known_hosts)` |
| R15-D14-01 / ADR-136 重新 seal | `04` §4.6.5 线框去向下增加 `◇` 行（分支顶端已不是上次的汇总提交 → 创建 `…-v2`，原分支不动），并补规则说明；F7 第 4 步同步 |
