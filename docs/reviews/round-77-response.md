## 条目

### R77-D8-01（次要）：已解决

**唯一定义改写**：`08` L386（§8.6.3）。
- 自动 “重启并恢复” 期间不生成条目。
- 重启解除 `engine_crash` 后，照常经准入与准备阶段（`06` §6.2.4）。其中的失败按 `prepare_failed`（Host 握手、开场组装）或 `satellite_missing`（卫星重建）自己的条目处理，不另生成 `stalled{crashed}`。因此删去 “失败” 分支。
- 只在两种情形下生成 `stalled{unresponsive|crashed}`：
  - 上一次崩溃后 10 分钟内再次崩溃，不再自动重启；
  - 应用启动时因 `resumeOnLaunch` 关闭而没有自动解除。
- 删去 “`autoResume` 为假” 分支：`engine_crash` 的 `autoResume` 恒为真（`06` L64），不按次数改写。

**启动时**（`06` L101，§6.1.4 第 5 项，一条守卫）：已生成该条目的 `engine_crash` 在启动时不自动解除，由人处理。重复崩溃的 Goal 因此不会在每次启动时再崩一次，这是更严格的一侧。

**选项**：“结束本 Run” 改为 “放弃（`goal.abandon`）”，不处理则保持暂停（§5 观察 7）。

**引用**：
- `06` L64（Engine Host 一行）、L1179（F4，注明重启中的准备失败归 F4b/F14）；
- `12` L406（导言）、L430；
- `16` L195（映射行）、L63（Mode 表，观察 7）；
- `04` L1510。

**测试**：G43 (r)（`14` L131）。
- 自动重启时 Host 握手失败：只有 `stalled{prepare_failed}`，没有 `stalled{crashed}`；
- 10 分钟内连续崩溃两次：第二次后生成 `stalled{crashed}`，重启 Tower 后仍暂停、条目保持打开、没有自动重启。

### R77-D12-01（次要）：已解决

**目标**：`09` L468，第 2 步，唯一定义。取 Run 的 Pi 在 cwd（卫星根）实际加载的那个文件，只在 base 树上求值，也就是 `Project.defaultBaseRef` 在镜像中的当前提交。

- 复制补丁时不自动询问，人可以手动退役。

### R77-D13-01（次要）：已解决

取第一种写法，以 `09` L460–L463（§9.11）为唯一定义。
- **何时计算**：卫星不在默认位置时，每个 Run 开始前计算。“不在默认位置” 包括人设置了 `worktreeRoot`，或强制回退。
- **比较什么**：比较两个完整的 `contextFiles()`。仓库根以上的各级按路径比较，仓库根这一级按名字比较；没有对应项的即为缺失文件。

### R77-D13-02（次要）：已解决

取第一种写法，在 `16` L703（`ProjectLocalFile` 行，唯一定义）加一条守卫。

**`add` 时检查**：`project.local_files.add` 只接受在用户检出中被 git 忽略的路径，即 `git check-ignore` 为真；被跟踪的路径不算。
- 不满足时返回 `E_STATE`。
- 提示先把路径加入 `.git/info/exclude`（只在本机，影子会复制它，`10` §10.1.2），或加入 base 中的 `.gitignore`。

**复制前复核**：每次复制前的重新判定同时复核这一点。
- 不再被忽略的条目这次不复制，按 “不可读或不存在” 一条处理：不改写 `secretBy`；本应复制的条目发 L1 通知。
- 已在卫星中的副本不改动，与 ADR-176 只对变为机密的条目删除副本的做法相同。

**建议同步**为 “先让 git 忽略它，再加入清单”：
- `00` L89；`11` L349；`09` L463；
- `05` L1329；`06` L890；
- `14` G46 (ap)。

**残余**（已写进 ADR-205）：只靠用户检出中未提交的 `.gitignore` 改动忽略的路径，`check-ignore` 为真，但在卫星中不被忽略。
- 所以提示首选 `info/exclude`。
- 这样的文件若进入检查点，照常出现在差异中，上下文文件按 `protected_path` 阻断。
- 危害与评审的界定相同。

**测试**：G46 (bh)(6)（`14` L134）。
- 未被忽略的 `AGENTS.md`：`add` 返回 `E_STATE`；
- 加入 `info/exclude` 后：照常播种，Agent 的 Pi 加载它；它不进入检查点、pin、seal 与差异，`protected_path` 与复核都不列出它。
