# 第 33 轮评审回应 · `04` 与 `12`

依据 `15` ADR-159（机密投递的统一模型，唯一定义在 `11` §11.7）。

| 条目 | 处理 |
|---|---|
| 机密标注（取代 R32 的写法） | `04` §4.10：默认 `env` + 独占窗口，带机密的标准标注 `运行期间其他 Goal 的 Agent 暂停新工具调用（独占窗口）`；项目关闭独占窗口时改为风险标注；`file` 方式不标注，跳过计数增加时提示 `该标准以文件注入机密，请确认测试读取 <NAME>_FILE`；§4.15 项目设置增加“机密独占窗口（默认开）”；`12` 同步 |
| 独占窗口状态 | `04` §4.10：其他运行中目标的实况行 `‖ 等待机密窗口（G-0136 的验证）`；`12` §12.6.4 新增一行（中性） |
| `verify_env_error{stage:"secret_window"}` | `04` §4.10：等待超过 5 分钟时的需要你卡片，三选一 等待 / 中止其他 Goal 的当前调用 / 以 file 方式重试；`12` §12.6.5 新增一行 |
| MCP 设置 | `04` §4.15：引擎页 MCP 服务器行在 `env` 有形如机密的值时提示 `建议改为由该服务器自己读取钥匙串或文件`（只显示键名）；`12` 同步 |
| 提示清单补齐 | `04` 卡片第 5 行提示清单补 `base_unchanged_nonancestor`、`base_fetch_failed`（保留到下一次成功获取）、文件注入提示；F7 第 5 步补获取总时限 60 秒与 `base_fetch_failed` 的显示；`12` 词表同步 |

## 工时

独占窗口的实况行与需要你卡片、标准行三种标注、MCP 提示：**0.05 人周**（前端 0.04 + 设计 0.01）。

## 仍需他人处理

| 事项 | 需要谁 |
|---|---|
| `secret_window` 卡片“中止其他 Goal 的当前调用”的命令名 | `05`、`16` |

补充：`secret_window` 卡片的“中止其他 Goal 的当前调用”只在挡住窗口的是 Tower 自己的沙箱 bash 调用时出现（只中止该次调用、不暂停那个目标）；扩展或 MCP 工具的调用只提供 等待 / 以 file 方式重试，并注明“无法单独中止”（Pi 1.2.0 的限制）。`04` §4.10 与 `12` §12.6.5 同步，工时不变。
