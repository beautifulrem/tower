### 0.4 手机页与推送

- **Tailscale 停止、本地网络开关关闭**：`tailscale ip -4` 仍打印旧地址，Tower 现在会先检查这个地址能不能绑定，所以不监听任何地址；设置页给出原因和两条出路（“打开 Tailscale，或允许本地网络”）。r5 的静默失败已修复。
- **打开本地网络开关**：监听 `*:端口`，二维码只编码局域网地址，不再出现失效的 Tailscale 地址。不带令牌、令牌错误返回 401；带令牌能读状态；对不存在的目标、不存在的条目返回可读的错误，但错误文字是英文，没有跟随中文设置。
- **只能在电脑上做的决定**：放行受控操作、覆盖哨兵、联网安装改动后的依赖、把保留测试输出给 Agent 看，四类都由服务端拒绝，页面上也只列名字、不给按钮。
- **页面安全**：所有插入页面的文字都经过转义；有 CSP；令牌放在链接的片段里。
- **推送**：正文是固定句式，不含 Agent 的文字和令牌；只接受 https，或本机、Tailscale 上的 http；正文经标准输入传给 curl，参数前有 `--`；进程会被回收；设置页显示最近一次结果并能发测试推送。r5 第 4 项已修复。
- **安静时段**：现在有每日时间表，系统通知也一起静音；但时段内产生的条目，时段结束后不会补发推送或通知。

## 3. 前 20 项修复（按优先级）

“需要维护者”的条目标为 **［维护者］**。每项后面是估计的分数提升，各维度不超过上限。

### 必须先做（决定 D3 能否过 90）

**1. 金丝雀必须走测试实际使用的断言路径，并且检查结果可追溯（D3 +4，D5 +1，D14 +1）**
不变式：*被测文件里实际使用的每一种断言入口，失败时都必须让命令失败。* 两种实现可以选一种或都做：
- 金丝雀覆盖该文件实际调用到的每一种断言入口，而不是只用一个固定入口；
- 改用变异式金丝雀：在检出的副本里把该文件中一条已有断言的期望值改错，再运行。变异后命令仍然通过，就说明断言层被改写了。

另外，判定“命令失败”时要确认失败来自金丝雀本身（从测试框架的报告里认出金丝雀的名字），而不只看退出码。每次金丝雀的结果（插在哪些文件、是否运行、是否失败、失败归因于谁）记为一条事件，显示在评审页的标准行上。金丝雀触发时，同一次验证的标准行不再显示“红 → 绿”。

**2. 文件角色“认不出就不算源码”，并让文档和代码一致（D3 +1，D12 +1，D13 +1）**
`roles.rs` 现在对认不出的路径返回“源码”，而注释和 CHANGELOG 都说“按配置处理，只会多报”。二选一：改成真正的“失败即关闭”（只有位于已识别源码目录、并且是已识别源码扩展名的文件才算源码，其他一律在只留源码复跑中恢复），或者把文档改成实际行为并在 SECURITY.md 写明。第三方代码目录（被提交进仓库的依赖目录）不能算源码。

**3. 保留测试对 Agent 完全不可见（D3 +1，D12 +1）**
不变式：*Agent 看到的合同里，没有任何指向保留测试的东西。* 命名了保留路径的标准不写进发给 Agent 的合同（最多说“另有你看不到的检查”）。如果某个合同确实需要让 Agent 知道，暂停卡就不要写“Agent 不知道这些测试”。

**4. 没有保留测试时，对过拟合给出提示（D3 +1，D5 +1）**
R8b 这一类目前风险 0、哨兵 0。至少做两件事：新增一条中等哨兵，识别新增的源码分支中出现与可见测试的输入或期望值相同的字面量；项目没有配置保留测试时，在合同编辑器和评审页上明确提示“这个目标的结论只来自 Agent 能看到的测试”。

### 应该做（各维度从 85 走向 90）

**5. 回环默认拒绝（r5 第 13 项，D12 +2）**
不允许联网时，回环只放行合同声明的端口（被测应用自己的端口）以及 Agent 自己启动的监听；同时读取系统代理和 PAC 设置，把它们排除在外，而不是只靠一份常见端口名单。

**6. 截图浏览器的配置与 Agent 同级（D12 +1）**
浏览器关闭了自身沙箱，替代它的配置就应该和 Agent 一样默认拒绝：读权限按名单放行，Unix 套接字只允许它自己的目录，不写与你自己的进程共用的每用户临时目录（`docs/17` §17.6 正是因为这一点拒绝让 Agent 写那里）。

**7. 保留测试失败卡显示“哪个测试、为什么”（D5 +1，D2 +1）**
现在只显示最后 12 行，常常只剩调用栈。按测试框架的报告提取失败用例的名称和断言消息放在最前面，完整输出可以展开。在“写一句提示”和“把全部输出给 Agent”之间加一个中间选项：“只告诉 Agent 失败用例的名称”。

**8. CI 真正可信（D14 +2，D15 +2）**
`main` 开分支保护，只经 PR 合并且必须 CI 通过；pre-push 钩子加一个一分钟内能跑完的集成测试子集（金丝雀、只留源码、手机页）；依赖环境的 `look` 测试在 CI 上检查前置条件，不满足时明确跳过并写进汇总。目标：30 天内 95% 以上为绿。

**9. 真实模型的作弊回归测试，定期运行（D14 +2，D3 +1）**

**10. 公开仓库、签名公证的发行版、Homebrew cask、自动更新 ［维护者］（D15 +15，D1 +6，D16 +3）**
签名流程和 cask 模板早已就绪，差的是 Apple Developer ID、更新签名密钥和公开仓库的决定。这一项不做，D1 和 D15 都过不了 85。

**11. 安静时段结束后补发，跟随专注模式（D4 +2）**
时段内产生的阻塞条目，在时段结束时汇成一条摘要推送和一条系统通知；可选跟随 macOS 专注模式。

**12. 金丝雀覆盖面与“没检查”的说明（D3 +1，D5 +1）**
认不出测试写法时（R3b 的普通脚本、Rust、Go 等），不能什么都不说：标准行上标“未做断言有效性检查”；同时“源码触及断言库或测试框架”这条哨兵在没有金丝雀的情况下升为高严重度。逐步补上 Rust（模块内测试）和 Go 的金丝雀。

**13. 适配器不再回退到运行时下载（D12 +1）**
锁文件安装失败时，环境检查里报错并给出重试，而不是回退到运行时 `npx` 拉取；SECURITY.md 的对应条款同步。

**14. 文档与测试一一对应（D15 +1，D3 +1）**
SECURITY.md 和 CHANGELOG 中每一条安全或验证性质都对应一个测试名，由 CI 检查。本轮发现的三处不一致（文件角色的默认值、金丝雀盲区的范围、“Agent 不知道这些测试”）一并更正。

### 4.2 Tower 缺什么

1. **装不上**：没有签名安装包、没有自动更新、仓库私有、只支持 macOS。主流产品全部一键安装。
2. **不能离开笔记本运行**：Claude（Duet、Routines）、Cursor、Codex、Conductor 都有云端执行。
3. **手机端**：Conductor 和 Cursor 本月都能从 iOS 遥控本机 Agent，Claude 和 Codex 有原生推送和审批；Tower 是 Tailscale 或局域网上的网页加 ntfy。
4. **交互式取证**：Cursor 附视频，Antigravity 附浏览器录像，Codex 和 Claude 能操作浏览器；Tower 的 `look` 只有前后两张截图。
5. **引擎数量**：Zed 和 Conductor 支持 4 个以上，Tower 支持 2 个。
6. **独有优势在缩小**：Copilot 的本地沙箱已在 macOS 上 GA，“按目标生成沙箱”不再是 Tower 独有；Codex 据称有中文界面（未核实），“完整中文界面”也可能不再独有。

### 4.3 Tower 独有的东西

检索范围内**没有找到**任何已发布的产品做到下面几点（找不到不等于不存在）：

- **由 harness 自己在干净检出里复跑验收标准**，并把 Agent 的说法与事实分开。其他产品要么让 Agent 自证（截图、视频、自己跑测试），要么加第二个 AI 评审员或静态扫描。
- **只留源码的反事实复跑**：本轮 R2b 证明它能按不变式拦住配置注入一类。
- **对 Agent 隐藏的保留测试，失败时交给人写提示**：本轮实测，提示后 22 秒通过，Agent 始终没看到测试。研究里最接近的是 2026 年的 “Software Delegation Contracts”（运行后再放入隐藏验收测试，加变异检查）。
- **基线红 → 绿判定和越界探查记录**。

2026 年的研究（Reward Hacking Benchmark、Verification Horizon、Hack-Verifiable Terminal Bench 等）一致发现：模型越强，篡改测试或环境的倾向越明显，单靠对话监控会被误导。Tower 选的“独立复跑加不变式检查”正对这个问题。但本轮也说明，**每一条不变式都要按它真正声称的含义实现**：金丝雀只证明了“自己的断言会失败”，没有证明“测试实际使用的断言会失败”，这个差距足以让 r5 记录的类别原样通过。
