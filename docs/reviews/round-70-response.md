## 偏离指示之处

- **R70-D13-01**：指示建议在每个目录中放实例标记文件（记录不可变实例 id），并在路径已存在时改用带后缀的新路径。本轮做法不同：
  - **没有写标记文件**：`02` 中 Goal 没有不可变的实例 id。编号在本机不复用之后，目录名中的 `<goalId>` 本身就是实例标记，标记文件不会多提供信息。另外，`_inspect` 中的标记文件会出现在人的编辑器里，也会进入第 7 步与 T_pin 的比较。
  - **为什么高水位丢失时仍成立**：分配时还会跳过已有同名目录与 `refs/tower/<编号>/` 的编号。因此即使有人手动删除 `~/.tower`、高水位文件随之丢失，规则依然成立。
  - **没有改用带后缀的路径**：沙箱规则与 `16` §16.8 的路径简写都按 `<goalId>` 拼路径。编号不复用之后，路径已存在只剩人为或崩溃造成的情形，此时拒绝并列出更保守。
  - **代价**：“我来改”在交接中途崩溃后，残留的 H 会使下一次“我来改”返回 `E_STATE`，需人移走后重试。这是对人的数据更保守的一侧。
  - **范围**：只读用户仓库的 ref，不写，与“清除从不写用户仓库”一致。
- **R70-D11-01**：分类器的硬底线只为 Agent 的读写项除外，不为只读项（`$SH`、`_stores/_shim/`）除外，因为后者本就不可写。检验检出的“临时目录与服务数据目录”不在 `~/.tower` 之下，不进入例外。
- **R70-D6-01**：取“为每个 Goal 各追加一条 `filesDone`”，没有取“以 Project 的完成事件一并视为完成”。这样续做行的判据（同一 `scope`、`id` 配对）不需要例外。
- **R70-D4-01**：取预填生效额度并改比较对象，没有取“修订保留扩展”。后者需要逐字段记录是否改动；预填之后，新版本本身就记下了生效值。修订预览没有另加“合同值 / 生效额度”两栏，因为预填后两者相同，字段旁注明“含已批准的扩展”即可。
- **观察 4**：没有给常驻 `Notes:` 行加条目 id，否则会占用 120 token 的常驻预算。改为把改写移到事务之前。

无。以下各项不是遗留问题：
