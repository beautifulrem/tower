**收敛规则**（同 ADR-186–236）：只用三种办法关闭条目：
1. 把说法改弱，但保证为真；
2. 删除或推迟不属于 M1 主循环的机制；
3. 在已有的唯一定义处加至多一条守卫、一行或一个字段。

**本轮的取向：不留任何之后可能删除数据的推迟续做**；不丢你的工作；全部不变式保留。两条重要条目同源：一个保守的 “推迟” 或 “不删除”，因为没有记下推迟或留下了什么，后来变成 “删除过多”（D12-01）或 “永远不删除也不告知”（D13-01）。两条都在已有的唯一定义处关闭：
- 清除一次完成。不可访问的根由你在确认框中接受 “不触碰”，记入库外的一个小清单，只用于列出；
- 迁移把旧位置记入 Project 行已有的 `settings` JSON，存储面板与清除照常找到它。

新增的只有：
- `~/.tower/purge-leftovers.json`（清除遗留清单）：只含根的路径与清除时间，Tower 自有、在数据库之外；“清除全部” 与 `goal-id-hwm` 一样保留它；
- `Project.settings` 的两个字段：`relocatedFrom: [{checkoutPath?, wtRoot, at}]` 与 `defaultCheckout`（后者此前只在 `10` §10.1.1 中提到、没有落点）；
- 存储面板的两种标注（`迁移后遗留`、`清除时未删除（当时不可访问）`）与一段确认框文字（`原路径已不可访问，未交还的修改将无法取回`）。

不新增状态、暂停原因、事件类型、表、列、命令、决定种类、Needs-You kind、landmark、`wait_reason` 值、锁或进程。

安全不变式全部保留：
- Tower 不会自动把机密交给 Agent 可影响的进程。
- 路径不可访问时，Tower 对任何 Goal 都不删除、不改名、不重建，也不执行丢失处理。路径丢失的确认由你发出，只写数据库。
- 人的工作现场不自动删除（ADR-228）。
- 清除从不写用户仓库，也不再有之后会删除数据的续做；`project.relocate` 仍仅本机。

安全问题只写到设计层面。

## R109-D12-01（重要）：推迟中的 “清除全部” 在完成时删除此后新建的数据

**按指示，清除从不推迟**。唯一定义移到 `09` §9.12.4 “不可访问的根”（L575）。`06` §6.1.6 隐私清除一行（L143）、Project 不可达一行的出口（L139）与 §6.4.3 `privacy.purge`（L952）只引用它。
- **确认框**：列出这时不可访问的 `<wtRoot>`。判定只按 `roots[].wtRoot`，用同一组线程与 5 s。确认框写明：其下 Tower 创建的目录（卫星、`_gitdirs`、`_verify`、`_stores`）这次不会删除，之后 Tower 也不会自动删除。你接受后才执行。
- **记录**：这些根不写入事件的 `roots`，只记入 `~/.tower/purge-leftovers.json`，只用于列出。执行中或崩溃续做中才变为不可访问的根，同样不触碰、记入清单，并在结果中列出。
- **一次完成**：其余部分（`~/.tower` 中的副本与可访问的根）在这一次中删除。完成即追加 `filesDone: true`；`all` 档随后删除数据库，应用回到首次运行（`09` L569，`04` §4.18.1）。
- **之后**：清单中的根重新可访问时，存储面板把其下 Tower 创建的目录列为 `清除时未删除（当时不可访问）`，由你一键删除（`10` §10.2 “列出的来源” L259，§10.3.2 “清理工作目录” L457）。清单从不触发自动删除；某个根下已没有这类目录时，该项移除。
- **`project` 档**：崩溃之后的续做在接受界面命令之前完成（`06` L143），所以不会删到再次添加的同一项目（同一 ProjectId）此后的 `~/.tower` 内容。
- **删除**：“`all` 档的数据库在全部完成之后才删除” 及其推迟续做。lint (d) 新增 `deferred purge continuation`，取严格模式；被取代的说法登记到 `16` §16.1.13（L660）。
- **同步**：`04` §4.15 的存储面板与清除确认框（L1287）；`14` G35e (q) 的清除一组（L120）。

## R109-D13-02（次要）：旧路径上的人工编辑检出与检验检出使 Goal 永远不可达

**按指示**，`06` §6.1.6 Project 不可达一行 ③（L139）增一个例外：**路径丢失的确认**（唯一定义）。

## R109-D7-01（次要）：验证的非零退出按全部必需路径判定；反向竞争未登记

**按指示**，`06` §6.1.6 的 “失败先判可达”（L139）只判定**该操作实际读写的路径**：
- 验证：槽位所在的 `<wtRoot>`，以及 pin 所在的影子；
- 写回：来源目录与卫星；
- 重建与接管物化：卫星与要物化的目录。

**反向竞争**登记为可接受（`06` L139，`07` §7.4.1 L499，与磁盘满一句并列）：卷短暂停顿使操作失败，而判定时卷已恢复。这时按真实的失败执行失败出口：
- 验证记为失败，计返工；
- 写回生成 `stalled{write_back_failed}`，人工编辑检出保留。

操作确实失败了，不丢工作。

**伪代码**（`07` L465）：在 `recordFact` 之前补这一判定。
